# STRATA 数智教学系统

STRATA 2.0 是一套面向中学课堂的教学系统。老师可以在这里备课、组织课堂活动、布置测试和评价，学生可以在课堂中查看资源、作答、提交作品并参加小组学习。

系统可以部署在学校自己的服务器和局域网中。日常教学数据保存在校内，不要求学校把学生数据上传到公共云平台。AI 和在线文档都是可选能力，没有配置时也不影响普通备课和上课。

> 项目目前处于持续开发和学校试用阶段，部分研究功能仍需结合真实教学继续验证。

## 老师可以怎样使用

### 课前备课

- 建立课程和课时，并分配给自己的任教班级。
- 按实际教学顺序安排课件、视频、网页、题目、任务和作品提交。
- 从共享题库选题，也可以维护自己的题目并组成测试。
- 提前设置自评、互评和教师评价内容。
- 按需要使用自己的 DeepSeek API 辅助生成题目、评价内容和学习网页。

### 课堂教学

- 开始课堂后，按环节逐步向学生投放学习内容。
- 使用签到、随机点名、抢答、倒计时和课堂广播。
- 查看每道题的提交人数、作答结果和正确情况。
- 开启实名文字聊天，可分别使用全班聊天、师生私聊和小组聊天。
- 开启小组合作，为小组安排成员、协作文档和共享文件空间。
- 课堂结束前按需要开启学生自评、小组互评和教师评价。

### 课后查看

- 查看学生作答、附件、测试结果、课堂表现和评价记录。
- 查看日、近 7 日、近 30 日和单元学习情况。
- 查看系统给出的教学关注建议，并由老师决定是否采用。
- 查看隐性分层和分组建议。学生端不会显示内部层级。

## 一节课怎么走完

1. 老师在“课程备课”中建立课程并选择任教班级。
2. 新建课时，按课堂顺序加入资源、题目、任务和评价内容。
3. 到“课堂教学”中选择课时和班级，新建本次课堂。
4. 开始课堂，在独立的课堂控制台逐个投放学习环节。
5. 根据需要开启签到、互动、小组合作、聊天或评价。
6. 结束课堂，查看学生完成情况和课堂记录。

### 关于“第 n 周学习任务”

课堂实际绑定的是“课时”，不是固定周次。系统不限制一门课程只能有 8 周或 8 个课时。

当前开发数据中出现的“第 n 周学习任务”只是模拟出来的课时名称，不是老师必须填写的周次字段。新建课堂时可以按课时名称或序号搜索，因此一学期安排多少个课时都可以。

### 关于小组共享空间

每个小组的共享文件空间默认是 **20 MB**，界面会明确显示单位 `MB`。老师可按本节课的任务需要调整容量。这个空间主要用于课堂过程材料和小组成果，不建议当作长期网盘使用。

## 四类账户

系统对外只有超级管理员、学校管理员、教师和学生四类账户。

### 超级管理员

用于维护多所学校、学校管理员和系统运行情况，也可以导入成员校交付的数据包进行跨校汇总。成员校不需要持续连接一台公共云服务器。

### 学校管理员

负责本校的教师、学生、班级、任课关系和学科前测；查看本校数据是否完整，以及模型训练和发布情况。学校管理员不代替老师制定课堂评价或调整具体教学活动。

### 教师

负责本人任教班级的课程、课时、课堂、学生、题库、测试、评价标准、资源、公告和留言。老师可以确认、拒绝或人工调整系统给出的教学建议。

### 学生

学生端以课程学习和课堂参与为主，不使用管理后台式页面。新生首次登录后可以修改密码、选择班级并完成相应学科的前测，再进入后续学习。

## 学习记录有什么用

系统记录的是与教学有关的过程事实，例如：

- 学生是否打开资源、观看到什么进度。
- 是否作答、答案是否正确、作答用了多长时间。
- 是否按时提交任务和附件，老师给出了什么评价。
- 签到、抢答、点名、小组合作和课堂互动情况。
- 自评、互评、教师评价和测试结果。

这些记录用来帮助老师了解学生近期学习情况，并为后续分层和分组建议提供依据。系统不会因为一次答错、一次缺勤或一次扣分就自动改变学生层级，也不会绕过老师直接调整学生安排。

开发环境中的模拟数据只用于检查流程能否跑通，不能代替真实教学效果验证。正式研究仍需要真实学校试用、隐私审查和规范的研究设计。

## 研究与教学设计

STRATA 不把“收集更多点击次数”当作智能教学。项目真正要解决的是：在不公开给学生贴标签的前提下，怎样把分散的学习过程整理成可信证据，帮助老师及时调整任务、资源、支持方式和小组安排。

项目已经围绕学生行为、过程性评价、动态分层和动态分组完成 30 轮科学审查。完整结论、研究边界和文献索引见 [学生行为分析、过程性评价与 AI 隐性动态分层设计报告](docs/student_behavior_ai_stratification_design.md)。

### 研究问题

当前设计围绕以下问题展开：

1. 哪些课堂和课后行为可以被稳定、准确地记录？
2. 哪些记录只代表操作事实，哪些经过验证后可以支持学习投入、学习策略或学科实践等解释？
3. 学生近期的完成、作答、评价和资源学习情况，能否预测下一阶段的掌握、成长、任务完成或逾期风险？
4. 全局模型加班级校准，能否比简单规则和传统统计方法给出更稳定的教师建议？
5. 教师采用建议后，是否真的改善了教学决策和学生学习，而不是只提高了模型指标？
6. 结果能否在不同班级、学期、学科和学校中保持稳定，并避免对部分学生群体造成不公平影响？

### 从课堂事实到教学建议

系统按照以下顺序形成证据：

```text
课堂与学习事件
  -> 检查记录是否完整、重复、迟到或缺少关联
  -> 按日、7 日、30 日、单元和课时汇总学习指标
  -> 在预先确定的时间点冻结当时可用数据
  -> 等待随后学习结果形成
  -> 在同一数据范围比较多种统计和机器学习方法
  -> 生成只对任课教师可见的候选建议
  -> 教师接受、调整、拒绝或暂缓
  -> 记录实际投放和后续学习结果
```

这条链路保留每一步的版本、时间和来源。后续可以重新计算，也可以查清某条建议当时使用了哪些数据。

### 学习事件与“分母”

所有完成率、正确率和按时率都必须有明确分母。例如：

- 必做任务完成率 = 已完成的有效必做任务数 / 已到期的有效必做任务数。
- 首次作答正确率 = 首次答对的客观题数 / 有明确答案的首次作答题数。
- 资源完成率 = 达到完成规则的必看资源数 / 实际投放的必看资源数。

没有给学生布置任务，不等于完成率为 0；没有可评分题目，也不等于学生得 0 分。系统会分别保存“没有学习机会、尚未开始、正在进行、设备离线、数据有误、材料不足、不适用于当前任务”等原因，避免把缺失数据误当成学生表现。

首期已登记 25 项学习指标，主要包括：

- 任务机会、完成率和按时提交情况。
- 有效学习时长、活跃天数和资源完成情况。
- 首次作答得分率、正确率和近期变化。
- 修改答案、重试进步、主动求助和坚持完成等研究候选指标。
- 自评与师评差异、互评质量和小组贡献等评价派生指标。
- 离线、异常记录和教师支持等数据检查信息。

点击、在线时长、聊天次数和课堂积分不能直接等同于能力、核心素养或学习投入。尚未完成统一采集或效度验证的指标会显示“暂不可计算”，不会补出一个看似完整的数值。

### 教师评价与核心素养证据

评价标准由任课教师围绕课程和任务制定，学校管理员不代替教师评价学生。当前评价链路是：

```text
评价方案 -> 学习目标 -> 评价依据 -> 学习任务 -> 评价标准 -> 评价指标 -> 1-5 星表现说明
```

评价可以按任务启用成果表现、学习策略、自我调节、协作表现和学科实践等方面。自评、互评和师评分开保存，不互相覆盖；签到、在线时长、服从性和课堂积分不能直接作为学科核心素养结论。

评价标准发布后保留不可修改的历史版本。课时设计只选择已发布版本和评价方式；课堂第一次开启评价时冻结实际使用的完整内容。没有足够作品或作答材料时使用“暂不评价”并记录原因，不能用 1 星或 0 分代替。

这套设计让教师能够看到学生在具体任务中的表现，但平台不会仅凭一次五星评价生成永久能力标签。不同版本评价标准如需纵向比较，必须保留共同指标并验证可比性。

### 题库、共同测试和可比性

题目分为三种用途：

- **普通题**：用于日常教学和练习。
- **共同题**：所有学生在可比条件下完成，用来建立班级、学期和学校之间的共同测量基础。
- **分层题**：面向 A、B、C、A/B 或 B/C 内容带，用于提供不同难度和支持，不替代共同题。

个人题目保存在“我的题目”，教师本人使用不需要审核；只有主动申请进入学校共享题库时才进入审核流程。AI 生成题默认是草稿，必须经过教师确认。未经内容审核、试测、稳定性和题目功能检查的 AI 题，不能直接作为共同锚题或正式研究结果。

系统保存题目版本和组卷时版本，并统计难度、正确率、区分度和选项分布。有效样本少于 30 时只显示“数据不足”，不输出看似精确但不稳定的结论。

### 分析时间点和冻结数据

正式分析不是随时从数据库抓一份数据就开始训练。系统先建立分析时间点 `T0`，固定当时的学校、班级、学科、课程、学生范围和指标版本，再保存两种视图：

- **当时可用数据**：在 `T0` 前已经发生并已经到达服务器的数据，是训练和实际判断唯一允许使用的输入。
- **事后完整数据**：允许纳入规定时间内稍后补传的数据，只用于检查离线补传影响。

系统随后等待未来 7 日等结果窗口结束，再生成匿名、不可修改、可重复核对的数据版本。这样可以防止把学生未来表现提前混入模型输入，也避免先看到结果再挑选有利数据。

当前已经实现的首期结果是“随后 7 日必做任务完成率”和“随后 7 日新增逾期任务数”。它们只用于判断学生是否可能需要计划提醒或教师核查，不代表学科掌握。

正式内容分层还需要下一次计划共同测试的掌握结果、测量版本、锚题和不确定性。掌握、成长、完成和逾期必须分别保存和建模，不能简单加成一个难以解释的“综合能力分”。

### 动态分层

系统中的 A/B/C 是教师内部使用的内容投放代码，不是学生身份：

| 内容带 | 教学含义 |
| --- | --- |
| A | 拓展挑战 |
| A/B | 拓展与核心之间的过渡 |
| B | 核心发展 |
| B/C | 核心与基础之间的过渡 |
| C | 基础提升 |

分层按学科、课程和有效期保存。同一名学生在不同学科或不同时间可以处于不同内容带。学生只看到自己的学习目标、任务、资源和教师反馈，不看到 A/B/C、预测概率、班级排名或模型理由。

动态调整不能只看最近完成率，也不能一次波动就改变层级。正式策略需要共同掌握证据、近期变化、预测不确定性、连续证据、升降滞回、冷却期、单次最多调整一级和教师确认。模型只给候选建议，不能自动改变学生层级。

### 动态分组

内容分层和课堂分组是两件事。教师根据任务目的选择分组方式，系统可以提供三个候选方案：

- 随机组合：适合一般交流和减少固定标签。
- 准备情况接近：适合同步难度任务和针对性指导。
- 相邻互助：让准备情况相近但存在适度差异的学生协作。
- 能力互补：结合任务所需角色和技能安排成员。
- 项目稳定组：项目周期内尽量保持成员稳定。

候选方案还要考虑组数、人数、历史同组次数、学生关系、设备条件、角色覆盖和教师设置的必须同组或不能同组约束。教师可以调整后再确认。活动进行中原则上冻结成员，只在阶段边界重新分组；学生只看到中性组名和当前组员，不看到算法依据或同伴层级。

### 模型比较与班级专属校准

平台不会只训练一种模型然后宣称有效。相同冻结数据会先比较：

| 编号 | 方法 | 作用 |
| --- | --- | --- |
| M00 | 总体平均 | 最低比较标准 |
| M01 | 透明规则 | 检查少量明确指标能做到什么 |
| M02 | 正则化统计模型 | 提供可解释的线性或逻辑基线 |
| M03 | 班级收缩模型 | 检查班级环境差异 |
| MODEL-02 | CatBoost、LightGBM | 与上述基线在完全相同的数据折上比较 |

“一个班级一个专有模型”不等于每班用几十名学生从零训练一套复杂模型。当前采用的是：

```text
全局或学科基础模型 + 班级残差收缩校准参数 + 班级策略设置
```

这样既保留班级差异，又减少小样本模型过拟合。样本不足时不启用高级模型，也不强行输出结果。

模型会记录 MAE、MSE、RMSE、R²、覆盖率、Brier 分数、校准截距和斜率、残差分布、特征重要性、重复训练稳定性及班级间误差差异。二分类任务不使用 R²。学校管理员可以在分层分析页面查看 ECharts 图表、下载高分辨率图片和 XLSX 明细。

所有方法都按相同方式检查：

- 按时间留出，验证对后续时间的表现。
- 按学生整组留出，避免同一学生同时出现在训练和测试中。
- 按班级整组留出，检查新班级表现。
- 使用另一学校的兼容数据，检查跨校表现。
- 按测量或课程版本留出，检查版本变化；没有第二版本时明确显示“暂不适用”。

系统还会执行标签打乱、随机匿名编号、未来字段检查、数据质量字段隔离和班级身份误用检查。任何检查不通过时，候选会被阻止发布。

### 夜间更新、发布和回滚

正式部署后，后台任务分阶段运行：

- `01:30`：检查前一完整自然日的学习记录。
- `02:50`：冻结到时的分析时间点并更新已经成熟的未来结果。
- `03:10`：在最新合格数据版本上运行统计和模型比较，生成候选版本。

夜间任务只生成候选，不直接替换当前版本。学校管理员也可以选择一个冻结数据版本手动训练。发布前会检查数据状态、模型文件和校验码；成功发布会生成带清单、公钥和 Ed25519 签名的离线模型包。训练或发布失败时保留当前版本，历史版本经过重新校验后可以回滚。

教师只有在候选正式发布后才能看到本人任教范围内的学生建议。教师的接受、修改、拒绝或暂缓会作为实施记录保存，但不会被直接当成下一轮训练的“正确答案”。

### 科学结论分级

为了防止把工程结果写成教学结论，项目将证据分成七级：

| 等级 | 当前可以回答的问题 |
| --- | --- |
| C0 | 数据是否按定义正确记录和重放？ |
| C1 | 学习指标是否能够稳定、重复地计算？ |
| C2 | 指标是否真的支持某个学习构念解释？ |
| C3 | 模型能否在指定学生和时间范围预测计划结果？ |
| C4 | 建议能否帮助教师做出更好的教学决策？ |
| C5 | 教学干预是否造成了学习结果改变？ |
| C6 | 结论能否迁移到新的学校、时间和群体？ |

低等级证据不能自动证明高等级结论。例如，日志完整不能证明学生投入高，预测准确不能证明模型造成学习进步，教师接受建议也不能证明建议一定正确。

### 面向论文的研究路线

项目计划将测量研究、预测研究和教学效果研究分开：

1. **影子运行**：模型生成建议但不改变教学，用于检查数据、评价工具、预测性能、稳定性和教师工作量。
2. **测量与预测研究**：预先登记研究问题、样本、结果和分析方法，锁定数据版本后比较多种模型，并报告校准、不确定性、公平性和跨校表现。
3. **决策支持研究**：比较教师独立判断、模型独立建议和教师结合模型建议的决策质量与工作负担。
4. **教学效果研究**：在前述阶段通过后，采用班级或教师为单位的集群随机、阶梯楔形或其他可识别设计，研究动态支持是否真正改善学习。
5. **外部验证**：在新的学校、学期和学科独立复验，形成可迁移范围和停用条件。

目标期刊方向包括 *Computers & Education*，但软件功能完成或模拟数据跑通不代表已经形成可投稿结论。正式研究前需要完成伦理审批、未成年人和监护人同意、教师培训、研究预注册、数据锁定、偏离记录和分析代码归档。

### 伦理、隐私和公平

- 学生数据默认在校内处理，按角色和任教范围访问。
- 外部 AI 不接收学生姓名、账号、原始答卷、聊天、学习档案或内部层级。
- 跨校数据包默认去除直接身份，不包含聊天原文、答卷正文和作品文件。
- 学生和监护人应知道采集的数据类别、用途、保存期限和申诉方式，并能更正身份匹配错误。
- 拒绝研究使用不应影响学生正常参加课程。
- 教师确认所有分层和分组建议，系统不得自动分班、自动降级或自动处分。
- 公平检查覆盖测量机会、数据缺失、预测误差、建议覆盖、教师处理和后续学习结果。删除敏感字段本身不等于已经公平。
- 小样本人群不输出不稳定比较；报告群体差异时必须同时给出样本量和不确定性。

详细要求见 [伦理与隐私检查表](docs/ethics_privacy_checklist.md)和[正式学校试用方案](docs/school_pilot_protocol.md)。

### 文献、预注册与复现材料

科研文献集中保存在 [`docs/references/student_behavior_ai_stratification/`](docs/references/student_behavior_ai_stratification/README.md)：

- 已收录 105 篇经 DOI 核验的文献，其中 72 篇发表于 2021-2026 年。
- `papers/` 保存 47 篇可合法公开获取并已验证 PDF 文件签名的全文。
- `references.bib` 和 `references.ris` 可直接导入 Zotero、EndNote 等文献管理工具。
- `papers_manifest.csv` 记录文献编号、引用键、DOI 和研究主题。
- `oa_download_report.csv` 记录开放获取状态、下载地址和失败原因。
- `search_protocol.md` 记录检索问题、检索词、纳入排除标准和证据使用边界。

文献覆盖学习投入、自我调节学习、形成性评价、评价标准、差异化教学、学习分析、知识追踪、动态分组、人机协同、算法公平、预测模型报告、数据泄漏、隐私和 K-12 教师数据素养。该文献库用于设计与验证规划，目前不宣称是已经完成的系统综述。

正式研究开始前应冻结并归档以下材料：

- 研究问题、主要和次要结果、样本与排除规则。
- 评价标准、共同题集合、锚题和测量版本。
- 分析时间点、指标版本、未来结果版本和冻结数据清单。
- 数据切分方式、候选模型、超参数范围、比较指标和停止规则。
- 公平性检查、缺失处理、敏感性分析和负对照。
- 教师培训、实施忠实度、建议处理和不良后果记录。
- 源代码提交号、依赖版本、模型包校验码、分析脚本和图表生成脚本。
- 与预注册不一致的修改及原因，不能在看到结果后悄悄改写研究方案。

学生级原始数据属于受保护的未成年人教育记录，默认不公开。论文可以在学校协议和伦理审批允许的范围内提供变量字典、分析代码、模拟数据、去标识汇总结果和复现步骤；受控学生数据的申请条件必须明确，不能只写“可向作者索取”。

## 私有化部署说明

- Django、Vue、ECharts 和页面资源都由本地服务器提供，不依赖 CDN 或公网字体。
- 开发和单机体验可以使用 SQLite；学校正式部署建议使用 PostgreSQL。
- Redis 用于实时课堂连接和后台任务。
- ONLYOFFICE 是可选组件。安装后可以在网页内预览或协作编辑 Word、PPT 和 Excel；没有安装时，其他课堂功能仍可使用。
- DeepSeek 是老师自愿配置的可选服务。没有填写 API Key 时，普通备课、上课、作答和评价不受影响。
- 学生电脑通过浏览器访问学校服务器，不需要逐台安装 Python、Node.js 或数据库。

## 给开发和维护人员

### 技术组成

- Python 3.12
- Django 5.2 LTS + Django REST Framework
- Vue 3 + TypeScript + Vite
- PostgreSQL 16/17（学校正式部署建议）
- Redis + Celery + Django Channels
- ECharts

前后端已经分离：业务页面由 Vue 提供，Django 负责接口、权限、数据、后台任务和 WebSocket。

### 系统怎样运行

```text
教师 / 学生 / 管理员浏览器
          |
          +-- Vue 页面 --HTTP--> Django REST API --+--> PostgreSQL
          |                                        +--> 本地媒体与资源文件
          |
          +-- WebSocket -------> Django Channels -----> Redis
                                                   
学校后台定时任务 -------------> Celery + Redis -------> 数据检查、汇总、模型候选

可选：Django <---------------> ONLYOFFICE Document Server
可选：教师主动使用 AI --------> 教师自己的 DeepSeek API
```

- Vue 只负责页面和交互，不直接连接数据库。
- Django 根据登录账户和任教关系判断能访问哪些学校、班级和学生。
- PostgreSQL 保存正式业务数据；上传的课件、作品和模型文件保存在学校服务器指定目录。
- Redis 同时承担实时消息通道和 Celery 任务队列。开发时可以临时使用内存通道，正式课堂不能依赖单进程内存通道。
- Celery Worker 执行后台任务，Celery Beat 按时间发起每日检查和夜间分析。
- ONLYOFFICE 与 DeepSeek 均不属于普通教学流程的强制依赖。

接口约定见 [API 契约](docs/api_contract.md)，数据表和状态关系见 [数据模型](docs/data_model.md)，前端目录和组件规则见 [前端架构](docs/frontend_architecture.md)。

### 运行前准备

当前脚本主要面向 Windows PowerShell。开发机至少需要：

- Python 3.12。
- Node.js 和 npm，仅用于修改并重新构建 Vue 前端。
- 学校正式部署使用 PostgreSQL 和 Redis。
- 需要网页内编辑 Office 文档时再安装 ONLYOFFICE Community Edition。

从 `.env.example` 创建本机配置：

```powershell
Copy-Item .env.example .env
```

正式部署前至少需要修改 Django 密钥、AI 加密密钥、数据库账号密码、允许访问的主机和 Redis 配置。`.env`、数据库密码、教师 API Key、模型签名私钥和隔离区密钥都不能提交到 Git。

### 第一次安装

项目已经准备离线 Python 依赖包时，在 PowerShell 中执行：

```powershell
.\scripts\install_offline.ps1
```

初始化或更新数据库：

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py sync_learning_event_schemas
.\.venv\Scripts\python.exe manage.py sync_analysis_definitions
```

本地开发默认可以先使用 SQLite。学校正式部署前，再切换到 PostgreSQL 和 Redis。

### 启动系统

只在本机开发：

```powershell
.\scripts\run_dev.ps1 -Port 8010
```

让同一局域网的电脑访问：

```powershell
.\scripts\run_lan.ps1 -Port 8010
```

在服务器后台运行：

```powershell
.\scripts\start_lan_background.ps1 -Port 8010
```

启动后访问：

```text
http://127.0.0.1:8010
http://<学校服务器的局域网 IP>:8010
```

实时课堂和聊天使用 WebSocket。正式部署应使用项目提供的 ASGI 启动方式，而不是只运行 Django 开发服务器。

### 修改和构建前端

Vue 源码位于 `frontend/`。修改后执行：

```powershell
cd frontend
npm.cmd install
npm.cmd run build
cd ..
```

构建结果会写入 `static/frontend/`。只有开发机需要 Node.js，普通教师机和学生机不需要安装。

### PostgreSQL 和后台任务

切换数据库配置：

```powershell
.\scripts\switch_to_postgres.ps1
```

启动 Celery 后台任务：

```powershell
.\scripts\run_celery_worker.ps1
.\scripts\run_celery_beat.ps1
```

后台任务用于整理学习记录、生成学习情况汇总，以及在夜间准备新的模型候选版本。候选版本必须经过检查和发布，教学建议仍需老师确认。

### ONLYOFFICE

`.env` 配置示例：

```env
ONLYOFFICE_DOCUMENT_SERVER_URL=http://127.0.0.1
ONLYOFFICE_JWT_SECRET=<与 Document Server 一致的密钥>
```

学校服务器地址、端口或密钥改变后，需要重新检测文档服务。具体步骤见 [ONLYOFFICE 集成说明](docs/onlyoffice_integration.md)。

### 模拟一批测试数据

没有真实教学数据时，可以生成一批可清理的模拟数据，用来检查页面、统计和训练流程：

```powershell
.\.venv\Scripts\python.exe manage.py generate_synthetic_learning_data `
  --school-code SIM-RESEARCH `
  --seed 20260719 `
  --classes 4 `
  --students-per-class 30 `
  --weeks 12 `
  --end-date 2026-07-18
```

`--weeks` 支持 `1-52`，这里只表示模拟数据覆盖多少周，不是正式课程的课时上限。先加 `--dry-run` 可以只查看预计生成量。清理方法见 [模拟数据说明](docs/synthetic_data_research_track.md)。

## 数据和账号边界

- 学校数据库、上传文件、模型文件、日志和备份包不提交到 Git。
