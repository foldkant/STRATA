# STRATA 数智教学系统

STRATA 是一套面向中学课堂的数智教学系统。平台以课程标准为依据，连接课程与课时设计、课堂教学、学习评价、学习情况分析、分层教学和小组学习，帮助教师根据学生在具体学习目标上的实际表现安排后续教学。

系统支持学校私有化部署。教师、学生和管理人员通过校园网络访问，教学数据默认保存在学校服务器内，不要求上传至公共云平台。

项目目前处于持续开发和学校试用准备阶段。主要教学流程已经能够运行，课程标准管理、评价重构、学习起点诊断、动态分层、动态分组和 AI 辅助起草评价已经完成工程实现与测试数据验证。工程流程可运行不等同于已经证明教学效果，真实教学成效仍须通过正式试点、教育研究和持续复核加以验证。

## 教育理念与设计原则

STRATA 坚持以下设计原则：

- **以课程标准为依据**：学习目标、学习活动、评价任务和评价标准应能够追溯到相应学段、学科和版本的课程标准原文。
- **以学习过程为线索**：综合使用作答、作品、操作、答辩、观察和评分记录，不用单一考试成绩代替完整的学习情况。
- **关注差异但不固化学生**：分层建议服务于一段时间内的教学内容安排，不把学生划为固定能力类别。
- **分层与分组相互区别**：学习内容层级建议用于安排学习内容，小组安排服务于具体任务、阶段、角色和资源条件。
- **教师承担专业判断责任**：系统和 AI 只提供草稿、候选方案与辅助信息，不自动发布评价，不自动调整学习内容，也不自动确定学生分组。
- **材料不足不等于表现较低**：缺失材料、设备问题、未获得学习机会和仍待评价必须分别记录，不换算为零分或低水平。
- **保护学生隐私与学习机会**：学生不接触内部层级代码、模型概率或班级排名；研究退出不影响正常学习机会。
- **区分工程验证与教育效果**：页面可用、数据可计算、模型可运行，只说明工程流程得到验证，不能直接说明教学效果已经成立。

## 四类用户

### 超级管理员

超级管理员负责平台范围内的学校、学校管理员、课程标准、跨校数据接收和系统运行情况。

课程标准管理覆盖义务教育 K1-K9 和普通高中 K10-K12。每个版本保存原始 PDF、来源、正式题名、发布日期、文件校验值、逐页可检索文本、结构化内容和 AI 检索片段。新版本发布后不覆盖旧版本，已经使用的评价仍保留原版本和原文位置。

### 学校管理员

学校管理员负责本校教师、学生、班级、任课关系、学习起点诊断实施、学习数据检查和学校运行情况。

学校管理员不代替任课教师制定课堂评价，也不直接决定每名学生的学习内容层级或小组安排。涉及学生个人的教学建议由任课教师结合学习材料复核。

教育实验研究支持模块仍在重新设计。正式启用前，需要进一步明确实验班与对照班、共同前测与后测、问卷和表现任务、数据用途、知情同意、分析方案及结果解释边界。当前工程页面和测试数据不得视为完整的教育实验分析功能。

### 教师

教师负责本人任教范围内的课程、课时、课堂、学习活动、评价、题库、测试、资源、学生学习情况、分层建议和小组安排。

教师可以在课时设计中直接建立或选择评价方案，也可以使用 AI 辅助形成评价初稿。评价内容经过教师逐项修改、复核和发布后，才能绑定课时并在课堂中使用。

### 学生

学生通过学习空间进入课程、课堂、测试任务、学习资源和学习档案。学生可以查看教师安排的学习目标、活动、资源和反馈，但不会看到内部学习内容层级代码、模型概率、教师处理记录或班级排名。

## 一节课的完整流程

### 1. 建立课程与课时

教师在“课程学习”或“课程备课”中建立课程，选择任教班级，并按教学内容建立课时。课时由若干学习环节组成，每个环节可以安排：

- PPT、Word、PDF、Excel、视频、图片、链接和压缩包等学习资源。
- 单选题、多选题、判断题、填空题、简答题和附件任务。
- 操作任务、表现任务、短项目、作品展示和答辩。
- 个人学习与小组合作活动。
- 学生自评、小组互评和教师评价。
- 经教师复核的 AI 学习网页或网页表单。

资源、任务和题目可以分别排序。一个学习环节可以同时呈现学习材料和作答任务，便于学生边学边做。

### 2. 设计本课评价

评价设计是课时设计的一部分。教师不必离开课时设计页面即可：

1. 读取本课的课程、课时、学习环节和课程内容。
2. 选择适用的课程标准版本与原文依据。
3. 明确本课学习目标、学习活动和评价用途。
4. 选择测试、操作、项目、作品、答辩或混合评价方式。
5. 建立评价任务、评价指标、具体表现和 1-5 星表现说明。
6. 区分个人评价材料与小组评价材料。
7. 保存草稿，完成人工复核后发布不可修改的版本。
8. 将明确版本绑定到相应学习环节。

评价方案库用于保存、复用和管理教师已经建立的方案，不要求教师在备课时切换到独立页面才能完成本课评价。

### 3. 建立并开始课堂

教师选择课程、课时和班级建立本次课堂。课堂开始并投放学习环节后，学生才能进入相应内容。

课堂控制台支持：

- 投放、关闭和切换学习环节。
- 发起签到，并记录正常、迟到、请假或缺勤。
- 随机点名、抢答、倒计时和课堂通知。
- 查看学生作答进度、客观题结果和附件材料。
- 预览教师已经投放的文档、视频、图片和其他学习资源。
- 开启实名文字交流和小组合作。
- 开启学生自评、小组互评或教师评价。
- 查看评价完成情况并提供课堂反馈。

课堂积分、签到和在线时长用于课堂组织，不直接作为学科学习目标、核心素养或学习内容层级的判断结果。

### 4. 课后查看学习情况

课堂结束后，教师可以查看学生的作答、作品、操作记录、评价、测试和课堂参与情况。系统按学习目标和时间整理相关材料，帮助教师判断：

- 哪些学习目标已经形成较充分的材料。
- 哪些学习目标仍需补充作答、作品或观察。
- 学生可能需要哪些讲解、练习、资源或学习支持。
- 是否需要调整后续学习内容或小组任务。

系统不会把零散点击、在线时长或聊天数量直接解释为能力、态度或核心素养。

## 课程标准管理

课程标准内容按照以下关系整理：

```text
核心素养
  → 课程目标
    → 课程内容
      → 学业质量
```

这四类内容为教学设计与学习评价提供依据和适用范围，不直接换算为学生分数。

课程标准处理采用后台队列。上传或替换 PDF 后，系统在后台完成文本提取、逐页整理、结构化处理和检索片段生成，管理员可以继续使用其他页面。处理失败、取消或中断的任务可以重新排队，并保留任务状态和错误记录。

发布前需要完成人工复核。教师设计评价时，只能引用已经完成人工复核并作为当前版本发布的课程标准内容。每条引用均保留版本、页码、原文位置和文件校验值。

## 评价体系

### 评价关系

评价设计保留以下关系：

```text
课程标准原文及版本
  → 课标依据
    → 学习目标
      → 学习活动
        → 评价任务
          → 评价标准
            → 学生评价材料与评分记录
```

评价标准包括评价指标、具体表现、暂不评价条件、1-5 星表现说明、评分示例和后续教学建议。

### 支持的评价方式

| 评价方式 | 适用的主要学习材料 |
| --- | --- |
| 测试式评价 | 客观题、简答题、作答记录和评分记录 |
| 操作式评价 | 操作过程、操作结果、截图、文件或观察记录 |
| 项目式评价 | 项目作品、过程记录、个人说明、合作记录或答辩 |
| 作品评价 | 文档、程序、设计成果、图像、视频等作品材料 |
| 答辩评价 | 口头说明、问题回应、论证过程和答辩记录 |
| 混合评价 | 两种及以上评价方式形成的相互补充材料 |

平台不会默认用测试替代项目、操作、作品或答辩。教师应根据学习目标、课程内容和学生需要选择能够真实观察学习表现的评价方式。

### 个人与小组材料

- 个人作答、个人操作、个人说明和能够归因到个人的观察，可以支持个人学习情况判断。
- 小组作品和共同成果作为小组材料保存，不能自动转写为每名成员的个人表现。
- 项目学习可以同时保存小组成果与个人贡献材料。
- 未提交、设备问题、未获得机会和仍待评价分别记录，不记为 1 星、0 分或较低水平。

### 评价版本

评价草稿可以持续修改。教师完成人工复核后，系统生成不可修改的发布版本。已经绑定课时的版本不会因为教师后来修改草稿或发布新版本而改变。

学生自评、小组互评和教师评价分别保存，不互相覆盖。评价材料能否用于更新学习情况，需要另行检查目标对应、个人归属、材料质量和评分质量，课堂星级不会自动进入分层建议或模型训练。

## AI 辅助起草评价

AI 辅助起草评价从课时设计进入，完整流程为：

```text
选择课程、年级、单元和课程标准版本
  → 补充或读取本次课程内容与评价用途
  → 检索已经人工复核的课程标准原文
  → AI 建议适合的评价方式
  → 教师确认评价方式
  → AI 生成评价方案初稿
  → 系统检查引用与内容对应关系
  → 教师逐项采纳、修改或删除
  → 保存评价方案与评价标准草稿
  → 教师人工复核、试用和发布
  → 绑定课时并在课堂使用
```

AI 可以辅助起草：

- 学习目标。
- 评价依据。
- 学习活动与评价任务。
- 评价指标与具体表现。
- 1-5 星表现说明。
- 评分示例。
- 暂不评价条件。
- 后续教学建议。

每次起草保存模型名称、提示内容、课程标准引用、原始返回、教师修改差异和自动检查结果。AI 不能直接发布评价、绑定课时、进入课堂评分，也不能直接生成分层或分组决定。

教师可以配置学校允许使用的 AI 服务。API Key 加密保存在学校服务器中，不写入日志、提示记录或 Git。发送给外部 AI 的内容不得包含学生姓名、学号、联系方式、原始答卷、聊天内容或其他能够识别个人的信息。

普通备课、课堂教学、评价和测试不依赖 AI；未配置 AI 时仍可完整使用手工流程。

## 学习起点诊断（前测）

学习起点诊断用于了解学生在相关学习目标上的初始情况，不等同于一张客观题试卷，也不根据一次总分直接确定学生层级。

诊断工具可以包含：

- 单选题和多选题。
- 简答任务。
- 表现任务。
- 操作任务。
- 短项目。
- 学习支持问卷。

每次实施绑定不可修改的诊断工具版本、班级、时间和用途。学生提交后保留逐项作答、作品、操作、附件和评分记录。

学习支持问卷只提供兴趣、自我效能、学习支持或设备条件等线索，不进入学科学习目标水平判断。主观材料在教师评价完成前保持“等待评价”，不提前形成学习目标初始情况。

以下情况不会记为零分或较低水平：

- 学校或教师未提供本次评价机会。
- 学生尚未形成相应材料。
- 设备或网络出现问题。
- 材料仍在等待教师评价。
- 当前材料不足以支持学习目标判断。

## 动态分层

动态分层在教师端呈现为“分层建议”或“学习内容层级建议”。它回答的是：在当前课程、学习目标和时间范围内，教师可以为学生安排怎样的学习内容与学习支持。

系统建立“学生 × 学习目标 × 时间”的学习情况版本，保存材料覆盖、有效期和不确定性。学习内容层级建议与学习支持建议分别呈现：

- 学习内容层级建议关注下一阶段学习内容的范围和挑战程度。
- 学习支持建议关注讲解、示例、练习、资源、时间和教师帮助。

建议形成后，教师先查看相应学习目标和材料，再选择接受、调整、暂缓或拒绝。材料不足时显示“暂不建议”，不会自动进入最低层级。

内部层级代码仅用于教师安排教学内容，不是学生身份或永久能力标签。同一名学生在不同学科、课程、学习目标和时间可以有不同建议。学生端只显示具体学习目标、任务、资源和反馈。

## 动态分组

动态分组服务于具体学习任务，不是把学生长期固定在同一小组。

教师先明确：

- 本次任务的学习目的和阶段。
- 每组人数与角色要求。
- 设备、资源和时间条件。
- 必须同组、不能同组或需要保持稳定的关系。
- 学生参与机会与近期同组情况。

系统据此生成多个候选方案。教师比较并调整后，按以下顺序使用：

```text
生成候选方案
  → 教师检查与调整
  → 确认启用
  → 通知学生
  → 记录实际成员、角色和参与机会
```

系统不会先启用默认分组。学生只看到中性组名、本组成员和任务角色，不会看到内部层级或算法依据。

## 题库、测试与资源

### 题库与测试

- 教师建立的题目进入个人题库。
- 教师主动申请共享后，题目才进入学校审核流程。
- 已审核的共享题目可以被其他教师查看和使用。
- 支持 XLSX 批量导入和 AI 辅助生成题目草稿。
- 组卷后冻结题目与评分版本。
- 客观题可以自动评分，主观题和附件任务由教师评价。
- 支持普通题、共同题和分层题，但分层题不能代替所有学生共同完成的共同题。

共同题用于观察共同学习目标。不同学习内容层级的原始分数不能在缺少共同参照时直接比较。

### 教学资源

教学资源包括教师备课资源、课堂投放资源、校内共享资源、跨校资源和学生项目。学生能够查看已经向其班级或课堂投放的资源。

ONLYOFFICE 是可选能力。配置后可以在网页中预览或协作编辑 Word、PPT 和 Excel；未配置时，其他教学功能仍可使用。文档回调必须校验 JWT，并限制服务器代请求地址、文件类型、文件大小和可覆盖版本。

## 小组合作与课堂交流

教师可以在课堂中开启小组合作，选择 Word、PPT 或 Excel 作为协作文档，也可以允许小组共享文件。共享空间大小由课堂任务设置，默认每组 20 MB。

课堂文字交流分为：

- **全班交流**：教师始终可以发言，学生参与需要教师开启。
- **师生交流**：学生与教师一对一沟通，其他学生不可查看。
- **小组交流**：本组学生和教师可以查看，教师可以进入任意小组。

平台不提供学生之间的一对一私聊。需要审核的内容先进入教师处理区域，不直接向其他学生公开。警告、撤回或课堂处理均须由教师确认。

## 学习情况与研究边界

平台记录与教学直接相关的学习事实，例如：

- 教师实际投放的学习资源、任务与评价机会。
- 学生作答、修改、作品提交和操作过程。
- 个人评价材料与小组评价材料。
- 教师提供的讲解、提醒、练习和额外支持。
- 学习目标在不同时间的材料覆盖与评价结果。

计算完成率、正确率等指标时，系统同时保存分子、分母、计算窗口和缺失原因。没有布置任务、尚未开始、设备问题、材料待评价和数据错误不能统一记为零。

研究数据在固定分析时间点形成匿名版本，避免使用后来产生的结果解释先前情况。学生姓名、账号和学号不进入跨校研究数据包。聊天原文、原始答卷和作品文件默认不进入外部分析。

目前的模型与分析结果只用于工程验证和教师影子查看。平台不把内部建议当作正式教学效果，也不把学生课堂积分、班内排名或教师既有手工层级作为模型训练的正确答案。

## 教育研究与试点

正式教学研究应按照以下顺序推进：

1. **影子运行**：后台形成建议，但不自动改变学生任务，先检查数据完整性、建议稳定性和教师工作负担。
2. **评价工具研究**：检查学习目标、评价任务、表现说明和共同题是否能够稳定反映预期学习内容。
3. **预测研究**：在研究开始前明确问题、样本、结果和分析方法，比较不同方法的预测、校准、公平性和跨校表现。
4. **教师决策研究**：比较教师独立判断、系统建议和教师结合建议三种条件。
5. **教学效果研究**：前述条件满足后，再采用适当的班级或教师层面研究设计判断教学调整是否产生学习增益。
6. **外校复核**：在不同学校、学期和学生群体中重新检查适用范围与停用条件。

正式试点前应完成学校和伦理审批、学生及监护人知情同意、教师培训、研究预注册、数据保存期限和退出流程。

科研设计与多轮科学论证保存在 [`docs/`](docs/README.md)。这些材料用于支持后续论文和研究决策，不代表已经获得真实教学效度、信度、公平性或因果效果证据。

## 安全、隐私与数据规则

- 学校数据库、上传文件、课标处理文件、模型文件、日志和备份不提交到 Git。
- `.env`、数据库密码、教师 API Key、模型签名私钥和隔离区密钥不得提交到 Git。
- 生产环境使用不安全密钥、调试模式或不安全 Cookie 设置时，应拒绝启动。
- 登录接口具有按账号和访问地址的失败次数限制。
- 教师只能查看本人任教范围，学生只能查看本人数据和已经授权的课堂资源。
- 文件下载、ONLYOFFICE 预览和回调均执行对象级权限检查。
- 已发布课程标准、评价版本、诊断工具版本和学生提交不可原地覆盖。
- AI 形成的题目、评价和学习网页必须经教师确认后才能发布。
- 系统不得自动调班、自动降低学习要求、自动处分或自动扣分。

## 私有化部署

### 技术组成

- Python 3.12
- Django 5.2 LTS
- Django REST Framework
- Vue 3
- TypeScript
- Vite
- PostgreSQL 16/17
- Redis
- Celery
- Django Channels
- ECharts

开发和单机体验可以使用 SQLite；学校正式部署建议使用 PostgreSQL。Redis 用于实时课堂消息和后台任务。前端字体、图标、图表和业务资源均由学校服务器本地提供，不依赖公共 CDN。

### 运行关系

```text
教师、学生与管理人员浏览器
          |
          +-- Vue 页面 --HTTP--> Django REST API --+--> PostgreSQL
          |                                        +--> 校内文件存储
          |
          +-- WebSocket -------> Django Channels -----> Redis

后台任务 ---------------------> Celery + Redis -------> 课标处理、数据检查与 AI 起草

可选：Django <---------------> ONLYOFFICE Document Server
可选：教师主动使用 -----------> 学校允许使用的 AI 服务
```

### 本地配置

从示例创建本机配置：

```powershell
Copy-Item .env.example .env
```

正式部署前必须修改 Django 密钥、AI 加密密钥、数据库密码、允许访问的主机、HTTPS、Redis 和 ONLYOFFICE 配置。

### 安装依赖

使用项目内准备的离线 Python 依赖：

```powershell
.\scripts\install_offline.ps1
```

安装前端依赖：

```powershell
cd frontend
npm.cmd install
cd ..
```

### 初始化数据库

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py sync_learning_event_schemas
.\.venv\Scripts\python.exe manage.py sync_analysis_definitions
```

### 启动系统

本机开发：

```powershell
.\scripts\run_dev.ps1 -Port 8010
```

校园局域网访问：

```powershell
.\scripts\run_lan.ps1 -Port 8010
```

服务器后台运行：

```powershell
.\scripts\start_lan_background.ps1 -Port 8010
```

访问地址：

```text
http://127.0.0.1:8010
http://<学校服务器局域网地址>:8010
```

正式部署应使用 ASGI 服务，不应只使用 Django 开发服务器。

### 后台任务

本地或学校服务器需要分别运行通用后台任务和定时任务：

```powershell
.\scripts\run_celery_worker.ps1
.\scripts\run_celery_beat.ps1
```

课程标准 PDF 处理可以使用独立任务队列：

```powershell
.\scripts\start_curriculum_ocr_worker.ps1
```

AI 辅助起草评价使用通用应用任务队列，避免与耗时的课程标准处理任务互相阻塞。

### 构建前端

```powershell
cd frontend
npm.cmd run build
cd ..
```

构建结果写入 `static/frontend/`。构建脚本只保留当前版本和上一版本引用的哈希资源，并清理过期文件。普通教师机和学生机不需要安装 Node.js。

### ONLYOFFICE

`.env` 配置示例：

```env
ONLYOFFICE_DOCUMENT_SERVER_URL=http://127.0.0.1
ONLYOFFICE_JWT_SECRET=<与 Document Server 一致的密钥>
```

具体配置与安全要求见 [ONLYOFFICE 集成说明](docs/onlyoffice_integration.md)。
