# 课堂实名文字聊天设计

## 1. 功能范围

课堂聊天是 `ClassroomSession` 的可选运行能力，只在课堂状态为 `running` 时可用。第一版只提供实时文字聊天，不包含语音通话、语音消息、图片、附件和学生间私聊。

教师可以分别开启三种聊天方式，也可以同时开启：

- 全班聊天：开启后，本班教师和学生均可发送实名文字消息。教师始终具有发言和管理权限。
- 与老师聊天：每名学生只与本课堂教师形成一对一会话，其他学生不可见。教师端按学生选择会话。
- 小组聊天：依赖本课堂已经开启的小组合作及分组结果。学生只能进入自己的小组，教师可以进入任意小组。

每节课堂默认全部关闭。课堂结束时自动关闭全部聊天开关，学生不能继续发送消息。

## 2. 前端交互

教师和学生复用 `ClassroomChatDock.vue`：

- 入口采用固定在课堂右下角的“课堂聊天”按钮，并显示总未读数。
- 桌面端打开 430px 右侧抽屉，移动端打开全宽抽屉，不改变课堂资源区尺寸。
- 标签为全班、老师/私聊、小组；教师额外有审核标签。
- 教师在抽屉内设置三类聊天权限，学生只看到已开启的聊天标签。
- 私聊通过学生下拉列表切换，小组聊天通过小组下拉列表切换。
- 所有消息显示真实姓名；头像暂用用户 ID 映射的固定纯色和姓名首字，同一用户颜色保持稳定。
- `Enter` 发送，`Shift+Enter` 换行，单条消息最多 500 字。
- 待审核消息仅发送者和教师可见，并明确显示“待教师审核”。

## 3. 本地言论判断

聊天过滤完全在学校本地执行，不依赖 DeepSeek 或其他公网服务。

第一版判断来源：

- 本地敏感表达词库。
- Unicode 规范化、空格和符号分隔后的变体匹配。
- 威胁伤害和直接侮辱的规则表达式。
- 60 秒内重复发送相同内容。
- 10 秒内异常连续发送；超过硬限制时返回 `429`。

学生命中规则后：

1. 消息入库，但状态为 `pending`。
2. 消息不向全班或小组公开。
3. 教师审核队列实时出现提示。
4. 学生只能看到自己的待审核消息。

教师处理方式：

- 放行：消息改为 `visible`，进入原聊天范围。
- 警告：消息改为 `removed`，从所有学生的聊天记录中消失，并向发送学生显示一次性警告反馈。
- 撤回：消息改为 `removed`，从所有学生的聊天记录中消失，并向发送学生显示一次性撤回反馈。
- 扣分：消息改为 `removed`，从所有学生的聊天记录中消失；教师确认分值后同步扣减学生积分，并向发送学生显示一次性扣分反馈。

学生点击反馈中的“知道了”后写入 `LearningEvent.metadata.action=classroom_chat_moderation_feedback_ack`。已确认反馈刷新后不再重复出现；未确认反馈会继续显示，避免学生漏看警告或扣分结果。原消息只在教师端审核记录和聊天历史中保留。

系统不自动扣分。扣分建议值为轻微 1 分、一般 3 分、严重 5 分，教师可以修改，范围为 0-100 的正数。

## 4. 权限与安全

- WebSocket 连接必须有有效 Django 登录会话。
- 教师只能进入自己创建的课堂会话。
- 学生只能进入自己当前班级正在进行的课堂。
- 私聊、小组消息不进入全班 WebSocket 分组，不能依靠前端隐藏来实现隔离。
- 消息通过 REST API 校验、过滤和落库；WebSocket 只推送服务器产生的“数据已变化”事件。
- 客户端不能通过 WebSocket 直接广播任意消息。
- 消息只保存纯文本，前端使用 Vue 文本插值渲染，不执行 HTML、Markdown 或脚本。
- 学生不能编辑或删除已发送消息。教师撤回后，任何学生都不能再读取原消息；教师端仍保留原文、审核人和审核时间用于审计。

## 5. 数据与 AI 使用边界

每条消息写入 `LearningEvent.event_type=chat_message`，但事件元数据不重复保存聊天原文。审核结果写入 `LearningEvent.event_type=teacher_intervention`。

后续特征工程可以使用：

- 各聊天范围参与次数。
- 有效互动频次和时间分布。
- 重复刷屏次数。
- 待审核次数及教师最终确认的严重度。
- 警告、撤回和扣分次数。
- 小组讨论参与度。

默认不得把学生聊天原文发送给外部 AI API。教师确认的审核结果可以作为言论判断模型的监督数据，但不直接作为学生 A/B/C 分层标签；分层仍需结合完整学习行为和教师最终确认结果。

## 6. 实时与降级

正式部署使用：

```text
Vue ClassroomChatDock
  -> Django REST API（校验、过滤、落库）
  -> Django Channels
  -> Redis channel layer
  -> 教师/学生定向 WebSocket 分组
```

开发环境 `CHANNEL_LAYER_BACKEND=memory` 时可在单个 ASGI 进程内实时推送。学校正式部署必须使用 Redis，并设置：

```env
CHANNEL_LAYER_BACKEND=redis
REDIS_URL=redis://127.0.0.1:6379/0
```

浏览器连接失败时，组件每 5 秒短轮询同步，发送和审核仍然可用。生产服务必须通过 Uvicorn/ASGI 启动，不能用 Waitress/WSGI 承载课堂聊天。

## 8. 验收要求

- 默认关闭三类聊天。
- 未开启时学生不能发送。
- 全班消息只对当前班级可见。
- 师生私聊不向其他学生返回任何线程摘要或内容。
- 小组成员不能进入其他组。
- 可疑消息在教师放行前不向目标范围公开。
- 扣分必须由教师确认，并同步积分和学习事件。
- 课堂结束后开关自动关闭。
- 桌面 1440px、平板 760px、手机 375px 无横向溢出。
- WebSocket 断开时轮询降级可用。
