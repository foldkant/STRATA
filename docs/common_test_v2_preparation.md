# 共同测试第二版本准备指南

## 目标与边界

第二版本用于建立同一学科跨时间比较的测量基础，并为后续 V-E、IRT 和 BKT 收集必要数据。版本结构准备完成不等于测量有效，也不能替代真实学生作答、教师审核和统计检验。

## 角色分工

- 教师：编写、试用和修订题目，确认知识点及评分答案。
- 学校管理员：发布共同题集合、维护版本关系和锚题范围。
- 研究负责人：在采集前锁定分析方案、样本范围、排除规则和停止条件。
- 模型任务：只读取已冻结版本和真实作答，不自动决定题目有效性。

## V1 到 V2 的组成

V2 应明确分为：

- 锚题：题干、选项、答案、评分和比较编号均不变，并通过 `anchor_source` 指向 V1 项目。
- 修订题：内容发生变化，必须生成新题目版本，不能继续标记为锚题。
- 新题：覆盖新增或原本不足的知识点。
- 退出题：保留在 V1 历史中，不从数据库删除。

锚题比例不在代码中写死。研究团队应在预注册中根据测试长度、内容覆盖和学生负担确定目标范围，并记录任何偏离。

## 平台操作

1. 学校管理员进入“题库审核 -> 共同题集合”。
2. 在已发布 V1 上点击“准备下一版本”。
3. 系统载入原题、比较编号和锚题来源。
4. 对内容不变的题保留锚题关系；修改题先创建新题目版本，再作为非锚题加入。
5. 为每道题确认统一知识点；平台保存题目版本与知识点映射。
6. 发布 V2 后绑定到新的测试，不能覆盖已完成的 V1 答卷。
7. 采集前导出题集清单并由两名教师复核内容、答案、难度和课程覆盖。

## 数据准备条件

### V-E 版本比较

- 至少有两个明确关联的共同测试版本。
- 存在内容完全不变的锚题和稳定比较编号。
- 两个版本均有真实、可核对的学生作答。
- 保留班级、学期、学校和施测条件，检查版本与群体是否混杂。
- 样本不足时只显示“数据不足”，不输出可比结论。

### IRT

- 保留逐题作答、计分、缺失和作答版本。
- 题目参数必须在预先规定的模型与样本条件下估计。
- 检查局部独立、模型拟合、题目参数稳定和群体差异。
- 未完成上述检查时不把能力值用于学生分层。

### BKT

- 每道题至少映射一个规范知识点，主知识点和权重可追溯。
- 保留按时间排序的作答序列、重试、提示和评分结果。
- 同一知识点需要多次真实学习机会，不能把单次共同测试伪装成知识追踪。
- 题目版本或知识点映射变化时生成新版本，不改写历史序列。

## 采集前检查表

- [ ] V1 已发布且内容哈希固定。
- [ ] V2 明确引用 V1。
- [ ] 每个锚题都指向上一版本且内容完全一致。
- [ ] 每个修订题都已生成新题目版本。
- [ ] 每题已映射知识点，未映射项有明确处理计划。
- [ ] 测试说明、时长、设备和课堂条件已尽量一致。
- [ ] 学生知情、家长同意和伦理审批状态已记录。
- [ ] 预注册已锁定主要结果、排除规则和版本比较方法。
- [ ] 测试数据与正式数据可明确区分。

## 停止条件

发现泄题、答案错误、锚题被改动、施测条件严重不一致、身份匹配错误或大范围缺失时，暂停版本比较。修复后保留原记录并建立新版本，不直接修改已完成答卷。
