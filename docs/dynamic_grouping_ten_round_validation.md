# STRATA 学生动态分组十轮科学核查与开发方案

> 日期：2026-07-20  
> 范围：课堂活动、任务驱动学习和项目式学习中的学生动态分组。  
> 关联：[动态分层五轮方案](dynamic_stratification_five_round_validation.md)、[动态分层第 6-15 轮核查](dynamic_stratification_review_rounds_06_15.md)。  
> 性质：设计核查与实证规划，不是动态分组教学效果的既有证明。

## 1. 当前结论

前面的动态分层报告只规定了“内容带不能自动等于协作小组”，没有建立完整动态分组机制。本次十轮核查形成以下结论：

1. 没有一种分组策略适用于所有任务；必须先确定本次协作目的。
2. 同层、异层、随机、技能互补和项目稳定组都应保留，但用途不同。
3. 正式动态分组不能直接读取全局 `current_layer`，只能读取当前学科、当前任务和当前时间点的内部准备度证据。
4. 学习完成困难不等于能力低，不能把完成支持需求高的学生集中为“困难组”。
5. 动态不等于频繁换组。课堂短任务在活动边界换组，项目组原则上在阶段边界才调整。
6. 第一版正式算法采用“任务策略 + 约束优化 + 教师确认”，不训练黑箱分组分类器。
7. 小组历史必须版本化保存，重新分组不能删除旧成员、聊天、协作文档或提交证据。
8. 小组结果不能复制成每个成员相同的个人掌握结果，必须保留个人共同任务或个人贡献证据。
9. 学生只看到中性组名、组员、角色和任务，不看到同层/异层、A/B/C、算法理由或其他学生数据。
10. 动态分组是否改善学习，必须比较具体策略并处理同伴干扰，不能用分组算法目标值证明有效。

## 2. 当前实现审计

2026-07-20 已完成 DG-01 至 DG-07 的工程实现。下表保留原问题和当前处理结果：

| 原问题 | 当前处理 | 后续研究 |
| --- | --- | --- |
| 一节课堂只有一套可变分组 | `GroupingPlanVersion` 保存不可变计划，旧组、聊天、文档和文件归档保留 | 检查跨阶段恢复与长期存储成本 |
| 默认依赖过渡期 A/B/C | 默认随机基线，教师选择任务目的 | 比较不同任务下的策略效果 |
| `ai_layer` 回退同层 | OR-Tools 本地生成随机、任务优先和稳定优先三个候选 | 用真实课堂验证目标权重 |
| 输入跨学科 | 只读取当前课程、学科、任务和决策点的准备度证据 | 验证任务准备度的测量效度 |
| 重分组删除历史 | 新计划生效时旧计划和材料只读保留 | 制定学期归档策略 |
| 角色只有组长/成员 | 支持协调、记录、资源、展示和核验，并允许教师调整 | 验证角色轮换机会是否公平 |
| 没有搭档历史与锁定 | 保存搭档历史，支持锁定、拖动、选择移动和重算 | 确定稳定窗口和重复合作阈值 |
| 没有公平与结果记录 | 保存完整性、人数差、准备度差、角色机会、小组产出和个人掌握结果 | DG-08 预注册影子比较 |

学生端只接收教师确认后的中性组名、角色和协作入口，不接收 A/B/C、策略权重或他人证据。DG-08 的真实效果研究仍未完成，当前优化目标值不能作为教学有效性证据。

## 3. 第一轮：先定义协作任务，再选择分组策略

### 3.1 被否决的方案

- 在课程开始时给每个班生成一套永久小组。
- 不区分补缺练习、互教讨论和项目创作，统一采用同层组。
- 只要开启“小组合作”就由系统自动决定最佳组。

### 3.2 文献约束

协作学习与合作学习包含不同任务结构、责任安排和互动机制，不能只靠“把学生放在一起”实现 [G1]。协作认知负荷研究也提示，任务复杂度、成员知识和协调成本共同影响协作条件 [G2]。

### 3.3 采用的任务类型

| 任务目的 | 首选候选策略 | 说明 |
| --- | --- | --- |
| 聚焦补缺与教师分组指导 | 准备度接近组 | 临时提供相近支架，不形成长期身份 |
| 同伴解释与互教讨论 | 相邻准备度混合组 | 避免差距过大，确保每人有解释和提问机会 |
| 开放问题解决 | 多维互补组 | 兼顾知识、操作、表达和调节角色 |
| 项目式学习 | 技能互补稳定组 | 一个项目阶段内稳定，阶段边界再审查 |
| 课堂基线或低风险活动 | 随机组 | 作为公平、简单和研究比较基线 |
| 正式个人测试 | 不分组 | 个人共同测量不能受小组答案替代 |

教师必须先选择任务目的，系统才允许生成候选组。

## 4. 第二轮：同层与异层没有统一赢家

### 4.1 被否决的方案

- 认为同层分组一定更适合分层教学。
- 认为异层分组一定可以通过“好学生带差学生”提高全组表现。
- 用 A、B、C 的极端混合代表异质性越高越好。

### 4.2 文献约束

已有研究直接比较合作学习中的同质和异质组，也有算法研究提出多种分组目标 [G3-G4, R69-R70]，但这些证据不能支持脱离任务的统一优胜策略。学生能力分组还存在身份、机会和教师期待风险 [D6-D8, C5-C6]。

### 4.3 采用的组合规则

- 准备度接近组只服务短期补缺、同速练习或教师定向指导。
- 相邻混合组优先组合 A/B 或 B/C 边界，不默认把准备度差距最大的学生放在同一组。
- 互教组不能长期固定同一批高准备度学生承担讲解责任。
- 项目组不以 A/B/C 为主要轴，优先技能、兴趣、可用时间、角色和项目需求。
- 随机组始终保留，既是可用策略也是研究基线。

## 5. 第三轮：分组输入必须多维、按任务并受限制

### 5.1 被否决的方案

- 只使用总分或层级进行聚类。
- 使用未经验证的“视觉型/听觉型学习风格”。
- 把性别、家庭背景等敏感字段直接放入优化目标。
- 用聊天原文、情绪猜测或一次课堂扣分决定组员。

### 5.2 正式输入

动态分组只读取决策点之前的版本化事实：

| 输入 | 用途 | 限制 |
| --- | --- | --- |
| 任务准备度 | 接近或相邻混合 | 来自当前学科/任务的可比较掌握证据，不读全局层级 |
| 知识与技能覆盖 | 项目技能互补 | 必须绑定任务需求和证据来源 |
| 角色历史 | 角色轮换 | 不把“组长次数多”解释为能力高 |
| 搭档历史 | 降低过度重复或隔离 | 只统计共同任务，不分析私人关系文本 |
| 实际可用状态 | 排除请假、设备不可用 | 不能作为能力低或降层证据 |
| 协作贡献候选 | 平衡任务负荷 | 编辑、上传和发言只是事实，需与任务和材料关联 |
| 教师锁定/避让 | 安全、支持和课堂实际 | 只对授权教师可见并保存原因代码 |

敏感属性只允许用于合法公平审计或必要的无障碍支持，不作为追求表面均衡的优化权重。

## 6. 第四轮：小组人数、角色和协作脚本

### 6.1 被否决的方案

- 认为所有任务的最佳人数都是 4 人。
- 每组只设一个永久组长，其他人都是普通成员。
- 仅通过聊天数量或文档编辑次数判断贡献。

### 6.2 文献约束

组内角色配置与参与模式可能关联协作过程和结果 [G5]；协作调节研究强调规划、监控、情绪和共同调节，而不只是完成作品 [R65, G6-G8]。现有证据不足以给 STRATA 一个适用于所有任务的唯一最佳组人数。

### 6.3 平台规则

- 默认目标人数可以保持 4 人，但必须由任务策略配置最小、目标和最大人数。
- 短讨论通常使用较小组；复杂项目可以使用较大组，但不得超过教师实际可管理范围。
- 角色扩展为：协调、记录、资源、展示、核验，教师可按任务启用子集。
- 角色按活动或项目阶段轮换，避免同一学生长期承担领导或低可见工作。
- 系统只生成角色候选，教师可以锁定、交换或取消角色。

## 7. 第五轮：动态更新必须保护协作稳定性

### 7.1 被否决的方案

- 学生层级每晚更新，小组也每晚自动变化。
- 活动进行中发现新数据就立即换人。
- 项目组每节课重新优化。

### 7.2 双时间尺度

- `证据更新`：每天或事件到达后更新准备度、支持状态和搭档历史。
- `分组决策`：只在新课堂活动、课时环节或项目阶段开始前生成。

正式规则：

1. 活动开始后冻结当前成员和角色，除非教师因安全、请假或严重冲突手动调整。
2. 短课堂组在当前活动结束后失效，不形成永久身份。
3. 项目组在当前里程碑内稳定，下一阶段才允许重组候选。
4. 分组策略保存最短稳定周期、最大成员变动比例和重复搭档上限。
5. 单次低分、未提交或聊天处理不能触发自动换组。
6. 每次调整保存旧组、新组、原因和受影响材料，不能删除旧证据。

“动态”的含义是按任务阶段重新评估，而不是频繁打乱关系。

## 8. 第六轮：第一版正式算法采用约束优化

### 8.1 为什么不先训练黑箱模型

目前没有足够真实数据说明“某名学生与哪些同伴组合是最优反事实”。历史小组又受到教师选择、任务类型和既有层级影响，直接监督学习会复现旧政策。动态分组算法研究可以证明组合方案可计算 [G4, G9, R69-R70]，但不能把算法目标值当作教学效果。

### 8.2 两层算法

```text
学习模型层
  -> 当前任务准备度、技能证据、完成支持、访问状态和不确定性

约束优化层
  -> 任务目的 + 硬约束 + 软目标 + 历史稳定性
  -> 生成多个候选分组
  -> 教师预览、锁定、调整并确认
```

第一版建议使用本地离线可部署的 OR-Tools CP-SAT；若安装器尚未提供 OR-Tools，则使用确定性启发式算法并保留相同策略合同。

“一班一个专有模型”在分组场景中实现为“学校/学科准备度模型 + 本班任务证据、搭档历史和约束 + 本次候选运行”，不是为几十名学生单独训练一个预测谁与谁最配的黑箱模型。

### 8.3 硬约束

- 每名当前可参与学生恰好进入一个组。
- 组人数在策略版本的最小和最大范围内。
- 教师锁定成员和锁定小组必须满足。
- 必要的避让、安全和无障碍约束必须满足。
- 已请假或本次无参与机会的学生不进入候选。
- 策略启用的关键角色必须覆盖；角色证据不足时返回冲突并由教师处理。

硬约束不能满足时，系统返回冲突说明，不能静默删除学生。

### 8.4 软目标

```text
总目标 = 任务适配
       + 技能覆盖
       + 角色轮换
       + 挑战与领导机会公平
       - 过度重复搭档
       - 不必要的成员变动
       - 任务负荷失衡
       - 极端准备度差距
```

权重保存在 `GroupingPolicyVersion`，由学科组和教师审定。系统至少返回随机、任务首选和稳定优先三个候选，不能只给一个无法比较的“最优组”。

## 9. 第七轮：公平、身份和学生权益

### 9.1 被否决的方案

- 学生看不到 A/B/C，所以按层固定小组就没有影响。
- 总让高准备度学生担任组长或帮助者。
- 把参与少的学生集中到同一个组。

### 9.2 必须审计的机会

- 共同核心任务和挑战任务机会。
- 解释、提问、展示、领导和核验机会。
- 与不同同伴合作的覆盖及重复搭档程度。
- 教师反馈、协作资源和设备支持。
- 被单独隔离、频繁换组或长期处于同一角色的情况。
- 学生提出换组、冲突或支持请求的处理。

学生只看到“第 N 组”等中性名称。组名、URL、JSON、下载文件名、聊天线程和协作文档标题不得包含层级、策略或能力推断。

## 10. 第八轮：小组证据与个人证据必须分开

### 10.1 被否决的方案

- 一个小组作品得 5 星，就给所有成员相同掌握标签。
- 文档编辑次数多就代表贡献大。
- 组内聊天数量多就代表协作质量高。

### 10.2 证据结构

| 证据 | 分析单位 | 用途 |
| --- | --- | --- |
| 小组作品与评价标准 | 小组 | 判断共同产出质量 |
| 个人共同题或反思 | 学生 | 判断个人掌握和迁移 |
| 角色履行材料 | 学生 × 角色 × 任务 | 描述任务责任完成 |
| 文档版本、上传和里程碑 | 小组及可验证编辑者 | 过程审计，不直接等同贡献质量 |
| 自评、互评和师评 | 评价者 × 被评价者 × 标准版本 | 过程性评价，需检查一致性和偏差 |
| 聊天与互动计数 | 小组 × 时间窗 | 协作旁证，不读取为个人能力 |

自动分析和反馈研究说明协作过程可以被记录并用于支持 [G6-G8]，但这些代理不能替代作品、个人测量和教师核查。

## 11. 第九轮：教师工作流、实时课堂和历史材料

### 11.1 教师流程

1. 选择当前环节或项目阶段。
2. 选择任务目的和组人数范围。
3. 查看可用学生、数据不足、请假和约束冲突。
4. 生成随机、任务首选和稳定优先候选。
5. 锁定学生、拖动调整、重新计算未锁定成员。
6. 预览每组技能覆盖、历史搭档和角色，但不显示能力型评价文字。
7. 确认并冻结计划。
8. 课堂开始后学生收到新组、角色和任务。

### 11.2 实时与文件规则

- 新计划生效时通过 WebSocket 通知学生，旧聊天线程关闭为只读。
- 旧协作文档、上传、评价和聊天按原组保留，不能移动到新组或物理删除。
- 新组创建新的 ONLYOFFICE 文档 key 和共享空间。
- 教师手动换组必须明确旧材料归属和新任务起点。
- 学生可以申请教师复核当前分组，但不能查看算法理由和其他学生信息。

## 12. 第十轮：实证研究必须比较“策略 × 任务”

### 12.1 研究问题

不能只问“AI 分组是否有效”，而应问：

1. 在聚焦补缺任务中，准备度接近组是否优于随机组。
2. 在同伴解释任务中，相邻准备度混合组是否优于同层组和随机组。
3. 在项目任务中，技能互补稳定组是否改善作品质量、个人掌握和参与公平。
4. 动态换组是否带来增益，还是增加协调成本和教师负担。

### 12.2 主要结果

- 个人层面：共同题掌握、迁移任务、成长和个人反思。
- 小组层面：冻结评价标准下的作品质量、里程碑达成和协作调节。
- 公平层面：角色、发言、挑战、领导和教师反馈机会。
- 实施层面：教师调整率、生成时间、冲突率、学生换组申请和系统拒绝率。

### 12.3 研究设计

- 先进行影子分组：系统生成候选但不改变真实组，检查可行性、冲突和公平。
- 再在预先选定任务中比较随机、教师常规和任务驱动候选。
- 随机单位根据污染风险选择班级、活动或预先登记的任务序列。
- 同一学生和同伴重复出现，分析必须考虑学生、组、班级、教师和时间结构。
- 小组成员会相互影响，不能使用假定学生完全独立的简单回归。
- 策略和权重在测试结果揭晓前冻结，失败和不良结果同样报告。

## 13. 正式动态分组策略

### 13.1 策略清单

| 策略代码 | 页面名称 | 适用任务 | 主要依据 |
| --- | --- | --- | --- |
| `random_baseline` | 随机分组 | 一般活动、研究基线 | 当前可参与学生和固定随机种子 |
| `readiness_aligned` | 准备度接近 | 聚焦补缺、同速练习 | 当前任务准备度和支架需要 |
| `readiness_bridged` | 相邻互助 | 同伴解释、讨论 | A/B、B/C 边界和解释机会 |
| `skill_complementary` | 技能互补 | 开放问题、短项目 | 任务技能需求和角色证据 |
| `stable_project` | 项目稳定组 | 跨课时项目 | 原组稳定、技能覆盖和阶段约束 |
| `manual` | 教师设置 | 特殊课堂条件 | 教师锁定和结构化理由 |

不再保留“AI 分层分组”作为正式页面名称。AI 或统计模型只提供准备度和支持证据，实际分组由可解释策略生成。

### 13.2 动态触发

| 场景 | 是否自动重新生成 | 处理方式 |
| --- | --- | --- |
| 夜间模型更新 | 否 | 更新候选证据，不改活动中小组 |
| 新课堂环节开始 | 教师可选 | 生成新候选，确认后生效 |
| 新项目阶段开始 | 教师可选 | 优先稳定原组，只调整必要成员 |
| 学生请假或设备故障 | 否 | 教师临时处理或重新生成未锁定成员 |
| 单次低分、缺交、扣分 | 否 | 只更新支持记录 |
| 严重冲突或安全问题 | 教师处理 | 保存紧急调整及原因，不等待优化器 |

## 14. 计划数据模型

以下模型尚未实现，名称可在迁移评审时调整：

- `GroupingPolicyVersion`：任务目的、人数范围、硬约束、软目标权重、稳定规则和策略版本。
- `GroupingDecisionPoint`：绑定学校、班级、课程、课堂环节或项目阶段及计划生效时间。
- `GroupingCandidateRun`：保存输入快照、算法版本、随机种子、候选数量、约束冲突和目标分解。
- `GroupingPlanVersion`：教师确认后的不可变分组计划，保存有效期、前一版本和调整原因。
- `GroupingPlanGroup`：中性组名、组序号、任务角色需求和内部目标摘要。
- `GroupingPlanMember`：成员、角色、是否锁定、来源候选和加入/退出原因。
- `GroupingPairHistory`：学生对在特定任务和时间窗内的合作次数，只保存结构化事实。
- `GroupingOpportunityAudit`：角色、领导、挑战、展示、教师反馈和重复搭档机会。
- `GroupingOutcomeSnapshot`：分开保存小组产出、个人共同任务、协作过程和实施结果。
- `GroupingTeacherDecision`：教师接受、调整、重新生成、手动设置和原因；不作为唯一最优分组标签。

现有 `ClassroomGroupCollaboration/ClassroomGroup/ClassroomGroupMember` 迁移为运行态兼容结构。历史记录必须保护性保留，禁止继续通过删除旧组和文件实现重新分组。

## 15. 开发顺序

| 编号 | 开发内容 | 完成条件 |
| --- | --- | --- |
| DG-01 | 停止默认按层分组 | 默认改为随机或教师先选任务策略；`ai_layer` 不再回退同层 |
| DG-02 | 建立策略和决策点 | 任务目的、人数范围、角色、稳定规则可版本化 |
| DG-03 | 建立不可变分组计划 | 同一课堂支持多个环节版本，重新分组不删除旧证据 |
| DG-04 | 实现约束优化候选 | 至少返回随机、任务首选和稳定优先方案及冲突说明 |
| DG-05 | 完成教师确认界面 | 支持锁定、拖动、重算、角色调整和二次确认 |
| DG-06 | 完成学生实时切换 | 中性组名、角色、聊天、文档和共享空间按计划正确切换 |
| DG-07 | 建立协作证据与公平审计 | 小组结果、个人结果、角色和机会分开保存 |
| DG-08 | 完成影子分组和实证准备 | 策略比较、干扰结构、主要结果和停止规则预注册 |

DG-01 至 DG-03 应与动态分层 DS-01 至 DS-06 并行开发。正式分组只读取版本化的任务准备度证据，不能继续依赖过渡期 `StudentProfile.current_layer`。

模拟数据可以验收每名学生恰好进入一组、人数范围、锁定/避让、角色覆盖、历史保护、实时切换和公平审计计算，但不能证明某种分组策略提高了真实学生学习。
