# 教师评价与教育实验页面纠偏记录

> 日期：2026-07-22  
> 范围：教师端“评价设计”、学校管理员端“教育实验”  
> 性质：产品与数据纠偏记录，不构成教育效果结论。

## 1. 本次发现的问题

1. 学校管理员页面把研究阶段代码、研究闸门、集群、数据锁和校验值等研究技术记录作为主界面内容，不符合学校日常工作表达。
2. 教师评价页面虽然已经保存“课程标准依据—学习目标—学习活动—评价任务—评价标准”的底层关系，但主页面仍按数据对象平铺，教师难以看出完整的评价设计过程。
3. 教师账号只有一份未发布的迁移草稿，没有测试式、操作式、项目式评价实例，也没有课堂试用实例。
4. 学校管理员账号没有教育实验草稿，页面只能呈现空状态。

| Research study | 教育实验 | 主界面 |
| Protocol | 教育实验方案 | 主界面 |
| Gate | 开展条件 | 主界面 |
| Cohort arm | 实验班、对照班、观察班、外校复核班 | 主界面 |

| Missingness | 缺测、设备问题、未获得机会和材料不足 | 主界面 |

研究方法中的原始字段和不可修改记录仍在后端保留，用于版本追溯、数据分析与研究复核，但不再占据学校管理员的主要操作路径。

## 3. 教师评价页面

页面主流程固定为：

```text
确定课程内容与学习目标
  → 设计学习活动与评价任务
  → 制定评价标准
  → 课堂试用与改进
```

教师首先看到以下教育边界：

- 测试只是评价方式之一；操作、项目、作品和答辩均可形成评价材料。
- 小组成果不能直接代替个人表现。
- 课程标准提供方向和质量参照，不直接换算成一次任务的分数。
- 没有获得评价机会、设备故障或材料不足时标记为“暂不评价”，不能按低表现处理。

评价方案列表直接展示学习目标、评价方式、学习活动数量、评价任务数量、课程标准依据数量和当前使用状态。指标、目标和任务的内部代码不再作为教师主要填写内容。

## 4. 信息科技评价实例

教师账号 `foldkant` 已建立并发布三类带明确“信息科技示例”标识的评价实例：

1. 测试式评价：个人作答与评分记录。
2. 操作式评价：个人操作过程与观察记录。
3. 项目式评价：小组数据作品与个人方法说明、答辩材料分开保存。

三类方案均对应普通高中信息科技课程标准当前发布版本，并保存核心素养、课程目标、课程内容和学业质量依据。另建立一条“项目评价课堂试用计划”，状态为待进行，没有伪造参与人数、试用结果或评分一致率。

原有“迁移草稿”没有发布版本，也没有课堂使用记录，已在备份后清除。

## 5. 学校管理员教育实验页面

学校端主流程固定为：

```text
明确实验问题
  → 确定共同测量
  → 安排实验班与对照班
  → 确认开展条件
  → 记录实际教学实施
  → 整理后测、问卷和分析数据
```

页面明确说明：

- 实验班与对照班使用一致的学习起点诊断。
- 后测可采用测试、表现任务、作品评价或问卷，应由研究问题决定。
- 建立实验草稿或实施计划不会自动改变学生评价、动态分层或动态分组结果。
- 缺测、设备问题、请假或未获得机会不能补成低分。
- SPSS 数据准备和统计差异不等同于教育效果结论。

学校管理员 `xlzx_admin` 已建立一项“信息科技项目式学习班级对照实验”示例草稿。该草稿只有教育问题和适用课程，没有登记虚假伦理信息，没有安排班级，没有启动实施，也没有生成教育效果结论。
