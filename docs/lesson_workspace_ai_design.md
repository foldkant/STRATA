# 课时学习工作台、资源预览与 AI 学习单设计

## 调整结论

当前教师端第一版的“课堂活动”更像后台管理列表，不适合作为真实上课界面，也不适合作为主要备课界面。

后续核心应改成“课时学习过程”：教师备课时制作同一份学习过程，学生学习时浏览同一份学习过程，课堂教学时控制同一份学习过程的开启、收集和反馈。

```text
课程
  -> 课时
      -> 学习片段 / 教学过程环节
          -> 学习资源预览
          -> 平台活动题
          -> 任务单/作品提交
          -> 学生行为事件
```

也就是：课程管理不是简单维护课程和课时；教师真正要制作的是一个个学生可学习、课堂可投放、课后可分析的课时片段。

同一份课时学习过程有四种模式：

```text
教师备课模式：制作学习过程，上传资源，配置题目、任务、评价和 AI 学习单。
学生学习模式：按片段浏览资源、完成题目、提交作品。
课堂授课模式：教师控制当前片段、发布活动、收集作答和查看完成情况。
课后复盘模式：查看行为数据、提交情况、评价结果和分层建议。
```

课程教学模式要影响工作台默认结构：

- 任务驱动学习：以课时学习过程为中心，重点是资源学习、课堂题、任务实践、作品提交和即时反馈。
- 项目式学习：以项目工作流为中心，重点是驱动问题、项目阶段、里程碑、甘特图、小组协作、项目日志、阶段成果和量规评价。
- 两种模式共用资源预览、题库、提交、评价、AI 学习单和行为采集能力。
- 两种模式都必须记录班级学习日志和学生学习日志，不能只记录最终分数、最终作品或提交时间。

## 页面结构

### 教师备课模式

教师备课不是单纯的学生浏览页，而是“片段化制作工具”。页面建议：

```text
左侧：课程 / 课时 / 片段目录
中间：当前片段编辑区
右侧：资源库 / 题库 / AI 助手 / 属性设置 / 学生预览
```

教师按片段制作：

```text
片段 1：情境导入
  - 上传导入图片、视频、PDF 或网页学习单
  - 添加导入问题

片段 2：知识学习
  - 上传 PPT、Word、PDF、视频等课件资源
  - 配置单选、多选、判断、填空或主观题

片段 3：任务实践
  - 发布任务说明
  - 提供素材包
  - 设置作品上传入口

片段 4：展示评价
  - 配置自评、互评、教师评价和量规

片段 5：小结反思
  - 设置反思题、出口卡或学习记录
```

每个片段应支持：

- 学生可见说明。
- 教师备课备注。
- 资源附件。
- 题目与答案。
- 任务提交要求。
- 是否必做。
- 目标层级。
- 预计时长。
- 发布状态。
- 是否写入学生学习日志。
- 是否写入班级学习日志。

任务驱动学习的日志重点：

- 学生进入任务。
- 资源学习和停留。
- 作答与修改。
- 作品草稿、提交和再次提交。
- 教师反馈后是否修正。
- 班级共性错误和教师干预。

项目式学习的日志重点：

- 项目阶段推进。
- 里程碑完成情况。
- 甘特图计划和实际进度偏差。
- 小组分工与协作记录。
- 个人项目日志。
- 阶段成果和最终成果迭代。
- 自评、互评、师评和量规差异。

### 学生学习 / 教师预览模式

学生端和教师预览学生视角时，可参考资源网站结构：

```text
顶部：课程名 / 课时名 / 班级 / 上课状态 / 发布状态

左侧：资源预览区
  - 视频
  - 图片
  - PDF
  - PPT/Word/Excel 转换预览
  - 代码/文本/Markdown
  - 压缩包文件清单

右侧：本环节任务区
  - 当前环节说明
  - 单选题 / 多选题 / 判断题 / 填空题 / 主观题
  - 讨论 / 提问
  - 作品上传
  - 课堂任务
  - 小结反思
  - 学生提交入口
```

课时环节不是“资源环节”和“题目环节”的简单串联。一个环节可以同时包含资源、视频、PPT、课堂题、任务和作品提交。学生学习时应在左侧查看当前环节资源，在右侧完成当前环节题目或提交任务；环节切换只作为轻量导航，不能挤占主要作答区域。

### 课堂授课模式

课堂授课不是重新做一套内容，而是对已备好的学习过程进行控制：

- 选择班级和课时。
- 开始课堂。
- 开启当前片段。
- 发布片段中的题目、任务或学习单。
- 查看学生完成状态。
- 收题、关闭片段、进入下一片段。
- 记录教师干预和学生行为。

## 新的信息架构

教师端导航建议保留：

```text
课程管理
课堂教学
资源管理
题库资源
任务与测试
```

但职责调整为：

- `课程管理`：维护课程、课时、教学过程环节和资源绑定。
- `课堂教学`：选择某个课时和班级进入实时课堂控制台。
- `资源管理`：维护个人资源库，支持预览和绑定到课时环节。
- `题库资源`：维护题目，供课时环节、测试、前测复用。
- `任务与测试`：维护更正式的作业、测试、成绩与批改。

## 资源预览技术路线

要求：私有化部署、离线可运行、不要依赖公网预览服务。

### 第一阶段推荐方案

```text
上传文件
  -> Django 保存原文件
  -> 按类型选择预览方式
  -> Vue 左侧预览区加载预览内容
```

支持方式：

| 文件类型 | 预览方式 |
| --- | --- |
| 图片 | 浏览器原生 `img` |
| 视频 | 浏览器原生 `video` |
| 音频 | 浏览器原生 `audio` |
| PDF | PDF.js 或 ONLYOFFICE PDF 预览 |
| TXT/MD/代码 | 后端转义后前端展示 |
| Word/PPT/Excel | 优先使用 ONLYOFFICE Docs；无协作需求时可转 PDF 预览 |
| Excel 表格 | 可选用 openpyxl 读取前几张表，生成表格预览 |
| ZIP/RAR/7z | 展示文件清单，不默认解压预览内部文件 |

说明：

- PDF.js 是 Mozilla 的 Web 标准 PDF 渲染器，可以离线打包到前端使用。
- ONLYOFFICE Docs 已在本机验证通过，可以不用 Nextcloud，由 STRATA 自己管理账户和权限。
- Word、PPT、Excel、PDF、表单和协作文档在检测到 ONLYOFFICE 时优先走 ONLYOFFICE。
- LibreOffice headless 可作为无协作场景的后备转换方案。
- ONLYOFFICE 不是必装依赖。成员校无法安装时，平台仍要通过 PDF.js、浏览器原生预览、LibreOffice 转 PDF、openpyxl 表格预览和文件下载保证基本教学可用。

### 不建议第一阶段做的事

- 不直接在浏览器中裸打开 Office 原文件，应通过 ONLYOFFICE 或转换产物预览。
- 不依赖微软、WPS 或第三方云预览。
- 不把压缩包自动完整解压到公开目录。
- 不允许宏文件执行。
- 不让学生上传文件后立即进入可执行网页环境。

### 预览安全规则

- 文件大小限制。
- MIME 类型检测，不能只信扩展名。
- 计算 SHA256，避免重复转换。
- 转换任务在临时隔离目录执行。
- 转换后只暴露 PDF、图片、文本等安全产物。
- 压缩包检查路径穿越和解压膨胀风险。
- 失败的预览任务显示“无法预览，可下载原文件”。

## DeepSeek 接入设计

DeepSeek API 官方兼容 OpenAI/Anthropic 风格接口，适合封装成统一 `AIProvider`。

平台侧应这样做：

```text
教师配置 DeepSeek Key
  -> 后端加密保存
  -> 教师测试连接
  -> 生成学习单草稿
  -> 后端校验 JSON DSL
  -> Vue 预览
  -> 教师确认发布
  -> 学生作答
  -> LearningEvent 记录全过程
```

AI 功能边界：

- AI 只能辅助生成草稿。
- AI 不直接发布内容。
- AI 不直接修改学生成绩、分层或档案。
- AI 生成的题目、学习单、网页必须由教师确认。
- AI 输出必须经过结构化校验。
- 教师可以关闭 AI 或删除自己的 Key。

## AI 生成分层题

课时设计器中的“AI 生成分层题”用于降低教师出题成本，但不能替代教师专业判断。

流程：

```text
教师填写出题方向、题型、层级、数量
  -> Django 使用该教师自己的 DeepSeek Key 调用 chat/completions
  -> 要求模型返回平台题目 JSON
  -> 后端清洗并校验题型、选项、答案、分值、层级
  -> Vue 展示题目草稿
  -> 教师直接加入或编辑后加入当前环节
  -> 保存环节后进入学生端课堂题
```

分值策略：

- 手动出题：选择/判断默认 2 分，填空默认 3 分，简答默认 5 分。
- 分层题：A、B、C 层分值先按基础分生成建议，A/B、B/C 等相邻层级会给轻微差异，教师可改。
- AI 出题：AI 返回的 `score` 和 `layer_scores` 是建议值，不会自动发布。
- 后续接入分层模型后，AI 可以根据历史作答和教师修正给更合理分值，但仍必须由教师确认。

训练边界：

- `layer_scores` 是题目设计上下文和特征，不是模型分层的唯一 label。
- 真正的分层训练 label 应优先使用教师最终确认的层级、AI 建议采纳/拒绝结果、后续学习表现。
- 学生作答时需要保存题目配置快照，避免教师后续改分值影响历史训练数据解释。

## AI 生成网页学习单

不能让 AI 生成任意 HTML、CSS、JS 并直接发布。

推荐使用“平台 DSL”：

```json
{
  "title": "数据可视化学习任务单",
  "blocks": [
    {"type": "markdown", "content": "阅读材料并完成任务。"},
    {"type": "single_choice", "id": "q1", "stem": "下列哪项属于数据清洗？", "options": []},
    {"type": "textarea", "id": "q2", "label": "写出你的分析过程"},
    {"type": "file_upload", "id": "work", "label": "上传作品"}
  ]
}
```

前端只渲染白名单组件：

- 标题。
- Markdown 文本。
- 图片。
- 视频。
- 表格。
- 单选。
- 多选。
- 判断。
- 填空。
- 长文本。
- 文件上传。
- 简单图表。
- 评分量规。

禁止：

- 任意 `<script>`。
- 任意 iframe 外链。
- 任意远程资源。
- 任意表单提交到外站。
- 任意内联事件。
- 任意读取 Cookie 或本地存储。

如果后续确实要支持“网页作品”：

- 使用 iframe 沙箱。
- 禁止同源权限。
- 只允许静态 HTML/CSS。
- 不允许外部网络请求。
- 所有文件走平台资源白名单。

## 页面改造路线

### 第一阶段：资源预览

1. 扩展资源模型，增加文件类型、大小、hash、预览状态。
2. 增加 `DocumentAsset` 和 `DocumentVersion`，接入 ONLYOFFICE 文档编辑配置和保存回调。
3. 前端增加左侧预览组件。
4. Office 文档优先使用 ONLYOFFICE。
5. PDF.js 作为 PDF/轻量预览方案。
6. LibreOffice 作为后备转换方案，写入私有化部署文档。

### 第二阶段：课时学习过程

1. 新增 `LessonStep`。
2. 课程管理中进入“课时设计”。
3. 教师端按环节组织资源、题目、任务、作品提交和学习单。
4. 学生端按同一环节同时显示左侧资源预览和右侧本环节任务。
5. 课堂教学端只控制环节开启、收题和进度，不重新创建内容结构。

### 第三阶段：课堂活动融合

1. `ClassroomSession` 不再单独承担内容结构，只表示一次上课。
2. `ClassroomActivity` 绑定到 `LessonStep`。
3. 教师课堂页控制当前环节开启、关闭和收集。
4. 学生端实时看到当前环节。

### 第四阶段：AI 学习单

1. 教师配置 DeepSeek API。
2. 后端封装 AI Provider。
3. AI 生成平台 DSL。
4. 教师预览确认。
5. 发布给学生。
6. 学生作答和行为进入 `LearningEvent`。

## 对当前代码的处理建议

当前已做的 `CourseClass` 可以保留。

当前已做的 `ClassroomSession` 也可以保留，但职责调整为“某次上课记录”，不是课程内容结构。

当前已做的 `ClassroomActivity` 后续应增加可选字段：

- `lesson_step`
- `source_question`
- `worksheet`

这样它可以从“独立课堂活动”变成“课时环节在某次课堂中的运行状态”。

当前 `/teacher/classroom` 页面后续应重做为：

```text
左侧资源预览
右侧本环节任务
底部或顶部课堂控制条
```

不再以课堂活动表格作为主体验。

## 参考技术

- PDF.js：Mozilla 的 PDF 渲染器，可作为内置 PDF 预览组件。
- LibreOffice headless：本地命令行转换 Office 文件到 PDF。
- ONLYOFFICE Docs：已验证可自托管接入，适合 Office 预览、编辑、协作和小组文档。
- DeepSeek API：支持兼容 OpenAI/Anthropic 风格调用，适合封装为可选 AI Provider。

## 部署约束记录

成员校部署以本地离线为主，后续只在夜间同步必要资源数据或导出数据包，不依赖云服务器持续在线。

后续 setup 安装流程必须记录并处理：

- 检测 ONLYOFFICE 是否已安装。
- 根目录离线安装包 `onlyoffice-documentserver.exe` 可作为可选安装源。
- 检测 ONLYOFFICE 与 STRATA 的端口占用，允许调整 Django/ASGI 端口。
- 安装失败不阻断 STRATA 主系统。
- 无 ONLYOFFICE 时关闭“协作编辑”按钮，保留“预览 / 下载 / 转 PDF 预览”。
- 每次资源预览能力检测结果要在管理员界面可见，便于成员校维护人员判断问题。

- 已实现教师端 `/teacher/lessons/:lessonId/design` 页面，支持新增、编辑、删除、上移下移和保存环节。
- 已实现环节字段：标题、类型、学生说明、教师备注、排序、必做、预计时长、目标层级、状态、日志采集开关、AI 生成目标。
- 已实现教师资源管理第一版，资源上传到教师个人资源库，支持课件、视频、PDF、Office 文档、文本和压缩包等本地文件。
- 课时设计右侧“资源”页签已接入资源上传和资源库列表，教师可在备课时上传资源并立即加入当前环节。
- 课时设计左侧上下文卡片不展示任教班级长列表，只显示学科、课程和当前课时，班级范围由课程管理页维护。
- 资源、题目、文档和活动当前仍以名称数组保存，用于验证教师备课流程；其中资源名称可来自真实上传资源。
- AI 接入已支持教师保存、清除和测试 DeepSeek Key；课时设计页暂只保存 AI 生成目标，不直接调用模型生成学习单。
- 后续要把名称数组升级为真实 `LessonStepResource`、题库、ONLYOFFICE 文档、AI 学习单 DSL 和学生提交模型。
