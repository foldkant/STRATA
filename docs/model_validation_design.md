# 统计验证与模型比较

> 版本：LONG-01 / MODEL-01 v2 / MODEL-02 v3 / MODEL-03 v4  
> 更新日期：2026-07-20

本模块用于验证学习数据、比较候选方法并生成教师审核建议。模型结果始终对学生隐藏；学校管理员查看汇总，任课教师只查看本人课程的个人建议。任何模型都不能自动修改学生层级。

当前 LONG-01 至 MODEL-03 使用的正式工程结果是“随后 7 日完成率”或“随后 7 日新增逾期数”。因此当前模型只用于完成支持预测和工程验收，不能解释为学科掌握模型，也不能用当前班内三分位 A/B/C 作为正式内容投放依据。正式动态内容带必须按[动态分层五轮科学验证与实证研究方案](dynamic_stratification_five_round_validation.md)和[第 6-15 轮核查](dynamic_stratification_review_rounds_06_15.md)完成 DS-01 至 DS-06。

## 1. 固定数据基础

每条分析记录对应“学生 × 学科 × 预先建立的分析时间点”。系统先冻结当时可用的学习指标，再等待随后 7 日结果成熟，最后生成不可修改的数据版本。

- 输入只使用 `operational_available` 快照，不读取时间点之后的信息。
- 指标键包含时间窗，例如 `opp_completion_rate__7d`。
- 缺失值保留原因，不用 0 代替。
- 正式数据和模拟批次不能混合。
- 少于 30 条测试记录时只显示“数据不足”，不报告性能结论。
- 正式训练结果只允许预先计划的共同掌握、可比较成长、后续完成和逾期；`current_layer`、教师历史 A/B/C、课堂积分和班内排名不得作为学生能力标签。
- 教师建议处理和实际内容投放作为实施与处理变量单独保存，不覆盖原始预测，也不自动变成下一轮真值。

## 2. LONG-01

LONG-01 在同一冻结版本内报告个人内变化、学生间差异、班级描述差异、重复测量相关结构和确定性范围。结果只描述关联，不使用因果措辞。

## 3. MODEL-01

| 编号 | 方法 | 用途 |
| --- | --- | --- |
| M00 | 总体平均 | 最低比较标准 |
| M01 | 透明规则 | 核查少量明确指标的方向 |
| M02 | 正则化统计 | 线性或逻辑统计基线 |
| M03 | 班级收缩 | 检查班级平均差异，不解释个人能力 |

所有方法使用相同验证范围：

- `V-A`：按时间留出。
- `V-B`：按学生整组留出。
- `V-C`：按班级整组留出。
- `V-D`：使用另一学校最新且同学科、同特征集、同结果定义的数据版本。
- `V-E`：测量或课程版本留出；没有第二个可比较版本时显示“暂不适用”。

## 4. MODEL-02

MODEL-02 在同一数据折比较 M00-M03、CatBoost 和 LightGBM。当前依赖固定为：

- CatBoost 1.2.10
- LightGBM 4.7.0
- scikit-learn 1.8.0
- NumPy 2.5.1
- pandas 3.0.3
- SciPy 1.18.0

每次运行保存：训练和测试数量、预测和拒绝数量、平均残差、残差平方和、MAE、MSE、RMSE、R²、覆盖率、Brier 分数、校准截距和斜率、残差分布、特征重要性、重复训练稳定性及班级间误差差异。二分类结果不使用 R²。高级模型实际预测数未达到 30 时，MODEL-03 不启用。

`V-D` 每所外校只取最新兼容版本，避免把同一学校的历史版本重复计入测试集。跨校学科通过冻结清单中的标准学科键匹配；正式部署后需要由学校管理员维护学科标准映射。

## 5. 防误判检查

每次比较固定保存五项检查：

- 标签打乱后不应稳定优于总体平均。
- 随机匿名编号不应稳定优于总体平均。
- 输入名称不能包含未来结果字段。
- 离线、数据错误等审计字段不能进入首期主模型。
- 班级身份只用于差异检查，不解释为学生能力。

检查失败时结果标记为 `blocked`，不生成班级候选。

## 6. MODEL-03：完成支持模型

MODEL-03 采用“全局结构化模型 + 班级残差收缩校准”，不为几十名学生从零训练独立树模型。

1. 从 MODEL-02 中选择可报告且主要指标较好的 CatBoost 或 LightGBM。
2. 使用完整冻结数据训练全局模型。
3. 计算班级残差，并向全局残差收缩，保存每班校准参数。
4. 保存模型文件路径和 SHA-256。
5. 为每名学生生成当前兼容格式的 A/B/C 教师审核候选，用于验收审核、发布和回滚流程。
6. 新候选生成后，旧的待处理模型候选标记为“已由新版替代”。

教师可采纳、保持、调整或暂缓。当前过渡实现中，采纳和调整会更新 `StudentProfile.current_layer` 缓存，保持和暂缓不改层级；后续改由版本化 `StudentSubjectBand` 生效。学生端不返回层级、置信度、模型原因或排名。

当前 A/B/C 由班内预测分布切分，含义是测试期的相对完成支持分组，不是课程标准参照的 A/B/C 内容带。正式学校不得据此自动降低或提高题目难度。下一阶段必须完成：

1. 将完成率和逾期数分别输出为支持信号，不再映射正式内容带。
2. 增加下一次计划共同测量的掌握结果、测量版本、锚题和不确定性。
3. 由学科组审定的标准参照阈值生成 A、A/B、B、B/C、C 或“暂不建议”。
4. 使用连续证据、滞回、冷却期、单次一级和教师确认形成版本化 `StudentSubjectBand`。

RMSE、MAE、R2、Brier 和校准指标只评价预测。它们不能证明动态分层提高了学习效果；教学效果必须另行开展前瞻性集群研究。

## 7. 夜间任务

每天 03:10 执行 `run_nightly_model_validation`：

1. 每个学校、学科、特征集和结果定义只取最新冻结版本。
2. 运行 LONG-01、MODEL-01、MODEL-02 和 MODEL-03。
3. 相同数据和代码版本直接复用已有结果。
4. 生成候选版本，等待教师确认。

Celery Beat 默认不传测试参数，因此正式任务自动排除模拟批次。开发验收可手动执行 `run_nightly_model_validation(include_test_data=True)`。

学校管理员也可以在 `/app/school-admin/models` 选择一个已冻结数据版本，点击“开始模型训练”。手动入口依次运行 LONG-01、MODEL-01、MODEL-02 和 MODEL-03；相同数据版本与代码版本复用已有结果，不重复制造记录。训练失败不会改变当前发布版本。

页面默认使用通俗的“运行概览”，展示当前模型、训练记录数、班级参数、教师候选和发布状态。MAE、MSE、RMSE、R²、平均残差、覆盖率与残差分布使用 ECharts 展示，并支持高分辨率 PNG 下载。研究验证折、负对照和历史签名包放在“详细检查”。XLSX 同时提供精确模型指标和匿名预测明细，便于后续使用 Python、R 或统计软件复现论文图表。

- 每校 24 个分析时间点、576 条已观察冻结记录。

- CatBoost、LightGBM 在 V-A 至 V-D 均实际预测，覆盖率为 1；V-E 因没有第二测量版本显示暂不适用。
- V-D 每校使用另一学校 576 条最新兼容记录。
- MODEL-03 每校生成 96 条教师待确认候选和 4 组班级校准参数。
- 模型文件校验码与磁盘文件重新计算结果一致。
- XLSX 已包含模型卡、比较结果、重复测量、防误判检查、稳定性、班级差异、班级校准、班级参数和匿名预测明细。
- PostgreSQL 17.10 完整迁移及 8 项专项测试通过。

详细记录见[MODEL-02/03 工程验收报告](model02_model03_validation_report.md)。模拟结果只能证明程序可运行，不能证明模型对真实学生有效。

上述 96 条候选是测试期完成支持分组。即使全部通过发布、签名、教师确认和回滚，也不构成掌握层级有效性证据。

## 9. 候选发布与回滚

- 夜间任务只生成 `candidate`，教师在候选发布前看不到对应 MODEL-03 建议。
- 学校管理员发布时依次校验候选状态、比较运行、阻塞问题、教师确认规则、模型文件路径和 SHA-256。
- 发布生成包含清单、模型文件、公钥和 Ed25519 签名的离线 ZIP，并在切换当前版本前执行自校验。
- 同一学校、学科和测试数据范围只允许一个当前版本；正式数据与测试数据相互隔离。
- 发布失败不改变当前版本，成功和失败均写入不可修改审计。
- 回滚先重新校验历史模型包，成功后才切换当前版本；历史发布记录不删除。

专项回归已在 SQLite 和 PostgreSQL 各验证发布、篡改拒绝、失败保护、新版本替换、旧版本回滚、跨校权限和教师可见性。运维流程见[模型发布、校验与回滚](model_release_operations.md)。
