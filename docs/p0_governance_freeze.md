# P0 术语、权限、版本与数据用途工程冻结清单

> 冻结编号：`P0-GOV-20260722-v1`  
> 生效日期：2026-07-22  
> 适用对象：产品界面、API、数据库模型、管理命令、导出、工程文档和后续 P1—P4 开发  
> 冻结性质：工程治理基线，不等同于课程标准专家复核、评价效度结论、伦理批准或教育实验结果。

## 1. 冻结依据和优先级

发生名称或边界冲突时，按以下顺序处理：

1. 本冻结清单规定的角色、版本和数据用途硬边界；
2. `terminology.md` 的统一产品名称；
3. `p0_p1_curriculum_governance_acceptance.md` 的 P0—P1 状态和验收规则；
4. `p0_as_is_to_be.md` 的当前实现范围；
5. 科学设计文档中的研究术语和拟议对象。

研究文档可以使用效度、测量误差、评分一致性、IRT、DIF 等学术概念，但不能据此新建与统一产品名称冲突的菜单、字段或数据真值源。

## 2. 术语冻结

| 必须使用的产品名称 | 准确定义 | 禁止替代或误用 |
| --- | --- | --- |
| 评价方案 | 教师围绕学习目标、评价依据、学习任务和评分规则形成的可版本化设计 | 不简称“测试方案”；不把课标原文机械改写后称为完成评价设计 |
| 评价标准 | 一组适用于明确课程和任务的评价指标 | 不使用“五星量规”作为产品栏目 |
| 评价指标 | 教师可以依据评价材料判断的一项具体表现 | 不使用“量规条目”；材料不足时必须允许暂不评价 |
| 星级表现说明 | 1—5 星对应的可观察表现 | 不使用“锚点”作为普通教师栏目；不得把缺失补成 1 星 |
| 评价材料 | 测试作答、作品、操作、实验、展示、答辩、过程材料等支持判断的材料 | 不把签到、时长、兴趣或设备条件直接当学科表现 |
| 学习状态 | 学生在具体学科目标、时间和材料范围内的当前表现及不确定性 | 不称永久能力、人格或固定层级 |
| 学习内容层级 | 教师在限定教学窗口内确认的内部内容安排 | 不向学生显示 A/B/C，不称学生身份或能力等级 |
| 分层建议 | 系统面向教师提供的可拒绝学习内容安排候选 | 不自动生效，不把前测一次得分直接变为层级 |
| 分组候选方案 | 针对具体任务、阶段和约束生成的候选成员与角色安排 | 不把学习内容层级直接复制成同层组或异层组 |
| 分组计划 | 教师确认的特定任务成员与角色安排 | 不称永久学生群体，不把计划机会当实际机会 |
| 课程标准内容条目 | 经复核的核心素养、课程目标、课程内容或学业质量原文条目 | 普通界面不称“节点”；不直接生成学生得分 |
| 当前使用版本 | 新建工作引用的某个已发布课程标准版本 | 不是覆盖文件，不表示历史记录自动跟随更新 |
| 测试数据批次 | 明确用途、来源、对象清单和清单校验值的一组非正式数据 | `test`、`111`、`SIM` 等名称不能单独构成批次证据 |
| 测试数据对象标记 | 测试数据批次中一个精确模型和主键的审计登记；误标只撤销生效状态并保留原记录 | 不允许按模糊标题批量推断，不直接登记个人账号或学生档案 |

其他统一名称、兼容名称和停用名称以 `terminology.md` 为准。

## 3. 权限冻结

| 角色 | P0—P1 允许 | 明确禁止 |
| --- | --- | --- |
| 超级管理员 | 管理课程标准档案、版本、原文件、来源、解析、复核流程、发布、归档、恢复和测试数据批次登记 | 不代替任课教师制定成员校评价；不把未复核课标用于正式评价；不按名称模糊标记测试数据 |
| 独立课标复核人员 | 核对逐页文本、四类内容条目、层级关系和原文位置并留痕 | 不复核本人创建或提交的版本；不以 AI 摘要替换原文 |
| 教师 | 只读已发布课程标准；后续选择适用版本和内容条目，制定、修改并审核本人课程的评价 | 不修改国家课程标准；不直接发布课标；不读取其他学校的内部数据 |
| 学校管理员 | 只读已发布课程标准；管理本校账号、班级和数据检查 | 不编辑课程标准或教师评价内容；不读取跨校个人明细 |
| 学生 | 后续查看教师公开的学习目标、评价要求、实际任务和本人结果 | 不读取课标治理后台、内部学习内容层级、模型参数、他人材料或分组优化依据 |
| 系统/AI | 保存、解析、检索并提示待复核内容；后续在受控入口生成可编辑初稿 | 不自动发布、自动确认课标对齐、自动评分、自动分层或自动分组 |

权限必须由服务端实施，不能只隐藏按钮。教师和学校管理员只读已发布内容；课程标准写入、测试批次登记和治理操作仅限超级管理员。生产设置下，创建/提交、复核和发布必须职责分离。

## 4. 版本冻结

1. 课程标准、评价方案、评价标准、评价指标、评分说明、内容带政策、分组政策和研究数据版本必须使用明确版本标识。
2. 草稿可以更正；进入复核后的课程标准页和内容条目不可直接修改；发布版本不可原地修改或删除。
3. 新文件、新修订、新适用范围或正式内容变化必须新建版本，并保存替代关系和差异。
4. “当前使用版本”只是指向已发布版本的关系；恢复历史版本只更新该关系并生成操作记录，不删除后续版本。
5. 历史评价、课堂、分层、分组和研究数据必须继续引用当时版本，不能静默跟随当前版本。
6. 无来源、无文件校验值、无原文位置或未完成规定复核的课标内容不得进入正式评价引用。
7. 任何 AI 模型、系统提示、检索库、评分器或用途变化都必须产生新版本；相同供应商模型名不能视为可重放证明。
8. 测试数据批次清单不可覆盖；对象范围或用途变化时必须建立新批次并说明旧批次处置。

## 5. 数据用途冻结

| 数据用途 | 可以包含 | 可以支持的结论 | 禁止用途 |
| --- | --- | --- | --- |
| 正式教学运行 | 经授权的真实课程、任务、评价材料和教师决定 | 当前业务事实和经授权的教学支持 | 未经批准的研究、跨校个人比较、外部 AI 发送可识别学生数据 |
| 开发测试 `development_testing` | 明确测试批次、测试账号和非正式内容 | 页面、接口、迁移和状态流转是否工作 | 正式学校统计、模型训练、教育效果或科研结论 |
| 验收测试 `acceptance_testing` | 冻结验收场景和明确对象清单 | 工程验收条件是否通过 | 推断评价有效、分层准确、分组有效或 AI 质量 |
| 迁移验证 `migration_verification` | 迁移前后快照、数量、哈希和映射结果 | 迁移完整性、幂等性和回滚能力 | 教学判断、学生比较和模型训练 |
| 研究沙盒 `research_sandbox` | 经批准的去身份或合成研究副本 | 预先限定的探索性方法结果 | 直接影响学生；冒充正式确认性研究；绕过伦理、同意或用途期限 |
| 正式研究 | 另行批准、预注册并冻结的数据版本 | 协议允许范围内的描述、预测或因果结论 | 使用开发/验收批次补样本；把工程测试写成 SCI/SSCI 效果证据 |

所有用途都必须保留来源、时间、版本、观察机会和缺失原因。未投放、未参加、未提交、未评分、材料不足、技术问题和不适用于当前任务必须分开记录，不能统一补成 0 分、1 星或最低学习内容层级。

## 6. 历史和手工测试数据登记规则

1. 合成数据继续使用 `SyntheticDatasetRun`，不得重复建立手工批次作为第二真值源。
2. 历史/手工测试对象使用 `TestDataBatch` 和 `TestDataObjectMarker`；初期只允许登记白名单内的非个人根对象。
3. 每个批次必须有唯一 `TEST-` 编号、唯一用途、来源类型、说明、精确对象清单、对象名称快照和 SHA-256。
4. 正式登记前必须先执行 `--dry-run` 并核对对象；正式登记需要超级管理员和 `REGISTER_TEST_DATA` 显式确认。
5. 标题、前缀、创建人、日期或所在开发机都不能单独证明某对象是测试数据。
6. 模糊对象保持“未分类并待人工确认”，不得自动删除、排除或纳入测试批次。
7. 误标正式对象时使用 `revoke_test_data_marker`，记录撤销人、时间和不少于 10 个字符的原因；原批次和对象记录保留，正式查询只识别仍生效的标记。
8. `exclude_explicit_test_data_objects` 和 `assert_no_explicit_test_data_objects` 为直接根对象查询提供统一排除或阻断；它们不会自动传播到子记录。正式训练或统计必须先把证据范围解析回课程等治理根对象，再执行阻断。
9. 在所有正式统计和训练入口完成上述根对象检查前，手工批次对象及其下游数据不得进入正式分析任务。

示例：

```powershell
python manage.py register_test_data_batch `
  --batch-code TEST-MANUAL-COURSE-4-20260722 `
  --purpose acceptance_testing `
  --source-kind historical_manual `
  --description "只用于界面和迁移验收，不得进入正式统计、训练或科研结论。" `
  --target courses.Course:4 `
  --actor superadmin `
  --dry-run
```

只有在后台任务安全边界内应用 `learning_analytics.0032` 后，才能去掉 `--dry-run` 并添加：

```powershell
--confirm REGISTER_TEST_DATA
```

误标撤销先 dry-run，再显式确认：

```powershell
python manage.py revoke_test_data_marker `
  --target courses.Course:4 `
  --actor superadmin `
  --reason "经来源台账复核，该课程属于正式教学数据，原测试标记错误。" `
  --dry-run

python manage.py revoke_test_data_marker `
  --target courses.Course:4 `
  --actor superadmin `
  --reason "经来源台账复核，该课程属于正式教学数据，原测试标记错误。" `
  --confirm REVOKE_TEST_DATA_MARKER
```

## 7. 变更和解冻条件

本冻结清单只能通过新版本变更。变更申请至少包括：原因、教育含义、角色影响、数据用途影响、数据库迁移、历史兼容、测试、回滚步骤和责任人。以下变化必须重新审查：

- 新增或停用产品术语；
- 扩大任一角色的读写范围；
- 放宽复核或发布条件；
- 允许历史记录跟随当前版本；
- 把一种数据用途提升到另一用途；
- 扩大测试数据对象白名单；
- 让 AI 输出直接进入评分、分层、分组或正式研究数据。

## 8. 本次冻结的剩余治理边界

- 本文件建立的是可执行工程规则，不声称已经取得外部专家、学校或伦理委员会签字。
- P0/P1 最终代码已经形成专用分支提交和本地 Git 标签；具体提交与标签记录在 `p0_baseline_manifest.json`。跨机器部署前仍应推送至受控远端或制作不可变源代码包。
- `learning_analytics.0032` 尚未应用到正在被 OCR worker 写入的开发库；应用结果必须在 `p0_data_migration_ledger.md` 追加，不得提前写成已完成。
- 模糊历史对象仍需项目负责人逐项确认；未确认不等于正式数据，也不等于测试数据。
