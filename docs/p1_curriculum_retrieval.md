# P1 课程标准 AI 检索边界

## 当前实现

P1 面向平台内数量有限、由超级管理员治理的课程标准，采用本地 `keyword_v1` 关键词检索。候选生成使用数据库 `icontains`，最多读取 1000 条候选，再进行确定性排序；当前实现不调用外部大模型、向量数据库或第三方检索服务。

检索单元同时覆盖逐页原文和结构化内容条目。每个分片固定保存课程标准版本哈希、PDF 哈希、页码范围、逐页哈希、来源文本哈希和内容条目哈希。对外提供分片前，会重新核对分片清单的稳定摘要；即使分片数量未变化，只要正文、分片 ID、来源哈希或页哈希被改动，该索引也会判定为失效并要求重建。

内容条目的 `content` 是经过治理的结构化条目文本，不等同于完整 PDF 页面原文。原文追溯接口通过 `source_pages` 单独返回对应 `CurriculumStandardPage` 的页码、真实逐页文本、内容哈希和复核状态。

实际执行批量重建时必须使用 `--actor <超级管理员账号>`；命令会在索引发生重建时写入 `retrieval_index_rebuilt` 审计记录。`--dry-run` 只读取待处理范围，不要求执行人，也不会写索引或审计记录。

2026-07-22 12:40 开发库验收快照中，34 个已处理版本已生成 4,411 个检索片段，失败 0；剩余 14 个扫描版本继续由低优先级队列逐个处理。`audit_curriculum_standards --published-only --strict` 对两份当前使用的信息科技课程标准返回 0 个错误、0 个警告；对全部 48 个版本的只读审计返回 0 个错误，警告仅用于提示仍待后台文字识别、尚未发布或尚无当前使用版本的草稿状态。

机器可读导出同时提供单个自包含的结构化 JSON 与流式 JSONL。两种格式都保存版本、PDF/正文校验值、逐页文本、内容条目和原文页码；结构化 JSON 还按 `standard`、`version`、`pages`、`content_items` 和 `retrieval` 分组，便于管理员复核及后续受控的 AI 准备任务读取。

## 替换边界

`backend`、分片标识和原文追溯契约已经分离。课程标准数量或并发量明显增加后，可新增数据库全文检索或向量检索后端，只替换候选生成与排序层；版本隔离、权限、发布状态过滤、稳定分片 ID、页码追溯和完整性校验不得绕过。任何向量后端均应以已发布的相同分片快照为输入，并记录嵌入模型、参数和索引版本。
