# P2 评价核心重构：冻结契约与验收清单

> 契约版本：`P2-EVALUATION-CORE-20260722-v1`  
> 适用范围：信息科技 / 信息技术课程的教师评价方案、评价标准、发布版本与课堂使用  
> 当前状态：工程实现与隔离自动化验收已通过；正式开发库迁移待 P2—P5 统一切换窗口执行  
> 性质说明：本文是产品与工程验收契约，不是课程标准专家审定、评价效度证据、伦理审批或 SCI 实证结论。

## 1. 教育含义与流程边界

教师评价设计必须保留以下可追溯关系：

```text
课程标准原文及版本
  └─ 课标依据（核心素养、课程目标、课程内容、学业质量）
       └─ 学习目标
            └─ 学习活动
                 └─ 评价任务
                      └─ 评价标准（评价指标、表现水平与评分示例）
                           └─ 作答、操作、作品、答辩、观察和评分记录
```

课程标准提供方向、内容范围和学业质量参照，不直接换算为分数。学业质量是阶段性综合表现参照，不能被系统自动解释成单个任务等级。

本阶段不引入学校行政审批。评价方案和评价标准由课程教师承担专业责任，冻结流程为：

1. **编辑中**：教师可保存尚未完成的草案。
2. **教师复核确认**：系统执行完整性、关系覆盖、材料一致性和课标追溯检查；教师确认当前内容可进入版本发布。
3. **发布不可变版本**：只有当前内容与复核确认时的内容校验值完全一致，才可发布。
4. **可选课堂试用**：试用、评分培训和评分一致性检查使用独立记录，不混入内容复核状态。

“教师复核确认”只表示教师已检查内容完备性和适用性，不表示已经获得行政批准，也不表示该评价工具已经取得效度、信度或公平性证据。

## 2. 状态、审计与版本

内容复核状态只保留：

| 状态 | 教育含义 | 可执行操作 |
| --- | --- | --- |
| `draft` | 编辑中 | 编辑、保存、提交教师复核确认 |
| `reviewed` | 教师已完成复核 | 发布当前内容；再次编辑后自动回到编辑中 |
| `legacy_unverified` | 历史版本待复核 | 只读追溯，不得新绑定课堂 |

方案和标准草案保存复核人、复核时间和规范化内容校验值；发布版本同时冻结这些审计信息。任何内容修改或课标依据调整都必须清空原复核信息并回到“编辑中”。

内容校验值不包含状态名称、显示文案和时间等流程元数据，避免“完成复核”这个动作本身改变被复核内容的校验值。

历史迁移不得根据旧状态名称推断已经完成新流程下的教师复核。旧可变记录迁移为“编辑中”；旧发布版本迁移为“历史版本待复核”，保留原文和历史关系，但不能新增课堂绑定。

## 3. 评价方案关系约束

发布前必须同时满足：

- 每条学习目标关联同一已发布课程标准版本中的核心素养、课程目标、课程内容和学业质量依据，并能追溯到页码、原文和内容校验值；
- 每条学习目标至少有评价依据、学习活动和评价任务；
- 每个学习活动至少被一个评价任务使用；
- 评价任务所关联的每个学习活动，必须与该任务至少共享一个学习目标；
- 评价任务的每个学习目标，必须至少得到一个所关联学习活动的支持；
- 评价任务权重合计为 100%；
- 方案级评价方式由评价任务自动推导，必须与全部任务方式的去重集合完全一致，不能人工维护第二份值；
- 发布版本除 JSON 快照外，还保存“评价任务—学习活动”等不可变显式关系，便于追溯、查询和后续研究数据审计。

关系代码是系统生成的稳定标识。代码在界面中只读；删除上游对象时必须同步清理尚未发布草案中的下游引用，不能留下孤立关系。

## 4. 六类评价方式

评价方式依据需要观察的学习表现选择，平台不得默认用测试替代操作、项目、作品或答辩。

| 评价方式 | 至少需要的材料语义 | 边界 |
| --- | --- | --- |
| 测试式评价 | 作答记录或评分记录 | 不能只用小组作品代替测试作答材料 |
| 操作式评价 | 操作记录或观察记录 | 应保留实际操作过程或可归因观察 |
| 项目式评价 | 作品、操作、观察或答辩材料中的至少一种 | 小组项目材料与个人表现材料分别保存 |
| 作品评价 | 作品材料 | 可补充观察或说明，但作品是必要材料 |
| 答辩评价 | 答辩记录 | 可补充观察或评分记录，但答辩记录不可缺失 |
| 混合评价 | 至少两种非“混合”的组成方式，并分别具备相容材料 | 必须明确组成方式，不能把“混合”作为无含义的兜底项 |

以上是工程层最低一致性约束，不代替教师基于课程内容、学习目标和教学情境进行专业判断。

## 5. 个人与小组评价材料

- `individual`：只允许支持个人表现判断的材料；
- `group`：保存为小组材料，不伪填某名学生；
- `both`：评价标准必须由一个同时适用两类材料的指标，或由个人指标与小组指标组合，完整覆盖个人和小组两类材料；
- 小组作品、共同得分或小组完成情况不能自动转写为任一成员的个人学习水平；
- 个人作答、个人操作、个人说明、个人答辩或能够归因到个人的观察，才可进入个人材料覆盖率；
- 材料缺失、设备问题、未获得机会和等待评价不等于低表现，不补成 0 分或低等级。

## 6. 评价标准与确切方案版本

评价标准草案必须绑定一个明确的、已经完成教师复核并发布的评价方案版本，不得只绑定可变的方案草案，也不得在发布时自动选择“最新版本”。

方案发布新版本后，既有评价标准仍指向原方案版本。教师若要采用新方案版本，应显式新建或修改标准草案、重新完成教师复核并发布新标准版本。

每项评价指标必须：

- 关联确切方案版本中的学习目标和评价任务；
- 与所选任务至少共享一个学习目标；
- 使用与所选任务相容的个人 / 小组归属和材料类型；
- 提供可观察的预期表现、暂不评价条件、1—5 星表现说明、评分示例和后续教学建议；
- 在发布版本中保存“评价指标—评价任务”和“评价指标—学习目标版本”的不可变显式关系。

## 7. 课堂使用、安全与并发

课堂环节只能新增绑定满足以下条件的评价标准版本：

- 版本状态为“教师已完成复核”；
- 复核人、复核时间和复核内容校验值完整，且校验值与发布内容一致；
- 标准绑定确切的已复核评价方案版本；
- 课程、学科和学校范围与课堂环节一致；
- 课标依据和完整评价关系链可追溯。

已经在课堂使用的旧版本继续保留并可追溯，不因新版本发布而回写或替换。

方案和标准发布必须幂等。相同内容的重复请求返回同一版本；SQLite 并发造成唯一约束竞争或短暂写锁时，服务应有限重试、读取竞争胜出的版本或返回明确的 `409` 冲突，不得返回未处理的 `500`，也不得生成重复版本或孤立关系。

已完成的试用记录保存完成人、完成时间和完成内容校验值。完成后模型层禁止修改和删除；后续更正通过新增补充记录完成，不覆盖原记录。

| 验收项 | 必须验证的结果 | 当前状态 |
| --- | --- | --- |
| 完整关系链 | 四类课标依据、目标、活动、任务、指标均可双向追溯，缺链时拒绝复核 / 发布 | 通过 |
| 活动与任务目标一致 | 无共同目标或任务目标未获活动支持时拒绝 | 通过 |
| 六类评价方式 | 六类均有正向用例；材料不相容和混合组成不足均被拒绝 | 通过 |
| 方式唯一来源 | 方案方式始终等于任务方式去重集合，前后端均不能产生漂移 | 通过 |
| 个人 / 小组材料 | 方案和标准版本分别冻结材料归属；`both` 完整覆盖；小组材料不形成个人水平 | 通过（实际学生材料存储在 P3 验收） |
| 草案与复核 | 不完整内容可保存草案，但不能完成复核；编辑已复核内容后状态重置 | 通过 |
| 确切方案版本 | 标准始终绑定教师实际选择的方案版本，新版本不静默漂移 | 通过 |
| 不可变发布 | 已发布版本不能修改 / 删除，相同内容发布幂等 | 通过 |
| SQLite 竞争 | 确定性冲突测试无 `500`、无重复版本、无孤立关系 | 通过 |
| 课堂安全门 | 未复核、历史待复核、跨课程版本不能绑定；合格版本可以绑定 | 通过 |
| 试用完成记录 | API、模型 `save` 和 `delete` 均不能改写已完成记录 | 通过 |
| 信息科技三类方案 | 测试式、操作式、项目式方案分别通过，项目个人 / 小组材料清楚分离 | 通过 |
| 前端交互 | 草案保存、复核确认、发布状态、确切版本选择、错误提示和重复点击防护可用 | 通过 |

P2 只有在上述聚焦测试、Django 系统检查、迁移检查、Vue 类型检查和相关 Vitest 全部通过后才能解锁 P3。测试数量与最终结果必须以当次命令输出登记，不能沿用历史数字。

## 9. 迁移与回滚边界

P2 数据迁移必须先在数据库备份副本演练，并核对方案、标准、版本、指标、试用记录和课堂绑定数量。生产开发库迁移前停止 Web 写入和异步 worker；迁移后先执行聚焦测试和只读审计，再恢复服务。

若迁移、权限、校验值、版本关系或课堂绑定出现不一致，应停止服务并恢复迁移前数据库与媒体备份。不要通过覆盖已发布版本、删除历史材料或手工伪造复核状态进行“修复”。
