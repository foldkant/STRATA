# 信息科技评价、动态分层与动态分组 P2—P5 重构与工程验证记录

> 记录版本：`P2-P5-IT-20260722-v1`  
> 适用范围：信息科技/信息技术课程；P2 评价核心、P3 学习起点诊断、P4 动态分层、P5 动态分组  
> 记录性质：工程设计、风险处置和自动化验证记录。它不是课程标准专家审定、评价效度证明、伦理审批、模型效果证明或 SCI 实证结果。

## 1. 底层设计结论

平台不把课程标准直接转换成分数，也不把一次测试结果直接转换成学习内容层级或小组。课程标准提供方向、内容范围和质量参照；教师评价必须经过完整的教学与评价设计链。

```text
核心素养—课程目标—课程内容—学业质量
                    │
                    ▼
            课程标准内容条目（带版本、页码、原文）
                    │
                    ▼
课标依据 → 学习目标 → 学习活动 → 评价任务 → 评价标准
                                      │
                                      ▼
                 作答、操作、作品、答辩、观察和评分记录
                                      │
                                      ▼
        学生 × 学习目标 × 时间的学习目标情况版本
                         ├─ 学习支持建议
                         └─ 学习内容层级建议
                                      │
                                      ▼
任务目的、阶段、角色、资源和约束 → 分组候选 → 教师复核 → 启用 → 通知
```

四项不可跨越的边界：

1. “学业质量”是阶段性综合表现参照，不是单个评价任务的自动标签。
2. 测试、操作、项目、作品和答辩各自适合观察不同表现；平台不得默认用测试替代全部评价。
3. 小组作品是小组评价材料。只有能够归因到个人的作答、操作、说明、答辩或观察记录，才能支持个人学习情况判断。
4. 材料缺失、设备问题、未获得机会和等待评价均不等于低表现，不得补成 0 分、1 星或 C 层。

## 2. 术语与对象冻结

| 产品名称 | 工程对象 | 教育含义与边界 |
| --- | --- | --- |
| 课标依据 | 课程标准版本与内容条目引用 | 必须追溯到已发布版本、原文页码和内容校验值 |
| 学习目标 | 评价方案中的版本化目标 | 对应课程内容和预期学习表现，使用教育领域规范表达 |
| 学习活动 | 学生为达成学习目标经历的活动 | 不是评分项；必须说明与学习目标的关系 |
| 评价任务 | 产生规定评价材料的任务 | 明确评价方式、个人/小组归属、材料类型和权重 |
| 评价标准 | 若干评价指标及星级表现说明 | 每项指标必须关联学习目标和评价任务 |
| 学习起点诊断（前测） | 已发布诊断版本、提交与材料记录 | 只形成目标级初始情况，不直接确定固定层级 |
| 学习目标情况版本 | 学生×学科/课程×目标×时间的不可变记录 | 保存材料覆盖、有效期、估计与不确定性 |
| 学习支持建议 | 教师可确认或暂缓的支持安排 | 与学习内容层级建议分开，不把需要支持等同于低层级 |
| 学习内容层级建议 | 教师可拒绝的内容安排候选 | 材料不足时显示“暂不建议”；教师确认后才生效 |
| 分组候选方案 | 针对具体任务生成的多个备选 | 不是默认组，也不是学生能力分类 |
| 分组计划 | 教师复核并显式启用的成员与角色安排 | 只服务明确任务和阶段；通知是独立动作 |

## 3. P2 评价核心重构

### 3.1 已实现关系

每个已发布评价方案保存并冻结：

- 至少一条已发布课程标准内容条目引用；
- 学习目标及其对应的课程标准内容条目；
- 评价依据及其对应的学习目标；
- 学习活动及其对应的学习目标；
- 评价任务及其对应的学习目标、学习活动、评价方式、材料归属、材料类型和权重；
- 评价内容、思维要求、允许的帮助、评分方式和后续教学建议。

同一学校、学科和课程中的学习目标代码先形成稳定的逻辑身份，再按每次已发布评价方案形成不可修改的 `LearningTargetVersion`。目标版本分别冻结目标表述、方案版本、四类课标依据、内容校验值、发布人和发布时间。测试式、操作式、项目式和学习起点诊断可以指向同一逻辑目标，但任何评价事实都必须保留当时使用的精确目标版本，不能只保存同名文本或“当前版本”。

每个已发布评价标准进一步冻结：

- 评价指标与已发布评价方案版本的关系；
- 指标所对应的学习目标和评价任务；
- 个人、小组或两类材料的适用范围；
- 可接受的材料类型；
- 暂不评价条件；
- 1—5 星具体表现、评分示例和后续教学建议。

### 3.2 发布硬约束

发布服务现在执行以下拒绝规则：

- 引用仍在方案草稿、但不在已发布版本中的目标或任务时拒绝；
- 任一学习目标没有评价依据、学习活动或评价任务时拒绝；
- 任一学习活动没有评价任务时拒绝；
- 评价任务权重之和不为 100% 时拒绝；
- 评价标准未覆盖全部评价任务时拒绝；
- 指标与评价任务没有共同学习目标时拒绝；
- 个人/小组材料归属不一致时拒绝；
- 指标与任务没有共同材料类型时拒绝；
- 签到、出勤、积分、在线时长等运行数据被写入学科评价指标时拒绝。

### 3.3 课堂评价事实投影

课堂提交先形成不可修改的评价提交和材料清单，再逐条投影到统一评价材料库：

- 每条材料同时冻结评价指标、评价任务、学习目标版本、个人/小组归属、真实来源及来源版本；
- 小组作品保存为小组材料，`student` 不被伪填为某名组员；只有个人作答、操作、说明、答辩或可归因观察进入个人材料覆盖率；
- 材料缺失、未观察、不适用、技术问题分别保存，不互相改写，也不形成 0 分；
- 课堂 1—5 星及其评价描述在完成任务、量尺和评分者校准前标记为“描述性、未校准”，目标水平估计保持为空；
- 由此形成的学习目标情况版本设置有效期，并保留统一材料 UUID；后续修订评价只能追加新提交和新状态，不能覆盖历史。

### 3.4 信息科技三类验收方案

新增管理命令 `seed_p2_p5_information_technology`，可在明确确认后为指定信息科技课程建立：

1. 测试式评价方案：个人作答与评分记录；
2. 操作式评价方案：个人操作与观察记录；
3. 项目式评价方案：小组作品与个人说明/答辩分别保存、分别评价。

命令只生成工程验收数据，并输出可登记到 `TestDataBatch` 的非个人根对象清单；它不把这些数据用于正式教学统计、模型训练或研究结论。

## 4. P3 学习起点诊断与评价材料

### 4.1 诊断任务与版本

- 产品用语统一为“学习起点诊断（前测）”。
- 支持客观题、量表、简答、表现任务、操作任务和短项目。
- 发布时生成不可修改的 `PretestPaperVersion`，保存全部任务、目标、材料要求和满分。
- 每次提交绑定发布版本和尝试次数；已保存提交不可修改或删除。
- 新的学科素养诊断任务必须选择课标依据完整的已发布学习目标版本；代码和名称只是冻结显示值，不能由客户端自由替代目标身份。历史未映射版本仅保留用于审计，不能进入正式建议。

### 4.2 诊断实施批次

诊断工具版本与一次具体实施分离。`DiagnosticAdministration` 冻结学校、学科、课程、用途、批次编码、精确试卷版本、开放时间、关闭时间以及班级指派快照：

- 学习起点诊断、教育实验前测、教育实验后测和工具试测使用不同用途；
- 实验班与对照班在同一研究前测批次中必须绑定同一精确版本，不能分别读取“最新试卷”；
- 发布后不能更换试卷、班级角色、机会状态或实施口径；
- 学生只能看到本人当前班级被指派且处于开放状态的批次；旧兼容地址也不得回退到全校最新版本；
- 提交同时写入实施批次、试卷版本和请求摘要。相同幂等标识与完全相同材料只返回原记录，材料、状态或附件发生变化时返回冲突；并发提交不得重复写入。

### 4.3 机会和缺失状态

整份提交和每个评价任务分别记录：

- `observed`：已获得评价机会并形成材料；
- `missing`：材料缺失；
- `device_issue`：设备或技术问题；
- `not_offered`：未获得评价机会。

非必交任务空白不进入得分分母。没有任何可观察任务时可以再次参加诊断；已经形成有效诊断提交后，重复提交被拒绝。

### 4.4 主观材料评分闭环

简答、操作、表现任务和短项目提交后先形成“等待评价”材料。教师或有权限的学校管理员评分时：

1. 原提交和原材料保持不变；
2. 追加一条评分材料，记录评分人、时间、得分、固定满分和反馈；
3. 依据同一目标的现有材料重新计算覆盖情况；
4. 追加新的学习目标情况版本，并继承实施批次、精确学习目标版本和原材料校验链；
5. 重复评分同一材料返回冲突，不覆盖历史。

客户端不能修改发布版本中的满分。仍有材料等待评价时不生成目标水平估计。

## 5. P4 动态分层

### 5.1 唯一状态真值

学习内容层级的唯一运行真值是 `StudentSubjectBand`：

- 有课程时按学生、学校、学科、课程和有效期解析；
- 无课程时按学生、学校、学科和有效期解析；
- 无明确学科上下文的学生账号管理和全局统计不再展示或筛选层级；
- 课堂等明确课程上下文可以继续使用兼容响应字段名，但值必须来自当前课程/学科记录。

`StudentProfile.current_layer` 进入停用兼容阶段，不再作为生产读取或写入来源。待部署观察和旧客户端核验完成后，再通过独立迁移物理删除字段。

### 5.2 学习目标情况版本

每个版本保存：学校、班级、学生、学科、课程、学习目标、材料来源及版本、材料状态、覆盖率、估计、不确定性、有效期、材料引用和内容校验值。版本不可原地修改或删除。

硬约束包括：

- 覆盖率、估计和不确定性均在 0—1 范围；
- 有效期结束时间必须晚于开始时间；
- 学校、班级、学生、学科和课程范围必须一致；
- 材料不足或未形成观察时，估计必须为空；
- 学科级与课程级来源使用不同唯一约束，避免空课程值绕过重复检查。

正式记录还必须绑定课标依据完整的精确学习目标版本并设置有效期。自由文本代码、历史未映射题目、过期材料和没有估计不确定性的结果只能保留或展示，不能进入正式学习内容层级建议。

共同测试进一步按精确目标版本形成不可变的 `StudentMasteryTargetResult`。重新评分生成新的来源校验值和新快照；旧快照、目标结果和已经由教师处理的建议均不被后台重算覆盖。

### 5.3 两类教师建议分离

| 建议 | 回答的问题 | 不允许的推断 |
| --- | --- | --- |
| 学习支持建议 | 当前应提供何种提示、反馈、时间或教师支持 | 需要支持不等于学习内容只能降低 |
| 学习内容层级建议 | 下一教学窗口适合安排何种内容范围与挑战程度 | 不得由材料缺失自动进入 C 层 |

材料不足、测量误差过大、共同任务不足、稳定期或连续窗口条件未满足时，系统保存拒绝原因并显示“暂不建议”。教师已经复核的决定不会因后台重新计算被改回待确认。

学习起点诊断只用于形成初始目标情况。系统生成初始学习内容建议时，必须同时满足：同一已发布实施批次、精确目标版本、课标依据完整、评分完成、材料在有效期内、覆盖率达到政策要求且不确定性已明确估计。任一条件不满足即形成可审计的“暂不建议”，不自动进入 C。即使形成候选，也必须由教师查看目标材料后确认；分组服务只读取教师已经确认的内容安排，不直接按前测总分分组。

## 6. P5 动态分组

### 6.1 状态流程

P5 将分组拆为六个可审计步骤：

1. 保存小组合作草稿；
2. 明确任务目的、学习阶段、角色、资源、安全约束、学习机会要求和稳定期；
3. 生成至少两套候选方案；
4. 教师检查成员与角色、锁定或调整后确认复核；
5. 教师显式启用，才创建实际小组、成员、角色和学习机会；
6. 教师显式通知学生，才发送班级通知和实时事件。

“复核”不等于“启用”，“启用”不等于“已通知”。保存设置、生成候选和复核方案均不会提前改变学生所在小组。

### 6.2 约束与实际记录

- 支持锁定成员和教师调整；
- 支持禁止同组组合等安全约束；
- 支持必需角色、资源和在线编辑/上传条件；
- 支持稳定期，防止项目过程中频繁换组；
- 启用前重新核对班级学生名单；
- 启用后记录实际成员、角色和学习机会；
- 替换或关闭时归档旧方案和材料，不静默删除；
- 学生端只接收已启用的成员、角色和任务，不接收内部学习情况、策略权重或候选比较依据。

## 8. 迁移、测试数据与回滚

### 8.1 迁移顺序

1. 停止 Web、异步任务和课程标准处理进程；
2. 备份数据库和媒体目录并计算校验值；
3. 在备份副本按迁移图应用 `learning_analytics.0033`、`learning_analytics.0034` 以及 `learning.0021`—`learning.0026`；其中 `learning.0025` 显式依赖 `learning_analytics.0034`，`learning.0026` 为共同测试目标结果补充受保护的精确来源关系，不得手工跳过依赖顺序；
4. 运行系统检查、迁移检查和 P2—P5 聚焦测试；
5. 再对开发库应用迁移；
6. 运行信息科技验收数据命令；
7. 使用 `register_test_data_batch --dry-run` 核对方案和标准对象，再显式登记；
8. 启动服务并分别以教师、学校管理员、学生账号完成角色与隐私检查。

迁移期间必须先停止 Web 写入和课程标准处理 worker。文件系统队列中的未领取消息保留；正在处理的 OCR 任务应先请求安全取消并等待最终状态。恢复后 worker 仍使用单任务、单并发、单逻辑处理器和低优先级运行，不与 Web 请求同步处理整份 PDF。

### 8.2 回滚边界

- 代码回滚使用迁移前提交和数据库备份，不使用 `git reset --hard` 处理用户工作区。
- 已发布评价版本、诊断提交、评价材料、学习目标情况版本和已启用分组计划均保留历史，不执行原地覆盖式回滚。
- P5 对旧 `confirmed` 计划提供兼容迁移：正向映射为 `active` 并补充启用人/时间，逆迁移可恢复旧状态。
- 若迁移后角色权限、材料数量、内容校验值或分组状态不一致，停止服务并恢复迁移前数据库与媒体备份。

## 9. 科学研究边界与下一步验证

本次工程测试只能证明状态流、约束和追溯链按设计工作，不能证明评价有效、分层准确、分组有效或学生学习得到改善。后续拟用于论文的研究必须另行完成：

1. 由信息科技课程与评价专家独立复核学习目标、评价任务和星级表现说明；
2. 通过认知访谈检查学生是否按预期理解任务；
3. 使用双评分与概化研究检查任务、评分者和场合带来的误差；
4. 在独立时间、班级、教师、任务和学校上验证学习情况模型，并报告拒绝率、校准、不确定性和不同群体表现；
5. 动态分组研究按实际随机化单位设计，区分计划机会和实际参与机会，考虑组内干扰与实施偏差；
6. 实验班/对照班研究在查看结果前冻结课标版本、评价方案、前测、后测、问卷、主要结果、缺失处理和统计方案；
7. 开发测试与验收测试批次不得进入正式研究样本或效果结论。
8. `formal_training_queryset()` 仅提供“待人工审查的冻结数据集候选”，不等于批准训练，也不宣称估计已经完成心理测量校准；它只接纳具有不可变共同测试目标结果来源、完整可比性链、非学习起点诊断、非模拟学校、`is_test_data=False` 且目标结果、目标情况和总体快照的保守不确定性代理均不高于 0.20 的记录。该门槛在代码中以 `conservative-proxy-gate-v1` 明确标识；0.20 只是当前工程排除门槛，不是已经取得效度证据的心理测量标准。正式训练前仍须单独冻结数据集版本，记录纳入排除规则、审批人、审批时间、代码版本与数据哈希。

既有 30 轮科学反证记录继续作为研究设计依据；本文件记录的是这些风险在 P2—P5 工程中的对应处置，不能把“完成若干轮论证”表述成已经完成若干次外部实验或同行评审。
