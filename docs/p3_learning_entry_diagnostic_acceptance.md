# P3 学习起点诊断与评价材料验收契约

> 适用范围：信息科技课程；学习起点诊断、教育实验前测/后测与诊断工具试测。  
> 冻结日期：2026-07-22。  
> 当前状态：设计契约、工程实现与隔离自动化验收已通过；正式开发库迁移留待 P2—P5 统一切换窗口。

## 1. 阶段目标

P3 把旧“前测卷—总分—完成标记”流程改造为可追溯的“诊断工具版本—实施批次—逐项材料—逐项评分—学习目标初始情况”流程。

本阶段只回答三个问题：

1. 学生在什么诊断用途、什么实施批次、使用哪个不可修改的工具版本形成了哪些材料；
2. 哪些材料可以支持某个课标对齐学习目标的初始判断，哪些仍待评价或不能用于判断；
3. 缺失、设备问题和未获得机会如何被如实保留，而不被换算为零分、低水平或固定层级。

P3 不直接生成 A/B/C 学习内容层级，不直接生成分组，不建立心理测量效度结论，也不实现 SPSS 推断分析。这些分别属于 P4、P5 和后续研究验证阶段。

## 2. 冻结术语

| 产品与教育用语 | 含义 | 不再使用或限制使用的说法 |
| --- | --- | --- |
| 学习起点诊断（前测） | 教学决策前，为了解相关学习目标的起始情况而组织的一组评价活动 | 不把它等同于一张客观题试卷 |
| 学科学习诊断 | 与课标依据完整的学习目标相对应，可包含客观题、简答、表现任务、操作任务和短项目 | 用户界面不再使用容易被理解为单一纸笔考试的“素养测试” |
| 学习支持问卷 | 了解兴趣、自我效能、学习支持或访问条件，只形成支持线索 | 不称为学科能力测试，不进入学科学习目标水平判断 |
| 诊断工具 | 可编辑的工具主记录及其任务草稿 | 不把草稿称为已实施前测 |
| 诊断工具版本 | 发布时冻结的题目/任务、目标映射、材料要求、评分键和满分 | 不读取“当前最新版”替代历史版本 |
| 诊断实施批次 | 一次具体实施，冻结用途、课程、工具版本、时间、班级、实验角色和评价机会 | 不把工具版本与一次实施混为同一对象 |
| 评价任务 | 学生需要作答、操作、完成作品或说明过程的最小单元 | 任务不一律称为试题 |
| 评价材料 | 作答、作品、操作记录、观察、答辩或评分记录 | 材料缺失不等于低质量材料 |
| 学习目标初始情况 | 由合格材料形成的目标级、带覆盖率/不确定性/有效期的阶段性记录 | 不称为永久能力、先验、层级或学生标签 |

数据库内部枚举为兼容历史数据可以暂时保留 `literacy`、`attitude`、`Pretest*`；新增界面、接口说明、审计信息和研究文档使用上表用语。

## 3. 对象与版本边界

```text
诊断工具草稿
  -> 发布并冻结诊断工具版本
  -> 建立诊断实施批次
  -> 冻结课程、用途、班级/实验角色、机会状态与时间
  -> 学生提交绑定精确版本和请求摘要
  -> 形成逐项评价材料
  -> 客观任务自动计分 / 主观任务等待教师评价
  -> 形成课标对齐的学习目标初始情况
```

必须满足以下不变量：

1. 已发布工具版本、学生提交、提交绑定、原始评价材料、附件和追加评分记录不可原地修改或删除；
2. 每次提交同时绑定实施批次、精确工具版本、内容校验值、尝试序号和幂等标识；
3. 正式学科学习诊断的每项任务必须绑定课标依据完整的精确学习目标版本；代码和名称只是冻结显示值；
4. 历史未映射数据和工具试测数据保留原始事实并明确标记，不补造课标映射；
5. 学习支持问卷可以保存逐项回答和材料，但不得生成或进入正式学科学习目标估计、学习内容层级建议和模型训练标签；
6. 新发布版本不覆盖旧版本，也不得静默改变已提交材料的解释口径。

## 4. 评价任务与材料

| 任务形式 | 主要材料 | 评分状态 | 可形成正式目标初始情况的条件 |
| --- | --- | --- | --- |
| 单选、多选 | 逐项作答与固定计分键 | 自动完成 | 精确目标版本、有效机会、固定满分、材料完整 |
| 简答 | 文字作答 | 等待教师评价 | 教师追加评分后，且仍满足目标与版本条件 |
| 表现任务 | 个人表现说明、观察或附件 | 等待教师评价 | 能归因到个人并按冻结标准评价 |
| 操作任务 | 操作过程说明、截图/文件或观察 | 等待教师评价 | 过程材料可追溯且能归因到个人 |
| 短项目 | 作品、过程说明及必要附件 | 等待教师评价 | 必须存在个人可归因材料；小组作品不能直接替代个人判断 |
| 量表 | 问卷逐项回答 | 按问卷规则处理 | 只形成学习支持线索，不形成学科目标水平 |

原始材料与评分判断分开理解：原始材料始终保留；教师评价以追加评分记录保存，不覆盖学生提交。客观任务的自动计分结果随原始作答、固定计分键、精确版本和得分/满分共同冻结，不得用整卷总分作为分层或分组输入。

## 5. 状态轴

状态不得被压缩成一个“已完成/未完成”字段。

| 状态轴 | 允许值 | 教育含义 |
| --- | --- | --- |
| 班级评价机会 | `offered` / `not_offered` | 是否由学校提供了本次评价机会 |
| 整体或任务材料情况 | `observed` / `missing` / `device_issue` | 是否形成材料；学生不能自行声明 `not_offered` |
| 材料处理状态 | `available` / `pending_review` / `missing` / `device_issue` / `not_offered` / `not_observed` / `not_applicable` | 材料能否进入相应用途 |
| 评分进度 | `not_started` / `pending_review` / `completed` / `not_applicable` | 是否完成评分；不代表目标水平高低 |
| 目标材料状态 | `available` / `partial` / `insufficient` / `pending_review` / `not_observed` | 仅描述目标判断依据是否充分 |
| 课程访问 | `deferred` / `eligible` / `exempt` | 与提交、评分、目标判断分别表达，不复用全局首次使用标记 |

强制规则：

- `missing`、`device_issue`、`not_offered`、`not_observed` 不得写入 0 分；
- 未形成观察时，目标估计、测量误差和水平结论必须为空；
- 混合异常必须保留逐项原因，不能用整体状态覆盖并丢失设备问题等事实；
- 主观材料仍待评价时，不提前形成目标水平估计；
- 问卷维度、历史未映射任务和工具试测不得伪装成正式学习目标初始情况。

## 6. 实施批次与教育实验

1. `entry_diagnostic`、`research_pretest`、`research_posttest` 和 `pilot` 分开保存用途；
2. 教育实验前测或后测发布时，实验班与对照班必须处于同一实施批次并使用同一精确工具版本；
3. 发布后班级、实验角色、机会状态、工具版本和实施时间不可替换；关闭只能追加关闭人和关闭时间；
4. 学生只能查看本人当前班级被指派的批次；未开放或已关闭时不得泄露题目、选项、材料要求、答案或版本校验值；
5. `not_offered` 是实施事实，不是学生表现；相应学生免于提交，也不产生低水平记录；
6. 研究前测/后测材料与教学建议保持来源隔离，不能因研究用途自动改变教学安排。

## 7. 权限与数据保护

- 学校管理员只能管理本校工具、批次和材料；
- 教师只能查看和评价本人实际任教课程/班级范围内的材料，不能仅凭同校同学科越权；
- 学生只能读取本人的批次、提交和附件；附件下载必须再次执行对象级权限判断；
- 附件记录原文件名、大小、类型、SHA-256、工具版本、提交和材料关系；存储路径不得采用用户提供的相对路径；
- 外部 AI 不得接收学生原始问卷、自由文本、健康、无障碍或可直接识别个人的信息；
- 测试数据、历史未映射材料和研究数据必须保留数据用途标识，不能直接进入正式训练集。

## 8. 迁移与兼容

1. 旧已发布/已归档工具可生成不可变历史快照；草稿继续等待人工复核；
2. 旧数据只在已有明确事实时回填，不能从题目文本猜测学习目标版本；
3. 旧整卷 `answers` 与 `score` 字段仅作兼容快照；新链路以逐项材料、目标级结果和追加评分为依据；
4. 全局 `StudentProfile.pretest_completed_at`、`is_first_use` 和其他 onboarding 字段不再由某一学科诊断提交写入；
5. P3 所需的实施批次、精确目标版本、提交幂等和材料字段必须位于 P3 可追溯的迁移链中，不能依赖名称上归属于 P4 的迁移才具备基本完整性；
6. 正式开发库只在 P2—P5 全部隔离验收通过后一次迁移；失败时恢复数据库备份并回退应用版本，不删除已形成的历史材料。
