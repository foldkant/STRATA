# P4 动态分层验收记录

## 1. 阶段范围

P4 只重构信息科技学科的动态分层，不进入动态分组。平台以学习目标级材料形成可追溯的学习情况版本，分别提出学习支持建议与学习内容层级建议，最终由任课教师查看依据后确认、调整或暂缓。

## 2. 术语与教育含义

| 平台术语 | 含义 | 禁止替代的含义 |
| --- | --- | --- |
| 学习目标情况 | 学生在特定学习目标、材料和时间范围内呈现的当前情况 | 固定能力、智力或永久水平 |
| 学习支持建议 | 关于支架、反馈、资源、节奏和学习机会的建议 | 对学生贴层级标签 |
| 学习内容层级建议 | 关于后续学习内容复杂度与挑战度的候选安排 | 自动决定学生去向 |
| 当前学习内容层级安排 | 教师已经确认、且仍在有效期内的课程内安排 | 学生的全局属性 |
| 暂不建议 | 当前材料不足以支持内容层级变化 | 默认进入 C 层 |

内部 A/B/C 仅表示同一课程内学习内容的挑战度安排，不向学生端展示，不代表学生的固定类别。

## 3. 不可突破的数据与决策约束

1. 学习情况的最小单位是“学生 × 学科 × 课程（可选）× 学习目标版本 × 时间”。
2. 学习目标情况、材料结果和建议依据采用追加版本；已经用于决策的来源、哈希与目标版本不得改写。
3. 缺失、未获得学习机会、设备问题、待评分、材料不足、目标未映射、材料过期或不确定性过高时，只能形成“暂不建议”，不得自动进入 C。
4. 学习起点诊断仅用于形成目标级初始情况；不得直接作为正式模型训练标签。
5. 学习支持建议与学习内容层级建议是两条独立流程。确认支持建议不得改变内容层级。
6. 系统生成的是候选建议，不是决定。教师必须看到目标、材料覆盖、有效期、不确定性和理由后，才能确认或调整内容安排。
7. `StudentSubjectBand` 是运行时唯一的课程/学科内容层级真值；`StudentProfile.current_layer` 仅作历史字段，不得再被生产逻辑读写。
8. 每次生效均关闭同一范围的旧安排并追加新版本，保留教师、时间、来源建议和材料快照。
9. 正式训练候选必须排除测试/合成租户、历史未映射、学习起点诊断、缺失或过期材料，以及没有精确目标版本和共同测评来源的数据。
10. 任课教师只能处理其明确任教班级和课程范围内的记录；同校或同班但未任教该课程不构成权限。

## 5. 数据迁移与回滚边界

- 历史 `StudentProfile.current_layer` 不迁移为正式内容层级决定，避免把无来源旧值伪装成课标对齐材料。
- 历史单目标内容建议只建立兼容关联，标记和保留原来源；新建议必须绑定全部目标情况版本。
- 正式开发库迁移与备份在 P3、P4、P5 全部专项验收后统一执行；执行前保留数据库文件、迁移清单和校验摘要。
