# P5 动态分组验收记录

## 1. 阶段范围

P5 面向信息科技课堂的动态分组。分组服务于具体学习任务，不把学生固定为某种“类型”，也不直接使用单一总分或全局层级自动决定成员。标准流程固定为：

`确定任务 → 生成多个候选 → 教师检查与调整 → 教师复核 → 明确启用 → 通知学生 → 记录实际参与机会与结果`

## 2. 术语与教育含义

| 平台术语 | 含义 |
| --- | --- |
| 分组任务 | 本次学习任务的目的、阶段、角色、资源、安全约束和学习机会要求 |
| 候选方案 | 供教师比较的成员与角色安排，不是已经生效的分组 |
| 教师固定 | 教师明确要求在本次候选生成与调整中保持的成员位置 |
| 稳定期 | 已启用小组保持连续工作的最短时间窗口 |
| 学习机会 | 每名学生实际获得的协作、编辑、资源分享、表达或同伴讲解机会 |
| 已复核方案 | 教师检查并保存，但尚未在课堂生效、尚未通知学生的版本 |
| 已启用方案 | 已成为课堂运行安排，但学生通知仍需单独执行 |

## 3. 不可突破的约束

1. 未先明确任务目的、学习阶段、角色和资源时，不得生成候选。
2. 至少形成两套可比较候选；系统不得默认选择或自动启用第一套方案。
3. 每名学生恰好出现一次；小组人数、角色、安全分开约束和教师固定必须在候选生成、教师调整和启用前重复校验。
4. 分组依据只能使用与当前任务相关、仍有效且可解释的学习准备信息；不得回退读取 `StudentProfile.current_layer`。
5. 材料不足时可以使用随机基线或教师设置，但必须明确说明依据不足，不得伪装为模型优化结果。
6. 学习机会是硬约束与后续审计对象；启用时记录实际成员、角色和预期机会，课堂结束后保存实际参与结果。
7. 稳定期内不得用新方案替换已启用小组；教师固定不得在确认调整时被移动。
8. “复核”“启用”“通知”是三个独立且可审计的动作。复核不建组，启用不自动通知，未启用方案不能通知。
9. 新方案采用追加版本；旧方案、实际成员、角色、机会和结果不得被覆盖。
10. 学生端只呈现自己的小组、角色、任务与资源，不呈现准备度、层级、候选比较或教师内部判断依据。
11. 任课教师只能处理其本人课程与课堂；同校其他教师无权查看或操作。
