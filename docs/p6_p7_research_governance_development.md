## 1. 教育实验研究阶段定义（独立编号 E1—E6）

E1—E6 用于检验 P2—P5 方案是否具有足够证据支持特定研究用途；它们与评价开发路线 P6、P7 不是同一组阶段。

| 阶段 | 研究范围 | 工程作用 | 不能提前声称 |
| --- | --- | --- | --- |
| E1 | 独立盲评、认知访谈 | 检查课标—目标—任务—评价标准的内容与反应过程 | AI 评价已经有效 |
| E2 | 回顾性测量与预测验证 | 冻结历史队列、时间边界、分析方案和缺失处理 | 预测结果具有因果效果 |
| E3 | 前瞻性影子运行 | 实时生成但不向学生实施建议，检查漂移、容量和安全 | 动态分层或分组提高学习 |
| E4 | 有限咨询试点 | 教师可以查看建议，平台不直接执行教学决定 | 咨询试点等同于随机试验 |
| E5 | 冻结政策集群试验 | 按预注册实验组/对照组政策估计特定版本的 ITT | 对所有学校、学科和版本普遍有效 |
| E6 | 未参与开发学校的外部确认 | 检查迁移、异质性和最差站点表现 | 一次外部确认证明全国推广有效 |

## 2. AS-IS 与 TO-BE

### 2.1 开发前

- 学习起点诊断批次可以保存实验班和对照班角色，但没有独立研究协议版本。
- 没有统一保存伦理审批、预注册、功效分析、教师培训、安全监测和政策冻结闸门。
- 没有区分“计划分配”和“实际暴露”，无法系统记录交叉暴露、部分实施和污染。
- 分析页面具有工程模型验证能力，但没有研究数据锁、变量字典、样本筛选与分析运行版本。
- 学校管理员无法导出一份同时包含协议、集群、实际实施、数据锁和分析参数的可复核研究包。

### 2.2 本次工程底座

- 新增独立 `research` 模块，不继续扩大 `api/views.py` 或 `api/services.py`。
- 建立研究项目与不可修改的研究协议版本；同一项目的修订必须形成新版本。
- 协议冻结研究问题、估计目标、主要结果、安全结果、纳入排除、缺失处理、分析方案、停止规则和结论边界。
- E4—E6 必须同时冻结评价、学习内容层级和动态分组政策，并保存 SHA-256。
- 建立追加式研究闸门记录；新的结论不能覆盖历史审批或审查记录。
- 建立班级集群分配；研究启动后不得追加或改写。
- E5 启动前至少冻结实验组和对照组，且工程最低要求不少于四个集群；正式样本量仍以预注册功效分析为准。
- E6 只允许未参与开发、未提前接触冻结政策的外部确认集群。
- 建立计划、启动、结束和数据锁定的受控状态序列，禁止跳步和普通批量改写。
- 建立实际暴露记录，区分按方案实施、未实施、交叉暴露、部分实施和暂不确定，并保存机会摘要、污染与实施忠实度。
- 建立不可修改的数据锁和分析运行记录，保存数据截止、变量字典、缺失/排除摘要、统计参数、软件版本、结果摘要和失败原因。
- 学校管理员可以导出 SPSS 可读的 XLSX 研究包；导出进入审计日志。

## 3. 强制研究闸门

不同阶段只在其全部必需闸门最新结论为“通过”后允许启动。`有条件通过`不会被静默当作通过。

| 阶段 | 必需闸门 |
| --- | --- |
| E1 | 伦理审批、知情与退出安排、评价工具审查、评分者培训 |
| E2 | 预注册、数据治理、数据质量 |
| E3 | 伦理审批、预注册、知情与退出安排、数据质量、教师培训、安全监测 |
| E4 | E3 全部闸门，加政策冻结 |
| E5 | 伦理审批、预注册、知情与退出安排、数据质量、功效分析、教师培训、安全监测、政策冻结、集群分配方案 |
| E6 | 伦理审批、预注册、知情与退出安排、数据质量、安全监测、政策冻结、外部独立性 |

平台只保存闸门材料编号和结论，不能自行冒充伦理委员会、学科专家、外部学校或预注册平台。工程测试中的模拟编号不得用于正式研究。

## 4. 权限与隐私

- 研究治理接口只允许本校学校管理员访问。
- 学校管理员不能读取其他学校的协议、班级分配、运行或数据锁。
- 教师和学生不能访问研究治理接口。
- 研究包第一版只导出协议、班级级分配、实际实施、变量字典和分析元数据，不直接导出可识别学生名单。
- 学生级研究数据仍须由后续经授权的匿名数据集构建流程生成，并执行小单元披露检查。
- P6/P7 的 `automatic_action_enabled` 固定为 `False`；研究模块不能自动发布评价、改变学习内容层级或启用动态分组。

## 5. 学校管理员页面

入口：`/app/school-admin/research`

页面采用“研究项目列表 + 当前项目工作区”，工作区分为四个短标签页：

1. 协议与边界；
2. 研究闸门；
3. 班级分配；
4. 运行与数据锁。

长协议通过分段表单录入，复杂操作使用带焦点约束的弹窗；小屏幕改为单列，不使用一个无限向下滚动的超长管理页面。
