# 教师课堂控制台排版优化记录

复验对象：`/app/teacher/classroom/309`

## 一、问题定位

资源标签栏异常增高并不是按钮自身高度导致，而是资源舞台实际包含“标题、资源标签、资源预览”三个区域，原样式却只定义了两行网格。资源标签因此占据弹性行，桌面端被拉高到约 495px，资源预览被推到首屏以下。

原页面还同时横向展示“学习过程、资源、环节任务、课堂状态”四块内容，最重要的资源舞台只有约 409px 宽。五道题完整展开后，桌面页面达到 1657px，平板和手机超过 3300px；窄屏四个环节操作中还曾只有“下一环节”可见。

## 二、本次重排

- 桌面改为“学习过程—资源主舞台—课堂信息”三段式工作台。
- 资源标签使用独立网格行，视觉高度为 42px；长名称单行省略，并保留完整标题提示和 `tablist/tab/aria-selected` 语义。
- 资源主舞台占据中间全部内容区，不再与环节任务并列分割。
- 右侧将“环节任务、课堂情况、课堂活动”改为同一情境栏中的三个页签。
- 题目默认呈现关键信息摘要，教师按需展开选项、参考答案和完成情况入口。
- 桌面控制台固定在一屏内，学习过程、资源和课堂信息各自在所属区域内滚动。
- 平板与手机将学习环节改为横向流程条，课堂快捷操作保持单行，四个环节操作全部保持在可视范围内。
- 手机和平板资源舞台采用有上限的视口高度，避免一个预览占据整页；课堂聊天缩为 48px 图标按钮。
- 1440px 触摸屏仅增大触控区域，不再错误切换成手机布局。
- 有倒计时和无倒计时采用不同网格行定义，倒计时出现时不会把主工作区挤出视口。

## 三、真实页面测量

|项目|优化前|优化后|
|---|---:|---:|
|桌面资源标签高度|495px|42px|
|桌面资源舞台宽度|约 409px|约 813px|
|桌面整页高度|1657px|900px|
|平板整页高度|3371px|1939px|
|手机整页高度|3612px|1978px|
|窄屏环节操作|部分按钮位于视口外|4 个按钮全部可见|

桌面、平板和手机均无页面级横向溢出。资源标签切换、课堂信息页签切换、题目展开和原有课堂评价入口均已通过浏览器自动化验证。
