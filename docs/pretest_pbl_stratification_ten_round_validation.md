## 1. 本次纠偏后的最终结论

前一版思路把“共同测试”放得过重，无法覆盖项目式学习、探究、实验、设计、创作、表达、体育实践等学习形态，也没有充分利用现有学科前测承担起点诊断和初始支持的潜在业务位置。当前前测尚未建立测量效度和分层链路，本次十轮论证对目标架构作出以下修正：

1. **评价不等于测试。** 测试只是采集证据的一种方式；评价任务还可以是实验、作品、项目、演示、口头答辩、实作、表演、观察记录和学习档案。
2. **需要起点证据时，入场诊断应在相应教学决策之前完成。** “前测”应理解为按最小必要原则配置的入场诊断方案，可以包含客观题、简答、表现性微任务、适龄量表和访问条件核验，而不是要求所有学生完成同一张卷子或全部证据包。支持量表不得成为惩罚性课程门禁，并应允许跳过、替代或稍后完成。
3. **课程标准四段链不是总分公式。** `核心素养 → 课程目标 → 课程内容 → 学业质量` 用于确定学习目标和质量边界，之后还必须建立 `可评价学习目标 → 可观察材料 → 评价任务 → 评分规则`，不能从课标文本直接跳到分数。
4. **项目式学习不强制补一场普通测试。** 如果纸笔题不能呈现目标能力，应使用共同表现性任务、个人工件、现场操作、口头答辩或迁移演示作为个体锚点；只有当某个先备知识或概念确实适合题目测量时，才补充短测。
5. **小组作品不等于个人掌握。** 小组成果只形成组级结果；个人学科学习情况只能读取与具体学习目标匹配、可归因到个人且通过评分要求的作品、决策、答辩、演示或迁移表现。个人反思默认用于了解反思、自我调节或支持需要；只有反思本身要求独立呈现目标学科推理并使用共同冻结评价标准评分时，才可作为补充材料，不能单独确定学习内容层级。
6. **态度不能与掌握度相加。** 兴趣、价值感、自我效能、焦虑、合作偏好和自我调节属于支持或情境信息，不得与学科表现合成“综合素养分”，更不得据此降层。
7. **前测形成的是目标级临时状态，不是永久标签或层级本身。** 状态必须带目标范围、证据覆盖、不确定性、有效期和 `usable/limited/evidence_insufficient/not_comparable`；版本化内容带政策应用切点后才形成 `candidate/boundary/abstain`，教师确认后才写入教学安排。
8. **状态估计、分层和分组是三个对象。** `MeasurementSnapshot/StudentSubjectState` 描述测量结果；`StudentSubjectBand` 是政策和教师确认后的内容投放决定；分组是针对具体任务和稳定窗口的成员与角色安排。项目组主要依据任务需求、经门控的个人证据、角色轮换、自愿主题偏好、实际可参与条件和稳定性约束生成，不直接按 A/B/C 排队。
9. **模型训练不能把教师评分、AI 评分或模型自己的层级当真值。** 预测标签必须来自未来、独立、可比、个体化的学习表现；分组、支架、教师反馈和任务难度必须作为干预事实记录。干预后的未来结果可以验证既定政策下的预测，却不是“最佳内容带/最佳组别”的真值；学习最优干预还需要明确因果估计目标、处理版本、可比组和随机或准实验设计。
10. **AI 的第一步不是生成题目，而是判断需要哪种证据。** AI 必须先读取权威课标版本、课程内容、教学模式和学生阶段，再选择测试、表现性任务、项目证据或混合方案，最后生成评价依据、学习任务和评分规则草稿。
11. **当前实现还没有上述闭环。** 前测保存整卷 `answers` JSON、一个原始总分和提交时间，但没有逐题评分事实、满分、维度结果和测量误差，也未进入正式分层；PBL 项目业务主链尚未实现；现有评价版本、课堂证据、小组协作和学习机会模型可以复用，但需要扩展。
12. **现阶段不应训练“最佳分组”黑箱模型。** 应先完成证据结构、版本冻结、机会记录、个体与小组归属、透明规则、教师确认和影子试点，再用真实纵向数据比较策略。

一句话概括新架构：

> 前测提供带不确定性的初始观测；日常任务、项目过程和表现性评价提供连续证据；评价系统保证证据与课标、目标、任务、评分者和个体归属可追溯；状态模型按目标更新，内容带政策和分组策略再分别调用状态；未来独立学习结果用于预测验证，干预优劣另以因果研究验证。

若后续采用 Bayesian 状态模型，施测前的分布才是 prior，前测结果是用于把 prior 更新为 posterior 的观测证据；本文不把前测分数本身称为“先验”。

## 2. 术语和边界

| 名称 | 本文定义 | 不能等同于 |
| --- | --- | --- |
| 前测/入场诊断 | 教学开始前，为了解先备知识、学科实践起点、支持需要和访问条件而组织的一组评价活动 | 一张选择题试卷；永久能力鉴定 |
| 普通测试 | 以题目作答为主要证据的 `Assessment/TestAssessment` 类任务 | 全部评价 |
| 表现性任务 | 要求学生完成操作、探究、创作、表达、演示、答辩或真实情境问题解决的任务 | 随意看作品打印象分 |
| 项目式学习评价 | 围绕驱动问题、阶段、里程碑、过程材料、成果、展示和反思形成的证据链 | 只看最终文件；给全组同一能力分 |
| 共同锚任务 | 对目标、关键条件和量规进行冻结，使不同学生或时间点结果可解释地比较的个体任务 | 必须是选择题；所有人作品完全相同 |
| 可评价学习目标 | 希望由评价材料支持的、明确到学科内容和预期表现的学习目标 | 模糊的“综合素养高” |
| 掌握/准备度状态 | 学生在特定学科、目标和时间点上的测量估计，保存证据范围与不确定性 | 内容带决定；人格、努力、态度或全局能力 |
| 支持需要 | 计划、提醒、支架、访问、情绪安全、求助和反馈方面的教学需要 | 低能力 |
| 内容带/分层决定 | 版本化政策读取有效状态、结合错误代价并经教师确认后形成的内容投放安排 | 测量值本身；公开身份；固定班级；项目角色 |
| 分组 | 针对某次任务或项目阶段的成员与角色安排 | 分层结果的直接复制 |

后续界面、API、数据库和研究文档必须保持这些边界。尤其禁止继续使用“前测总分 = 初始能力 = 初始分组依据”这一条直线逻辑。

## 3. 当前实现审计

### 3.1 学科前测：流程骨架已实现，但测量链路未成立

| 审计项 | 当前真实状态 | 科学与工程缺口 |
| --- | --- | --- |
| 套卷类型 | `PretestPaper.Kind` 只有 `literacy` 和 `attitude`，按学校、学科、类型和版本管理，见 `learning/models.py:562-609` | 没有明确区分学科诊断、表现性起点、支持量表和访问条件 |
| 题型 | 单选、多选、量表、简答，只有自由文本 `dimension`，见 `learning/models.py:612-642` | 没有课标版本、核心素养、课程目标、课程内容、学业质量或先备目标的正式映射 |
| 提交 | `PretestSubmission` 只保存整份答案、一个原始总分和时间，见 `learning/models.py:645-669` | 没有逐题评分事实、满分、子维度结果、评分状态、误差、覆盖和工具快照 |
| 自动评分 | 只对单选、多选做完全匹配；量表和简答不计分，见 `api/pretest_views.py:548-577` | 纯态度量表总分恒为 0；简答没有人工评分流程；不同套卷原始分不可比 |
| 发布门槛 | 专用发布动作只要求至少一题，见 `api/pretest_services.py:837-861` | 没有蓝图覆盖、计分键、目标年级、课标绑定、内容审核、试测和公平性门槛；直接保存为已发布还可能绕过专用发布检查 |
| 历史保护 | 有作答时禁止物理删除，旧发布版本自动归档 | 已发布套卷和题目仍可编辑关键定义，可能改写历史测量含义 |
| 事件 | `pretest.submitted` 只记录类型、版本、答题数和原始总分，见 `learning_analytics/services/operational_events.py:57-83`；事件未声明学习机会要求，也不会形成成熟评分事实 | 没有逐项目标证据、学习机会、可比性和不确定性；当前成熟评分事实只由 `item.graded` 路径产生 |
| 学生门禁 | 学生进入部分课时前检查当前发布前测是否完成 | 完成某一学科当前已发布类型后即写全局 `is_first_use=False`，没有完整核验改密、选班或其他要求；新版本又可能按 paper ID 重新阻塞课时，却不恢复全局首次使用状态 |
| 初始分层 | 文档写有“首次分层输入”，但生产链路不存在 | 没有 `PretestSubmission → StudentMasterySnapshot → StratificationDecision → StudentSubjectBand` 路径 |
| 动态分组 | `same_layer/balanced_layer` 读取正式 A/B/C 映射分值，`ai_layer/stable_project` 才读取课程级 `StudentSubjectBand.evidence_snapshot.task_readiness.score` | 前测目前既不产生正式内容带，也不产生任务准备度，因此不会进入任一路径 |

2026-07-22 的运行库只读快照中，前测为 1 套草稿素养套卷、0 道题、0 份提交；已有的 `StudentSubjectBand` 记录来自验收种子或教师流程，不来自前测。该快照只说明当前环境状态，不代表未来部署数据。

额外一致性问题：

- 文档要求 `literacy` 与 `attitude` 两类都完成，但实现是“完成当前实际发布的类型”；只发布一类时也会判定完成。
- `pretest_completed_at` 是学生全局单一时间，表达不了“学生 × 学科 × 工具 × 版本”。
- 量表中点在管理端和学生端存在不同文字，反应选项语义尚未冻结。
- 后端对量表与文本主要检查非空，未严格校验响应属于题目选项或符合题型；学生端量表还会忽略题目保存的选项并固定渲染本地五点量表。
- 题目分值缺少非负、有限值和合理上限约束；直接访问已发布套卷也没有目标年级、班级、课程资格和学科启用状态的完整校验。
- 学生答案接口没有返回标准答案，这一安全边界是正确的，应继续保留。
- 当前没有覆盖“发布—学生作答—逐项评分—状态—候选—教师决定”的前测端到端自动化测试；现有相关检查主要是学生隐私表面的 GET 可访问性，不能证明测量链路成立。

### 3.2 项目式学习：可复用零件存在，项目业务主链未建立

| 审计项 | 当前真实状态 | 结论 |
| --- | --- | --- |
| 页面 | 教师 `/teacher/projects` 和学生 `/student/projects` 均为占位组件，见 `frontend/src/router/index.ts:85-87,137-139` | 项目工作台尚未实现 |
| 项目实体/API | 文档规划 `ProjectWork/ProjectMilestone/ProjectGanttItem/ProjectLog/ProjectSubmission`，但代码中没有对应实体和项目路由 | 不能贯通驱动问题、阶段、里程碑、交付、评价和状态更新 |
| 课程标记 | `Course.teaching_model` 可标记 `pbl`，课时环节支持任务、上传、讨论、评价、反思和文档 | 只是教学模式标记和通用环节，不是项目生命周期 |
| 个人作品 | `StudentWorkAttachment` 有上传版本和前序版本 | 可复用，但缺项目、阶段、里程碑、个体/小组范围和证据要求 |
| 课堂小组 | 已有计划版本、成员角色、不可变协作文档和共享文件 | 目前绑定单场课堂，不能表达跨课时项目团队和阶段稳定期 |
| 评价 | 评价方案、标准、指标、课堂冻结、自评/互评/师评和修订链已经存在 | 可复用，但证据上下文仍以单场课堂、单个学生最新材料为主 |
| 学习机会 | `LearningOpportunity` 有 `PROJECT` 类型及 `instructional_phase/unit_key/group_key/artifact_key/role_version` 等通用扩展槽 | 没有 Project/Phase/Milestone 实体外键、参照完整性、项目事件写入或状态转换；当前小组协作只投放 `DOCUMENT/TASK`，不能视为项目证据链已接入 |
| 资源中心“学生项目” | 作为作品展示资源，成员为文本/JSON，过程材料可选 | 不是可靠的项目学习证据系统，不能直接用于个人掌握或训练标签 |

当前正式 `StudentMasterySnapshot` 强关联普通测试、测试尝试和共同题集合，生产构建器只处理 `TestAttempt`。因此，即使课堂已有作品和五星评价，PBL 证据也不会形成正式掌握快照或内容带。

### 3.3 现有评价与分组基础

现有 `EvaluationPlan/EvaluationPlanVersion` 已保存学习目标、评价依据、学习任务、内容范围、思维要求、支持选项和评分规则；`EvaluationStandardVersion`、指标版本、评分示例、课堂冻结快照和不可变提交链也已经完成。这些基础应扩展，不应另造一套相互平行的“项目评分系统”。

需要修正的准入问题：

- 当前“已发布”不必然等于“已经内容审核、课堂试用和评分一致性检查后可进入正式测量”，已有绑定入口也未完整把审核状态变成机器准入条件。
- 当前评价证据链接主要抓取同课堂、同环节、同学生的最新作答与最新作品，不能同时链接项目阶段、组交付物、多个个人证据片段和展示答辩。
- 当前课堂评价提交的目标仍必须是用户，`group` 只是可选上下文；尚不能原生表达“评价对象就是项目组或组交付物”。课堂星级可以追溯，但 `evaluation.rating.submitted` 尚不会生成指标级成熟评分事实。
- 现有 1-5 星是序数观察，不能默认跨指标、构念和评分者求均值后进入掌握状态；当前试用记录中的汇总一致率也不足以重建双评、裁决和评分漂移。
- 当前 `stable_project` 仍是单场课堂外壳；`PROJECT_STAGE` 只有枚举而没有项目/阶段外键，候选生成器实际仍使用教师请求触发。
- 当前所谓“技能互补”主要读取单一 `task_readiness.score`；角色按组内顺序轮转，优化器平衡的是标量准备度和搭档历史，并非知识、实践、表达和调节向量。
- 当前公平检查主要阻断漏分或重复学生；展示、领导和文档编辑机会是按分配角色预填，而非实际发生事实，尚不能证明学生获得了相应机会。
- 当前生产结果仍以未来完成率和新增逾期为主；评价、自评互评和协作候选特征登记为研究用途且 `model_input=False`，实际特征生成器也未接入。因此当前 PBL 评价既不会生成正式掌握，也不会进入生产模型。

## 4. 总体证据架构

```text
权威课程标准库（超管维护、版本化、原文与结构化内容并存）
  └─ 学段 / 学科 / 版本
       ├─ 保留原文目录与段落层级
       ├─ 核心素养节点
       ├─ 课程目标节点
       ├─ 课程内容与先备节点
       ├─ 学业质量节点
       └─ typed edges：supports / addresses / integrates /
                       prerequisite / evidenced_by
                           ↓
                 可评价学习目标登记表
                           ↓
          可观察证据要求 + 适用评价方式选择
          ├─ 题目/短测
          ├─ 表现性微任务
          ├─ 实验/操作/表演/口语
          ├─ 项目阶段、工件、展示与答辩
          └─ 反思、自评、互评、师评及过程事实
                           ↓
          冻结任务版本 + 量规版本 + 机会与评分者记录
                           ↓
             追加式、可纠错的证据账本
          ├─ individual：可归因个人
          ├─ group：只说明小组
          ├─ support：支持与情境
          └─ operational：运行事实，不直接说明能力
                           ↓
                多轴学生状态与不确定性
          ├─ 学科内容掌握 M
          ├─ 目标对齐的个人学科实践表现 P
          ├─ 支持需要 S
          ├─ 角色轮换与机会证据 R
          ├─ 兴趣与偏好 I
          ├─ 访问与机会 X
          └─ 证据覆盖与不确定性 U
                           ↓
          教学决策（彼此分离、均由教师确认）
          ├─ 内容带候选：版本化政策读取 M/P/U
          ├─ 支持处方：读取 S 与 X
          └─ 任务分组：在决策点派生 TaskReadiness，
                         再结合 R/I/X/U 与任务约束
                           ↓
          记录真实投放、角色、支架、教师调整和机会
                           ↓
          未来独立、可比的个人表现用于预测验证；
          教学政策优劣另以因果研究验证
```

课程标准四类内容不是对所有学科都成立的固定父子树。平台必须保留原文结构，并用有类型的多对多关系表达交叉联系；学业质量不能被强制挂成某一课程内容的唯一子节点。

这条架构的核心不是把更多数据加起来，而是确保每项数据回答一个明确问题，并且不越权解释。`M` 与 `P` 均按具体学习目标存储，分别表示内容理解和个人学科实践表现；同一材料不能同时进入两轴后再次加权。真正的 `TaskReadinessSnapshot` 只在具体任务决策点由任务要求与仍然有效的目标材料派生。`R` 只服务角色轮换和机会公平，不代表“合作能力”；`I` 只使用学生自愿、可撤回的主题偏好；`X` 只服务可访问性、参与资格和替代安排，均不得降低内容挑战或制造长期同质组。

## 5. 学习目标与证据方式的匹配

平台必须先判断“什么表现能证明这个目标”，再选择评价方式。以下为默认建议，不是固定模板：

| 学习目标或课程形态 | 优先评价材料 | 可补充材料 | 不宜单独使用 |
| --- | --- | --- | --- |
| 概念、事实、规则识别 | 选择、匹配、简答、解释题 | 概念图、口头解释、应用题 | 点击数、在线时长 |
| 数学推理与问题解决 | 解题过程、证明、建模、迁移任务 | 短测、口头追问、错因订正 | 只有最终答案 |
| 科学探究 | 实验设计、变量控制、数据、推理、实验记录 | 概念短测、答辩、复现实验 | 只看实验成品或是否成功 |
| 信息技术/通用技术/工程设计 | 原型、代码、设计记录、测试与迭代、演示答辩 | 关键概念短测、个人修改任务 | 只看界面漂亮或提交次数 |
| 语文/外语 | 阅读解释、写作版本、口语表现、真实交流 | 词汇语法短测、同伴反馈 | 单次总分代表全部语言能力 |
| 历史/道德与法治/地理 | 证据分析、论证、资料解释、情境决策 | 知识短测、展示、研究报告 | 只记事实或只看演示包装 |
| 艺术 | 创作过程、作品、表演、阐释、修订 | 鉴赏短答、作品集、展示 | 只评价“好看/好听” |
| 体育与健康 | 动作实作、体能/技能规范、战术应用、健康方案 | 自我监测记录、口头说明 | 只用书面测试评价动作技能 |
| 跨学科项目式学习 | 阶段工件、过程决策、组成果、个人工件、展示答辩、反思与迁移 | 针对先备知识的短测 | 只看最终产品；全组同分 |
| 学习态度与支持需要 | 经验证的适龄量表、学生陈述、访问与机会事实 | 教师结构化观察、求助记录 | 作为学科能力或内容带依据 |

普通测试仍有价值，但只用于适合它的主张。项目式学习也可以含短测，但短测是为特定先备知识或概念服务，不是为了让所有学科重新退回“考试中心”。

## 6. 前测的目标模型

### 6.1 前测应从固定“两套卷”改为按需选择的四类入场证据组件

| 证据包 | 典型内容 | 主要输出 | 是否可影响初始内容带 |
| --- | --- | --- | --- |
| 学科先备诊断 | 先备概念、关键知识、常见错误、必要技能，可含客观题和简答 | 目标级初始掌握与误差 | 可以，需通过测量门槛 |
| 起点表现任务 | 小型实验、写作、设计、口语、操作、探究或迁移任务 | 目标对齐的个人学科实践表现 | 可以，仅对相关目标且需个体评分 |
| 学习支持量表 | 兴趣、价值感、自我效能、焦虑、自我调节、求助倾向 | 支持需要和教学沟通线索 | 不可以 |
| 访问与经验核验 | 设备、网络、语言、无障碍、既往机会、相关项目经验 | 访问支持、替代安排、证据解释条件 | 不可以 |

四类不是所有学生的强制清单。学校和学科应按具体决策的最小必要证据选择组件；已有近期、可比且覆盖充分证据的学生可以豁免或进入自适应路由。支持量表必须告知用途，允许跳过、替代或稍后完成，默认不得阻塞课程。载体也按学科变化：体育可用动作实作，外语可用口语与短写作，信息技术可用调试或小型设计，艺术可用短作品与阐释。

### 6.2 前测输出不是一个总分

初始状态建议表示为：

```text
InitialSubjectState(T0) = {
  mastery_by_target: M0,
  individual_practice_by_target: P0,
  support_profile: S0,
  collaboration_and_role_context: R0,
  interest_preferences: I0,
  access_and_opportunity: X0,
  evidence_coverage_and_uncertainty: U0,
  measurement_status: usable | limited | evidence_insufficient | not_comparable,
  valid_until,
  evidence_snapshot_hash
}
```

`P0` 只表示与明确学习目标对齐、由个人呈现的学科实践表现，不是泛化“项目能力”。`R0` 默认可以未知；若有学生自愿的角色偏好或既往机会事实，也只能作为角色轮换上下文，不能命名为协作能力。相同表现不得同时进入 `M0` 和 `P0` 后重复计权。

禁止使用：

```text
overall = literacy_score + attitude_score
initial_content_band = cut(overall)
initial_group = students_with_same_band
```

前测先形成目标状态，不直接产生层级。覆盖不足、主观题未评分、实施异常或不可比时，状态标记为 `limited/evidence_insufficient/not_comparable`。版本化内容带政策只能读取与当前课程目标相关且用途合格的 `M0/P0` 并考虑 `U0`：证据不足或不可比时产生 `abstain`；可用状态的区间跨越切点时才产生 `boundary`；其余情况才产生 `candidate`。教师确认后才写入 `StudentSubjectBand`。`S0/I0/X0` 只影响支持、沟通、主题偏好和可访问性安排，任何缺失都不能默认归入 C。

内容带切点必须通过课程目标、学业质量表现描述、专家标准设定、切点不确定性和错误后果审查建立，并定期复审。禁止按班内分位数、人数配额或“让三层人数好看”倒推阈值；工程占位值不得宣称为课标达标线。分类稳定只说明给定切点后的重复性，不证明切点本身合理。

### 6.3 初始分层和初始分组的顺序

1. 明确本次教学决策是否需要新的起点证据；已有有效证据时执行豁免或自适应路由。
2. 发布经审核的入场诊断版本，学生完成本学科最小必要的证据组件。
3. 先处理缺席、设备、语言、无障碍和异常作答，不能将这些情况计为低分。
4. 形成目标级临时状态和不确定性。
5. 版本化内容带政策形成候选、边界或拒绝；教师查看证据后确认初始内容支持，不向学生显示 A/B/C。
6. 第一次任务分组按任务目的生成：证据不足时优先随机或教师平衡基线，不伪装成“技能互补”。
7. 首个共同任务或项目里程碑中出现合格、可归因个人的新证据后重新估计；纯小组里程碑不能更新个人状态。前测影响随新证据的信息量变化，决策有效期到期不等于删除历史证据。
8. 项目先声明团队稳定窗口，通常与 Phase 对齐；只有 `regroup_boundary` 允许生成新候选。缺席、安全、严重冲突或无障碍需要可由教师紧急调整，但必须保留旧计划和结构化理由。

前测的价值是减少教师对起点的盲区，而不是给学生提前定性。

### 6.4 完成要求、复测与敏感信息

前测要求必须按“学生 × 学科 × 工具版本 × 用途”记录，至少区分 `required/optional/waived/alternative/expired`，并保存宽限期、替代版本和补测原因。onboarding、首次学科诊断和周期复测彼此独立；发布新版本默认不得重新封锁已经正常学习的学生，除非存在经审核的迁移政策。

兴趣、自我效能、焦虑、语言、设备、无障碍和体育健康信息可能比普通成绩更敏感。平台必须执行最小必要采集、适龄告知、跳过/替代、字段级权限白名单、保留期限、纠错、复核和申诉；原始量表与访问条件应和掌握证据隔离存储。外部 AI 不得接收学生原始量表、自由文本、健康或无障碍信息。历史完成、逾期、时长和点击不能被改名为“当前可用性”后用于挑选组员。

## 7. 项目式学习的正式评价链

### 7.1 一个项目必须先声明评价用途

项目可以同时服务四种用途，但结果必须分开：

| 用途 | 回答的问题 | 主要证据 |
| --- | --- | --- |
| 形成性反馈 | 下一步应改什么 | 草案、日志、检查点、师生反馈和修订 |
| 小组成果评价 | 团队共同产出达到什么质量 | 组交付物、展示、里程碑和共同量规 |
| 个人学习评价 | 该学生能独立说明或完成什么 | 个人工件、答辩、演示、决策说明、迁移任务 |
| 研究/模型验证 | 状态更新或分组是否改善未来学习 | 预先登记的独立个人结果与共同锚点 |

用途不同，允许的证据与聚合方式不同。形成性反馈材料未经验证时，可以帮助教学，但不能自动成为正式内容带或训练标签。运行时必须有真正的 `EvaluationTarget` 作用域：评价对象是个人时绑定学生，评价对象是小组或组交付物时绑定项目团队，两者互斥；服务层禁止把组观察展开或复制成学生观察。一个项目若承担多种用途，必须为每个 `claim × criterion × use` 单独保存证据规则和准入状态，或拆成不同评价版本；不得用方案级单一状态覆盖全部用途。

每个评价用途还必须具有机器可执行的测量准入状态：`feedback_only | trial | formal`。“已发布”只代表版本被冻结，不代表量规已经有效。`trial` 可以生成明确标记为 `research_only` 的分析快照，用于估计任务、评分和群体表现并决定能否晋级，但禁止进入正式学生状态、内容带或生产训练标签；只有完成规定审核、试评和评分门槛且相应用途为 `formal`，才可以生成正式 `MeasurementSnapshot`。

### 7.2 项目证据链

```text
驱动问题与真实情境
  → 课程标准内容条目与学习目标
  → 项目目标、阶段目标和里程碑
  → 每个里程碑的必需组证据与必需个人证据
  → 角色与学习机会
  → 方案、日志、数据、代码、作品、测试、修订等版本化工件
  → 展示、演示或口头答辩
  → 自评、互评和教师逐项评价
  → 组级成果快照 + 个人目标观察
  → 经过可比性和不确定性门控的个人状态更新
```

项目最终作品只是链中的一个节点，不是全部证据。

### 7.3 个体与小组归属规则

| 证据 | 正确分析单位 | 可否更新个人掌握 |
| --- | --- | --- |
| 小组最终作品及组量规 | 小组/作品 | 不可直接更新 |
| 小组里程碑完成 | 小组 × 阶段 | 不可直接更新 |
| 文档版本、上传、聊天和任务板事件 | 小组或可验证操作者 | 只作过程与审计旁证 |
| 经版本、责任范围、实际操作/答辩或独立复现交叉核验的个人工件 | 学生 × 目标 × 任务 | 通过门控后可以；上传者或编辑者身份本身不够 |
| 个人口头答辩、演示和现场追问 | 学生 × 目标 × 任务 × 评分者 | 通过门控后可以 |
| 个人迁移或复现任务 | 学生 × 目标 × 共同锚点 | 通过门控后可以 |
| 自评 | 学生 × 自己 × 指标 | 用于反思和自评校准，不能单独定层 |
| 互评 | 评价者 × 被评价者 × 指标 | 用于反馈与协作证据，不能单独定层 |
| 教师评价 | 评分者 × 学生/小组 × 指标 | 量规经验证且证据可归属时可用 |
| 个人反思 | 学生 × 反思/支持目标 | 默认进入反思、自我调节或支持轴；只有独立呈现目标学科推理且按共同量规评分时，才可作该学科目标旁证 |
| 缺席、设备故障、未获角色或展示机会 | 学生 × 机会 | 记缺失/机会不足，不能记 0 |

### 7.4 “无普通测试”的最低个人锚点

项目不需要为了形式再安排一张卷子，但如果项目要形成个人指标观察，至少要有一项与同一目标一致、可归因到个人、使用冻结标准并记录机会的证据。通过这一“归属门槛”只足以形成指标级观察或本任务范围内的临时状态；若要更新跨任务正式内容带，还必须满足预注册的独立任务/场合/评分者数量、目标覆盖、版本可比性、决策可靠性和不确定性门槛。可选形式包括：

- 学生独立解释本组设计的原理、证据和权衡；
- 现场复现关键操作或调试一个变式问题；
- 提交个人设计说明、代码片段、实验分析或写作片段；
- 从冻结蓝图和等价题池按可审计规则分配项目答辩问题；
- 在新情境中完成短的迁移演示；
- 对一个失败方案进行个人诊断并提出修订。

这些都是测量，但不是传统意义上的统一纸笔测试。同一目标不自动意味着不同项目证据可比；各组围绕不同项目作答时，必须控制共同任务要求、允许帮助和难度，或通过锚任务完成链接，否则只能作任务内解释。

## 8. 十轮科学反证与设计决定

每一轮都记录待证命题、最强反例、采用决定、放行门槛和残余风险。所有阈值必须在试点前按用途和错误代价预注册，不能看完结果后反调，也不应凭空给全系统指定一个统一数值。

### 第一轮：课标四段链能否直接变成评价分数

**待证命题**

只要 AI 找到 `核心素养 → 课程目标 → 课程内容 → 学业质量`，就可以直接生成学习目标、量规和综合分。

**最强反例与证据**

同一行为可能同时受到知识、表达、资源、协作和任务熟悉度影响；课标对齐只说明内容来源，并不自动证明任务观察到了目标构念。教育评价需要协调认知模型、观察任务和解释模型，而不是从标准文本直接跳到分值。[National Academies 的评估三角](https://www.nationalacademies.org/read/10019/chapter/4)和[证据中心设计](https://doi.org/10.1002/j.2333-8504.2003.tb01908.x)均支持先建立证据论证。

**采用决定**

正式链路改为：

```text
课标版本与条款
→ 可评价学习目标
→ 目标构念及禁止混入因素
→ 可观察证据
→ 任务/情境/允许帮助
→ 评分规则与暂不评价条件
→ 解释范围
```

各维度先分别保存；未经验证不得合成一个“核心素养总分”。

**放行门槛**

- 每个正式评价指标均有课标版本、条款、目标、内容范围、预期质量表现和证据说明。
- 学科专家能说明该任务为何能引出目标证据，以及哪些表现不能被解释为该目标。
- AI 引用可回到原文页码/段落和结构化节点；教师发布前逐项确认。
- 专家无法一致解释测量对象时，只能用于反馈，不进入分层或模型。

**残余风险**

课程标准本身具有综合性，拆分过细可能失去整体学习意义；需要在“可测量”与“完整任务”之间保留双层表示。

### 第二轮：一次前测能否同时测掌握、态度和项目能力

**待证命题**

把素养题、态度问卷和项目偏好汇总成一个前测总分，可以提高初始分层准确度。

**最强反例与证据**

掌握、动机、自我效能、焦虑、兴趣和访问条件是不同构念，反应机制和有效用途不同。领域先备知识与后续表现有关，但其对学习增益的关系高度依情境变化，不能把相关性解释为固定命运。[领域先备知识元分析](https://doi.org/10.1080/00461520.2021.1939700)汇总了大量效应并显示影响存在显著异质性。

**采用决定**

前测拆为学科先备诊断、起点表现任务、学习支持量表、访问与经验核验四类证据包；分别形成 `M0/P0/S0/X0`，不再计算 `literacy + attitude` 总分。

**放行门槛**

- 每类工具在发布前声明用途、构念、目标人群和禁止用途。
- 态度量表保存子量表、反向题、计分键、适龄性、实施说明和验证状态。
- 学科表现结果不得读取态度题；支持处方不得把态度低解释为能力低。
- 缺失、跳过、技术故障和无机会不得变成 0 分。

**残余风险**

多证据包会增加学生负担，应采用最小必要测量、适应性路由和分时完成，并验证是否产生额外焦虑或课程阻塞。

### 第三轮：前测能否直接形成稳定 A/B/C

**待证命题**

只要设定两个分数线，一次前测就可以准确生成初始 A/B/C，并直接驱动资源和小组。

**最强反例与证据**

临界点附近会受题目抽样、状态、实施条件和评分误差影响，同一学生在平行版本上可能跨界。分类决策需要关注分类准确性和一致性，而不只是整体相关或内部一致性；二者说明给定分类规则的重复性与误分概率，不等于已经证明切点有课程意义，也不等于与独立外部标准一致。[Livingston 与 Lewis](https://doi.org/10.1111/j.1745-3984.1995.tb00462.x)提供了分类准确性与一致性估计框架。[Park、Kim 与 Lee](https://doi.org/10.1111/jedm.12338)只可作为“由多个测量形成二元决策也要验证规则”的方法先例，不能证明本平台三层 A/B/C、任意加权或某一切点有效。

**采用决定**

前测只生成带目标范围、覆盖与不确定性的 `InitialStudentSubjectStateVersion`。版本化 `ContentBandPolicyVersion` 再依据经标准设定的切点生成 `StratificationDecision(candidate/boundary/abstain)`；教师审阅证据与错误代价后，才可写入内部 `StudentSubjectBand`。首次合格的共同个体证据到达后重新估计状态，不能让前测分数直接改层。

**放行门槛**

- 报告目标覆盖、测量误差、边界附近分类准确性与一致性。
- 不确定区间跨越界线时保持边界，不强制输出单一层。
- 新入场状态设置有效期和首个复核决策点。
- 切点由课程目标、学业质量表现描述、专家标准设定及错误后果审查建立；不得按班内分位数、配额或期望层级人数倒推。
- 错分代价、分界规则和拒绝规则在查看试点结果前预注册；另用独立外部结果检验其效标关系。

**残余风险**

边界决策会让产品看起来“不够智能”，但强制给出确定答案会把不确定性隐藏成错误决策。教师确认是责任与情境判断环节，不是测量有效的证据；若教师频繁推翻候选，应调查工具、切点和实施流程。

### 第四轮：不同版本、群体和实施条件的前测结果是否可比

**待证命题**

只要套卷名称和学科相同，不同学校、年级、版本和设备上的原始分就可以比较。

**最强反例与证据**

版本难度、语言负担、设备、无障碍支持、教师提示和学生机会都可能改变分数含义，但这是三类不能混为一谈的问题：新旧工具的量尺链接/等值、同一构念跨群体的测量不变性与 DIF、以及实施条件是否改变可解释性。[教育与心理测验标准](https://www.aera.net/Publications/Books/Standards-for-Educational-Psychological-Testing-2014-Edition)要求为特定分数用途提供效度、公平性和可靠性证据；[Meredith](https://doi.org/10.1007/BF02294825)支持的是跨群体测量不变性假设，不是版本等值方法。DIF 不显著也不等于小样本下没有偏差，发现 DIF 也不自动证明整套工具无效。

**采用决定**

发布工具与题目冻结，修订生成新版本。系统分别保存：版本链接设计与系数；群体不变性/DIF 结果及敏感性分析；每次施测的允许帮助、设备、语言、无障碍和异常条件。每份结果按其具体比较用途标记 `comparable/limited/not_comparable`；即使同一版本，跨群体或实施异常也可能 `not_comparable`。

**放行门槛**

- 发布后题干、答案、分值、计分键、量表文字和评分标准全部冻结。
- 新旧版本只有通过锚题/锚任务与链接审查后才能计算进步。
- 检查 DIF、测量不变性、设备与语言敏感性并报告区间；DIF 触发项目审查、认知访谈和敏感性分析，再决定保留、分组参数化、改写或停用。
- `not_comparable` 禁止用于其声明范围内的层级移动，不限于跨版本；样本不足时结论为证据不足。

**残余风险**

小规模学校可能长期无法独立估计复杂模型，需要使用上级校准、透明回退和跨校研究包，同时避免把跨校均值当作本校学生真值。

### 第五轮：项目式任务是否天然比测试更有效

**待证命题**

只要任务是真实项目，就自然能测到核心素养，比普通测试更全面，也无需额外验证。

**最强反例与证据**

作品质量可能主要反映家庭资源、软件熟练度、美术包装、教师帮助或强势组员，而不是目标学习。这里的构念无关变异风险应由表现性评价的效度论证支持；[Linn、Baker 与 Dunbar](https://iro.uiowa.edu/esploro/outputs/journalArticle/Complex-Performance-Based-Assessment-Expectations-and-Validation/9984371102102771)指出复杂表现评价仍需验证任务要求、可迁移性、公平性和后果。[K-12 科学与技术 PBL 系统综述](https://doi.org/10.1080/03057267.2016.1226573)和[低龄 PBL 系统综述](https://doi.org/10.1371/journal.pone.0249627)只支持“PBL 定义、实施与效果证据存在异质性且值得审慎试点”，不能单独证明上述具体混入因素，也不能证明任何项目天然有效。

**采用决定**

每个项目先定义可评价学习目标和无关因素，再设计阶段、里程碑、小组材料、个人材料、允许帮助和可访问性；“项目精彩”不是评价指标。

**放行门槛**

- 项目任务通过内容覆盖、认知复杂度、真实性、可观察性和可访问性审查。
- 每个正式量规指标能够回指主张和具体证据，不使用“整体印象”代替。
- 通过学生试做、认知访谈或边做边说，核查学生实际理解的任务是否与设计者意图一致，并记录非目标语言、技术和资源负担。
- 家庭资源和技术条件可能影响的部分提供校内机会或等价替代。
- AI 只生成草稿；教师确认任务适配、可完成性和课程时间成本。

**残余风险**

高度真实的项目难以完全标准化；平台应允许任务内解释与跨任务解释使用不同证据等级，而不是为了可比性牺牲真实性。

### 第六轮：一个项目和一个评分者能否代表稳定水平

**待证命题**

学生在一个项目上得高分，就可以更新为稳定高层；只要量规写得清楚，一名教师评分已经足够。

**最强反例与证据**

表现性评价受任务、场合、方法和评分者影响。经典研究显示任务抽样往往是重要误差来源，一个任务上的成功不一定能概化到同类任务。[Shavelson、Baxter 与 Gao](https://doi.org/10.1111/j.1745-3984.1993.tb00424.x)及[Gao、Shavelson 与 Baxter](https://doi.org/10.1207/s15324818ame0704_4)均支持估计任务抽样与概化风险；后者样本中的评分者误差较小，不能反向外推为所有本地教师评分都可靠。[Myford 与 Wolfe](https://iro.uiowa.edu/esploro/outputs/journalArticle/Detecting-and-measuring-rater-effects-using/9985123697302771)可支持在多面 Rasch 框架下检查严厉/宽松、晕轮、随机性和差异评分者效应；跨时间漂移需另作纵向设计与本地检查，[Myford 的评分者时间稳定性研究](https://onlinelibrary.wiley.com/doi/10.1111/j.1745-3984.2009.00088.x)提供的是方法先例，不证明本平台存在或不存在漂移。

**采用决定**

单项目结果默认只支持本任务范围内解释；跨任务状态需要多个任务/场合证据。教师、自评、互评和 AI 评分分来源保存；正式流程显式记录评分分派、评分观察、边界裁决和校准运行。1—5 星只作为序数观察，不跨指标或评分者直接求均值。

**放行门槛**

- 任务、场合、评分者和方法均进入证据元数据。
- 量规先处于 `feedback_only/trial`；完成内容审查、试评和预注册一致性门槛后才可升为 `formal`。
- 依据构念、设计与数据选择测量方法：例如用概化设计估计任务/场合方差，用多面模型检查评分者严厉度与交互，不能只报一个相关系数。
- 用 D-study 或预注册的证据累积方案决定最低任务和评分数量。
- 抽样双评之外，所有边界学生、重大分歧和高影响异常必须双评或裁决，并周期性用锚作品检查漂移。
- 评分漂移或任务特异性主导时，只生成反馈，不更新正式层级。

**残余风险**

增加任务和双评会提高教师负担，应通过抽样双评、共享锚作品和学校学科组校准降低成本，而不是取消质量检查。

### 第七轮：小组成果能否归因到每个学生

**待证命题**

小组成员共同完成项目，因此小组作品分可以作为每名成员的个人能力分；过程日志和编辑次数可以修正贡献。

**最强反例与证据**

搭便车、角色差异、强势成员、同伴帮助和机会不均会造成错误归因；编辑次数也不能说明编辑质量。[Webb 对协作评价的分析](https://doi.org/10.3102/01623737017002239)强调评价目的、群体过程、公平和个体解释必须协调。

**采用决定**

- 小组成果只更新 `group_product_quality`。
- 个人状态只能读取个人工件、个人答辩、个人迁移、经核验的决策说明或其他可归属证据。
- 项目日志、聊天、上传和文档编辑只作过程事实，除非与具体工件和目标证据建立可审核关联。
- 未获得某角色、展示或操作机会时记为机会不足，不推断能力低。

**放行门槛**

- 每个要形成个人指标观察的目标至少有一项可归属个人的同目标证据；这只通过归属门槛，不等于已足以更新跨任务正式状态。
- 证据记录 `target_scope=individual/group`，组证据不能在服务层复制为个人行。
- 个人贡献声明需要工件版本、责任范围或答辩等独立核验。
- 没有个人证据时结果为缺失，不允许用组分填补。
- 更新正式内容带还须满足预注册的任务/场合/评分者数量、目标覆盖、链接、可靠性和不确定性门槛。

**残余风险**

过度强调个体问责会削弱真实协作。解决方式是同时保留组级成果和个人学习两套结果，而不是把项目拆成一组彼此孤立的个人作业。

### 第八轮：多源证据能否直接加权平均并每天更新

**待证命题**

把前测、作业、项目、课堂评价、行为和 AI 分析按权重相加，就能得到更稳定的动态素养分，并可每天更新层级。

**最强反例与证据**

不同来源可能重复表达同一信息；缺失与未获机会容易被误作低分；行为频率受任务投放影响；频繁更新会造成抖动。证据越多不等于信息越多，尤其不能用模型自己的旧结论再次训练自己。

**采用决定**

先建立追加式证据账本：原记录不覆盖，但允许通过新事件完成纠错、撤销和取代并保留完整链路。再使用透明、可校准的状态更新模型。状态单位固定为“学生 × 学科 × 学习目标 × 决策点”；前测是基线观测，其影响应随新增证据的信息量与相关性变化，而不是按任意日历公式机械衰减。内容掌握、学科实践、支持、角色机会、兴趣、访问和不确定性分轴保存。

**放行门槛**

- 每条证据保存构念、目标、任务、版本、来源、评分者、个体/小组属性、机会、时间和不确定性。
- 非冗余证据数量、质量、来源依赖、非随机缺失、冲突处理、迟滞、冷却和决策有效期规则预注册。
- 来源冲突时先检查构念是否变化、评分者漂移、机会/帮助差异、任务不可比、选择性缺失和来源依赖；无法解释时扩大不确定性或拒绝，不能用平均值掩盖冲突。
- 高影响调整只在预先声明的课时/单元决策点或项目 `regroup_boundary` 发生，并由教师确认；状态过期只限制后续用途，不删除历史证据。

**残余风险**

复杂模型在样本不足时会给出虚假精确度；第一阶段应使用透明规则和保守拒绝。数据成熟后，应按构念、数据生成过程和决策用途选择估计模型，并用概化/评分者误差框架补充相应误差分析；Bayesian、IRT、概化理论与多面模型并非四个可随意横向竞赛的同类按钮。

### 第九轮：动态分层分组会不会制造自我实现差异

**待证命题**

根据前测和项目表现进行分层分组只会提高教学效率，不会改变后续数据本身。

**最强反例与证据**

低层学生若长期接触不到核心或挑战内容，后续结果下降可能反过来“证明”旧分层正确；项目角色长期固化也可能造成技能机会差异。关于能力分组的经典研究表明其效果与机会分配需要按情境审查，[Hoffer](https://journals.sagepub.com/doi/10.3102/01623737014003205)不能直接证明本平台一定产生某种结果，但支持把分组后果作为实证问题。一般性的 [performative prediction 研究](https://proceedings.mlr.press/v119/perdomo20a.html)说明预测与决策可以共同改变后续数据分布；“教育中的自我实现差异”在本平台仍是必须检验的风险，不是已被该机器学习论文证明的事实。

**采用决定**

- 所有学生保留共同核心学习机会和必要挑战机会。
- 任务、难度、支架、角色、组员、教师反馈和实际参与作为干预事实记录。
- 分组基于任务目的；证据不足时保留随机基线。
- 项目在预先声明的稳定窗口内保持团队稳定，通常按 `ProjectPhaseVersion` 划分；只有 `regroup_boundary` 才生成常规调整候选。
- 学生及其监护人不看到内部内容带、同伴证据或保密模型细节，但应获得适龄说明：本次分组目的、使用了本人哪类证据、如何更正事实和如何申诉；不能以“算法保密”为由剥夺程序知情。

**放行门槛**

- 审计核心/挑战任务、展示、领导、核验、反馈和不同同伴合作机会。
- 训练和评估按时间、班级、项目组和学校隔离，避免相邻事件泄漏。
- 若某群体持续失去核心机会、层级差距扩大或角色长期固化，停止自动建议。
- 受保护或敏感属性默认不作能力代理或分组优化权重，并审计其代理变量。确需为无障碍、语言支持或法定义务使用时，必须有明确合法基础、最小必要范围、用途隔离和访问审计。

**残余风险**

教师人工调整也可能带入既有期待偏差，因此教师决定同样需要结构化原因和后果审计。教师保留最终教学决定权；这不把系统责任转嫁给教师，学校、平台运营方和模型/工具所有者仍须分别承担教育治理、测量效度、安全隐私、权限和稳定运行责任。

### 第十轮：新系统是否真正优于教师现有做法

**待证命题**

只要模型预测更准或教师接受率更高，就说明“基线入场观测 + PBL 多源更新 + 动态分组”有效。

**最强反例与证据**

预测指标改善不等于学生学习改善；教师接受可能是自动化偏差；分组存在同伴干扰；复杂系统还可能增加工作量、申诉和不公平。

**采用决定**

先明确两个不同问题：预测研究检验状态能否预测既定政策下的未来结果；因果研究检验某个版本化教学/分组政策是否改善结果。正式效果研究至少包含两种必需策略：

1. 学校真实的常规教学与教师决策基线；
2. 基线入场观测 + 多源动态更新 + 任务分组候选 + 教师确认的新政策。

“只使用入场诊断的静态初始支持”仅作为可选第三臂：只有教育伦理上对其优劣确有真实不确定性（equipoise），且不会剥夺必要支持和共同核心/挑战机会时才可纳入。

先影子运行，再在预先选定的学科、年级和项目中有限试点，最后做跨时间和跨学校验证。若比较政策效果，应按班级/教师等自然聚类单位随机，或在确需分期推广时按预注册顺序采用阶梯楔形；不能把愿意采用的教师与不愿采用者直接比较后声称因果。[CONSORT 聚类随机试验扩展](https://www.bmj.com/content/345/bmj.e5661)用于规范聚类试验报告，[阶梯楔形设计方法](https://www.bmj.com/content/350/bmj.h391)要求显式处理日历时间趋势、周期效应、实施延迟与潜在延续效应。分析还必须考虑学生、组、班级、教师和学校层级、同伴干扰与跨组污染；[一般干扰下的因果估计](https://isps.yale.edu/research/publications/isps18-01)仅提供方法依据，不自动解决本地识别问题。

**放行门槛**

- 主要结果是未来共同个体迁移/表现任务，而不是模型自己的层级或教师接受率；结果任务须独立制作、在状态更新数据截止后实施、版本冻结并尽可能盲评。掌握或政策模型不得用同一评价场合、同一工件/答辩、标签派生值或截止点后的信息预测该结果；若结果评分者与历史评分者重叠，应显式建模评分者效应并做敏感性分析，不能再把标签称为完全独立。
- 同时报告学习结果、分类错误、拒绝率、公平、机会、教师负担、学生申诉和实施忠实度。
- 预注册因果估计目标、处理版本、主要/安全结果、最小可检测效应或功效、基线平衡、失访处理和意向性分析；报告同伴干扰与跨组污染的敏感性分析。
- 新政策需达到预注册的优效或非劣效标准，且主要安全指标不恶化；仅有预测提升不能证明教学政策有效。
- 任何严重公平、机会或隐私红线越界时回退人工模式，不用总体平均提升掩盖局部伤害。

**残余风险**

学校环境变化会影响外部效度，正式结论必须限定适用学科、年级、任务形态、学校条件和版本，不能宣称对所有课程普遍有效。

## 9. AI 生成评价功能的修订方向

### 9.1 AI 的正确工作流

```text
学校先配置并版本化课标过渡政策；教师选择学段、学科、课程、年级、
教学内容、教学模式、评价用途和本次明确采用的课标版本
  ↓
系统解析并冻结：显式选择的课标版本 + 过渡政策版本
（不得在历史方案中静默替换成“最新版本”）
  ↓
系统检索并展示：已人工复核的结构化节点、原文页码/段落及文件哈希
  ↓
AI 只能在获准课程标准内容条目范围内起草学习目标，并声明可能混入的无关因素
  ↓
AI 推荐证据方式：测试 / 表现性任务 / 项目 / 混合
  ↓
AI 生成评价蓝图：目标覆盖、任务、证据、允许帮助、个体/小组归属
  ↓
AI 生成学习任务与项目阶段，而不是默认生成题目
  ↓
AI 生成逐项量规、暂不评价条件、评分示例和后续教学建议
  ↓
系统执行课标引用、目标—证据—任务闭环、版本和安全检查
  ↓
教师修改、确认并保留修改痕迹；试用、内容审查和评分校准后，
按测量准入状态发布冻结版本
```

平台的默认版本策略应明确配置为：K1—K9 使用 2022 年版课程标准；K10—K12 对已有正式 2025 年版的学科使用 2025 年版，其余继续使用 2017 年版 2020 年修订。默认策略只是待教师确认的治理规则，不允许把“年份更大”当成自动替换条件。版本切换必须有生效日期、适用年级/学科、在途课程处理和历史引用保留方案。

### 9.3 AI 必须被禁止的行为

- 没有课标版本和原文依据时声称“符合课程标准”。
- 为所有目标默认生成选择题或一张统一测试。
- 用一个项目的整体观感推断所有核心素养。
- 自动把小组作品分复制到每名学生。
- 将态度、签到、时长、点击、聊天或逾期加进掌握总分。
- 材料不足时自动给 1 星、0 分或 C 层。
- 仅凭 AI 自己评分形成高影响分层、分组或训练真值。
- 将未经过试用和评分校准的量规标记为正式分析版本。
- 用当前模型的输出训练同一模型而不保留独立结果。
- 把未复核的 OCR/AI 抽取文本注册为官方课标节点，或让 AI 自行选择“最新版本”覆盖历史方案。
- 在任务材料、学生工件或检索内容中出现提示注入时，改变课标依据、评分规则、权限或数据外发范围。

### 9.4 AI 生成与 AI 评分必须分层验证

教师点击确认只能说明教师承担了发布决定，不能代替以下验证：

1. **文档转换验证**：核对 PDF 文件哈希、页码、段落、OCR/版面解析版本和置信度；对公式、表格、脚注与低置信片段抽样或全量人工复核。
2. **引用与版本验证**：检查每条生成主张是否只引用已审核节点，是否遵守显式过渡政策，以及更新课标后历史方案能否原样重放。
3. **内容效度验证**：由学科专家审查目标覆盖、认知要求、构念无关负担、遗漏与越界；用学生认知访谈和试做检查任务实际解释。
4. **评分验证**：AI 评分只能先与多名校准后的人类评分者比较条件一致性、分歧类型、群体差异、边界错误、跨任务/时间漂移和对抗性输入；同时估计人工评分分歧，不把单一教师分当无误差真值，也不能只报总体相关或均值接近。[Williamson、Xi 与 Breyer](https://www.ets.org/research/policy_research_reports/publications/article/2012/jely.html)可作为自动评分论证框架来源，但不证明本平台评分器已经有效。
5. **安全与隐私验证**：测试提示注入、越权检索、学生隐私外发、训练数据回流、模型/提示/知识库升级和供应商变更；任一版本变化都要重新界定影响范围。
6. **人机交互验证**：检查自动化依赖、教师是否真正阅读证据、修改成本、拒绝/覆盖理由与学科差异；“教师接受率高”不等于内容正确。

自动评分模型具有单独的合法训练边界：学生原始作答/工件可以作为模型输入，多名校准评分者的原始评分与裁决结果可以作为监督信号，因为该模型的明确任务就是复现受控评分规则。训练与验证仍须按学生、任务版本和时间隔离，保存评分者 facet 与分歧，并禁止把评分器输出再次当作其自身独立效度证据。多面评分模型也可以把评分者作为误差 facet；这不同于在掌握或分组政策模型中使用标签派生分数预测同一结果。

`state_axis` 只允许 `M/P/S/null`；组成果、角色机会、兴趣、访问和纯反馈指标使用 `null`，分别进入自身事实或上下文对象，不能伪装成状态轴。只有相应 `claim × criterion × use` 的证据通过预注册门槛，AI 产物才可从 `feedback_only` 升为 `trial` 或 `formal`；`trial` 快照仅供研究与校准。任务生成有效、量规有效和自动评分有效是三项独立结论，不得互相替代。

## 10. 建议的数据对象与现有模型衔接

下表是后续迁移评审所需的目标能力，不代表本轮已经创建数据库表。名称可在迁移设计时调整。

### 10.1 课程标准和评价对齐

| 对象 | 作用 | 与现有对象关系 |
| --- | --- | --- |
| `CurriculumStandardVersion` | 保存学段、学科、年份、官方来源、原 PDF、结构化文本、文件哈希和状态 | 由超级管理员维护；被历史方案引用后只归档/取代，不物理删除 |
| `CurriculumTransitionPolicyVersion` | 保存 K1—K9 2022、K10—K12“正式 2025 优先，否则 2020”等适用规则、生效日期和在途课程政策 | 教师方案必须冻结所用政策与标准版本，不静默跟随最新版本 |
| `CurriculumNode` | 表示核心素养、课程目标、课程内容、学业质量和原文层级/关系 | 保存页码、段落、抽取版本、OCR 置信度和人工复核状态；不以自由文本替代正式节点 |
| `LearningGoalDefinitionVersion` | 把课程标准内容条目转成可评价学习目标并版本化 | 供学习起点诊断、课堂和项目共同使用 |
| `CurriculumAlignment` | 规范化链接不可变节点、主张、评价方案版本、任务版本和量规指标版本 | JSON 只作冻结快照/缓存，不作为唯一权威关系 |

### 10.2 通用测量工具与前测用途

| 对象 | 作用 | 关键约束 |
| --- | --- | --- |
| `MeasurementInstrumentVersion` | 统一表示诊断、普通测试、表现任务和量表的用途、目标人群与蓝图 | 不再另造互不兼容的第三套“前测题库”；发布后冻结 |
| `MeasurementItemOrTaskVersion` | 冻结题目/表现任务、计分键、目标映射、允许帮助和作用域 | 能复用时链接现有 `QuestionBankItemVersion/CommonQuestionSet`，不能复制后失去版本关系 |
| `MeasurementAdministration` | 保存学生、工具版本、本次用途、条件、设备、辅助与异常 | 区分未参加、未获机会、技术问题与低表现 |
| `ResponseOrObservation` | 保存逐项作答、工件/操作观察、评分状态、评分者和证据引用 | 原始答案 JSON 只作兼容快照，不是唯一事实源 |
| `EvidenceEligibilityDecision` | 按 `claim × criterion × use` 判断某条观察可用于反馈、试验或正式状态及其理由 | 资格按用途和版本决定，可撤销/取代并审计 |

前测只是 `MeasurementInstrumentVersion.purpose=diagnostic_entry` 的一种用途，不应再形成独立且重复的题目、评分和结果体系。现有 `StudentMasterySnapshot` 可保留为普通测试支持的专门快照，或经严格迁移受控扩展为通用快照；不能同时保留两条互相竞争的“正式掌握真相”。已有提交保留原始记录并标记 `legacy/unlinked`；不能伪造课标映射或把历史原始总分装成已经验证的目标级测量。

### 10.3 项目式学习

| 对象 | 作用 | 关键约束 |
| --- | --- | --- |
| `ProjectVersion` | 驱动问题、课程、班级、周期、内容哈希 | 发布后不可覆盖 |
| `ProjectPhaseVersion` | 阶段目标、顺序、稳定分组窗口和显式重组边界 | 只在 `regroup_boundary` 常规重组，通常与阶段边界一致 |
| `ProjectMilestoneVersion` | 截止、依赖、必需组/个人证据和量规 | 没有个人证据时不能更新个人状态 |
| `ProjectTeamPlanVersion` | 项目团队方案及稳定窗口 | 关联现有 `GroupingPlanVersion`，跨课堂存在 |
| `ProjectTeamMembershipVersion` | 成员关系、有效起止、进入/退出原因 | 任何重组生成新版本，不覆盖历史成员关系 |
| `ProjectRoleAssignmentVersion` | 角色、责任、预计机会和有效窗口 | 角色不是能力标签；支持轮换与多角色 |
| `ProjectDeliverable` | 声明交付物范围、作者和证据要求 | 明确 individual/group |
| `ProjectArtifactVersion` | 工件版本、前序版本、哈希、提交者和共同作者声明 | 追加版本，不覆盖 |
| `ProjectLogEntryVersion` | 个人、小组和教师过程日志 | 日志事实不直接等于质量 |
| `ProjectPresentationAttempt` | 展示、答辩、现场追问与个体评分 | 保存实际展示者和评分者 |
| `ProjectContributionFact` | 学生 × 组 × 里程碑 × 角色的可验证事实 | 不自动生成贡献能力分 |
| `ProjectOpportunityFact/Transition` | 实际获得、拒绝、缺失或替代的操作、展示、领导、核验与反馈机会 | 区分计划机会和真实发生，不把无机会记成低能力 |
| `ProjectRegroupDecision` | 调整候选、边界、教师决定、理由与前后团队版本 | 只能在声明边界常规调整；紧急调整单独标记 |
| `ProjectInterventionFact` | 实际任务难度、支架、教师反馈、材料、时间和角色变化 | 作为后续因果与反馈回路分析的处理事实 |

### 10.4 通用证据和状态

| 对象 | 作用 | 关键约束 |
| --- | --- | --- |
| `EvaluationContext` | 将评价扩展到课堂、前测、项目、阶段和里程碑 | 复用现有评价版本体系 |
| `EvaluationTarget` | 明确评价对象是个人、项目组或组交付物 | 个人与小组目标互斥；禁止服务层展开组分 |
| `EvaluationEvidenceLink` | 一次评价可链接多个版本化证据 | 不再只取“最新一份”；纠错、撤销和取代均保留链路 |
| `CriterionObservation` | 学生/小组 × 指标 × 用途 × 任务 × 评分者 × 量规版本 | 保存暂不评价和证据引用；同一指标不同用途不共享准入结论 |
| `ScoringAssignment` | 评分任务、盲评条件、评分者与截止 | 支持抽样双评和边界全量双评 |
| `RatingObservation` | 单评分者对单证据单指标的原始序数/类别判断 | 原始星级不直接求平均，不被裁决结果覆盖 |
| `Adjudication` | 分歧、边界和异常的裁决过程与最终用途决定 | 保留各原始评分和裁决理由 |
| `CalibrationRun` | 锚作品、评分者训练、漂移与版本门槛结果 | 决定量规版本是否可进入 `formal` |
| `MeasurementSnapshot` | 目标级估计、误差、覆盖、任务/评分者影响、可比性和 `research_only/formal` 作用域 | `trial` 只生成研究快照；只有 `formal` 快照可进入正式内容带 |
| `StudentSubjectStateVersion` | 引用各轴的独立快照、证据清单和策略版本的不可变清单 | 每轴有独立访问、保留期和允许用途；不以宽 JSON 复制敏感原始值，不生成全局总分 |
| `ContentBandPolicyVersion` | 保存适用课程/年级/目标、标准设定依据、切点、错误代价、边界和拒绝规则 | 政策版本冻结；禁止按人数配额倒推切点 |
| `StratificationDecision` | 保存状态版本、政策版本、候选/边界/拒绝、教师决定和结构化理由 | 测量结果与教学决定分离，完整保留反转与申诉 |
| `TaskReadinessSnapshot` | 当前任务需求与学生有效目标证据的交集 | 供本次分组，不是永久能力 |
| `ProjectOutcomeSnapshot` | 分离组结果、个人结果、机会和干预 | 供后续研究，不直接回写真值 |

状态到内容带的唯一允许链路是：

```text
formal MeasurementSnapshot(s)
  → InitialStudentSubjectStateVersion
  → ContentBandPolicyVersion
  → StratificationDecision(candidate | boundary | abstain)
  → teacher review
  → StudentSubjectBand
```

任何测量或项目服务都不得直接写 `current_layer/StudentSubjectBand`。状态快照是证据估计，政策版本定义切点与错误代价，决策记录候选和拒绝，教师复核才形成内容投放事实。
`InitialStudentSubjectStateVersion` 是首次教学决策时的 `StudentSubjectStateVersion` 角色名称，不另建一套平行状态真相。

## 11. 对分层、分组和模型训练的影响

### 11.1 哪些信息可以进入哪类决策

| 信息 | 内容带/分层 | 支持处方 | 项目分组 | 模型输入 | 训练目标 |
| --- | --- | --- | --- | --- | --- |
| 经验证的目标级前测表现 | 初始临时依据 | 可参考薄弱点 | 与任务目标相交后使用 | 经版本化后可候选 | 不直接作为未来目标 |
| 经验证的个人表现/迁移任务 | 可更新 | 可生成反馈 | 可形成任务准备度 | 可以 | 独立、未来、可比时可以 |
| 小组作品质量 | 不可直接 | 可给组反馈 | 可评价组策略 | 仅组级或上下文 | 不可复制为个人目标 |
| 教师逐项评分 | 量规验证后可作证据 | 可以 | 可作任务相关旁证 | 保存评分者效应 | 不可直接当绝对真值 |
| 自评/互评 | 不可单独 | 可用于反思/协作支持 | 可作角色或反馈旁证 | 研究性、需偏差检查 | 不可单独使用 |
| 兴趣、态度、自我效能 | 不可 | 可以 | 作为偏好或支持约束 | 与掌握模型隔离 | 不可作为掌握目标 |
| 完成、逾期、时长、点击 | 不可 | 可以 | 只影响可用性/支持 | 可作支持或审计特征 | 不可作为能力目标 |
| 缺席、设备、无障碍、未获机会 | 不可计低 | 必须处理 | 作为硬约束 | 缺失机制/机会变量 | 不可记 0 |
| 当前层级、教师历史分层、模型建议 | 不可作新证据 | 决策历史 | 干预事实 | 可用于反馈回路审计 | 绝不能作为自己的标签 |

### 11.2 模型训练的硬规则

模型目标必须先拆开，不能把平台所有问题训练成一个“综合素养/最佳分组”标签：

| 模型或政策 | 合法目标 | 不能充当目标 |
| --- | --- | --- |
| 学习状态/掌握预测 | 未来、独立、可比且个体归属的同构念表现 | 当前层级、同一评价场合的标签派生分、完成率 |
| 支持需要预测/处方 | 预注册的安全支持结果、可参与性和后续独立学习结果 | 把焦虑、无障碍或求助本身预测成低能力 |
| 分组政策评估 | 小组成果、个人学习、机会公平与协作过程的多目标结果，并显式处理同伴干扰 | 单一组分、教师接受率或模型自己的推荐 |

所有训练与验证还必须遵守：

1. 每个样本保存 `decision_as_of`、`data_cutoff`、`label_window_start` 和 `label_window_end`；特征事件的 `occurred_at` 与平台 `received_at` 均不得晚于截止点。
2. 对掌握与政策模型，决策后的教师反馈、支架、角色、重组、工件修订和评分不得倒灌为 T0 特征；不得用同一评价场合、标签派生值或截止点后的信息预测自身结果。自动评分和多面评分模型按第 9.4 节的独立任务边界训练，不适用这条笼统禁止。
3. 前测是基线观测/初始协变量，不是后续效果真值；只有采用显式 Bayesian 模型时，施测前分布才称为 prior。
4. 同一学生、同一小组、同一项目和相邻时间事件不能随机拆入训练与测试两侧；按时间、班级、教师、项目组和学校组织验证。
5. 任务难度、支架、角色、分组、教师反馈、实际机会和工具版本是干预或暴露事实，必须记录；组内同伴结果不满足独立同分布假设时使用多层或干扰感知分析。
6. 组级结局只在组级或明确的干扰模型中使用；个人结果必须保持个人归属，不把组分复制为个人标签。
7. AI 生成任务、量规和评分均保存模型、提示、知识库、课标、任务和量规版本及人工修订；未经独立验证不能反哺成真值。
8. 使用拒绝预测、校准、时间外推、学校外验证、群体性能、选择性缺失、漂移和敏感性检查；数据不足时保持透明规则。
9. 未来结果只能验证既定政策下的预测表现。若要声称“哪种分组/支架使学习更好”，必须定义因果估计目标、处理版本、可比组、干扰假设和随机或准实验识别策略。

`TaskReadinessSnapshot` 在当前架构中不是监督学习目标，而是具体决策点上由冻结任务要求与有效 `M/P/U` 状态透明派生的可重放对象。未来若要把它改造成预测模型，必须另立明确的预测目标、独立结果、验证路线与模型卡，不能沿用同名派生值悄悄替换。

## 12. 开发与研究顺序

| 阶段 | 主要工作 | 完成条件 | 本阶段不能声称 |
| --- | --- | --- | --- |
| P0 统一设计 | 冻结本文术语、证据归属、禁止聚合和状态轴 | 设计评审通过，旧文档冲突列入修订清单 | 已有有效前测/PBL 模型 |
| P1 课标底座 | 超管管理课标 PDF、结构化文本、版本、节点、哈希和替换；建立引用接口 | 教师能追溯原文，版本更新不改写历史 | AI 已理解课标或自动对齐正确 |
| P2 前测重构 | 多类证据包、发布冻结、逐项评分、目标级结果、实施条件和临时状态 | 客观题、表现任务和量表各自通过工程与首轮内容审查 | 前测可稳定自动分 A/B/C |
| P3 AI 评价生成 | 先选证据方式，再生成任务和量规；教师审核、试用和校准 | 目标—证据—任务闭环与版本测试通过 | AI 评分可独立作高影响决策 |
| P4 项目主链 | 项目、阶段、里程碑、团队、交付物、日志、展示、答辩和多证据链接 | 一个真实项目可端到端追溯组证据与个人证据 | 项目星级已能代表稳定能力 |
| P5 状态与分组 | 通用测量快照、多轴状态、任务准备度、多维分组约束和机会审计 | 影子运行可解释、可拒绝、可回滚 | 自动分组提高学习 |
| P6 正式试点 | 评分校准、测量分析、策略比较、教师工作量和公平后果研究 | 预注册主要结果和停止规则完成，跨时间验证通过 | 对所有学校和学科普遍有效 |

应先完成 P0-P4 的证据工程，再讨论复杂模型。模拟数据可以验证状态、权限、版本、归属和回滚，但不能证明真实学生学习效果。

## 13. 验收与停止条件

### 13.1 工程验收

- 已发布前测、任务、量规和项目版本不可原地修改或删除。
- 任一结果可追溯到课程标准版本、学习目标、任务版本、评价材料、评分者和实施条件。
- 个人与小组证据在数据库、API、导出和分析中保持不同作用域。
- 未评分、未投放、未参加、技术故障、无障碍安排和其他缺失原因彼此区分。
- onboarding 完成、学科前测完成、工具版本到期和复测要求分别表达。
- 学生端、WebSocket、缓存、URL、文件名和导出不泄露内部层级、同伴证据和保密技术细节，但必须向学生及其监护人提供本人决定的适龄说明、所用本人证据类型、更正与申诉入口。
- AI 请求不外发未经授权的学生级证据；课标与任务版本可完整审计。

### 13.2 测量放行

- 内容覆盖、认知要求和目标映射经过学科专家审查。
- 量规经过锚作品、评分培训、抽样双评和漂移检查。
- 报告任务、场合和评分者误差；单任务不越级解释成稳定特质。
- 报告分类准确性、一致性、边界拒绝和误升/误降后果。
- 报告版本链接、DIF、测量不变性、访问条件和小样本不确定性。
- 证据不足时系统真的执行 `abstain/collect_evidence`，而不是界面上提示后仍生成 C。

### 13.3 教学与研究停止条件

停止动作必须和故障范围匹配，不能把“停研究结论”“停一个工具”和“全平台回退”混成同一按钮：

| 范围 | 动作 | 典型适用情形 |
| --- | --- | --- |
| 隔离单一工具/版本 | 停止该工具产生正式状态，保留形成性反馈或改用替代工具 | 某前测版本、任务、量规、锚题或 AI 评分版本失效 |
| 暂停单一班级/项目组/学校 | 停止该范围自动建议，由教师接管并保护学生机会 | 实施偏离、角色/机会失衡、冲突、异常失访或跨组污染 |
| 全局回退 | 关闭相关自动分层/分组写入，只保留影子计算和人工流程 | 系统性泄漏、越权、不可追溯、错误归属或广泛安全伤害 |
| 只停止研究声称 | 系统可在安全前提下继续教学辅助，但不得宣称优效、非劣效或普遍有效 | 功效不足、外部验证失败、研究污染或因果识别不成立 |

以下触发器及其阈值必须在试点前预注册，并明确对应动作范围：

- **泄漏与归属**：标签穿越；任务、量规、锚题或答案泄漏；掌握/政策模型用同一评价场合、标签派生值或截止点后信息预测自身结果；小组结果复制成个人结果；未经授权的 AI 数据外发。自动评分按第 9.4 节审计其合法输入—监督信号边界。
- **版本与追溯**：课标、任务、量规、评分器或 AI 模型/提示/知识库版本无法重放，历史定义被覆盖，或新版本未经验证即替换正式版本。
- **数据质量**：选择性缺失、失访不平衡、事件迟到/错序、评分漂移、异常拒绝率或边界学生频繁被强制分类，超过预注册范围。
- **效度与性能**：分类一致性、边界错误、评分稳定性、链接或校准低于门槛；时间外/学校外明显失效；新方法不优于透明基线且未达到非劣效标准。
- **教学伤害**：某群体持续失去共同核心、挑战、展示、领导、操作或教师反馈机会；层级/组别差距、申诉、反转率或机会不均恶化。
- **实施与容量**：教师负担超限、无法完成边界复核/校准、实施忠实度不足、跨组污染或角色轮换未按方案发生。
- **隐私与安全**：敏感量表、无障碍、健康、同伴证据或内部层级越权暴露；提示注入改变规则；AI 未经规定的人类审核直接形成高影响决定。

发生触发后先冻结受影响写入、保留审计证据、通知责任人并执行学生保护/替代教学，再进行根因分析。恢复必须使用新版本并重新通过相应用途门槛，不能在原版本上清除告警继续运行。

## 14. 本轮冻结的设计决定与待实证问题

### 14.1 可以立即冻结的底层规则

1. 不把评价等同于测试。
2. 当某项教学决定确需新的起点证据时，按最小必要原则在该决定前完成入场诊断；允许有效既有证据豁免、适应性路由和支持量表跳过/替代。
3. 内容掌握、个人学科实践、支持、角色/机会、兴趣、访问和不确定性分轴保存。
4. 不生成未经验证的综合素养总分。
5. 前测先形成可过期的目标级状态；内容带是版本化政策生成候选、允许边界/拒绝并经教师确认后的另一对象。
6. 项目作品保持组级，个人更新必须有个人证据。
7. 共同锚点可以是表现性任务，不必是纸笔测试。
8. 分组按任务和阶段决定，并在预先声明的稳定窗口内保持稳定；常规重组只发生于 `regroup_boundary`。
9. AI 先选择证据方式，再生成任务与评分规则。
10. 未来独立个人结果可验证既定政策下的预测；教学/分组政策优劣必须另做有识别条件的因果研究。

### 14.2 尚不能靠设计推断、必须用真实数据回答的问题

- 哪个学科、年级和单元最适合首个前测与 PBL 联合试点。
- 每个目标需要多少题目、任务、场合和评分者，才能支持相应决策。
- 初始状态有效期、内容带政策的边界范围、冷却期和连续证据数量。
- 不同学科态度量表是否需要独立结构，以及对支持处方是否有增量价值。
- 不同表现任务版本能否链接，在哪些条件下只能有限比较。
- 多维技能互补组是否优于随机组、教师常规组或阶段稳定组。
- 哪些个人答辩/迁移任务既能保证归属，又不会破坏项目真实性。
- AI 生成量规的内容有效性、评分一致性、教师修订成本和偏差。
- 动态更新是否改善未来学习，而不是只提高模型指标。
- 不同学校的设备、师资、课程和实施条件如何限制迁移。
- 哪些学生因缺席、设备、语言、无障碍、选择退出或教师选择而缺少证据，以及这种非随机可用性如何改变结论。
- 分组中的同伴干扰、成员构成、角色轮换、教师支架与项目难度各自及共同产生什么效果。

## 15. 文献检索与证据记录

### 15.1 检索问题

本轮围绕以下问题检索：

1. 前测与领域先备知识应如何解释，能否直接分类。
2. 表现性评价和项目式学习能否替代普通测试，以及任务抽样风险。
3. 评分者、自评、互评和小组评价能否作为个人掌握证据。
4. 多源证据、分类一致性、测量不变性和公平性需要哪些验证。
5. 动态分层分组是否会产生反馈循环和机会不平等。

检索概念块包括：`prior knowledge/pre-assessment/diagnostic assessment`、`performance assessment/task sampling/generalizability/rater effects/rater drift`、`project-based learning/K-12/systematic review`、`classification accuracy/consistency/multiple measures`、`group assessment/individual accountability`、`measurement invariance/DIF`、`ability grouping/opportunity`、`automated scoring/validity`、`cluster randomized trial/stepped wedge/interference`、`performative prediction`。

### 15.2 纳入边界

- 优先纳入原始测量研究、元分析、系统综述、权威专著/标准和方法论文。
- K-12 证据优先；高等教育证据只用于说明一般测量风险，不直接外推中小学生效果。
- PBL 效果文献只支持“值得试点且高度依实施”，不用于证明某一具体平台方案有效。
- 方法论文支持设计和验证要求，不提供 STRATA 的具体阈值。
- 本轮不是 PRISMA 系统综述；后续正式论文仍需阅读全文、双人筛选、偏倚评估和可复现检索。

# 2026-07-22 工程重构后的证据身份复核补记

本补记不增加“科学论证轮数”，也不把工程测试解释为外部实证。它记录十轮反证在 P2—P5 实现中的可检查约束，供后续研究方案、预注册和代码审计引用。

1. 学习起点诊断工具与诊断实施批次分离。实验班、对照班必须在同一前测实施批次中绑定同一精确试卷版本；后测和问卷另建明确用途批次。
2. 每个正式学科诊断任务绑定不可变学习目标版本，该版本同时追溯核心素养、课程目标、课程内容和学业质量原文。自由文本目标只保留为历史未映射材料，不进入正式判断。
3. 作答、操作、短项目、附件和评分分别保留原始事实；评分是追加记录，不能覆盖学生提交。
4. 未获得机会、设备问题、材料缺失、未观察和等待评分均不等于低表现。目标估计为空时，动态分层只能“暂不建议”。
5. 小组作品保留为小组事实；个人初始情况只使用可归因到个人的作答、操作、说明、答辩或观察。
6. 前测总分不是自动分层变量。系统只汇总同一实施批次中的目标级情况；版本、覆盖、有效期、评分完成情况或不确定性任一不合格即拒绝自动建议。
7. “不确定性未计算”不得编码为 0。只有记录了明确方法和数值的不确定性才可与政策阈值比较。
8. 即使形成初始候选，也必须经教师查看目标材料后确认；动态分组只使用已经确认的教学安排，不直接读取前测原始分数。

真实闭环的工程验收路径固定为：发布课标依据完整的学习目标版本 → 发布诊断工具版本 → 发布班级实施批次 → 学生按精确版本提交 → 教师/校管理员追加评分 → 形成新的目标情况版本 → 检查有效期与不确定性 → 生成待确认或“暂不建议”的内容安排。后续论文不得用单元测试通过替代工具效度、评分者一致性、测量不变性或实验效果证据。
