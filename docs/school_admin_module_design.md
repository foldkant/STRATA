# 学校管理员端功能设计

## 定位

学校管理员端是本校平台运营后台。  
它只管理本校数据，不查看其他学校，不做跨校分析，也不修改系统底层部署参数。

学校管理员负责：

- 本校教师、学生、班级、任课关系。
- 本校教师权限。
- 本校公共题库和评价模板。
- 本校模型训练与分层运行情况。
- 本校数据导出、灾备导出和操作日志。

## 权限边界

学校管理员可以：

- 查看和维护本校基础档案。
- 创建、编辑、停用本校教师和学生信息。
- 批量导入、导出本校教师、学生、班级、任课关系。
- 重置本校教师和学生密码。
- 配置教师扩展权限。
- 维护本校公共题库和评价模板。
- 查看本校模型训练任务、模型版本和失败日志。
- 手动触发本校范围内的训练任务。
- 导出本校数据采集包和灾备包。
- 查看本校操作日志。

学校管理员不能：

- 查看其他学校数据。
- 创建或修改超级管理员账号。
- 管理其他学校管理员账号。
- 接收其他学校数据采集包。
- 做跨校分析。
- 修改全局算法、全局训练策略和系统底层部署配置。

## 信息架构

### 1. 管理首页

本校数据屏，显示运行状态和待处理事项。

指标：

- 教师数。
- 学生数。
- 班级数。
- 课程数。
- 今日学习事件。
- 待处理事项。

趋势：

- 近 7 天登录事件。
- 近 7 天学习行为事件。

状态：

- 账号异常：停用账号、首次登录未改密账号。
- 数据任务：最近导入、最近导出、失败导出。
- 模型任务：运行中、失败、待确认分层建议。
- 系统状态：数据库、存储目录、日志记录。

### 2. 教师管理

字段：

- 登录账号。
- 姓名。
- 联系电话。
- 状态。
- 首次登录。
- 最近登录。
- 任课班级数。

功能：

- 新增教师。
- 编辑教师。
- 启用、停用。
- 删除教师。
- 重置密码。
- 批量导入。
- 下载模板。
- 导出 XLSX。

校验：

- 账号：`^[A-Za-z][A-Za-z0-9_]{4,31}$`
- 示例：`teacher1` 合法；下划线可用但不是必需。
- 姓名：2-24 位中文或字母。
- 电话：手机号或带区号固定电话。
- 密码：教师属于教学账号，允许 6-32 位课堂简易密码，例如 `123456`。

### 3. 学生管理

字段：

- 登录账号。
- 姓名。
- 学号。
- 所属班级。
- 当前层级。
- 首次使用状态。
- 前测完成状态。
- 小组号。
- 状态。
- 最近登录。

功能：

- 新增学生。
- 编辑学生。
- 启用、停用。
- 删除学生。
- 重置密码。
- 批量导入。
- 下载模板。
- 导出 XLSX。
- 按年级、班级、层级筛选。

规则：

- 新生由学校管理员先建账号，创建时可以暂不选择班级。
- 新生创建时不默认分层，`current_layer` 为空。
- 新生档案标记 `is_first_use = true`，`onboarding_status = new`。
- 学生首次登录后必须完成引导流程：修改自己的密码、选择本校启用班级、完成前测。
- 前测由两套内容组成：素养题和态度问卷。
- 未完成前测的学生登录后只能进入首次使用流程，不能进入正式学习平台。
- 前测完成后才进入分层计算或教师确认流程。
- 新生刚入学时可以没有学号，学生账号可以先分配。
- 学号支持后续批量导入匹配更新。
- 批量更新学号时优先按登录账号匹配，也可以辅以姓名、班级做人工核对。
- 已填写学号后，学号在班级内唯一；空学号不参与唯一约束。
- 学生转班要记录日志。

### 4. 教师权限

学校管理员给教师配置教学扩展权限。

权限项：

- 课程创建。
- 资源上传。
- 题库导入。
- 公共题提交。
- 公共题审核。
- 测试发布。
- 项目发布。
- 学生数据导出。
- 学习行为明细查看。
- 分层建议查看。
- 分层建议采用。
- 手动调整分层。
- 任教班级学生账号查询。
- 任教班级学生密码重置为 `123456`。
- 实时问答。
- 课堂控制。

功能：

- 单个教师配置。
- 批量配置。
- 权限模板。
- 权限变更日志。

第一阶段可以先建权限数据结构和列表页，实际权限拦截逐步接入教师端功能。

学生账号协助权限说明：

- 教师可被授权查询任教班级学生账号，方便机房上课时协助学生登录。
- 教师可被授权将任教班级学生密码重置为固定课堂默认密码 `123456`。
- 教师不能自定义学生密码。
- 教师不能新增、编辑、停用、删除学生账号。
- 教师不能修改学生姓名、学号、班级、分层和账号状态。
- 教师重置学生密码后，学生应标记为首次登录或要求下次登录改密。
- 所有教师重置学生密码操作必须写入操作日志。

### 5. 班级管理

字段：

- 年级。
- 班级名称。
- 入学年份。
- 学生数。
- 任课教师数。
- 状态。

功能：

- 新增班级。
- 批量新增班级：选择年级、入学年份、班级数量和起始班号，自动生成班级。
- 编辑班级。
- 启用、停用。
- 毕业归档。
- 批量升班：例如将 `高一1班`、`高一2班` 更新为 `高二1班`、`高二2班`。
- 当前页多选、全选、批量停用、批量删除。
- 批量导入。
- 下载模板。
- 导出 XLSX。
- 学生转班。
- 学生升班。

规则：

- 班级名称在学校内唯一。
- 批量新增时按 `{年级}{班号}班` 命名，例如 `高一1班`、`高一2班`。
- 批量新增如果发现同名班级，整批拒绝创建，避免只创建一部分。
- 批量升班只更新班级年级和班级名称，不修改入学年份、学生档案和历史学习数据。
- 批量升班如果发现目标班级重名，整批拒绝更新。
- 班级归档后不再允许新增学生，但历史数据保留。
- 班级毕业是归档动作，不做物理删除。
- 班级毕业后写入毕业时间和操作者，并停用该班所有学生账号。
- 班级批量删除前必须先停用或归档；如果已有学生、学习行为、模型或训练数据，保留停用/归档状态，不物理删除。

### 6. 任课关系

任课关系只表达“教师任教哪些班级”，不再绑定课程、角色或状态。

字段：

- 教师。
- 任教班级集合。
- 班级数。

功能：

- 按教师聚合展示任教班级。
- 在教师行点击“批量设置”，弹窗勾选多个班级。
- 支持全选启用班级。
- 保存时采用覆盖式设置：勾选结果就是该教师保存后的任教班级。
- 导出 XLSX。
- 按班级、教师和关键词筛选。

规则：

- 任课关系属于本校数据，只能选择本校教师和本校班级。
- 课程、公有课和私有课后续在课程模块单独处理。
- 同一学校内，同一教师和同一班级只能存在一条任课关系。
- 任课关系保存后同步维护班级教师关联，用于后续教师端班级权限判断。
- 任课关系不设置启用/停用状态；要取消任教，直接从该教师的任教班级中取消勾选。

### 7. 题库中心

学校管理员管理本校公共题库，教师管理个人题库。

模块：

- 公共题库。
- 题型管理。
- 知识点管理。
- 难度等级。
- 标签管理。
- 公共题审核。
- 导入记录。
- 使用记录。

功能：

- 新增、编辑、停用公共题。
- 批量导入公共题。
- 下载题目模板。
- 审核教师提交的公共题。
- 查看题目被哪些测试或活动使用。

### 8. 评价模板

维护本校统一评价标准。

模板类型：

- 前测模板。
- 问卷模板。
- 项目评价标准。
- 自评模板。
- 互评模板。
- 师评模板。

字段：

- 模板名称。
- 适用课程。
- 评价维度。
- 权重。
- 等级描述。
- 状态。

规则：

- 学校管理员维护模板。
- 教师引用模板发布到班级。
- 已被使用的模板不能物理删除，只能停用或复制新版本。

### 8.1 学科与学科前测

学科与学科前测由学校管理员维护，后续教师可以按权限参与出题或提交题目。

新版前测不再使用旧 WWW 中 `lessonId=-1`、`lessonId=-2` 这类特殊课时 ID。  
前测按“学科 -> 前测套卷 -> 题目”管理。

前测类型：

- 素养测试：用于判断学科基础、核心素养、问题解决能力。
- 学习态度问卷：用于判断学习兴趣、自我效能、合作倾向、课堂参与意愿。

功能：

- 维护本校学科。
- 每个学科维护素养测试和学习态度问卷。
- 新增、编辑、发布、归档、删除前测套卷。
- 新增、编辑、删除题目。
- 题目支持单选、多选、量表和简答。
- 题目可设置选项、答案、分值、评价维度、排序和必答。

规则：

- 每个学校独立维护学科，不跨校共享。
- 不同学科有不同前测，例如信息技术、通用技术、人工智能校本课可以配置不同套卷。
- 同一学校、同一学科、同一前测类型只保留一套当前发布版本。
- 发布新版本时，旧发布版本自动归档。
- 学生进入某学科正式学习前，必须完成该学科当前发布的素养测试和学习态度问卷。
- 前测结果写入学习档案，并作为首次分层输入之一。
- 已被学生作答的套卷或题目不能物理删除，只能归档或复制新版本。

已实现：

- `Subject` 学科模型。
- `PretestPaper` 前测套卷模型。
- `PretestQuestion` 前测题目模型。
- `PretestSubmission` 作答记录模型预留。
- 学校管理员 Vue 页面 `/school-admin/pretests`，菜单显示为“学科与学科前测”。
- 学科、套卷、题目的基础 CRUD。
- 发布和归档接口。

下一步：

- 题库 XLSX 模板下载、批量导入和批量导出。
- 学生首次使用流程中的前测作答页。
- 课程入口前的学科前测完成检查。
- 前测得分写入学习档案和初始分层特征。

### 9. 模型与训练

学校管理员只管理本校模型运行。

页面：

- 班级模型列表。
- 训练任务。
- 模型版本。
- 分层建议记录。
- 训练失败日志。

功能：

- 查看当前生产模型。
- 查看候选模型。
- 手动触发本校训练。
- 回滚模型版本。
- 导出模型运行报告。
- 查看教师采纳率和拒绝率。

规则：

- 模型不直接修改学生层级。
- 分层建议必须由教师确认。
- 模型切换和回滚必须写操作日志。
- 班级数据不足时显示明确提示。

### 10. 数据导出

学校端分两类导出。

本校数据采集包：

- 给项目方做跨校分析。
- 默认脱敏密码和敏感配置。
- 包含学校编号、采集窗口、系统版本、校验文件。

本校灾备包：

- 用于本校恢复。
- 包含业务数据和必要附件。
- 需要超级管理员或部署人员配合恢复。

页面功能：

- 新建导出任务。
- 选择导出范围。
- 选择是否脱敏。
- 查看历史导出。
- 下载导出包。
- 下载校验文件。

### 11. 系统设置

学校管理员可维护本校展示和基础策略。

字段：

- 平台显示名称。
- 本校 Logo。
- 首页文字。
- 当前学年。
- 当前学期。
- 密码策略。
- 上传文件类型。
- 上传大小限制。
- 本地存储目录状态。
- WebSocket 地址。

不做：

- 数据库连接配置。
- Redis 配置。
- Celery 配置。
- 全局算法参数。

## 密码策略

平台分两套密码策略。

管理员账号：

- 适用角色：超级管理员、学校管理员。
- 规则：8-32 位，至少包含字母和数字。
- 可使用字符：字母、数字、`@#$%^&*_.!+-`。
- 不允许使用 `123456` 这类低安全密码。

教学账号：

- 适用角色：教师、学生。
- 规则：6-32 位。
- 账号示例：`teacher1`、`student1` 合法；下划线可用但不是必需。
- 可使用字符：字母、数字、`@#$%^&*_.!+-`。
- 允许使用课堂简易密码，例如 `123456`，方便机房上课、统一发放和低年级学生登录。

后续学生管理、学生批量导入和学生重置密码必须复用教学账号密码规则。  
超级管理员创建学校管理员、学校管理员重置自身账号等场景必须继续使用管理员账号密码规则。

## 账户停用与删除规则

所有账户都支持删除，包括学校管理员、教师和学生。

删除前必须先停用：

- 启用状态的账号不能直接删除。
- 删除确认页必须提示“请先停用账号，再执行删除”。
- 已停用账号才能进入最终删除确认。
- 教师、学生列表支持当前页多选和全选。
- 批量删除时如果选中项里有启用账号，系统只执行批量停用，并提示用户重新选择后再删除。
- 删除动作必须写入操作日志，记录账号、姓名、角色、所属学校和操作者。
- 如果账号已有课程、资源、学习行为、评价记录等业务关联，系统应阻止物理删除，并提示保留停用状态。
- 后续学生管理也必须使用同一规则，不能绕过停用步骤直接删除学生。

日志类型：

- 登录日志。
- 账号变更。
- 权限变更。
- 班级变更。
- 任课关系变更。
- 导入导出。
- 题库审核。
- 模型训练。
- 系统设置。

功能：

- 按时间、操作者、动作、对象筛选。
- 导出 XLSX。
- 查看详情。

## 页面交互规范

- 采用与超级管理员后台一致的左侧导航、顶部标题、内容区布局。
- 首页可以有数据屏，公开首页不要做数据屏。
- 不把多个 CRUD 功能塞进一个页面。
- 列表页必须支持查询、筛选、分页。
- 批量数据页面必须支持导出 XLSX。
- 教师、学生、班级、任课关系必须支持下载模板和批量导入。
- 学科与学科前测第一版先支持界面维护；题目批量导入、模板下载和导出作为下一步。
- 表单必须有后端校验，前端使用 `pattern`、`maxlength`、`required` 做基础约束。
- 删除高风险数据时优先停用或归档，物理删除要检查关联数据。
- 固定视口布局下，内容区滚动，侧边栏不滚动。

## 数据隔离规则

所有学校管理员查询都必须带学校范围：

- 用户：`user.school_id = request.user.school_id`
- 班级：`class_group.school_id = request.user.school_id`
- 课程：`course.school_id = request.user.school_id`
- 行为事件：通过班级或用户限制到本校
- 模型任务：通过班级限制到本校
- 操作日志：`audit_log.school_id = request.user.school_id`

学校管理员不接受 URL 参数中的学校 ID 作为权限依据。  
学校 ID 只能从登录用户的 `request.user.school_id` 获取。

## 跨校资源审核

- 学校管理员只处理本校教师提交的 `external` 资源。
- 待审核资源不会进入学生跨校资源列表。
- 通过后状态为 `approved`；退回必须填写原因，教师修改后可重新提交。
- 审核操作写入 `AuditLog`，不允许管理员直接修改教师资源正文。

完整规则见 `docs/resource_center_design.md`。

## 数据检查

- 独立页面 `/app/school-admin/data-quality`，不塞入管理首页或模型页面。
- 学校管理员查看本校当前检查结果、七项指标、历史趋势、待处理问题、数据核对和自动检查记录。
- 可手动检查最近完整 7 日，并导出五工作表 XLSX。
- 每日 01:30 自动运行；同窗口重复调度复用已有运行，单校失败不影响其他学校。
- 未通过的报告暂停后续学生分析；需关注的报告允许继续但必须保留待处理问题。
- 检查指标不用于学生评分、核心素养、积分、奖章或分层。
- 当前开发校最近完整 7 日检查已通过，旧事件未转换比例为 0%。

详细口径与验收见 `docs/data_quality_pipeline.md`。

## 评价管理

- 页面：`/app/school-admin/evaluations`。
- 学校管理员维护本校课程的评价方案和评价标准。
- 评价方案包含学习目标、评价依据、学习任务和评分规则。
- 评价标准包含评价指标、1-5 星表现说明和评分示例。
- 发布后保留历史版本，后续修改生成下一版本。
- 教师和学生不能访问学校管理员评价管理接口。

完整规则见 `docs/evaluation_management.md`。
