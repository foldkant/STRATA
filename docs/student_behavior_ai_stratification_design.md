## 0. 决策摘要

1. 当前 595 条开发事件只能用于审计代码覆盖，不能用于训练或论文结果。
2. 新系统以 `LearningEventV2 + LearningOpportunity` 记录“发生了什么”和“学生实际获得了什么机会”，所有比率都有分母。
3. 测试成绩、五星量规、课堂激励积分和模型掌握估计分开存储；`StudentProfile.score` 不作能力标签。
4. 首轮注册 22 个可重算候选特征，并强制区分直接事实、理论代理、量规派生和情境/质量控制；未经效度研究的代理不得显示为 SRL、投入或能力分数。
5. 量规采用按任务启用的成果、策略、调节、协作和学科实践模块；参与/服从性不进入量规，AI 不动态改测量权重。
6. 模型先分别预测未来 7/14/28 日的掌握、必做任务完成、逾期和成长结局，再由预注册策略派生完成支持信号与支持处方，最后由掌握证据映射内容投放带；不直接学习永久能力层级。
7. 比较规则、Elastic Net、多层模型、CatBoost、LightGBM 和 IRT/BKT；未通过时间外推、留班/留校、校准和公平闸门的模型不上线。
8. “一班一模型”实现为全局/学科模型加班级惩罚校准器和策略参数；小样本班级不从零重训复杂模型。
9. 每晚在校内更新事实、特征和推理；班级校准按周且满足样本门槛才更新；全局模型按月/学期在中心端离线训练并签名分发。
10. 采用隐性动态分层：模型只生成任课教师可接受、修改、拒绝或延后的内部建议；学生不看到 A/B/C、边界带、风险概率、排名、模型理由或能力型分组依据，只看到学习目标、被分配的任务与支持。
11. 跨校只交换去标识化、加密和签名的研究包，不默认导出姓名、账号、聊天原文、答卷正文和作品文件。
12. 开发顺序先完成事件、机会、结果、量规、特征和计划结局，再训练模型；第一篇研究先验证测量和预测，教学效果另做簇随机或阶梯楔形研究。
13. 每项产品和论文结论绑定 C0-C6 科学主张等级；数据正确、预测有效、决策有用和干预有效不得相互替代。
14. 纵向分析区分学生间差异与学生自身变化；生产可用快照、事后重建快照、未观察和竞争状态分别处理。
15. AI 生成题默认是草稿，未经过专家审查、试测、DIF/漂移和链接验证，不得作为共同锚题或研究结局。
16. 公平审计覆盖测量、机会、观察、预测、建议覆盖、教师处理和学习后果；删除敏感属性不等于公平。
17. V1 禁止从观察性教师日志直接学习自动教学策略，也禁止在线强化学习自动调整内容带。
18. 模型验证具有学校、学科、测量版本和时间边界；实施忠实度、教师容量、学生自主性、生产漂移和退役与预测性能同等属于上线条件。

### 0.1 三十轮科学审查汇总结论

| 审查轮次 | 核心问题 | 汇总后的设计决定 |
| --- | --- | --- |
| 第 1-5 轮 | 构念、行为、时间过程、量规和教学行动 | 行为日志先作为事实或理论代理；所有比率使用机会分母；五星评价必须绑定任务锚点和证据；完成困难与掌握不足分开处理 |
| 第 6-10 轮 | 估计目标、验证总体、抽样、测量误差和决策效用 | 研究单位改为学生 × 学科 × 计划决策点；分别验证在读学生、新学生、新班级、新学校和新课程/时间；不把教师确认层级当作学生结局 |
| 第 11-15 轮 | 因果识别、人机协同、未成年人隐私、复现和停用 | 预测有效不能替代干预有效；教师确认不能替代安全验证；建立研究协议、负对照、停用、签名模型和学生数据不出校边界 |
| 第 16-20 轮 | 科学主张、纵向变化、观察过程、AI 题目和预测偏倚 | 产品和论文结论绑定 C0-C6；区分学生间与学生内效应；保留未观察和竞争状态；AI 题未经试测、DIF 和链接验证不能作为锚题或共同结局 |
| 第 21-25 轮 | 跨校迁移、公平链、解释稳定性、教师容量和策略学习 | 新学校必须重新评估迁移；公平覆盖测量到学习后果；不稳定解释不展示；建议量受教师容量约束；V1 禁止观察性策略优化和在线强化学习 |
| 第 26-30 轮 | 实施忠实度、小组干扰、隐私自主性、生产漂移和累积证据 | 分配、理解、投放、使用和完成分开记录；共同作品不复制为个人结局；治理覆盖群体隐私与学生自主性；模型需要 canary、回滚、独立复验和退役 |

三十轮审查形成以下总原则：**先证明数据可观察，再证明指标可测量；先证明模型可预测，再证明建议可决策；最后才研究分层干预是否产生学习增益。** STRATA 当前应先建设事件、机会、测量、质量、协议和影子验证基础设施，不直接用开发数据训练生产分层模型。

### 0.2 隐性动态分层制度

隐性分层是本系统的产品和治理原则。A/B/C、A/B、B/C 是教师进行差异化教学的内部内容投放代码，不是学生身份、公开称号或永久能力标签。分层按学科、课程和有效期保存，同一学生在不同学科、课程或时间可以不同。

| 信息或操作 | 学生 | 任课教师 | 学校管理员 | 超级管理员 |
| --- | --- | --- | --- | --- |
| 当前/建议 A/B/C 与边界带 | 不可见 | 可查看本人任教班级并调整 | 默认只看本校聚合分布和质量 | 只看去标识化跨校聚合 |
| 预测概率、不确定性、理由和反证 | 不可见 | 可查看并用于审核 | 默认只看聚合监测 | 只看模型级和学校级监测 |
| 被分配的资源、题目和支架 | 只看本人实际获得内容 | 可设计、预览和投放全部变体 | 不参与日常个体投放 | 不参与日常个体投放 |
| 学习小组 | 协作活动进行时可见组员，不显示能力构成、分组策略或层级 | 可见成员、候选方案、约束和分组依据 | 默认只看组数和运行状态 | 不看可识别小组成员 |
| 数据与建议纠错 | 可纠正基础事实、报告资源不可用或支持不适合 | 可纠正情境并接受、修改、拒绝或延后建议 | 处理治理与数据质量问题 | 处理跨校模式和模型包问题 |
| 个体层级导出 | 禁止 | 仅限本人任教范围、显式授权并写审计 | 默认禁止，特批用途单独审批 | 禁止导入可识别个体层级 |

学生端仍需透明展示学习目标、完成要求、评价标准、教师反馈、已获得支持及数据收集类别。隐性分层不等于隐瞒数据用途，也不能阻止学生纠正错误事实或请求教师复核。系统隐藏的是内部标签、概率、比较排名和分组推断，避免污名化、自我实现预言与同伴比较。

协作活动中学生必须知道当前组员才能完成任务，但不得看到“同层组、异层组、A 组”等命名，也不得看到组员层级或算法分组理由。学生资源和任务使用中性名称，禁止出现 `A层题`、`C层资源`、`低水平组` 等可推断标签。

```text
学习事件与机会 -> 测量/特征 -> 分开的计划结局预测 -> 内部内容带候选
                                               -> 任课教师私有审核
                                               -> 服务端生成个人投放清单
                                               -> 学生只接收任务、资源和支持
```

隐性分层不是密码学意义上的绝对保密：学生之间比较任务时仍可能推测存在差异。系统目标是禁止制度化标签、公开排名和接口泄漏，并通过中性任务命名、教师沟通规范和共同核心目标降低污名化风险，不能宣传为“学生绝对无法推断”。

## 1. 研究主张与边界

核心主张：STRATA 通过可审计的学习过程事件和经验证的任务级量规，分别预测下一周期掌握、必做任务完成、逾期与成长结局，生成多维证据画像和支持处方，再由班级校准策略与教师确认形成 A/B/C 内容投放建议。

这份方案不把以下内容视为已经成立的结论：

- 当前开发库中的事件数量不能证明行为指标有效。
- 点击次数、在线时长或课堂积分不能直接等同于学习投入、能力或素养。
- 教师原有 A/B/C 判断只能作为弱监督信息，不能作为唯一金标准。
- 单个班级 40-60 名学生不足以从零训练稳定的复杂模型。
- 相关性预测不能直接解释为动态分层带来了学习增益。

### 1.1 科学主张等级

每项指标、界面、模型和论文结论必须登记它实际支持的主张等级。高等级主张需要新增证据，不能由低等级结果自动升级：

| 等级 | 主张 | 最低证据 | 禁止跳跃 |
| --- | --- | --- | --- |
| C0 | 数据按定义被正确记录和重放 | 模式、幂等、时间、机会和黄金数据测试 | “日志完整，所以学生投入高” |
| C1 | 描述指标在声明窗口可可靠计算 | 分母、缺失、稳定性和重算一致 | “完成率可算，所以测量责任感” |
| C2 | 指标支持有限构念解释 | 内容、反应过程、结构、外部关系和后果证据 | “提高 AUC，所以已测得 SRL” |
| C3 | 在指定总体和 `T0` 可预测计划结局 | 锁定外层验证、校准、不确定性和透明基线 | “预测相关，所以它是原因” |
| C4 | 建议在真实容量下改善决策 | 教师单独/模型单独/团队比较、覆盖和净效用 | “教师接受，所以建议正确” |
| C5 | 干预造成学习或支持结果改变 | 可识别随机/准实验、ITT、实施和不良后果 | “模型组进步，所以模型造成进步” |
| C6 | 主张可迁移到新学校/时间 | 独立复验、测量链接、异质性和持续监测 | “一所外校有效，所以普遍有效” |

`ScientificClaimVersion` 保存目标总体、分析单位、主张等级、证据版本、允许措辞、禁止外推和状态。产品默认只展示已达到等级的表述；论文中预测、测量和干预效果使用不同证据链 [R42, R83, R85-R88]。

### 3.1 已有数据结构

当前 [learning/models.py](../learning/models.py) 已有：

- `LearningEvent`：主体、班级、课程、课时、事件类型、对象、时长、得分、JSON 元数据和时间。

### 3.4 当前计分逻辑

当前至少存在四套意义不同的得分：

1. 测试得分：客观题自动评分，主观题教师评分，汇总到 `TestAttempt.total_score`。
2. 课堂题得分：按题目基础分或 A/B/C 分层分值计算。
3. 五级量规：自评、互评和师评保存 1-5 星。
4. 课堂激励积分：抢答和随机点名默认加 2、减 1，聊天审核默认轻微 -1、一般 -3、严重 -5，累计到 `StudentProfile.score`。

需要修正的问题：

- 登录接口没有写 `login` 事件，虽然数据总览会读取该事件。
- 聊天扣分可使总积分为负；抢答和随机点名却把总积分截断为不低于 0，统计口径不一致。
- 含主观题的测试在学生提交时先写一次 `answer_submit` 得分；教师完成主观题评分后没有写最终成绩事件，原事件可能不是最终分。
- 教师评价事件的 `actor` 有时是教师，被评价学生只在元数据中，学生特征连接困难。
- 没有记录题目或资源是否真正向学生投放，无法区分“没完成”和“根本没有机会完成”。
- 没有事件 UUID、模式版本、客户端序号、作答尝试、模型版本、量规版本和分层投放版本。
- 原始答案或文字可能直接进入 `metadata`，隐私边界和特征使用边界尚不明确。
- 没有幂等键和去重机制，刷新、重试或网络抖动可能制造重复事件。

结论：当前实现可作为操作审计的起点，不能直接作为学习分析数据集。

## 4. 理论构念与证据模型

学习投入至少包含行为、情感和认知维度；技术环境中的可观测行为只能覆盖其中一部分 [R01-R04]。自我调节学习还涉及计划、监控、策略调整、动机与反思，不能仅由登录频率推断 [R05-R08, R29-R30]。因此采用“构念 - 指标 - 原始证据”三级模型。

| 构念 | 操作性定义 | 可用证据 | 不能单独作为结论的指标 |
| --- | --- | --- | --- |
| 学科掌握 | 对知识点和任务目标的当前达到程度 | 题目正确性、难度、知识点、延迟、重试、测试和作品量规 | 总积分、单次正确 |
| 学习成长 | 同一学生在可比测量上的纵向变化 | 前测、后测、锚题、知识点掌握轨迹、作品版本 | 两次不同难度测试的原始分差 |
| 行为投入 | 获得学习机会后持续参与并完成活动 | 有效活跃时长、完成率、按时率、主动重访 | 页面打开、浏览器停留 |
| 认知投入 | 学生执行主动、建构或互动性加工 | 解释、修订、策略切换、复杂题过程、讨论贡献 [R11] | 点击次数、资源数量 |
| 自我调节 | 计划、监控、求助、调整和反思学习 | 目标设置、进度检查、重做、求助、反思表单 | 学习总时长 |
| 协作 | 对共同成果的可辨识贡献和反馈质量 | 文档版本贡献、任务分工、同伴反馈、响应网络 | 聊天条数 |
| 教师支持需要 | 学生获得何种支持以及支持后的反应 | 干预类型、原因、强度、响应和后续变化 | 教师干预次数 |
| 项目与创新 | 在真实任务中设计、实现、迭代和表达的质量 | 里程碑、日志、甘特图、阶段成果、作品量规 | 最终文件是否上传 |
| 学习态度 | 动机、自我效能、价值感等经量表测量的状态 | 经验证的前测/周期问卷 | 平台行为的主观推断 |
| 信息科技学科素养 | 信息意识、计算思维、数字化学习与创新、信息社会责任 | 学科任务、表现性评价、ICT 素养工具 [R35] | 普通课程访问量 |

自动行为指标是某个构念的证据，不是构念本身。任何构念得分都必须保留证据来源、时间窗、缺失情况和版本。

### 4.1 近五年证据补充后的设计修正

本轮 DOI 输入清单补充了 43 篇 2021-2026 年文献，其中 36 篇位于当前日期向前五个完整发表年度 2022-2026。合并去重后的总库年代统计见第 18 节。新增证据没有支持“采集越多越好”或“复杂模型必然更准”，反而要求平台进一步收紧以下边界：

1. 行为轨迹对自我调节学习的解释必须同时检验构念效度、时间顺序和教学情境，不能把点击或停留直接命名为认知能力 [R41-R45, R64, R71-R72, R76-R77, R81]。
2. 仪表板必须回答“教师下一步能做什么”，而不只是显示次数、排名和相关性 [R46-R49]。
3. 预测模型必须把实际投放内容、题目难度、教师干预和班级教学条件纳入机会模型，否则容易把教学差异错误归因于学生 [R50, R66-R68]。
4. AI 反馈和推荐不得削弱学生能动性；教师确认不是形式审批，而是模型边界、课堂情境和学生权益的控制点。2026 年中学生随机对照研究也显示，不同 GenAI-SRL 支架对动机、策略和知识结果的作用并不一致 [R51-R55, R61-R62, R74, R78-R80]。
5. K-12 模型需要独立执行隐私、公平、透明、稳健性和可追责审计 [R56-R60]。
6. 算法分组已有可行实施案例，但分组目标、同质/异质策略和学习效果仍需前瞻性比较，不能由预测层级直接决定固定小组 [R65, R69-R70, R82]。

因此，STRATA V1 只采集平台内可解释、最小必要的交互证据；摄像头、麦克风、眼动、生理信号和屏幕录像不进入常规部署。多模态研究若未来开展，必须作为单独伦理审批和单独客户端模块，不与当前产品默认行为采集合并。

### 4.2 测量证据四级体系

trace data 的可获得性不等于构念效度。即使经过理论对齐和外部资料三角验证，轨迹协议对 SRL 过程的识别仍可能存在显著漏检和误判 [R42, R71]。STRATA 因此把数据分为四级，界面、特征库和论文必须使用对应名称：

| 等级 | 定义 | 允许表述 | 禁止表述 | 例子 |
| --- | --- | --- | --- | --- |
| E0 业务事实 | 服务端可直接核验的机会、结果或状态 | “已投放 8 项，按时提交 6 项” | “责任感 75 分” | 投放、提交、最终评分、离线时段 |
| E1 行为指标 | 由多个 E0 事实按冻结规则计算的描述量 | “近 7 日机会校正完成率” | “行为投入水平高” | 完成率、首次得分率、有效活动分钟 |
| E2 理论映射代理 | 有理论解释但尚未在本平台完成效度验证的轨迹模式 | “答案修改代理指标”“求助时机代理指标” | “认知投入”“自我调节能力” | 修改、重访、求助、坚持和时序模式 |
| E3 已验证构念分数 | 经内容、过程、内部结构、关系和跨群体证据支持的量规/测量结果 | 量规或工具正式构念名称及版本 | 跨未验证任务、学科或学校直接比较 | 经验证的任务量规维度、等值锚测能力估计 |

生产仪表板默认展示 E0/E1；E2 只能在研究或教师证据页以“代理指标”呈现并附数据来源；E3 必须绑定测量工具版本和适用范围。机器学习可以比较 E1/E2 的预测增量，但预测有效不等于构念测量有效。

### 4.3 轨迹效度研究

在把任何 E2 指标升级为 E3 前，至少完成以下本地验证：

1. 理论对齐：专家逐项说明原始事件为何能支持目标过程，并列出竞争解释。
2. 数据对齐：在小样本真实课堂中，将轨迹与经同意的课堂观察、刺激回忆、学习日志或 think-aloud 子研究对齐；think-aloud 可能改变学习过程，不能作为唯一标准。
3. 时间对齐：验证事件发生顺序、任务阶段和过程边界，而不只比较总频次。
4. 定量报告：分别报告覆盖率、敏感度、特异度、阳性预测值及不确定区间；不只报告相关系数或分类准确率 [R42]。
5. 泛化检查：至少跨任务类型和一个新的课堂/教师复验；未复验指标保留 E2 状态。

教师判断同样不是天然金标准。近期研究显示教师对学生 SRL 的判断可能准确性较低，并受成绩、性别和整体印象影响 [R79]。因此教师判断只能作为一种带来源的证据；测量研究中应在展示模型建议前独立收集，避免被模型污染。

### 4.4 构念网络与状态边界

每个拟升级为 E3 的构念建立 `ConstructEvidenceMap`：构念定义、相邻构念、预期收敛关系、预期区分关系、已知竞争解释、触发情境、任务阶段和适用总体。验证前预注册方向与大致强度范围，避免事后从大量相关中挑选支持证据。

- 同一轨迹在 `planning`、`execution`、`monitoring` 和 `reflection` 阶段可以有不同含义，阶段未记录时不得形成阶段性 SRL 结论 [R89]。
- 稳定学生差异、某学生相对自身基线的变化和某节课的短时状态分别命名，不把状态分数写成长期能力或人格。
- 模型预测增量属于 C3 证据，不自动提升 C2 测量效度；DIF、机会差异或教师评分偏差可以让高预测指标仍然不公平 [R83]。
- 未验证构念只展示任务内证据和竞争解释，不生成跨学科综合画像。

## 5. 新版学习事件规范

### 5.1 设计原则

- 先记录原子事件，再生成可重算的特征，不把特征直接写回原始日志。
- 每个结果必须有机会分母，例如“完成 8/10 个已投放任务”，不能只记完成 8 个。
- 客户端时间用于还原业务顺序，服务器接收时间决定某个预测时点当时是否真正可用；二者不能互相替代。
- 事件至少一次送达，服务端依靠 `event_id` 和幂等键去重。
- 事件模式有版本，旧客户端仍可被解析和迁移。
- 只采集教学目的所需的最低数据，不默认采集摄像头、麦克风、逐键输入、屏幕截图或任意浏览历史。
- 内部事件命名可映射 xAPI 或 1EdTech Caliper，但业务库不依赖外部云服务。

### 5.2 统一事件信封

建议将 `LearningEvent` 升级为以下逻辑结构：

```json
{
  "event_id": "uuid",
  "schema_version": "1.0",
  "event_name": "assessment.item.submitted",
  "source": "student-web",
  "client_version": "2.0.0",
  "actor_id": 24,
  "target_student_id": 24,
  "school_id": 1,
  "class_id": 3,
  "subject_id": 1,
  "course_id": 3,
  "lesson_id": 4,
  "session_id": 3,
  "step_id": 7,
  "object_type": "question",
  "object_id": "91",
  "opportunity_id": "uuid",
  "attempt_id": "uuid",
  "client_sequence": 18,
  "client_occurred_at": "2026-07-18T09:30:01+08:00",
  "server_received_at": "2026-07-18T09:30:02+08:00",
  "duration_ms": 42000,
  "score_raw": 2,
  "score_max": 3,
  "delivered_band": "B",
  "rubric_version": null,
  "model_version": "global-2026-07@class-cal-3",
  "privacy_class": "behavioral",
  "payload": {}
}
```

其中 `actor_id` 表示执行动作的人，`target_student_id` 表示证据归属学生。教师评分时二者不同，不能继续把目标学生藏在 JSON 中。

### 5.3 事件目录

| 领域 | 必须记录的事件 | 关键参数 |
| --- | --- | --- |
| 认证 | `auth.login.succeeded/failed`、`auth.logout` | 客户端、会话，不保存明文密码 |
| 学习机会 | `content.assigned`、`content.released`、`content.withdrawn` | 目标班级/层级、起止时间 |
| 学习会话 | `session.entered`、`session.heartbeat`、`session.left` | 前台/空闲状态、有效时长、网络状态 |
| 视频 | `video.played/paused/seeked/progress/completed` | 播放位置、总时长、回看区间 |
| 文档 | `document.opened/progress/completed` | 页码、页数、有效阅读时长 |
| 题目 | `item.exposed/started/answer_changed/submitted/graded` | 知识点、难度、尝试、响应时长、正确性、学生自报把握度 |
| 任务 | `task.started/submitted/resubmitted/reviewed` | 截止时间、版本、附件类型、量规版本 |
| AI 学习网页 | `learning_page.block_viewed/form_changed/form_submitted` | 页面版本、表单和控件 ID，不执行任意埋点代码 |
| 项目 | `project.milestone_changed/log_added/artifact_versioned` | 阶段、角色、计划偏差、成果版本 |
| 协作 | `group.document_edited/file_shared/feedback_submitted` | 小组、贡献类型、版本和反馈对象 |
| 自我调节 | `goal.set/progress_checked/help_requested/reflection_submitted` | 目标、求助对象、反思提示版本 |
| 课堂互动 | `attendance.recorded/quick_answer.responded/random_call.selected` | 签到与抢答机会、响应、教师反馈、激励积分；签到未响应不自动等同缺勤，随机点名选择不等同学生完成 |
| 教师干预 | `intervention.created/acknowledged/resolved` | 类型、原因、目标、强度、后续状态 |
| 支持处方 | `support.recommended/selected/delivered/exposed/used/declined/completed/outcome_recorded` | 处方版本、证据、教师决定、学生使用和近端结果 |
| 评价 | `rubric.rating.submitted/revised` | 自评/互评/师评、量规版本、每项星级 |
| 系统质量 | `client.offline/api.failed/upload.failed` | 错误类别和持续时间，不含敏感内容 |

当前工程首批已实现 `learning_page.opened`、`learning_page.block_viewed` 和 `learning_page.form_submitted`。`block_viewed` 只接收平台生成的区块 ID、类型、可见时长和比例；表单答案保留在业务响应表。`form_changed` 必须在完成离线队列、频率控制和字段级隐私审查后再启用，不能直接采集输入值或键盘轨迹。

系统质量事件必须进入分析数据。否则网络故障造成的“零行为”会被误判为低投入。

### 5.4 核心事件载荷契约 V1

`event_name` 表达业务含义，禁止继续使用一个宽泛类型再依赖 `payload.action` 区分。`payload` 只保存该事件特有且已登记的字段，未经登记的字段不能进入生产特征视图。

| 事件 | V1 必填载荷 | 服务端校验 | 对应机会分母 |
| --- | --- | --- | --- |
| `content.released` | `content_type`、`required`、`available_from/to`、`target_layers` | 内容和目标班级必须属于同一学校 | 生成 `LearningOpportunity` |
| `session.heartbeat` | `foreground`、`idle_seconds`、`network_state` | 相邻心跳间隔大于 120 秒不补算活跃时长 | 已进入的课堂/学习会话 |
| `video.progress` | `position_seconds`、`media_seconds`、`playback_rate` | 位置不超过媒体时长；快进不计为已观看区间 | 已投放视频区间 |
| `document.progress` | `page`、`page_count`、`visible_seconds` | 页数范围合法；后台标签页不累计 | 已投放页数 |
| `item.submitted` | `question_version`、`response_kind`、`attempt_no`、`response_time_ms`、`learner_confidence_rating` | `learner_confidence_rating` 仅表示学生自报把握度；答案正文进入业务答卷表，事件只保存引用和摘要 | 已曝光且允许提交的题目 |
| `item.graded` | `grading_state`、`score_raw/max`、`is_correct`、`grader_type` | 同一次作答只允许一个当前最终评分版本 | 已提交且可评分的题目 |
| `task.submitted` | `submission_version`、`submitted_at`、`due_at`、`artifact_count` | 附件明细保存在任务表，事件不复制文件名和正文 | 已投放任务 |
| `rubric.rating.submitted` | `rubric_version`、`criterion_ratings`、`rater_role` | 每项范围 1-5；评价者与对象关系合法 | 已开启的评价类型与量规项 |
| `intervention.created` | `intervention_type`、`reason_code`、`intensity` | 自由文本不进入研究导出；必须指定目标学生 | 具有干预资格的学生/小组 |
| `client.offline` | `started_at`、`ended_at`、`queued_event_count` | 客户端时长上限检查，恢复后与队列核对 | 同时段已投放机会 |

V1 明确不采集：逐键输入、剪贴板原文、聊天原文特征、任意浏览历史、摄像头、麦克风、精确设备指纹。主观答卷、聊天和作品保留在原业务表中，仅在获得专项批准后通过受控派生任务生成非识别特征。

### 5.5 事件质量状态机

每条事件进入事实层前依次经历 `received -> schema_valid -> context_valid -> deduplicated -> accepted/quarantined`。隔离事件不删除，保存错误码并允许重放。每天至少输出以下质量指标：

- `duplicate_rate`：重复 `event_id` 或幂等键数量/接收数量。
- `late_arrival_rate`：窗口关闭后超过 24 小时才到达的事件/接收数量。
- `context_error_rate`：学校、班级、课程或对象关系不合法的事件/接收数量。
- `offline_gap_minutes`：有学习机会但客户端报告离线或心跳缺失的分钟数。
- `opportunity_coverage`：可关联到明确学习机会的结果事件/全部结果事件。
- `final_grade_coverage`：存在最终评分版本的已提交题目/全部可评分提交。

任一核心数据源 `opportunity_coverage < 0.95` 或 `final_grade_coverage < 0.95` 时，相关特征快照标记为 `degraded`，不得触发自动层级建议；0.95 是 V1 工程闸门，后续根据试点数据修订，不是文献给出的通用阈值。

### 5.6 学习机会与过程片段

事件只有放回教学过程才可解释。`LearningOpportunity` 采用以下状态，不允许从“没有提交事件”反推状态：

```text
assigned -> released -> exposed -> started -> submitted -> graded
                   \-> withdrawn
                   \-> excused
                   \-> unavailable
```

- `assigned/released`：教师或系统确实向该学生投放并开放。
- `exposed`：客户端确认内容入口在可见前台呈现，不等于学生已阅读。
- `started`：发生内容类型定义的首个有效动作。
- `withdrawn`：教师撤回或替换，不进入未完成分母。
- `excused`：请假、转班或教师豁免，不进入未完成分母。
- `unavailable`：设备、网络、文件或服务故障导致不可用，作为技术机会损失处理。

每个任务同时保存过程单位：`session_id`、`step_id`、`lesson_id`、`unit_id` 和 `instructional_phase`。V1 阶段至少支持 `orientation`、`planning`、`execution`、`monitoring`、`revision`、`reflection`，但具体映射由课时设计显式标注，不由点击序列自动猜测。协作任务还必须保存 `group_id`、`artifact_id` 和角色分工版本，使个人、组、作品三个分析单位可区分 [R45, R64, R82]。

### 5.7 会话与时间测量规则

- 客户端心跳只证明页面处于前台且达到技术活跃条件，不能证明注意、认知投入或有效学习。
- 120 秒空闲阈值是 V1 会话切分参数，不是心理学阈值；报告中需对 60/120/300 秒执行敏感性分析。
- 视频观看使用去重后的播放区间，不用 `播放时长 × 倍速` 或页面停留代替。
- 文档只记录可见页区间和前台时段；OnlyOffice iframe 加载成功不等于学生阅读。
- 响应时长从题目真正可交互到最终提交计算，扣除后台、断网和教师暂停区间，并保留左/右删失标志。
- 所有持续时间保留原始区间和派生规则版本，不能只保存一个不可重算的分钟总数。

### 5.8 观察过程与竞争状态

每个分析结局必须能够重建以下流程，而不是只保存“有值/无值”：

```text
target_population
  -> eligible_at_decision_point
  -> opportunity_released
  -> technically_available
  -> exposed/started
  -> outcome_matured
  -> included_in_analysis
```

每一步保存状态、时间、原因和来源。`transferred`、`withdrawn`、`excused`、`long_absence`、`no_opportunity`、`unavailable`、`not_started`、`pending_grade` 和 `lost_event` 不能合并为同一个缺失码。转学、退课和任务撤回是竞争状态，不得变成失败结局。主要研究报告从目标总体到分析样本的完整流图及逐校/群体人数；结果可观察概率极低或缺少重叠时停止个体建议，而不是依靠极端权重补偿。

## 6. 得分与证据分离

不得再用一个可变总分承载所有含义。建议拆成四类事实表：

| 数据 | 用途 | 是否可作为模型特征 | 是否可作为主要预测结局 |
| --- | --- | --- | --- |
| `AssessmentOutcome` | 题目、测试和知识点成绩，保存原始分与满分 | 是，需按时间截断 | 计划内且可比时可作为未来掌握/成长结局 |
| `RubricRating` | 自评、互评、师评的逐项 1-5 级结果 | 是，需保留评价者和量规版本 | 经验证后可作为表现性结果 |
| `ParticipationPointLedger` | 抢答、点名、聊天等奖惩的不可变流水 | V1 主内容带模型禁用；只作课堂反馈、实施和敏感性审计 | 否 |
| `MasteryEstimate` | IRT/BKT 或预测模型输出 | 可作为下游策略输入 | 否，它本身是模型估计 |

`StudentProfile.score` 在迁移期仅作为课堂积分缓存，真实来源必须是不可变流水；重算结果应一致。所有成绩进入模型前统一保留 `raw_score`、`max_score`、题目难度、知识点、评分者和评分时间。

积分和奖章只承担课堂反馈与正向激励，不形成能力、品格或核心素养标签。学生可以查看自己的积分、来源流水和可核验证据奖章，但默认不提供班级/年级排行榜。奖章规则必须版本化并引用实际投放机会、任务或评价证据；“A 层达人”“低水平进步”“计算思维大师”等暴露内容带或超出证据范围的名称禁止使用。积分、奖章及其衍生字段均排除在 V1 主内容带模型之外，详细产品规则见 [学生评价、积分与奖章设计](student_evaluation_incentive_design.md)。

A/B/C 专属题允许使用不同课堂分值激励，但这些分值不自动具有跨层可比性。若各层题目不相同，原始得分率只能解释为“在实际投放题目上的表现”；内容带判断必须依赖共同锚题、经校准题目参数或独立共同测量。没有链接证据时，禁止把 A 层高难题低分与 C 层基础题高分直接排序，也禁止通过给某层设置更高分值制造掌握差异。

## 7. 特征工程

### 7.1 时间窗

每晚生成日、近 7 日、近 30 日和学期累计快照，但时间窗聚合只是一个视角。还需按当前环节、课时、任务阶段和教学单元生成过程快照；协作任务按个人、组和共同作品分别生成。所有特征只能使用预测时点之前的数据。建议同时保存：

- 绝对值：有效学习分钟、完成数量。
- 比率：完成数/已投放数、正确数/有效作答数。
- 变化：本周与前一周的差异、移动斜率。
- 稳定性：日间方差、连续中断天数。
- 同生基线：相对学生个人历史的标准化变化。
- 班级校准：只用于解释上下文，不替代标准参照。

不同窗口不直接拼成“越多越好”的特征集合。教学支持优先使用与决策周期匹配的窗口：课堂控制读取环节/课时，周度支持读取 7 日，单元分层读取单元与 30 日。学期累计用于档案，不用于掩盖近期变化。

### 7.2 V1 候选特征注册表

下表是首轮回顾性研究的冻结候选集，不是 22 个已经有效的“能力指标”。`min_n` 不足时返回空值及原因，不以 0 替代。运营快照按其 `as_of` 向前计算；正式研究只抽取预注册 `DecisionPoint(T0)` 对应的冻结快照。所有题目得分均使用 `T0` 前当时已完成的最终评分版本。

| 证据组 | 特征 | V1 用途 |
| --- | --- | --- |
| E1 直接行为指标 | `opp_completion_rate`、`on_time_submission_rate`、`active_minutes`、`active_days_ratio`、`resource_completion_rate`、`first_attempt_score_ratio`、`first_attempt_accuracy` | 描述和预测基线；仍不能单独命名为投入或能力 |
| E2 理论映射代理 | `retry_gain_ratio`、`response_time_median_z`、`answer_revision_rate`、`challenge_persistence_rate`、`help_request_rate`、`help_latency_minutes`、`reflection_completion_rate` | 只作研究候选和增量效度分析，界面明确标注“代理” |
| E3 前置测量派生 | `rubric_teacher_mean`、`self_teacher_gap_abs`、`peer_feedback_quality`、`collab_contribution_rate` | 仅在量规/贡献定义通过相应验证后启用；不得跨版本混合 |
| C 情境和质量审计 | `intervention_count`、`post_intervention_change`、`offline_opportunity_rate`、`event_quality_flag_rate` | V1 不进入主层级模型；用于分层评估、数据质量、不确定性/资格判定和后续因果分析，不得据此惩罚或降低层级 |

| 特征 ID | 计算定义 | 窗口 | `min_n` | 缺失语义/限制 |
| --- | --- | --- | ---: | --- |
| `opp_completion_rate` | 已完成必做机会数/已到期必做机会数 | 7/30 日 | 3 个机会 | 无已到期机会=`NO_OPPORTUNITY` |
| `on_time_submission_rate` | 截止前最终提交的任务数/已到期任务数 | 30 日 | 3 个任务 | 无截止任务=`NO_OPPORTUNITY` |
| `active_minutes` | 合并心跳区间后前台且空闲不超过会话规则阈值的分钟数 | 环节/课时/7/30 日 | 0 | E1 技术活动量；60/120/300 秒敏感性分析，不解释为注意或认知投入 |
| `active_days_ratio` | 至少存在 5 分钟有效活动的天数/存在学习机会的天数 | 7/30 日 | 3 天 | 无机会天=`NO_OPPORTUNITY` |
| `resource_completion_rate` | 达到资源完成规则的资源数/已投放必看资源数 | 7/30 日 | 3 个资源 | 不用打开次数代替完成 |
| `first_attempt_score_ratio` | 首次最终评分 `sum(score_raw)/sum(score_max)` | 14/30 日 | 5 题 | 只含可评分且 `score_max>0` 的题 |
| `first_attempt_accuracy` | 首次作答正确题数/有明确正确答案的首次作答题数 | 14/30 日 | 5 题 | 主观题不进入分母 |
| `retry_gain_ratio` | 重试最终得分率减首次得分率的机会加权均值 | 30 日 | 3 个重试题 | 未允许重试=`NO_OPPORTUNITY` |
| `response_time_median_z` | 按题目版本、交互方式和有效作答区间在训练折内标准化后的响应时长中位数 | 单元/30 日 | 5 题 | 保留删失和异常标志；不直接判定能力或努力 |
| `answer_revision_rate` | 提交前发生有效答案修改的题数/已提交题数 | 30 日 | 5 题 | 仅表示策略行为，不预设正负方向 |
| `challenge_persistence_rate` | 难题开始后完成提交数/已开始难题数 | 30 日 | 3 个难题 | 难题定义绑定题目难度版本 |
| `help_request_rate` | 主动求助数/已验证的可求助挑战片段数 | 单元/30 日 | 3 个片段 | 挑战片段定义未通过轨迹效度研究时保持 E2 且不进生产模型 |
| `help_latency_minutes` | 可求助挑战片段开始到首次有效求助的分钟数中位数 | 单元/30 日 | 3 次 | 未提供求助渠道=`NO_OPPORTUNITY`；方向不预设 |
| `reflection_completion_rate` | 已提交反思数/已要求反思数 | 30 日 | 3 次 | 只反映完成，不自动代表反思质量 |
| `rubric_teacher_mean` | 师评量规逐项均值，按量规版本分别计算 | 30 日 | 2 次评价 | 不跨未验证量规版本直接合并 |
| `self_teacher_gap_abs` | 同一任务、同量规版本的自评与师评逐项绝对差均值 | 单元/30 日 | 2 对评价 | 仅用于反思和测量研究，不进入风险或层级模型 |
| `peer_feedback_quality` | 经已验证反馈量规评分的具体性、可执行性和证据性 | 单元/30 日 | 3 条 | 未开展互评=`NO_OPPORTUNITY`；自动文本评分不得直接替代人工验证 |
| `collab_contribution_rate` | 按已公布角色和贡献机会校正的有效贡献率，分别报告个人、组和作品证据 | 单元/30 日 | 1 个小组任务 | 不以聊天/编辑次数或占全组比例直接表示贡献质量 |
| `intervention_count` | 教师支持事件数，按类型和强度分别统计 | 7/30 日 | 0 | 时间变化的教学条件；V1 只用于审计和分层分析 |
| `post_intervention_change` | 干预前后同口径结果的描述性变化 | 30 日 | 1 次可匹配干预 | 后处理变量；不进入主预测模型，不作因果效果 |
| `offline_opportunity_rate` | 离线覆盖的机会时长/全部机会时长 | 7/30 日 | 1 个机会 | 只作质量/公平审计和预测资格控制，不作学生风险特征 |
| `event_quality_flag_rate` | 隔离、迟到或异常事件数/该生全部事件数 | 7/30 日 | 1 条事件 | 只降低数据可信度，不改变学业或支持判断方向 |

特征方向不由名称预设。例如答案修改可能代表反思，也可能代表猜测；只有在任务类型、先验成绩和结果联合验证后，才能解释其含义 [R42-R45, R50, R71-R72]。

不能直接使用的高风险特征包括姓名、账号、学校真实名称、家庭背景代理变量和未经同意的敏感属性。受保护属性如性别若依法合规收集，只应用于公平性审计，默认不进入生产预测。

### 7.3 缺失值语义

必须区分：未投放、已投放未开始、开始未提交、设备离线、数据丢失、确实为零。把所有情况填成 0 会制造系统性偏差。每个关键特征都需要值、机会分母和缺失原因。

统一缺失代码为：`NO_OPPORTUNITY`、`NOT_STARTED`、`IN_PROGRESS`、`OFFLINE`、`DATA_ERROR`、`INSUFFICIENT_N` 和 `NOT_APPLICABLE`。研究特征视图保留“数值 + 缺失原因 + 机会分母”；生产模型只使用特征定义明确允许的缺失信息，禁止在导出前把所有缺失统一均值填补。

### 7.4 特征版本与防泄漏

每个 `FeatureDefinition` 固定证据等级、分析单位、公式、允许事件、窗口、最少观测量、截尾规则、已知竞争解释、允许用途、公平风险和版本。生成两种明确分离的快照视图：

- `operational_available`：只读 `client_occurred_at <= as_of` 且 `server_received_at <= as_of` 的事件，作为训练、外部验证和生产推理的主视图，复现系统在 `T0` 真正掌握的信息。
- `reconstructed_complete`：可在预注册 `allowed_lateness` 内补入业务发生于 `T0` 前的迟到事件，只用于数据质量、迟到敏感性和事后描述，不得替代主视图报告部署性能。

两种视图均保存 `as_of`、数据水位和视图类型。以下字段不能作为预测输入：预测窗口内结果、教师看到模型建议后产生的操作、最终层级确认、未来截止状态和由对应预测结局直接计算出的聚合值。

### 7.5 序列和阶段特征路线

V1 生产模型先使用可审计聚合特征；序列特征作为独立研究模块，不因技术上可计算就自动加入模型。升级顺序为：

1. 验证过程边界和事件顺序完整性，明确客户端离线补传和并发标签页的排序规则。
2. 先报告阶段转移、重访、停滞、求助前后和修改路径等描述性序列，不赋予 SRL 名称。
3. 将预注册轨迹模式与课堂观察、刺激回忆或学习日志对齐，报告覆盖率和误判。
4. 再比较过程挖掘、转移矩阵、序列/网络分析是否相对聚合特征产生稳定增量效度。
5. 只有在跨任务和跨课堂复验后，才将稳定模式加入生产特征集。

频次增加、过程序列改变和学习结果改善是三个不同命题。个性化支架可能改变活动频次但不改善学习结果，故模型和论文必须分别检验 [R40]。多通道或更细粒度数据也不天然更有效，数据流的时间对齐、分析单位、教学情境和参与者解释同样重要 [R45, R64, R71, R76, R81]。

### 7.6 特征块与增量效度

不得默认把 22 个候选特征一次性投入模型。所有目标按以下嵌套特征块比较，并使用完全相同的数据折：

| 特征块 | 内容 | 回答的问题 |
| --- | --- | --- |
| F0 | 机会结构、预测时点、学科/任务版本和训练折内历史结果基线 | 不看行为时能预测到什么程度？ |
| F1 | F0 + E1 直接行为指标 | 低推断风险行为事实是否有稳定增量？ |
| F2 | F1 + E2 理论代理 | 未完全验证的轨迹代理是否提供跨时间/班级增量？ |
| F3 | F1 + 已验证 E3 测量派生 | 量规/测量是否在不泄漏标签时提供增量？ |
| F4 审计 | 分别加入教学干预、离线和质量变量 | 性能是否依赖不宜用于决策的情境代理？ |

生产候选最多使用 F0-F3。若 F2/F3 只在随机切分有效、在时间或学校外验证失效，则不进入生产。F4 只做敏感性和公平审计；如果加入 F4 后性能显著变化，应调查教学条件或数据质量偏差，而不是直接采用更高的表面性能 [R50, R60]。

### 7.7 预处理和重复测量规则

- 所有标准化、截尾、缺失插补、类别编码、特征筛选和校准参数只在训练折拟合，再应用到验证/测试折。
- 按题目版本标准化的响应时长不得使用测试折均值；类别目标编码必须使用训练折内交叉拟合。
- 右偏计数优先比较 `log1p`、分位数截尾和原值，选择规则在嵌套验证内完成；不因数值异常自动删除学生。
- 同一学生的日快照高度相关。训练/测试按学生和时间分组，并对学生-预测周期设置权重，避免活跃学生贡献几十倍样本。
- 置信区间使用学生或班级层级 bootstrap，不把快照行当作独立样本。
- 特征选择报告跨时间折入选稳定性、相关结构和方向变化；方向在班级/学科间反转时，不给出统一行为解释。
- 表中 `min_n` 是计算稳定性的暂定门槛，需对门槛和窗口做敏感性分析，不作为科学常数。

### 7.8 缺失与公平处理

缺失指示本身可能携带设备、网络、请假和资源可用性信息。V1 主层级模型不使用 `OFFLINE`、`DATA_ERROR` 或 `unavailable` 作为学生风险证据；这些状态触发数据不足或人工核查。对其他缺失码，分别比较完全案例、带原因模型和多重插补的结果，并报告各群体缺失机制。任何因加入缺失指示而获得的性能增益都需要代理偏差审计，不能仅凭准确率保留 [R56-R60]。

### 7.9 因果角色注册

预测不要求所有输入都是原因，但必须知道变量在数据生成过程中的位置，防止把处理结果、碰撞变量或数据质量代理当作学生特征。每个 `FeatureDefinition` 增加 `causal_role`：

| 角色 | 例子 | V1 主模型规则 |
| --- | --- | --- |
| `baseline_state` | `T0` 前共同锚测、既往任务结果 | 可用，严格按时间截断并保留测量误差 |
| `instructional_opportunity` | 已投放任务、难度、开放时段、允许支持 | 必须用于定义分母和当前政策情境，不解释为学生属性 |
| `behavior_evidence` | 完成、修改、求助、资源使用 | E1 可用；E2 需增量效度和代理偏差审查 |
| `treatment` | 教师干预、模型支持处方、差异化投放 | V1 主内容带模型排除；用于审计或专门因果模型 |
| `post_treatment` | 干预后变化、是否采纳建议 | 禁止用于预测该次干预前本应作出的决定 |
| `outcome` | 未来锚测、未来完成/逾期、后续量规结果 | 只能作为结局，不得进入对应输入窗口 |
| `data_quality` | 离线、错误、迟到、缺失原因 | 只控制不确定性、资格和审计，不作为降层证据 |
| `protected_audit` | 合法收集的性别、特殊支持需求等 | 不进入 V1 决策模型，仅在授权环境中做公平审计 |

每个预测目标都维护简化因果图和时间图，至少包含学生既往状态、教师/课程、学习机会、行为、支持处理、技术可用性和结局。模型上一轮建议会影响支持、行为和下一轮数据，因此 `prior_model_version` 和实际处方必须进入审计事实，不能被当作自然发生的学生轨迹 [R50, R60]。

### 7.10 特征稳定性与跨校可迁移性

一个特征进入生产前同时满足语义、计算和关系稳定性：

1. 语义稳定：各学校客户端、课时设计和教师操作对事件含义一致；否则拆成不同特征版本。
2. 计算稳定：在事件重放、迟到数据和窗口敏感性下结果可重算，数值变化在预注册容差内。
3. 测量稳定：若声称 E2/E3，跨任务/学校的证据映射和类别功能可接受。
4. 预测稳定：在时间、班级、学校外折中方向、增量性能和校准贡献不发生无法解释的反转。

跨校迁移报告：特征可用率和缺失原因、分布差异、课程/教师分层分布、训练学校与目标学校可区分程度、逐校模型性能以及校准迁移。若一个域分类器仅靠特征就能轻易识别学校，说明模型可能依赖学校特有实施，需限制适用范围或重新定义特征。

禁止按当前班级排名、班内百分位或班级均值中心化后把结果解释为绝对准备度；这些相对量会随同伴构成变化并强制产生差异。班级统计只用于上下文/校准，准则参照判断使用共同测量和绝对机会事实。课程版本、事件版本或教学政策变化均触发特征兼容审查，不因字段名相同自动沿用模型。

### 7.11 个体内与个体间纵向特征

行为变化模型不得把学生间关系解释为学生自身变化。对时间变化特征 `x_it`，研究视图至少区分：

- `between_student_baseline`：只使用 `T0` 前历史得到的学生基线，表示稳定的既往差异。
- `within_student_deviation`：当前窗口相对该历史基线的偏离，回答该生此时是否不同于自己平时。
- `within_class_context`：班级/教师在该时点共同变化，只用于情境和多层估计，不作学生能力。

个人均值、斜率和标准化参数不能读取 `T0` 之后数据。纵向解释使用适合结局的多层模型、随机斜率或预注册非线性时间函数，并报告学生/班级聚类区间。每个行为分别检查学生间方向与学生内方向；二者相反或不稳定时，不发布统一的“行为越多越好/越差”解释 [R99]。

## 8. 过程性评价量规设计

### 8.1 证据中心测量链

任何前测、共同锚测、表现任务或量规都先定义“主张-证据-任务-评分”，不能从平台已有字段反推构念：

```text
Claim：希望对学生在特定学科和任务中的什么能力作出有限主张？
  -> Evidence：什么可观察成果/过程会支持或反驳该主张？
  -> Task：什么任务特征能公平地引出这些证据？
  -> Scoring：如何把证据映射为有不确定性的结果？
  -> Use：该结果只用于反馈、内容投放，还是研究标签？
```

每个 `AssessmentBlueprintVersion` 至少保存：目标总体、课程目标、主张、证据规则、任务规格、内容覆盖、认知复杂度、允许支持、评分模型、可比版本、预期用途和验证状态。行为轨迹也必须绑定证据规则；“点击了计划按钮”只能证明发生点击，除非验证链支持，否则不能直接证明学生进行了有效计划 [R42]。

量规按用途分级：

| 类型 | 教师自由度 | 可否作为跨班/跨校训练结局 | 必要条件 |
| --- | --- | --- | --- |
| `local_formative` | 可按课时目标创建和修改新版本 | 否，默认只用于当前任务反馈 | 任务化锚点、证据引用、版本和学生可理解性 |
| `school_common` | 学科组共同维护 | 经校内验证后可用于校内研究 | 共同蓝图、评分培训、任务/评分者误差和版本链接 |
| `research_linked` | 研究期间冻结 | 可以，在声明适用范围内 | 跨校共同任务/锚项、完整效度证据、可比性和不确定性 |

平台中教师自行生成的五星评价默认为 `local_formative`。AI 生成量规不会自动升级用途；只有经过规定验证的新版本才可成为 `school_common` 或 `research_linked`。

### 8.2 模块化量规蓝图

V0 采用任务级分析性量规，每项 1-5 级，与现有五颗星交互兼容。量规不是一张对所有课程、任务和学生都适用的通用人格量表；教师只选择该任务实际提供观察机会的模块。

| 模块 | 测量对象 | 启用条件 | 典型证据 | 不得混入 |
| --- | --- | --- | --- | --- |
| P 成果/任务质量 | 当前作品或复杂任务达到具体标准的程度 | 任务有可观察成果和明确标准 | 答案、作品、演示、代码、报告 | 登录、在线时长、课堂积分 |
| S 策略质量 | 完成当前任务时选择、解释和修订方法的质量 | 任务要求展示过程或理由 | 草稿、版本差异、解释、方案比较 | 仅凭最终成绩反推策略 |
| R 调节过程 | 在该任务中计划、监控、求助、调整和反思 | 平台显式提供并记录这些机会 | 计划表、进度检查、求助、调整说明、反思 | 一般出勤、服从性、教师整体印象 |
| C 协作与反馈 | 对共同任务的贡献、协调和反馈质量 | 真实小组任务且角色/贡献机会明确 | 分工、共同作品版本、反馈及采纳证据 | 聊天条数、编辑次数、组内人气 |
| D 学科实践 | 学科目标要求的思维和实践质量 | 由学科与任务蓝图定义 | 如计算思维、论证、实验、建模、创作 | 跨学科直接套用同一描述 |
| E 伦理与责任实践 | 与当前任务直接相关的安全、版权、信息判断和社会责任 | 任务确实产生相关决策证据 | 来源说明、隐私处理、版权和影响分析 | 泛化为学生长期品德标签 |

出勤、按时率、完成率和持续性属于 E0/E1 行为事实，不进入量规维度。它们可作为教师理解任务情境的旁证，但不能与成果或调节质量相加成“综合素养”。

量规效应不能被过度解释。现有元分析对学业表现显示总体正向作用，但对 SRL 的汇总效应较小且不确定性较大，不能因为学生使用了量规就认定其 SRL 已被有效测量或改善 [R16]。

### 8.3 自评、互评与师评

- 三类评价保留原始结果，不先求平均后覆盖。
- 评价者、评价对象、课堂、小组、量规版本和修改历史必须保留。
- 同一构念只有在不同评价者都能看到相同关键证据时才共用条目；证据可见性不同则建立角色版本，不能假设三方在测同一件事。
- 学生在正式互评前需要使用锚定样例进行练习和校准；互评分配避免只由好友或同组成员互相评分。
- 互评先分析评分者严厉度、异常分歧、有效评价数和偏差，再决定是否形成辅助结果；AI 可标记需要教师抽查的高分歧案例，但不自动裁决 [R53, R55]。
- 自评与师评差异本身可用于反思支持，但不能简单判定学生“不诚实”。
- AI 可以根据课时目标起草评价项、反馈问题和候选锚点，发布前必须由教师逐项确认并绑定量规版本；自动生成内容不得继承“已验证”状态 [R54-R55]。
- 形成性评价必须产生下一步行动，如修订、补充证据、同伴讨论或教师反馈；只有星级而没有可执行反馈，不构成完整形成性闭环。

### 8.4 测量权重与预测权重分离

此前“AI 在基准上下 20% 动态调整量规权重”的设想不保留。该规则没有可靠测量依据，会使同一星级在不同时期含义变化，并把提高预测性能误当成提高测量效度。

1. 量规构念、条目、锚点和计分规则由任务蓝图与测量验证确定，在一个正式研究周期内冻结。
2. 预测模型可以学习各个已冻结证据对未来结果的预测系数，但这些系数属于 `model_version`，不得回写为量规权重。
3. AI 只能在研究周期结束后提出“候选量规修订”，由专家审查、认知访谈和新一轮试评后形成新版本。
4. 新旧量规如果需要纵向比较，必须保留共同锚项并完成链接/等值研究；不能直接比较平均星级。
5. 探索性模型发现某条目预测力弱，不等于该条目没有教育价值；删除或改权必须回到构念和内容代表性判断。

这样可以让模型随数据更新，同时保持过程性评价的测量含义可解释、可复现。

### 8.5 量规验证

验证围绕量规的具体用途收集证据，不以单个信度系数宣布“量规有效”：

1. 内容代表性：任务蓝图覆盖哪些目标、哪些未覆盖，专家是否同意每个条目的相关性和锚点顺序。
2. 反应过程：教师、学生和同伴如何理解描述、查找证据并形成星级，是否存在与预期不同的评分策略。
3. 评分结构：条目是否支持预期维度；分析性量规的多个异质维度不要求人为追求高内部一致性。
4. 评分可重复性：学生、任务、评分者、时点和条目分别贡献多少误差。
5. 外部关系：与独立锚测、后续任务和其他测量的关系是否符合预注册假设，而非只寻找显著相关。
6. 使用后果：量规是否改善反馈和修订，是否增加教师负担、诱发迎合评分或对某些群体不利。
7. 泛化边界：未经链接和不变性证据，不跨任务、学科、年级、学校或量规版本比较平均星级 [R38]。

### 8.6 任务级条目规格

五颗星只是交互形式，每颗星旁必须有该任务的行为/成果锚点。下面的层级骨架只能帮助教师起草，不能直接作为所有任务的正式条目：

| 层级 | 起草骨架 | 必须任务化的问题 |
| --- | --- | --- |
| 1 星 | 关键标准尚未达到，现有证据不足以支持基本完成 | 哪个具体标准未达到？什么证据可观察？ |
| 2 星 | 部分达到，在直接示范或持续支持下形成不完整证据 | 允许的支持是什么？“部分”对应哪些要素？ |
| 3 星 | 独立达到任务蓝图中的核心标准 | 哪些核心要素必须全部出现？允许什么非关键错误？ |
| 4 星 | 超过核心标准，能解释、修订或在近迁移中应用 | 何种解释/修订构成可验证证据？ |
| 5 星 | 在新情境中稳定迁移、整合或创造，并能提供充分依据 | 新情境和“充分依据”如何界定？ |

每个正式 `RubricCriterion` 必须包含：模块、学科目标、任务版本、评价对象、证据来源、五个完整锚点、不可观察条件、允许支持、反例和两份以上锚定样例。若某项没有观察机会，记录 `NOT_ASSESSED`，不能按 0 或 1 星计。

评分界面同时显示“锚点文字、证据引用、星级”。教师不能只看到一排星星；至少选择一个证据引用，如答卷、作品版本、协作贡献、课堂观察或学习日志。极端评分和修改评分需要简短说明，但该要求本身也应在可用性研究中检查是否造成机械填写。

V1 计算规则：

- 每个维度保留 1-5 的序数值，不默认把相邻星级差解释为等距。
- 首轮研究主要报告任务内条目和模块分布，不把不同模块直接相加成“综合能力总分”。
- 只有任务蓝图和测量模型支持时才生成模块分数；跨任务纵向分数需要共同锚项或适当的多面测量模型，历史原始星级不变。
- 自评、互评和师评分别建模。互评采用评分者严厉度和有效评价数量校正前，仅作为辅助证据 [R53, R55]。
- AI 可起草任务化描述和证据提示，不可替教师自动产生最终星级 [R51, R54, R61-R62]。

### 8.7 量规验证协议与通过门槛

首轮试点采用以下预注册流程，数值是 V1 试点筛查规则，不是普遍心理测量定律：

1. 蓝图和专家审查：建议 6-8 名学科、评价和学习科学专家先检查目标覆盖，再独立评价相关性、清晰度和锚点顺序。`I-CVI`/`S-CVI` 作为描述性筛查，不能替代内容缺口讨论 [R36]。
2. 认知访谈：在每个目标年级邀请学生和教师完成“读锚点-找证据-给评分”的出声/回顾任务，样本持续到主要误解不再新增，而不是机械满足固定人数。
3. 样例库与培训：使用覆盖五级表现的作品进行评分、讨论和再评分，培训材料和教师达到校准要求的过程必须保存。
4. 盲评试点：跨多个任务抽取不同质量水平作品，由至少两名评分者独立评分；样本量按所需置信区间精度和方差分解设计，50 份只能作为早期可行性场景。
5. 一致性：序数条目报告加权 Kappa；连续/汇总结果在设计适用时报告 ICC 的模型、单次/平均测量、绝对一致/一致性类型及 95% CI [R39]。
6. 多面误差：若量规要跨任务、评分者和时间形成训练结局，优先使用概化理论或多面 Rasch 模型区分学生、任务、评分者严厉度及交互误差。
7. 内部结构：只有声称同一反映性构念的条目才检验有序 CFA 和 omega；分析性、形成性或刻意多维模块不以高 alpha/omega 为目标 [R37]。
8. 采用门槛：作为训练结局的评分，V1 暂以一致性点估计不低于 0.75 且 95% CI 下限不低于 0.60 为试点目标，并通过结局测量误差模拟检查结论稳健性；未达到时只用于形成性反馈，不作为主要结局。
9. 跨群体与后果：检验学校、年级、学科、时间和内容投放带的可比性、差异项功能、评分机会和负担；不满足时限制解释范围，不强行统一计分 [R38]。
10. 外部关系：只与独立锚测或之后的表现任务比较，避免同一教师同一次评分自证有效；教师整体判断与量规评分的关系只作偏差分析 [R79]。

### 8.8 类别功能、链接与测量误差

- 五星界面不保证五个类别在数据中可区分。检查类别使用率、阈值顺序、评分者混淆和每级锚定样例；若相邻级长期不可区分，研究分析可预注册合并类别，但原始评分保留且正式改版需新版本。
- `local_formative` 结果不得通过简单标准化混入跨校训练。只有 `research_linked` 或在声明范围内可链接的 `school_common` 结果可生成模型结局。
- 题目 IRT/知识追踪能力估计保存标准误或后验分布；量规多面模型保存学生估计及测量误差，不把估计点当作无误差真值。
- 预测研究对主要结果至少执行测量误差/结局误分类敏感性分析；条件允许时使用多重 plausible values 或概率结局传播不确定性。
- 共同锚项的内容、位置和曝光需受控；锚项泄露、反复练习或差异化投放会破坏链接，必须在数据中标记。

### 8.9 题库、AI 生成题与测验安全

题目是测量工具的一部分，不是生成后即可直接成为训练数据。`ItemVersion` 生命周期固定为：

```text
draft -> expert_reviewed -> pilot -> calibrated -> active
                                      \-> drift_watch -> retired/compromised
```

- AI 生成题保存模型提供商、模型名、提示模板版本、生成参数、教师输入方向、原始输出、人工修改和审查人；默认状态只能是 `draft`。
- 专家确认正确答案和课程对齐后可用于低风险形成性练习，但进入共同测量前仍需试测、项目分析、局部依赖、DIF、难度和链接验证 [R91-R93]。
- 同一提示批量生成的题按题族管理，防止语言模板造成局部依赖和模型识别来源而非掌握。
- AI 题未达到 `calibrated/active` 前，不得作为共同锚题、主要研究结局、IRT/BKT 校准基准或跨校分层依据。
- 题库保存曝光次数、位置、层级、答案泄露、参数漂移和课程改版。泄露或漂移只影响新链接，历史题目/结果版本不覆盖 [R90]。
- 按学校、年级、合法审计群体、设备模式和内容投放带检查 DIF 与差异机会；样本不足报告区间并限制用途，不以“不显著”宣称公平。

A/B/C 专属题可以服务差异化教学，但每个研究周期保留不随内容带变化的低负担共同锚测。班级校准器不能替代题目等值。

## 9. 预测目标与计划结局

动态分层不是一个单一三分类问题。先预测分开的可观察结果，再由教学策略生成完成支持信号、支持处方和 A/B/C：

1. `future_mastery`：下一次计划内共同测量的标准化掌握度及达标概率。
2. `future_required_completion`：未来窗口已到期必做机会的完成分子/分母。
3. `future_overdue_count`：未来窗口新增逾期任务数。
4. `growth_trajectory`：在个人基线和学习机会校正后的成长趋势。

`completion_support_signal` 不再作为一个把“完成率低”和“逾期多”混合起来训练的标签，而是由上述两个结果的预测分布和预注册策略规则派生。这样保留原始结果含义，也便于分别检查误判原因。

主要结局证据优先级：

| 优先级 | 结局证据 | 说明 |
| --- | --- | --- |
| 1 | 下一周期锚题/后测的标准化掌握或增益 | 最接近教学准备度，需保证可比性 |
| 2 | 经验证的表现性任务量规结果 | 适合项目与复杂能力 |
| 3 | 未来完成分子/分母和逾期数量 | 作为完成支持证据，需排除设备、缺席和未投放原因 |
| 4 | 教师确认层级 | 作为弱监督和接受度数据，不作唯一真值；教师判断本身也可能受师生特征影响 [R79] |
| 禁止 | 课堂总积分 | 教师依赖、机会不均且混合奖惩含义 |

所有预测结局必须使用预测时点之后的结果，防止结局泄漏。模型输入还必须记录当时实际投放的题目层级、资源难度和教师干预；分层本身会改变学生后续看到的内容，如果忽略这一点会形成干预反馈循环。

### 9.1 V1 结局合同

研究预测时点不等于每晚任务运行时点。每个学科预先注册 `DecisionPoint`，例如每周固定时点、单元开始或共同任务发布前；记索引时点为 `T0`。夜间系统可以滚动更新运营建议，但正式模型评价只使用冻结的 `T0`，避免同一学生连续 14 个夜晚被当作 14 个独立预测样本。

每个结局保存 `outcome_definition_version`、`decision_point_id`、观察窗口、资格判定、原始证据和最终状态。没有足够结果时是 `UNOBSERVED`，不能作为负例。

| 结局 ID | 预测窗口与计算 | 资格条件 | 排除/单独标记 |
| --- | --- | --- | --- |
| `mastery_next_planned_assessment` | `T0` 后预先指定的共同锚测得分率；有题目校准后转为能力估计 | 至少 8 道有效题、覆盖至少 2 个目标，其中至少 3 道共同锚题 | 未参加、版本不等价、评分未完成分别记录，不搜索窗口内“第一份有分数试卷”替代 |
| `mastery_threshold_next_assessment` | 依据该测量工具预先审定标准将连续掌握结果二分 | 同上 | 0.70 只可作为待审课程规则，不因模型效果选择阈值 |
| `required_completion_next_7d` | `(T0,T0+7d]` 内 `completed_required / eligible_due_required`，同时保存二项分子和分母 | 至少 3 个有效已到期机会 | 请假、不可用、撤回、转班从资格分母剔除并逐类报告 |
| `new_overdue_count_next_7d` | `(T0,T0+7d]` 新增逾期必做任务数量 | 至少 1 个有截止时间的有效机会 | 没有截止任务=`NO_OPPORTUNITY`，不是 0 风险 |
| `rubric_performance_next_planned_task` | `T0` 后预先指定共同表现任务的已验证模块向量 | 使用可链接量规版本且评分状态最终 | 不在窗口中事后挑选最早或最高分作品 |
| `growth_anchor_next_cycle` | 后一计划锚测能力估计减 `T0` 前指定可比锚测能力估计 | 前后有足够共同锚题且链接模型适用 | 直接使用两份难度不同试卷的原始分差被禁止 |
完成支持信号可在策略层暂定义为 `P(required_completion<0.50 OR new_overdue_count>=2)`，但 0.50/2 次必须由任务负荷、教师可干预容量和误判成本审定。它不是新的测量构念，也不覆盖两个原始预测结果。

教师确认的 `teacher_content_band` 单独保存为 `TeacherDecisionObservation`，记录确认时间、理由、当时是否已看模型建议及可见证据版本。它只用于弱监督、接受度、人机一致性和偏差分析，不属于学生未来结局，也不作唯一金标准。展示模型后的教师决定不得反过来作为同一模型的独立验证标签。

### 9.2 决策反馈循环控制

学生进入 A/B/C 后获得的任务不同，后续结果同时受到学生状态和教学干预影响。V1 数据必须保存 `delivered_band`、题目版本、难度、支架、教师干预和实际学习机会。回顾性预测阶段先回答“在现有教学政策下能否预测结果”；效果研究再用簇随机或阶梯楔形设计回答“动态分层是否造成改进”。二者不能混写为因果结论。

### 9.3 预测问题与估计量

每个模型在训练前必须完成以下规格，缺一项不得开始比较算法：

| 项目 | V1 规格 |
| --- | --- |
| 目标总体 | 指定学校、年级、学科、教学单元以及在 `T0` 具有相应学习机会的全部学生 |
| 预测单位 | 学生 × 学科 × 计划决策点，而不是事件行或任意夜间快照 |
| 索引时点 | 教师尚未看到本轮模型建议且结局窗口尚未开始的 `T0` |
| 输入窗口 | 相对 `T0` 冻结的历史窗口和任务阶段 |
| 结局 | 预先指定共同测量、完成分子/分母、逾期计数或任务级量规模块 |
| 预测估计量 | 当前教学政策下 `E[Y given X, policy=current]` 或 `P(Y given X, policy=current)` |
| 因果估计量 | 某支持相对另一支持的平均处理效应/条件效应；只能由相应实验或可识别设计估计 |
| 使用者和动作 | 任课教师在限定时间内选择内容投放带和支持处方 |

预测模型回答“在当前政策延续时可能发生什么”，不回答“给这个支持会改善多少”。SHAP、特征重要性和教师解释也不能把预测关联改写成原因 [R24, R31, R50]。

### 9.4 Landmark 预测与结局观察过程

每个正式预测样本是预注册 landmark `T0`，并明确预测跨度、成熟日期和竞争状态。同一学生可在不同计划决策点贡献样本，但需满足冷却/间隔规则并在推断中处理重复相关；任意夜间运行不会自动新增研究样本。

- 固定窗口结果保存资格分子/分母；没有机会不是 0。
- 若研究问题是“首次逾期时间”“退出课程时间”等时间结局，使用离散时间风险或适当生存/多状态模型，不把每晚未发生复制成独立负例。
- 转学、撤回、长期请假和技术不可用按预注册竞争事件、删失或不可观察状态处理，并报告不同处理假设的敏感性。
- 模型训练与生产推理使用 `operational_available`；事后补传数据只能进入独立的重建分析。
- 观察过程模型、插补和加权只在其假设可辩护时使用；MNAR 通过 delta/模式混合等敏感性呈现，不能声称被数据本身识别。

## 10. AI 动态分层模型

### 10.1 模型比较路线

| 阶段 | 模型 | 作用 |
| --- | --- | --- |
| V0 | 透明规则与量规基线 | 验证数据闭环，建立可解释对照 |
| V1 | 序数 Logistic / Elastic Net | 稳健、易解释的统计基线 |
| V1b | 多层/混合效应序数模型 | 显式处理学生嵌套班级和学校 |
| V2 | CatBoost 或 LightGBM | 处理中等规模表格数据、缺失和非线性交互 |
| V2b | 概率校准器 | 对全局预测做班级/学科校准 |
| V3 | IRT 或 Bayesian Knowledge Tracing | 估计知识点级掌握轨迹 [R26-R27] |
| 暂缓 | Deep Knowledge Tracing | 只有在跨校积累大规模题目序列后才比较 |

工程候选优先比较 CatBoost 和 LightGBM，而不是预先宣布某个模型最佳。CatBoost 对混合类别特征和缺失较方便；LightGBM 训练和部署成熟。最终选择必须由跨时间、跨班级和跨学校验证结果决定。树模型解释可使用 SHAP，但 SHAP 只解释模型如何形成预测，不证明因果 [R31-R32]。

### 10.2 “一班一模型”的科学实现

每个班拥有独立的模型包，但不独立训练复杂预测器：

```text
全局/学科预测模型
  + 班级特征基线
  + 班级概率校准器
  + 准则参照阈值
  + 班级层级迁移规则
  + 量规、特征和模型版本
  = 班级专属模型包
```

- 全局模型学习跨班级可复用规律。
- 学科模型处理不同学科行为和测量目标差异。
- 班级校准器修正本班评分、教学节奏和机会差异。
- 小样本班级只更新稳健基线和阈值，不重训树模型。
- 数据不足时回退到学科或全局模型；若预测区间、适用范围或数据质量仍不达标，则标记 `low_precision` 或 `abstain`，而不是只下调一个模糊分值。

这符合“每班专属”，又避免在 40-60 个样本上过拟合。

### 10.3 A/B/C 策略层

A/B/C 是仅供任课教师和内部策略服务使用的教学支持决策代码，不要求每班固定比例：

- A：已稳定达到核心目标且具备拓展准备度，提供更开放、更复杂任务。
- B：接近或达到核心目标，提供标准任务和适量支架。
- C：当前需要基础支架、更多反馈或更小步任务。
- A/B、B/C：模型不确定或处于边界时的相邻适配带，可投放相邻层共享题。

映射策略使用标准参照阈值，再做有限班级校准。禁止按班级强制三等分；如果全班达到标准，不应人为制造 C 层。

层级迁移保护：

- 预测区间过宽、测量误差过大或域适用性不足时不建议变层。
- 使用滞回阈值，升级和降级采用不同门槛。
- 设置至少一个教学周期的冷却期。
- 单次最多移动一级。
- 教师确认后才生效，拒绝和修改原因进入审计。
- 不向学生展示排名或“能力标签”，学生只看到适合自己的任务。

教师私有工作台可以显示当前带、建议带、边界状态、证据、不确定性和迁移历史。学生端 API、页面源代码、路由参数、WebSocket 消息、下载文件名、任务标题和浏览器存储均不得包含层级代码、概率或分组依据。内容投放由服务端按确认后的 `StudentSubjectBand` 解析，学生不能通过修改 URL 枚举其他层的变体。

当前 `StudentProfile.current_layer` 是全局单字段，无法表示同一学生在不同学科的差异。后续应改为按学生、学科、课程和有效时间保存的版本化 `StudentSubjectBand`；个人档案字段只作缓存或逐步废弃。

### 10.4 模型实验矩阵

所有候选模型读取同一冻结特征视图、结局合同和数据折，禁止为某一模型单独选择更有利样本。第一轮实验按目标分别训练，不直接训练 A/B/C：

| 实验 | 模型 | 输入 | 目的 | 主要输出 |
| --- | --- | --- | --- | --- |
| M00 | 总体发生率/上一时点状态 | 标签历史 | 最低无技能基线 | 概率或连续值 |
| M01 | 专家规则 | 6-10 个透明核心特征 | 验证闭环和提供教学可解释对照 | 风险/掌握规则分 |
| M02 | Elastic Net Logistic/Ordinal | 按 F0-F3 逐块加入允许特征、机会分母和允许的缺失信息 | 稳健统计基线、增量效度与方向审查 | 校准概率 |
| M03 | 多层 Logistic/累计链接模型 | M02 + 学校/班级随机截距 | 检查嵌套结构和教学情境 | 条件/边际概率 |
| M04 | CatBoost | V1 表格特征和受控类别变量 | 非线性与类别交互候选 | 未校准概率 |
| M05 | LightGBM | 与 M04 相同 | 非线性效率候选与交叉核验 | 未校准概率 |
| M06 | IRT/BKT | 题目-知识点作答序列 | 知识点掌握的独立子模型 | 掌握后验 |
| M07 | 组合模型 | M02-M06 的训练折外预测 | 检查简单堆叠是否有稳定增益 | 校准概率 |

M06 只服务于掌握度，不替代完成支持信号、成长和量规表现模型。M07 只有在训练样本足够且所有基础模型产生严格训练折外预测时才启用。深度序列模型不进入 V1，除非跨校数据达到预注册样本量且在学校外验证中相对 M02-M06 有稳定增益 [R26, R64, R67-R68]。

### 10.5 班级专属校准方法

对二分类目标，先得到全局/学科模型概率 `p_global`，再使用班级惩罚 Logistic 校准：

```text
p_class = sigmoid(a_class + b_class * logit(clip(p_global, 0.001, 0.999)))
loss = log_loss + lambda_a * a_class^2 + lambda_b * (b_class - 1)^2
```

- 班级累计至少 30 个可观测结局且正负例各至少 5 个时，只更新截距 `a_class`，固定 `b_class=1`。
- 至少 100 个可观测结局且正负例各至少 20 个时，才允许同时更新斜率；这通常需要跨多个教学周期。
- 样本不足时使用学校-学科校准器；仍不足则直接使用全局/学科校准概率。
- 正则强度由中心训练数据的留班验证选择并随模型包分发，学校不根据本班测试集调参。
- 多分类概率采用 `softmax(log(p_global,k) + a_class,k)` 的和为零截距校正；序数目标优先校准累计概率。
- 连续掌握/成长和逾期计数分别使用与其分布匹配的层级收缩校准，不把 Logistic 公式机械套用到所有目标。
- 校准器只使用当前决策点之前已成熟的结局，并在之后的决策点评价；同一批结局不能同时用于拟合和宣称校准改善。
- 班级校准只修正预测分布，不能移动课程标准的达标线，也不能用班级人数比例强制生成 A/B/C。若共同测量不可链接，必须停止内容带建议，不能让校准器掩盖测量不可比。

这些样本门槛是抑制单班过拟合的 V1 工程规则，需要在模拟和真实试点中做敏感性分析。“班级专属模型包”实际保存校准参数、班级基线、策略阈值和版本，而不是每天用几十名学生重训一棵树。

### 10.6 初始内容投放带映射 V1

在尚未获得足够研究数据前，策略层使用可解释的保守映射。设 `M` 为下一计划锚测达标概率，`U(M)` 为通过训练折 bootstrap、层级后验或其他预注册方法得到的概率不确定区间，`Q` 表示未来完成率和逾期数量形成的支持信号。`U(M)` 的覆盖水平由先导数据和教师决策容量预注册，不在测试集上选择。若模型未估计两个完成结局的联合预测分布，`Q` 保持为两个分量，不能用独立假设伪造一个精确 OR 概率。**内容难度层主要由可比掌握证据决定，完成信号只决定是否增加非内容支持，不能单独把学生降到 C 层。**

| 建议 | V1 条件 | 教学含义 |
| --- | --- | --- |
| A | `U(M)` 整体高于暂定 0.80 边界，掌握证据充分且数据质量正常 | 拓展任务；若 `Q` 高，另加计划/提醒支持而不降低内容难度 |
| B | `U(M)` 整体位于暂定 0.55-0.80 区间 | 核心任务和按需支架 |
| C | `U(M)` 整体低于暂定 0.55 边界，并排除试卷不可比和数据质量问题 | 基础概念、小步任务和更频繁的认知反馈 |
| A/B | `U(M)` 只跨 0.80 边界 | 投放 A/B 共用内容或由教师判断 |
| B/C | `U(M)` 只跨 0.55 边界 | 投放 B/C 共用内容并增加观察 |
| 不建议 | `U(M)` 同时跨两条边界、关键特征降级、有效机会不足或模型超出适用范围 | 只展示数据缺口，不生成层级 |

`Q` 高时触发的是完成支持处方和教师核查，而不是内容降层。阈值不是心理测量常模，也不是永久能力线。试点前由学科组确认，随后通过决策曲线、资源容量、误判成本和学生结果评估，而不是为了让 A/B/C 人数好看而调整。教师修改阈值或层级会记录为政策决策，不直接成为模型真值。

### 10.7 候选模型上线闸门

候选模型只有同时满足以下条件才进入教师影子试用：

1. 数据泄漏测试、重复学生测试和特征时间边界测试全部通过。
2. 在时间外推、留一班级和可用时留一学校验证中，相对 M01/M02 报告 Brier score 差值、bootstrap 95% CI 和决策曲线；最小有用增益由“少漏掉一个需要支持学生”和教师容量的实际代价在试点前确定，不再预设任意 2%。
3. 报告校准截距、斜率、平滑校准曲线、Brier 和适当的 ECE 敏感性分析；ECE 依赖分箱和样本量，不单独作为固定 0.05 闸门。
4. 公平闸门按预注册群体报告性能、校准、漏报/误报和支持分配差异及区间。允许差异上限依据教育后果定义，不以 `n=50` 或固定 Brier 差值代替精度分析。
5. 最差学校/班级的性能不因平均性能提升而明显退化；小样本班级使用层级收缩估计并明确不确定性。
6. 相对更简单模型的增益需在至少两个连续时间折中出现，并通过模型卡说明代价、失败模式、适用范围和 F0-F4 消融结果。
7. 影子试用还需通过教师任务模拟：教师能否正确理解建议、选择合适支持、识别错误数据，并在可接受时间内完成审核。

具体数值闸门将在先导数据、决策成本和功效/精度分析后预注册，不能根据最终测试集表现回调。任何模型即使达到闸门，也只能生成教师建议，不能自动改变学生层级 [R46, R56-R62]。

### 10.8 多维诊断与支持处方

A/B/C 只表示内容难度和支架强度的投放带，不承担完整诊断。每条建议先生成多维证据画像，再生成一个或多个支持处方：

| 证据组合 | 不应得出的结论 | 首选支持处方 |
| --- | --- | --- |
| 掌握低、完成正常、数据充分 | “不努力” | `CONCEPT_RETEACH`、`WORKED_EXAMPLE`、`GUIDED_PRACTICE` |
| 掌握高、完成信号高 | “能力低，应降 C” | `PLAN_CHECK`、`DEADLINE_REMINDER`、教师核查任务负荷/动机 |
| 掌握不确定、机会少 | 强行 A/B/C | `COLLECT_EVIDENCE`、共同锚题或教师观察 |
| 完成低且离线/不可用高 | “低投入” | `ACCESS_SUPPORT`、补做机会、延长截止，不生成降层建议 |
| 调节代理异常但掌握正常 | 已确诊 SRL 问题 | `PLANNING_PROMPT`、`PROGRESS_CHECK`，同时收集验证证据 |
| 作品达到核心但策略单一 | 学习失败 | `COMPARE_STRATEGIES`、`REVISION_FEEDBACK` |
| 小组收尾阶段停滞 | 某成员贡献低 | `GROUP_COORDINATION`、角色复核、里程碑检查 [R82] |
| 掌握稳定且成长良好 | 永久 A 层 | `EXTENSION_TASK`，下个周期重新判断 |

处方由版本化 `SupportInterventionDefinition` 管理，包含适用证据、禁忌条件、资源模板、预期近端结果和撤回条件。模型输出必须明确“为什么建议这个支持”和“什么证据可能使建议错误”，不能只输出风险分数。诊断到行动是独立需要验证的环节；知道更多数据并不会自然产生更好的教学 [R47, R66, R76]。

### 10.9 干预闭环与 AI 边界

每次支持依次记录 `recommended -> teacher_selected -> delivered -> exposed -> used/declined -> completed -> proximal_outcome`。仅投放或弹窗出现不能算作学生接受，也不能把未使用自动解释为抵触。教师可调整、延后或拒绝处方，学生可报告资源不可用、建议不适合或数据有误。

DeepSeek/生成式 AI 在该闭环中只用于起草教师可审查的反馈、例题、提示或资源，不直接读取可识别学生轨迹，也不自动发送个性化结论。每类 AI 支架分别验证目标结果和副作用；中学生随机试验显示，GenAI 支持可能影响特定动机结果，却未必改善努力、知识或策略表现，不能用“AI 反馈有效”概括 [R78]。不同人类/AI 反馈来源的效果还受人群、课程和实施方式影响 [R80]。

### 10.10 不确定性、拒绝预测与决策效用

每个预测分开记录四类不确定性：测量结果误差、学生结果的随机变异、模型参数/有限样本不确定性、目标学校/课程分布偏移。界面不得把最大类别概率直接称为“模型置信度”。

预测状态为：

- `eligible`：适用范围内、数据质量和证据量达到标准。
- `low_precision`：预测区间过宽或有效样本不足，只展示证据和补测建议。
- `out_of_domain`：学校、课程版本或特征分布超出模型卡范围。
- `data_degraded`：机会、评分或事件质量闸门失败。
- `abstain`：综合以上原因不生成内容带或支持处方。

模型评价报告覆盖率-风险曲线：随着系统提高拒绝比例，剩余建议的误差、校准和各群体覆盖是否改善。不能只报告“有建议学生”的高性能而隐藏被拒绝群体；各学校和审计群体都需报告建议覆盖率。

阈值选择使用预注册决策表，至少区分：漏掉真正需要概念支持、错误降低内容难度、错误提高内容难度、增加教师核查负担、延迟支持和不给建议。损失/效用由教师、学生和研究治理共同确定，并在外层测试前冻结。预测准确率、教师接受率和教育效用分别报告；教师接受不能自动证明建议正确 [R46, R60-R62]。

### 10.11 预测研究风险与持续验证

STRATA 采用教育领域预测研究检查表，并借鉴 TRIPOD+AI/PROBAST+AI 的通用预测原则，但不宣称临床规范可直接证明教育适用性 [R85-R88]。每次研究和模型包必须说明：总体、`T0`、当时可用预测因子、结局、样本量依据、缺失、全部候选模型、调参范围、数据角色、校准、区间、净效用、群体结果和失败运行。

禁止使用不带范围的“模型已验证”。验证声明固定为学校、学科、年级、课程/测量版本和时间组合。模型更新区分：

1. 仅修复不影响数值的工程版本。
2. 重新校准。
3. 参数更新。
4. 特征或预处理变化。
5. 结局/测量变化。
6. 完整重开发。

第 2-6 类都需要相应的外层验证；第 4-6 类不能沿用旧模型的外部验证结论。测试集访问和阈值回调次数进入审计 [R86, R100]。

### 10.12 解释稳定性与忠实度

模型解释进入教师界面前，需在 bootstrap、时间折和等性能候选模型间检查全局排序、符号和局部解释稳定性 [R94]。高相关特征按证据组解释，禁止任意突出一个代理变量。

界面按“事实证据 -> 模型关联 -> 反证/缺失 -> 适用范围 -> 支持动作”展示。局部解释不稳定时显示不稳定状态并退回证据摘要或 `abstain`；不能选择最符合教师印象的一次 SHAP。解释只描述模型如何形成预测，不使用“导致”“因为改变该行为即可改善”等因果措辞。教师理解、纠错、锚定和处理时间通过情境任务验证，视觉可读不等于理解正确。

### 10.13 自适应策略与强化学习禁区

V1 不从观察性教师决策日志直接学习“最优处方”，也不启用在线强化学习自动改变内容带。人工选择受未记录课堂信息影响，普通监督学习或 SHAP 无法消除时间变化混杂和策略反馈 [R95]。

未来只有在处理版本稳定、资格时点明确、历史分配概率可知、动作具有充分重叠且安全约束已审查时，才可研究离线策略评价。低风险可逆提示优先采用前瞻性微随机设计；多阶段处方优先 SMART。没有随机化或可辩护识别条件时，只报告实施关联，不输出个体处理效应或自动策略。

## 11. 夜间流水线与离线部署

成员校不依赖云服务，夜间任务在校内完成：

1. 校验事件模式、去重和补记客户端离线事件。
2. 关闭当天统计窗口，生成机会分母。
3. 生成日/7 日/30 日特征快照并执行质量检查。
4. 使用当前 champion 全局/学科模型推理。
5. 在样本量允许时更新班级校准器，不每日重训复杂模型。
6. 执行漂移、缺失率、校准度和公平性监测。
7. 生成候选 A/B/C 建议、分解的不确定性、适用状态和主要依据。
8. 次日教师看板审核，确认后写入有效层级版本。

全局模型不要求学校联网训练。学校定期导出经脱敏和校验的研究包，总中心合并后按周或月训练全局候选模型，再通过离线签名模型包分发到学校。学校部署时验证签名、特征模式和兼容版本后才切换。

学校研究导出包建议包含：

- `manifest.json`：学校匿名标识、模式版本、时间范围和校验和。
- 去标识化事件或经批准的事件子集。
- 特征快照、机会分母、计划结局观测和缺失原因。
- 量规版本、模型输出、教师审核和干预记录。
- 模型指标、漂移报告和审计摘要。
- 不默认导出聊天原文、作品原文件、姓名、账号和 API 密钥。

### 11.1 夜间任务 DAG

默认在学校本地时间 01:30 启动，学校管理员可调整时刻，但同一学校同一业务日期只能运行一个实例。Celery 编排以下有向无环任务：

```text
open_pipeline_run
  -> validate_and_deduplicate_events
  -> materialize_learning_opportunities
  -> finalize_assessment_outcomes
  -> build_feature_snapshots
  -> mature_outcome_observations
  -> score_global_subject_models
  -> update_eligible_class_calibrators
  -> run_data_and_model_monitoring
  -> create_candidate_decisions
  -> publish_teacher_review_digest
  -> close_pipeline_run
```

| 任务 | 输入/输出 | 失败处理 |
| --- | --- | --- |
| `validate_and_deduplicate_events` | 原始事件 -> 接受/隔离事件和质量报告 | 模式错误不重试；数据库暂态错误重试 3 次 |
| `materialize_learning_opportunities` | 投放记录 -> 学生机会事实表 | 关系不完整则停止后续特征任务 |
| `finalize_assessment_outcomes` | 答卷和评分版本 -> 最终结果事实 | 未完成人工评分保留 `PENDING`，不生成 0 分 |
| `build_feature_snapshots` | 事实表 -> 日/7/30 日快照 | 以 `run_id + student + subject + as_of` 幂等 upsert |
| `mature_outcome_observations` | 到期预测窗口 -> 冻结结局观测 | 不足资格写 `UNOBSERVED`，不静默丢弃 |
| `score_global_subject_models` | 特征快照 + champion 包 -> 原始预测 | 模型/特征版本不兼容立即失败并沿用旧建议 |
| `update_eligible_class_calibrators` | 新成熟结局观测 -> 候选校准器 | 未达样本门槛直接跳过；失败不影响全局推理 |
| `run_data_and_model_monitoring` | 数据质量、漂移、校准、公平报告 | 红色闸门阻止新建议发布 |
| `create_candidate_decisions` | 校准预测 + 诊断规则 -> 内容投放带和支持处方 | 仅创建候选记录，不写当前层级；访问/质量问题不得转成降层 |
| `publish_teacher_review_digest` | 候选建议 -> 教师待办 | WebSocket 失败可重试，数据库待办仍保留 |

暂态错误采用 60、300、900 秒指数退避，最多 3 次。每个任务先写临时版本，成功后原子切换；任何中间失败都不能留下部分学生已更新、部分未更新的生产建议。重跑使用同一 `run_date` 和新 `run_id`，旧产物保留审计但标记 `superseded`。

### 11.2 运行频率分离

- 每晚：事件校验、机会/结果事实、特征快照、推理、监测和教师摘要。
- 每周：在新成熟结局观测达到门槛时重估班级校准器和阈值稳定性。
- 每月或每学期：中心端合并学校研究包，重训全局/学科候选模型。
- 量规变更：只在正式研究窗口之外，经验证和审批发布新版本。

“每天夜间训练”在产品文案中应准确表述为“每天夜间更新数据和班级适配；复杂全局模型按月或达到数据门槛后训练”。否则单班日更会产生虚假的个性化和严重过拟合。

### 11.3 教师审核工作流

教师第二天看到的是“支持建议待审核”，不是自动排名。列表默认按“需要及时支持且证据完整”排序，并提供：当前投放带、建议投放带、多维证据画像、支持处方、不确定性与适用状态、近 7/30 日与单元证据、学习机会、数据质量、主要模型因素和最近干预。

教师可执行 `接受`、`保持原层`、`调整为 A/B/C`、`延后观察` 四种操作。保持、调整和延后必须选择结构化原因，如设备/请假、模型遗漏课堂表现、近期特殊情况、任务难度异常、教师已有支持计划或其他。批量接受只允许对“同课程、同建议、数据质量正常且非边界”的学生操作，仍需二次确认。

确认后生成新的 `StudentSubjectBand` 有效期，并保存建议版本、教师决定、理由和当时证据快照。学生只看到差异化任务和支持，不显示 A/B/C 字母、概率、班级排名或“风险学生”等内部标签。仪表板设计遵循可行动、人本和教师在环原则 [R46-R49, R61-R62]。

教师端属于私有工作台：只有实际任教关系有效的教师可查看学生姓名与个体内容带。课堂投屏、学生同屏演示和导出预览默认进入隐私模式，隐藏个体内容带、概率和风险原因；教师主动退出隐私模式需要二次确认。学校管理员默认只查看聚合分布、数据质量、教师处理率和公平监测，不因管理角色自动获得个体标签查看权。

教师可以把证据标记为“数据错误、缺少课堂情境、建议不适合或支持资源不可行”，但不能直接改写原始事件；系统创建可审计纠错记录并重算派生结果。学生端提供资源不可用、任务状态错误和建议不适合的反馈渠道。试点前使用访谈、共同设计、纸面/可点击原型和情境任务测试教师是否能正确理解并行动，而不是只在开发完成后询问满意度 [R46]。

### 11.4 跨校研究导出包 V1

文件名为 `STRATA_RESEARCH_V1_<school_hash>_<from>_<to>.zip`，目录固定如下：

```text
manifest.json
schemas/*.json
tables/learning_opportunity.parquet
tables/feature_snapshot.parquet
tables/outcome_observation.parquet
tables/rubric_rating.parquet
tables/model_prediction.parquet
tables/teacher_decision.parquet
tables/intervention.parquet
reports/data_quality.json
reports/model_monitoring.json
checksums.sha256
signature.ed25519
```

学生、教师、班级和课程标识使用 `HMAC-SHA256(study_export_secret, study_id + local_id)` 生成研究期内稳定假名；中心端不能由假名反推出本地账号。包默认不含原始答案、聊天、文件、姓名、学校真实名称、IP、设备指纹和外部 API 密钥。Parquet 依赖 `pyarrow`，加密压缩和签名依赖 `cryptography`/`pyzipper`，均须随离线 wheelhouse 分发。

导出前执行行数、模式、时间范围、主外键、重复键、缺失率和 SHA-256 校验。包使用中心端公开密钥加密并由学校部署密钥签名；超级管理员导入时先验签、解密和隔离检查，失败包不得进入跨校分析库。每次导出和导入均写审计记录。普通 XLSX 仅用于学校日常报表，不作为大规模研究数据交换格式。

### 11.5 人机协同与自动化偏差控制

“教师确认”不是安全性的充分条件。系统同时监测自动化偏差（盲从模型）、确认偏差（只接受符合既有印象的建议）、遗漏偏差（模型未提醒就不关注）和责任转移。

- 在影子验证中，教师先独立判断一部分标准化案例，再查看模型，比较教师单独、模型单独和人机团队的决策质量。
- 对真实待办默认先展示证据质量、共同锚测和缺失/反证，再展示内容带与处方；高影响降带建议需要主动展开理由并二次确认。
- 解释包含：数据时间窗、机会分母、支持/反对建议的证据、缺失、模型适用范围和可执行动作；SHAP 仅描述模型关联，不显示为“原因” [R31-R32]。
- 不显示多位小数的伪精确概率；当区间宽、目标学校偏移或测量误差大时明确 `abstain`。
- 教师可查看“如果这条证据错误，建议可能如何变化”的受限敏感性，不把未经验证的反事实生成当作因果解释。
- 每班/每天设置建议预算和重复提醒冷却期，按教师可处理容量发布。超出容量只汇总数据，不制造无法处理的红色告警。
- 系统记录查看、理解检查、决定、纠错、处理时间、后续动作和是否完成处方；接受率高不是成功标准。
- 教师培训包括构念边界、代理指标、缺失、校准、常见失败案例和学生沟通，不能只培训按钮操作。

学生拥有查看与纠正基础事实、报告不可用/不适合支持和请求教师复核的渠道。研究界面是否显示模型以及显示顺序必须与生产界面区分，避免用已经被模型锚定的教师判断评价模型 [R46, R51, R60-R62]。

## 12. 评估设计

### 12.1 数据切分

禁止随机拆分事件行或快照行。验证方案取决于部署问题，至少并行报告：

| 验证问题 | 外层切分 | 同一学生能否跨训练/测试 | 回答范围 |
| --- | --- | --- | --- |
| V-A 在读学生下一周期 | rolling-origin，严格早期训练、后期测试 | 可以，但测试期全部晚于训练期，且按学生聚类推断 | 对已有历史学生的时间外推 |
| V-B 新学生冷启动 | 学生整组留出 | 不可以 | 对没有平台历史的新学生 |
| V-C 新班级 | 班级/教师整组留出 | 仅当其班级不在训练中且历史不泄漏 | 班级教学情境迁移 |
| V-D 新学校 | 学校完整留出，预处理和阈值均不可看该校 | 不可以 | 真正跨校外部验证 |
| V-E 新时间/课程版本 | 课程或测量工具变更后的连续时段留出 | 可按 V-A 规则 | 课程、政策和概念漂移 |

内层只用于超参数、特征块、预处理和校准选择；外层测试结果不得用于回调阈值。班级校准器只使用该外层训练期内已成熟结局，不能读取测试期标签。

### 12.2 指标

| 目标 | 主要指标 |
| --- | --- |
| 连续掌握/成长 | MAE、RMSE、平均偏差、观测-预测平滑曲线、预测区间覆盖/宽度；R² 仅作补充 |
| 达标概率 | Log loss、Brier、校准截距/斜率和平滑曲线、AUCPR；ECE 做分箱敏感性而非唯一闸门 |
| 完成分子/分母 | 二项对数损失/偏差、校准和机会加权绝对误差，不把分母不同的比例视为同等精度 |
| 新增逾期计数 | MAE、Poisson/负二项偏差、零值校准；依据分布检查过度离散和零膨胀 |
| 序数量规模块 | 序数 log loss、MAE、二次加权 Kappa，并传播评分/任务测量误差 |
| 拒绝与稳定 | 建议覆盖率、覆盖率-风险曲线、内容带迁移率、短期反复率、冷却期违例 |
| 决策效用 | 漏支持、过度/不足挑战、教师核查负担、支持延迟和预注册净效用/决策曲线 |
| 人机协作 | 团队决策相对教师单独/模型单独的差异、接受/修改/拒绝、纠错率、处理时间和原因 |
| 教育效果 | 前测校正后测、共同锚测、完成分子/分母、任务量规和不良后果 |
| 公平性 | 各群体性能、校准、覆盖、误报/漏报、内容与支持机会分配差异及区间 |

所有区间按学生/班级聚类计算，并同时报告总体和逐校结果。阈值只能在训练/验证数据选择，外层测试集只评一次。准确率不能作为唯一指标；一个把大多数学生都预测为 B 的模型可能准确率较高，却没有教学价值。

### 12.3 漂移与上线门槛

- 输入特征分布、缺失机制、题目难度、结局分布和校准均需监测。
- candidate 只有在主要指标、校准和公平性均不劣于 champion 时才可进入教师试用。
- 任何指标低于门槛时继续使用旧版本，并记录失败原因。
- 模型回滚必须恢复模型、校准器、特征模式和策略阈值的完整组合。

### 12.4 抽样、有效样本量与选择偏差

研究报告必须给出流程：目标总体 -> 平台可覆盖学生 -> 符合本次决策点资格 -> 具有可用输入 -> 结局可观察 -> 纳入分析。每一步按学校、班级和预注册审计群体报告人数与原因。

- 研究同意与日常教学使用是不同法律/伦理基础。未进入研究的学生不能被悄悄当作训练样本；在合法且不识别个体的前提下，应比较参与与未参与总体特征以评估选择偏差。
- 有效样本量由学生、班级、学校数量、重复决策点相关性和结局发生率共同决定，不能以快照行数或固定“每变量 10 个事件”宣称充足。
- 预测模型样本量根据候选参数自由度、结局比例/方差、期望收缩、总体风险估计精度和校准精度规划；树模型同时报告学习曲线和外部验证区间宽度。
- 班级/学校数量过少时，多层随机效应和跨校公平结论可能不可识别，应减少模型复杂度或延后结论。
- 未参加计划锚测、转学、长期缺席和技术不可用属于不同结局缺失机制，不能一律完整案例删除。
- 主要分析预先指定缺失处理；可在合理 MAR 假设下使用多重插补/逆概率加权，并用 delta 调整或模式混合分析检验 MNAR 敏感性。结局插补、权重模型和分析模型均只使用当时可获得信息。
- 报告加权前后协变量平衡、极端权重和有效样本量；敏感性结果不一致时，不给出稳定泛化结论。

学生嵌套班级/学校且多次出现，所有性能区间和模型比较至少在学生层级重采样；跨校主张优先在学校层级重采样或报告逐校结果。教学条件与学生差异共同影响预测可迁移性 [R24, R50]。

### 12.5 反证与负对照

模型比较前运行以下反证测试；任何异常高性能必须先解释，不能当作模型优势：

| 测试 | 预期 | 失败含义 |
| --- | --- | --- |
| 标签置乱 | 性能回到无技能基线 | 切分、缓存、重复样本或评估代码泄漏 |
| 时间倒置/未来哨兵 | 管道拒绝未来字段；若故意研究则性能异常提示泄漏 | `as_of`、评分版本或截止状态泄漏 |
| 随机 ID/行序号 | 无稳定增量 | 模型记忆学生/导出顺序或重复行 |
| 仅学校/班级/教师模型 | 不应接近完整模型 | 主要依赖机构/教师代理，跨校主张不成立 |
| 仅机会和历史成绩 F0 | 作为强基线 | 行为特征没有增量时不得宣称过程分析贡献 |
| 无效行为负对照 | 与教学无关页面访问不应稳定预测 | 泛活跃度/设备使用被误认作学习 |
| 数据可用性负对照 | 离线/错误不应推动降带 | 技术条件被编码为学生能力 |

### 12.6 压力、操纵与停用规则

上线前模拟并测试：20%-50% 事件迟到/重复/丢失、某校集中离线、课程/试卷版本突变、教师评分整体上移、班级规模变化、转班、小组重组、只完成简单题、短时间大量点击、长时间挂页、教师改变投放以迎合模型、标签污染和极端类别不平衡。

- 小幅无教育意义输入扰动不应让非边界学生频繁跨带；边界学生应进入 A/B、B/C 或 `abstain`，而非伪稳定。
- 点击、停留和重复提交增加但掌握证据不变时，内容带不得机械提高。
- 学生或教师可能策略性操纵指标，故界面不公开可被刷取的精确权重，审计异常但不自动惩罚。
- 新课程/事件/量规/模型包先影子运行；签名正确只证明来源，不证明科学兼容。

出现以下任一情况，自动停止新建议并回退到规则/人工模式：核心机会或评分覆盖失败、目标域判定超界、外部校准显著失效、某群体持续出现不可接受的漏支持/降挑战、建议无法在教师容量内处理、安全/隐私事件、版本不兼容或干预出现预注册不良后果。停用后保留事件事实和审计，但不得继续显示旧预测。

每学期执行模型续用评审；没有新的可观察结局、性能/效用不优于透明基线或教育目标已改变时，应退役而不是永久维护。监测和停用是端到端学习分析审计的一部分 [R60]。

### 12.7 跨校迁移与异质性

`TransportabilityAssessment` 依次审查目标总体、教学机会、测量链接、特征语义、预测关系和决策成本。逐校报告数据流、校准、误差、建议覆盖、净效用和群体结果，并给出学校随机效应汇总与学校间预测区间；总体平均不能覆盖最差学校失效。

完整外部学校的预处理、特征选择、阈值和校准不得读取该校结局。使用该校结果更新后只能称本地适配验证。重新校准只允许在测量和语义仍可链接时修正预测分布；不能移动课程标准，也不能掩盖题目不等值。新学校先影子运行，域偏移大、测量不兼容或性能区间无法支持使用时保持人工模式 [R86, R100]。

### 12.8 分层公平审计

公平按以下链路逐层检查，而不是只计算一个分类指标 [R58-R60, R83-R84]：

```text
measurement
  -> learning_and_device_opportunity
  -> observation_and_missingness
  -> prediction_error_and_calibration
  -> recommendation_coverage
  -> teacher_processing
  -> educational_and_autonomy_outcomes
```

`FairnessAuditPlanVersion` 预先定义具体伤害、比较总体、合法审计属性、指标、精度、补救和停止规则。受保护属性保存在隔离审计视图，不进入 V1 决策模型，也不使用代理猜测缺失属性。交叉群体使用层级收缩与区间，同时报告原始人数；样本不足标记 `insufficient_for_fairness_conclusion`，不把不显著解释为公平。补救优先修复测量和机会；任何模型公平约束都需说明对课程标准、校准和其他群体的副作用。

### 12.9 容量约束与选择性预测

在固定教师容量下比较规则、模型和人机团队。每班/每天记录可处理建议数、预计与实际处理分钟、资源库存、积压、支持延迟和处方完成。排队综合紧迫性、可干预性、证据质量和等待时间，不以单一风险概率排序。

`abstain` 同时报告总体、逐校和审计群体覆盖；长期拒绝集中在数据稀疏或设备不足群体时属于公平失败。不可执行处方是系统/资源约束，不记为教师拒绝。模型只有在真实容量下相对透明基线提高预注册净效用且不制造不可接受积压时，才能扩展部署 [R96, R103]。

## 13. 面向 *Computers & Education* 的研究设计

### 13.1 建议研究问题

- RQ1：行为事件和分析性量规能否形成可靠、有效且跨学校/学科相对稳定的过程性评价构念？
- RQ2：全局模型加班级校准是否比规则、线性基线和单一全局树模型具有更好的时序预测与跨校泛化？
- RQ3：教师参与的动态分层是否改善学习增益、投入和支持及时性，并避免扩大群体差异？
- RQ4：教师如何理解、接受、修正和实际使用模型建议，其工作负担与信任如何变化？

### 13.2 分阶段研究

1. 测量研究：事件完整性、构念定义、量规内容效度和评分者一致性。
2. 回顾性预测：比较规则、序数模型、多层模型、CatBoost/LightGBM 和知识追踪。
3. 前瞻性可用性：教师在环但不自动生效，分析接受、修正和误用。
4. 效果研究：采用班级簇随机或阶梯楔形设计，比较动态分层与常规教学。
5. 混合方法：访谈教师和学生，解释信任、工作负担、标签感受和课堂实施差异。

正式样本量必须依据主要结局、预期效应、班级内相关系数、学校/班级层级和流失率做功效分析。不能因为“一个班约 50 人”直接宣称样本足够。

### 13.3 主要统计原则

- 学生嵌套于班级和学校，教育效果使用多层模型。
- 主要结局建议为后测或标准化任务表现，并控制前测。
- 模型论文和效果论文的研究问题分开；预测性能不等于干预有效。
- 预先注册主要结局、排除规则、缺失处理和主要分析。
- 报告效应量、置信区间、校准和失败案例，不只报告显著性。
- 教师修正结果既是实施指标，也是潜在人为偏差来源。

### 13.4 建议的首篇 *Computers & Education* 研究

首篇论文不应同时宣称“量规有效、预测准确、分层有效、AI 改变教学”四件事。建议主问题聚焦为：**在中学信息科技课堂中，人机协同系统能否比规则基线更可靠地预测下一周期掌握与完成支持信号，并帮助教师选择可解释的差异化支持？**

建议采用两个连续阶段：

**阶段 A：前瞻性观察与模型外部验证。** 以学生 × 计划决策点为预测单元，在至少一个完整学期内提前冻结 `T0` 快照，再观察预先指定共同锚测、未来完成分子/分母和逾期计数。开发学校用于训练和校准，至少一所学校完整留作外部测试。主要模型结局优先使用连续 `mastery_next_planned_assessment` 的预测误差和校准，二分类达标为课程标准审定后的次要结局；主要实施结局为教师接受/修改/拒绝比例及处理时间。该阶段不声称动态分层提高了学习结果。

**阶段 B：阶梯楔形或班级簇随机实施研究。** 班级而非学生随机进入“仅显示常规数据”或“显示模型建议并允许差异化投放”条件，减少同班污染。主要教育结局为共同锚测后测，控制前测；次要结局为支持及时性、必做任务完成率、量规表现和教师工作负担。模型建议的使用程度作为实施变量，不在主要意向性分析中事后筛除不使用的教师。

规划场景可按 6-10 所学校、每校 4-8 个班、两个学期估算，但这不是既定样本量。正式数量必须使用先导数据估计班级内相关系数、基线-后测相关、预期最小教育意义效应和流失率后完成多层功效分析。

### 13.5 分析计划骨架

| 分析 | 单位与模型 | 必须报告 |
| --- | --- | --- |
| 测量效度 | 作品/评价项；有序 CFA、广义信度和评分者模型 | 因子载荷、omega、Kappa/ICC、跨群体不变性 |
| 预测效度 | 学生-快照；时间嵌套验证和留校外验证 | Brier、校准截距/斜率、AUCPR、决策曲线、95% CI |
| 教师决策 | 建议-教师；多层 Logistic/多项模型 | 接受/修改/拒绝、理由、处理时间、教师差异 |
| 教育效果 | 学生嵌套班级/学校；多层 ANCOVA 或广义混合模型 | 调整后均值差、标准化效应、95% CI、ICC、缺失处理 |
| 公平与异质性 | 预注册群体交互和分群校准 | 分母、置信区间、探索性/验证性区分 |
| 过程机制 | 事件序列、访谈和课堂实施记录 | 实施忠实度、干预类型、失败案例和质性主题 |

模型开发报告遵循 TRIPOD 类预测透明原则的适用条目，并提供数据字典、特征版本、代码提交、模型卡和学校外性能。教育效果研究需要单独预注册；不得用同一回顾性数据同时选模型、选阈值和证明教学效果。

### 13.6 最低复现材料

- 冻结的事件、特征、结局和量规模式及版本变更记录。
- 完整数据流图、排除流程图和每阶段样本数。
- 所有模型超参数搜索空间、随机种子、软件和硬件环境。
- 按时间、班级、学校生成数据折的代码，避免研究者手工挑选折。
- 去标识合成数据、特征生成单元测试和可执行分析脚本。
- 模型卡、数据表、偏差审计、教师界面截图和实施培训材料。
- 预注册、伦理审批、知情说明、数据可用性和代码可用性声明。

### 13.7 干预因果识别路线

每个支持处方先定义处理版本、比较条件、随机化单位、近端/远端结局、干预窗口和因果估计量。不能把“模型推荐后学生变好”当作效果，因为教师选择、学生采纳和回归均值都会造成混杂。

| 干预类型 | 优先设计 | 主要随机化单位 | 关键风险 |
| --- | --- | --- | --- |
| 教师分析看板/内容带建议 | 班级簇随机或阶梯楔形 | 班级/教师 | 同一教师跨班污染、学校政策时间趋势 |
| 低风险提醒/计划提示时机 | 可行后使用微随机试验 | 学生 × 合格时点 | 提示疲劳、时变资格、同日多次干预 |
| 概念范例/支架类型 | 比较两个均符合课程标准的有效支持 | 学生或小组，视课堂污染而定 | 内容不等值、教师额外解释 |
| 小组形成/协作支架 | 班级或小组层设计并建模干扰 | 班级/小组 | 同伴溢出、成员变化、组间竞争 |
| 未响应后的第二阶段支持 | 数据与学校足够后考虑 SMART | 学生/班级按阶段再随机 | 样本量、路径复杂、版本冻结 |

主要效果按随机分配进行意向性分析；实际使用、教师遵从和学生接受作为实施结果与次要按方案/工具变量分析，不以“只分析采纳建议的人”替代随机比较。报告处理分配、实际投放、曝光、使用、退出、污染和协议偏离。

同班学生会共享教师、资源和同伴影响，标准无干扰假设通常不成立。试验需预先说明干扰网络和允许的处理映射；小组活动以组为分析单位或使用显式干扰模型，不能把同一共同作品复制成多个独立学生结局。自动分组不得依据未经验证的学习风格；同层、异层和随机分组的效果需在具体任务中比较 [R69-R70, R82]。

试验期间冻结基础模型、阈值、量规、处方和提示版本。紧急安全修复可以发布，但须记录偏离并进行分期分析。异质处理效应只在预注册少量变量上验证，其余作为探索；发现某群体效果差异后必须在新样本复验，不能立即让模型自动学习处理政策。

生成式 AI 支架的“持续使用”和“撤除后是否保持能力”应分别测量，以识别依赖或能动性变化 [R51]。任何支持效果研究同时记录不良结果：认知负荷、提示疲劳、减少自主选择、过度依赖、被降低挑战和教师额外负担。

### 13.8 预注册、数据锁与可复现性

正式分析前冻结 `ResearchProtocolVersion`，至少包含目标总体、决策点、主要/次要结局、资格/排除、特征块、缺失处理、模型候选、超参数空间、验证折、校准、阈值选择、群体审计、统计检验、区间方法和停止规则。

- 明确区分确认性、次要和探索性分析；探索发现必须标注并在新学校/时间复验。
- 外部学校测试集由独立数据管理员生成并锁定。研究团队只能通过固定评估任务获得有限汇总，不能反复查看后调模型。
- 原始数据水位、事件/特征/量规/结局/模型/处方版本、代码提交和环境锁文件形成不可变运行清单。
- 每次实验由本地 MLflow 或等价离线注册表记录输入哈希、数据折、参数、随机种子、依赖、硬件、输出和失败状态；失败运行不能从报告历史中删除。
- 对随机算法报告种子与非确定性来源；关键结果由第二个分析脚本或独立分析者从锁定数据重跑。
- 多结局、多个时间窗、多个模型和多个群体产生的比较必须在分析计划中控制错误发现或明确探索性，不能只报告显著组合。
- 阈值、`min_n`、会话规则、缺失和结局测量误差敏感性全部报告，不只保留支持主张的版本。
- 代码公开范围至少包括模式、合成数据生成器、特征单元测试、数据折、训练/评估和图表脚本；真实未成年人数据受限时提供申请流程和可复现实验容器/离线环境。
- 文献库当前是设计导向范围性证据库，正式论文不能称为系统综述；如论文包含综述主张，需另行完成数据库检索、双人筛选和流程报告。

论文中预测性能、测量效度和干预效果分别使用不同证据链。一个数据集若参与特征/阈值设计，不再称为完全独立验证集；模型论文使用过的外部学校也不能在下一版模型继续作为未见测试而不披露。

### 13.9 实施忠实度与教师数据素养

每项前瞻性研究同时测量 `reach -> viewed -> understood -> selected -> delivered -> exposed -> used -> completed`。实施忠实度包括覆盖、剂量、质量、响应、合理适配、协议偏离、污染、时间和成本。教师上线前通过数据分母、缺失、不确定性、代理指标和错误案例的情境考核；提供工具不等于具有数据素养 [R96, R101, R103]。

主要干预效果保持 ITT。实际实施、教师适配和学生使用是实施结局及预注册次要机制分析；不能只分析采纳建议者。合理适配与违约分开编码，教师和学校实施异质性单独报告。教师无法在真实时间内处理或执行处方时，先简化系统，而不是把未实施归咎于教师。

### 13.10 证据成熟度与独立复验

STRATA 使用以下累积证据阶段：

```text
concept -> feasibility -> measurement -> prediction
        -> decision -> impact -> transport -> surveillance
```

每级有独立研究问题、数据角色和发布闸门。关键主张至少在新的时间段和一所未参与开发的学校复验；外部学校的历史使用必须披露。失败模型、空结果、不良后果和退役原因进入实验注册。第一篇论文聚焦测量、前瞻性预测和教师决策可用性，不同时声称动态分层产生因果学习增益。正式系统综述另行执行数据库检索、双人筛选和质量评价；当前文献库只作设计证据映射。

## 14. 隐私、伦理与治理

### 14.1 用途、授权与未成年人保护

- 日常教学运行、学校质量改进、模型训练和学术研究分别建立目的、法律/伦理依据、数据字段、访问者、保留期和退出/纠错规则；不能用一次笼统同意覆盖全部用途。
- 研究使用需按适用的个人信息和未成年人保护要求获得学校/伦理审批、监护人知情同意及适龄学生知情/同意或依法确定的替代程序，具体由学校和法务确认。
- 学生与监护人可查看收集类别、用途、主要推断、保留期、共享范围和纠错/申诉渠道。拒绝研究参与不得降低正常课程资源和评价机会。
- 分层建议不用于惩罚、公开排名、招生纪律决定或限制学生长期学习机会；不得以“个性化”为理由永久降低课程挑战。
- 教师必须能查看证据时间窗、机会分母、不确定性、数据缺失和禁止解释，并可拒绝建议 [R33-R34, R56, R60]。
- 学生不显示个体层级与分组推断，但必须被告知平台会使用学习过程数据提供差异化任务和支持；隐性界面不能替代知情、纠错、申诉和正常课程机会保障。
- 教师不得在课堂公开点名学生层级、投屏个体分层表或使用带能力暗示的组名；确需与学生沟通时使用具体目标、当前证据和下一步支持，不使用 A/B/C 身份称呼。

### 14.2 数据最小化与保留

- 每个事件字段绑定明确教学/研究目的；“以后 AI 可能有用”不是收集理由。
- 生产模型只读取批准的特征视图，不直接读取任意 JSON、聊天原文、答案正文或作品文件。
- 高频心跳、页面可见区间和错误载荷只保留完成质量锁定和可重算所需的最短时间；派生会话事实验证后按政策降采样或删除。
- 有教育意义的机会、结果、量规和决定事实按学期/研究需要保留；原始事件、业务作品、研究数据和审计日志分别设保留触发点，不采用一个无限期或无依据的统一年限。
- 删除、纠正和限制处理请求必须传播到派生快照、后续训练排除表和研究导出；已发布研究中的不可逆汇总按审批说明处理。

### 14.3 威胁模型与本地部署控制

威胁至少包括：教师越权查看非任教学生、学校管理员账号被盗、服务器/备份盘丢失、恶意备份包、中心端跨包重识别、日志泄露、模型记忆训练个体、勒索软件、外部 API 提示泄露和签名密钥失窃。

- 超级管理员/学校管理员启用强密码和多因素认证；教师只访问任教班级，研究员只访问批准的假名化视图。
- Web、数据库、对象存储、备份和密钥分离；传输加密、静态加密、密钥轮换、恢复演练和不可变审计均需在 setup 验收。
- 日志禁止打印访问令牌、DeepSeek 密钥、答案正文和完整事件载荷；调试模式不得用于生产。
- 导入包先进入无执行权限隔离区，完成大小、路径穿越、压缩炸弹、模式、签名、哈希和恶意文件检查后再解析。
- 模型包只允许签名的声明式参数/安全格式；禁止对外来 `.pickle`、`.pkl`、`.joblib` 或任意 Python 对象直接反序列化，避免远程代码执行。
- ONLYOFFICE、Redis、PostgreSQL、Celery 和模型服务使用独立最小权限账号，不能共享 root 密码。

### 14.4 跨校导出与重识别控制

- 默认研究导出从学生 × 决策点的必要事实和特征开始，不导出逐心跳/逐点击原始事件。原始序列仅在专项协议明确必要时单独批准。
- 假名使用研究专属 HMAC 密钥；中心端不持有本地 ID 映射，不同研究默认不可链接。密钥轮换和遗失有明确处理流程。
- 导出前执行字段白名单、稀有类别、自由文本、精确时间、极端值和小单元重识别审查。对外报告执行小单元抑制或合并，并防止通过多张表差分恢复。
- k-匿名或删除姓名本身不足以保证匿名；跨校中心库仍按受保护个人级研究数据管理，限制查询、导出和二次共享。
- 模型发布前评估训练样本记忆、成员推断和反演风险；发现高风险时降低模型复杂度、改变产物或只分发中心推理结果，不能仅靠签名解决隐私泄露。

### 14.5 外部 AI 隔离

DeepSeek 等教师自带外部 API 不得接收学生标识、原始轨迹、答卷、聊天、量规评分、模型预测或研究数据。服务端通过字段白名单和模板生成教学主题级提示，密钥加密保存且不进入日志/备份研究包。若未来需要学生级 AI 分析，必须改用校内模型或通过新的隐私、伦理、安全评审，不能扩大现有接口权限。

### 14.6 制度隐私、群体隐私与学生自主性

隐私不是只靠本地部署、加密或某个隐私增强算法解决的技术问题；目的、制度治理、问责和学生能动性同样决定风险 [R97-R98]。

- 每个分析功能执行数据保护与自主性影响评估，说明必要性、替代方案、访问、保留、申诉、退出和群体影响。
- 除个人重识别外，审查班级、小组、稀有支持需求和交叉群体的群体隐私；多表发布防止差分恢复。
- 学生可查看并纠正基础事实、了解建议适用范围、拒绝非必要提示；拒绝研究或提示不减少正常课程资源 [R102, R104-R105]。
- 跨校默认继续使用最小化研究包。联邦学习不会因为“数据不离校”自动私密；只有在更新泄露测试、安全聚合、客户端认证、威胁模型和效用审查后才可作为候选。
- 若未来采用差分隐私，必须记录预算、组合、重复发布和群体/尾部效用；不能只标注“匿名化”。

## 15. 建议数据模型

以下是 PostgreSQL 生产物理模型。`learning_event_v2`、`learning_opportunity`、机会状态事实、`assessment_outcome` 的首批评分版本和 `participation_point_ledger` 已先在 Django 中以兼容 SQLite 的增量模型实现，其余表仍按路线图推进；正式试点还必须在 PostgreSQL 上复核约束、索引和并发行为。Django 模型可按业务域拆到 `learning`、`assessments` 和 `aiops`，数据库表统一使用学校作用域和不可变版本。

### 15.1 事实与事件表

| 表 | 核心字段 | 约束和索引 |
| --- | --- | --- |
| `learning_event_v2` | `event_id UUID`、`school_id`、`actor_id`、`target_student_id`、`event_name`、上下文外键、`opportunity_id`、`attempt_id`、双时间戳、分值、版本、`payload JSONB`、`quality_status` | 主键 `(school_id,event_id)`；按 `server_received_at` 月分区；索引 `(target_student_id,subject_id,client_occurred_at)`；`payload <= 16KB`；只增不改 |

| `research_analysis_run` | 协议、数据水位/哈希、代码提交、环境、折、参数、种子、结果、失败状态和产物哈希 | 成功与失败运行均保留；外部测试访问次数可审计 |
| `data_quality_report` | 范围、模式版本、重复/迟到/覆盖/缺失指标、闸门结果 | 与对应快照和 pipeline 绑定 |
| `model_monitoring_report` | 模型、时间范围、漂移、校准、性能、公平和策略稳定指标 | 指标带分母和置信区间；小样本标记不足 |
| `research_export` | 研究 ID、时间范围、模式、包哈希、签名、导出/导入状态、审计人 | 不在表中保存解密私钥或压缩包密码 |
| `scientific_claim_version` | C0-C6 等级、总体、分析单位、允许措辞、禁止外推、证据和状态 | 发布后不可覆盖；高等级不得只引用低等级证据 |
| `construct_evidence_map` | 构念、相邻构念、预期收敛/区分关系、竞争解释、触发情境和阶段 | 与测量工具/轨迹验证版本绑定；预测增量不能自动升级效度 |
| `fairness_audit_plan_version` | 伤害、群体、合法属性、链路层级、指标、精度、补救和停止规则 | 属性只进入隔离审计视图；小样本必须保留不足状态 |
| `transportability_assessment` | 目标学校/学科/版本、总体/机会/测量/特征/预测/决策兼容性和结论 | 本地适配前后分版本；不兼容时阻止模型包发布 |
| `implementation_fidelity_fact` | 分配、查看、理解、选择、投放、曝光、使用、完成、适配/偏离、时间和成本 | 与试验分配、处方和教师绑定；未实施原因不可覆盖 |
| `model_update_record` | 原/新模型、更新类别、触发漂移、数据范围、验证、审批、canary 和回滚 | 重新校准以上更新需新验证；完整包事务切换 |
| `privacy_autonomy_assessment` | 功能目的、必要字段、群体风险、替代方案、退出、纠错、保留和审批 | 未通过不得采集/导出；DeepSeek 学生数据隔离为硬约束 |
| `sensitive_inference_access_log` | 访问者、角色、学校/班级作用域、对象类型/ID、用途、字段类别、导出标记、允许/拒绝、时间和请求 ID | 对内容带、个体解释和分组依据的查看/导出只增不改；异常跨班访问触发告警 |

### 15.5 数据保留与迁移

- 原始接受事件不设无依据的统一 24 个月默认值；按事件目的、学校政策和研究审批分别配置保留触发点，超过必要期限自动进入删除/降采样任务。
- 高频心跳在生成可重算的会话区间、完成质量核验和申诉窗口后，按批准策略降采样或删除，不长期保留逐心跳轨迹。
- 业务答卷、作品和聊天遵循各自保留策略，不因进入分析系统而无限期保留。
- 现有 `LearningEvent` 不直接改名覆盖。先建立 V2 双写和对账，再停止 V1 写入；旧事件通过显式映射迁移，无法确定语义的记录标记 `legacy_unmapped`。
- `StudentProfile.score` 迁移为积分流水重算缓存；`current_layer` 迁移到首个 `StudentSubjectBand` 后只读，确认所有接口切换后再删除。

### 15.6 Django API 边界

| 接口 | 权限与用途 | 关键约束 |
| --- | --- | --- |
| `POST /api/v1/learning-events/batch/` | 已登录学生/教师客户端批量补传事件 | 每批最多 200 条；逐条返回 accepted/duplicate/rejected；服务端重建学校和用户作用域 |
| `GET /api/v1/teacher/classes/{id}/analytics/` | 任课教师查看本班学科概况 | 只返回受治理聚合和质量状态，不开放任意 JSON 查询 |
| `GET /api/v1/teacher/stratification/decisions/` | 教师查看待审核建议 | 必须限定任教班级、学科和预测时点；包含证据但不含受保护属性 |
| `GET /api/v1/teacher/stratification/decisions/{id}/evidence/` | 查看单个建议的特征、机会和缺失解释 | 返回模型卡字段、时间窗和数据质量，不返回 SHAP 因果措辞 |
| `PATCH /api/v1/teacher/stratification/decisions/{id}/` | 接受、保持、修改或延后 | 乐观锁版本；非接受操作要求结构化原因；写审计和 LearningEvent |
| `GET /api/v1/student/learning-feed/` | 学生获取本人当前可学习的资源、题目、活动和支持 | 服务端解析投放；响应不得包含 band/layer、候选变体、概率、理由、内部规则或其他学生信息 |
| `GET /api/v1/student/analytics-facts/` | 学生查看并纠正本人基础学习事实 | 只返回已披露的事实、完成状态和教师反馈，不返回模型特征权重、层级或同伴比较 |
| `GET /api/v1/school-admin/analytics/quality/` | 学校管理员查看事件和模型运行质量 | 只展示本校；不允许管理员修改研究事实 |
| `GET /api/v1/school-admin/analytics/stratification-summary/` | 学校管理员查看本校分层运行概况 | 只返回满足小单元规则的聚合分布、覆盖、迁移和处理率；默认不返回个体名单 |
| `POST /api/v1/school-admin/research-exports/` | 创建跨校研究包 | 异步任务；必须指定研究 ID、范围和批准的数据模式 |
| `POST /api/v1/super-admin/research-imports/` | 超级管理员导入学校研究包 | 先验签、解密、模式和去标识检查；失败包进入隔离区 |
| `POST /api/v1/school-admin/model-packages/import/` | 学校离线导入签名模型包 | 版本兼容、哈希、签名和回滚点全部通过后才可设为 candidate |

DRF Serializer 必须使用事件注册表按 `event_name + schema_version` 校验载荷，不能将客户端提交的 `school_id`、角色、评分状态或模型版本直接信任并写库。教师和学生使用完全分离的响应 DTO/Serializer，禁止通过动态字段开关复用一个可能误带层级字段的序列化器。任何学生身份访问分层建议、内容带历史和个体解释接口均返回 403；前端隐藏按钮不能替代后端对象级权限。

WebSocket、通知、离线缓存、XLSX、文件名和错误详情执行同一隐性策略。学生消息只携带实际动作，例如“新任务已发布”，不得携带 `target_band=A`；资源访问必须逐学生鉴权，不能依靠不可猜测 URL。外部 DeepSeek API 与上述分析 API 完全隔离，禁止将学生级分析数据发送给教师自带密钥。

## 16. 实施路线

本节定义科学阶段和工作包；具体代码顺序、阶段闸门、迁移与回滚按 [学生行为分析与 AI 隐性动态分层开发路线图](student_behavior_ai_stratification_development_roadmap.md) 执行。

### P0：治理与定义

- 冻结术语、构念、事件命名、禁止采集项和研究导出边界。
- 解决登录事件、最终主观题成绩、目标学生和积分口径问题。

### P1：研究级事件

- 实现事件 V2、机会表、幂等去重和客户端队列。
- 为视频、文档、题目、AI 网页、项目和协作补充受控 SDK。
- 建立事件完整性和网络故障监控。

### P2：量规与特征

- 实现证据中心蓝图、量规用途版本、证据绑定和逐项自评/互评/师评。
- 经过专家审查、反应过程和试评分后冻结首个 `research_linked` 版本。
- 实现计划决策点、环节/课时/单元及 7/30 日特征快照和可重算任务。

### P3：透明基线

- 上线规则与序数 Logistic 基线。
- 教师只看影子建议，不自动改变内容投放带。

### P4：模型比较

- 比较多层模型、CatBoost、LightGBM、IRT/BKT。
- 完成时间、班级和学校外验证、校准和公平性审计。

### P5：生产闭环

- 建立 champion/candidate、班级校准、滞回、冷却和回滚。
- 夜间推理，周/月级全局训练，离线签名模型包分发。

### P6：前瞻性研究

- 完成伦理审批、预注册、功效分析和教师培训。
- 开展簇随机或阶梯楔形研究及混合方法评估。

## 17. 第一阶段验收标准

开始训练任何模型前，至少满足：

- 核心事件均有机会分母、UUID、版本和幂等去重。
- 登录、题目最终成绩、评价对象和课堂积分口径一致。
- 事件重复率、缺失率和客户端离线率可量化。
- 量规通过内容审查和第一轮评分者一致性检验。
- AI 生成题与教师题有来源和生命周期，未校准题不会进入共同锚测或主要结局。
- 计划决策点和结局时间边界明确，不存在明显泄漏。
- 观察过程和竞争状态可重建，生产可用与事后重建数据不混用。
- 至少建立规则与序数模型基线。
- 验证按时间和班级分组，不随机拆事件行。
- 学生间与学生内变化分开，所有重复测量区间按学生/班级聚类。
- 每个建议带不确定性状态、反证/缺失、数据时间窗、模型/处方版本或明确 abstain。
- 公平审计覆盖测量、机会、观察、预测、建议、教师处理和后果。
- 模型在真实教师容量下优于透明基线，解释稳定性和教师理解达到影子门槛。
- 教师可拒绝、修改和回滚，学生不看到公开层级排名。
- 任课教师可查看本人任教班级的个体当前/建议带，学生无法通过 API、页面源代码、缓存、WebSocket、下载和直接对象访问取得层级或分组依据。
- 协作活动只向学生显示完成任务所需的当前组员，不显示层级构成、算法策略或能力型组名。

### 17.1 必须自动化的验收测试

| 测试 | 输入场景 | 预期结果 |
| --- | --- | --- |
| 事件幂等 | 同一 `event_id` 连续提交 3 次 | 接受事实只有 1 条，重复率计数正确 |
| 离线乱序 | 客户端离线后按乱序补传 20 条事件 | 按发生时间还原且保留接收时间；`operational_available` 不补入 `T0` 后才收到的事件，`reconstructed_complete` 可在允许迟到范围内补入并保持独立 |
| 可用时间泄漏 | 一条事件发生于 `T0-5m`、接收于 `T0+2h` | 主训练/验证快照在 `T0` 不含该事件；事后重建视图包含并标记迟到，二者不可覆盖 |
| 机会分母 | 教师只向 B/C 投放任务，A 未收到 | A 为 `NO_OPPORTUNITY`，不得记为未完成 |
| 最终评分 | 主观题提交后第二天教师评分 | 提交时结局未成熟；最终评分后只使用当前评分版本 |
| 评价归属 | 教师给学生评分 | `actor=teacher`、`target_student=student`，学生特征能正确连接 |
| 积分冲正 | 教师撤销一次抢答加分 | 原分录保留，新增反向分录，总分重算一致 |
| 特征时间旅行 | 在 `T+1` 插入未来高分结果后重算 `T` | `T` 快照数值不变 |
| 历史个人基线 | 计算 `T0` 的个人均值后再加入 `T0+30d` 行为 | `between_student_baseline` 和 `within_student_deviation` 均不变化 |
| 决策点冻结 | 同一学生连续 7 个夜间运行 | 运营预测可更新，但研究样本只生成一个预注册 `T0` 记录 |
| 计划结局 | 窗口内存在临时测验和指定共同锚测 | 只使用预先指定锚测，不选择最早/最高/最完整结果 |
| 竞争状态 | 学生在窗口内转学、请假或任务撤回 | 分别保存竞争/不可观察原因，不生成失败或 0 分 |
| 缺失语义 | 未投放、未开始、离线、数据错误各一例 | 返回四种不同缺失码，不被统一为 0 |
| 审计特征隔离 | 离线率或教师干预次数显著升高 | F4 审计报告变化，但 V1 主层级预测输入不包含这些字段 |
| 完成与掌握解耦 | `M>=0.80` 且完成支持信号高 | 不降为 C；保留较高内容难度并生成计划/核查处方 |
| 访问问题保护 | 掌握证据不足且多数机会为 `unavailable` | 不生成 A/B/C，生成访问支持和补充证据建议 |
| 量规可观察性 | 小组协作模块未在个人任务启用 | 保存 `NOT_ASSESSED`，不生成 0/1 星或拉低汇总 |
| 量规权重冻结 | 模型重训后预测系数改变 | 已发布量规条目、锚点和计分规则保持不变 |
| 量规用途隔离 | 教师创建 `local_formative` 五星量规 | 可用于反馈，但 OUTCOME-01 拒绝将其生成跨校训练结局 |
| AI 题生命周期 | DeepSeek 新生成一道答案正确的题 | 仍为 `draft`；不能成为共同锚题、IRT 参数或研究结局 |
| 锚题漂移 | 同一锚题曝光激增且参数显著变化 | 标记 `drift_watch/compromised`，停止新链接并保留历史版本 |
| DIF 与小样本 | 某审计群体只有 12 名学生 | 保留人数和区间，标记不足，不以不显著宣布无 DIF |
| 测量误差 | 同一能力估计点但标准误不同 | 结局保留不同不确定性，敏感性分析结果可追溯 |
| 支持状态链 | 教师投放处方但学生未打开 | 状态停在 `delivered`，不得记为 `used` 或有效 |
| 班级回退 | 班级只有 20 个成熟结局观测 | 不训练班级校准器，使用学校-学科或全局版本 |
| 模型不兼容 | 模型包要求特征集 V2，本地只有 V1 | 拒绝切换，champion 保持，写入错误报告 |
| 更新范围 | 模型改变特征或结局定义但只标记“重新校准” | 阻断发布，要求重开发级验证和新适用范围 |
| 不安全模型包 | 导入签名缺失或包含 `.pkl/.joblib` 的模型包 | 在隔离区拒绝，不执行任何反序列化代码 |
| 标签置乱 | 对训练结局随机置乱后运行全流程 | 性能回到无技能基线，否则阻断发布并检查泄漏 |
| 学校身份基线 | 仅使用学校/班级/教师字段训练 | 若接近完整模型，标记不可迁移并阻断跨校主张 |
| 解释稳定性 | 对同一学生在 bootstrap 等性能模型中解释方向反复变化 | 不显示单一原因，退回证据摘要或 `abstain` |
| 容量压力 | 每班每天 50 条建议但教师预算只有 10 条 | 评估固定容量净效用、积压和群体覆盖，不按风险分全部推送 |
| 刷行为压力 | 大量点击/挂页但掌握证据不变 | 内容带不机械提高，异常只进入审计 |
| 拒绝预测 | 目标学校偏移或预测区间超宽 | 保存 `out_of_domain/low_precision/abstain`，不生成旧建议 |
| 外部测试锁 | 研究人员第二次请求同一学校外测试明细 | 拒绝或只返回协议允许汇总，访问次数写审计 |
| 随机分配 | 教师未采纳实验处方 | 保留原随机分配和实际处理，主要 ITT 不删除该学生 |
| 观察性策略边界 | 从教师历史选择直接训练“最优处方” | 管道拒绝生产发布；无分配概率/重叠/识别证据只能描述 |
| 小组分析单位 | 4 人共同提交 1 份作品 | 只生成 1 条组/作品结局；个人证据需独立贡献引用 |
| 原子发布 | 生成一半建议时任务崩溃 | 教师看不到部分新建议；重跑可完整发布 |
| 学生隐私 | 学生端调用建议详情接口 | 返回 403/无内部层级概率，学生只获任务配置 |
| 学生响应字段 | 学生学习清单包含分层资源 | 只返回已分配内容；JSON、DOM、URL、缓存和下载文件名均不含 A/B/C、边界带、概率或理由 |
| 直接对象访问 | 学生修改资源或任务 ID 尝试访问其他变体 | 返回 403/404，不泄露变体是否存在、所属层级或其他学生投放情况 |
| WebSocket 隐性 | 教师确认内容带后向学生推送任务 | 消息只含任务发布信息，不含 `band/layer/confidence/strategy` 等内部字段 |
| 任课作用域 | 教师请求非本人任教班级的个体分层 | 返回 403 并写入敏感推断访问审计；本人任教班级正常显示 |
| 分组隐性 | 开启小组协作并采用同层或异层候选 | 学生只见当前组员和任务，组名与载荷不含层级、策略和能力理由；教师可见完整依据 |
| 投屏隐私 | 教师在课堂大屏打开分层看板 | 默认遮蔽姓名对应层级、概率和风险原因；退出隐私模式需要二次确认并写审计 |
| 导出隐性 | 学生导出档案或学校管理员导出常规报表 | 不包含个体层级、概率和分组依据；教师特批个体导出限定任教范围并记录用途 |
| 跨校导出 | 包含姓名、聊天原文、逐心跳、稀有自由文本或未知字段 | 导出前阻断并给出字段级/重识别风险错误 |
| 群体隐私 | 多张报表可通过差分恢复某小组唯一学生 | 阻断发布或合并/抑制小单元，记录查询组合风险 |
| 自动化偏差任务 | 教师先独立判断后查看含已知错误的模型建议 | 能计算改正/被锚定比例，错误高影响建议需二次确认 |
| 停用演练 | 校准失效、机会覆盖失败或出现严重不良后果 | 自动停止新建议、隐藏旧预测并回退人工模式 |
| 可复现训练 | 同一数据、折和随机种子运行两次 | 指标和模型产物在允许浮点误差内一致 |
