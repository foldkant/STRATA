## 2. 固定开发顺序

```text
评价标准进入课时与课堂（已完成）
  -> 评价缺少材料的处理与覆盖数（已完成）
  -> 题目从创建到停用的完整管理（已完成）
  -> 共同测试和不同版本结果比较（已完成）
  -> 学生学习情况按日、7 日、30 日和单元汇总（工程版已完成）
  -> 教师可查看、学生不可见的规则建议（已完成）
  -> 固定分析时间点与多窗口学习指标（已完成）
  -> 未来结果与匿名冻结数据版本（已完成）
  -> 重复测量与透明基线比较（已完成工程闭环）
  -> 模型卡、拒绝输出和负对照（已完成工程闭环）
  -> CatBoost/LightGBM 比较（模拟数据工程验收已完成）
  -> 班级调整参数和夜间更新（模拟数据工程验收已完成）
  -> IRT/BKT 与测量版本 V-E（后续研究）
  -> 校内正式试用
  -> 跨校独立验证和统一分析
```

不能跳过评价、题目和学习情况汇总，直接用开发库训练正式模型。

## 3. 当前开发任务

### 3.1 评价试用与审核记录

状态：**已完成，并已继续完成课堂使用闭环。** 当前小榄中学已生成 4 条带“测试-”前缀的记录用于页面和导出验证。

教师需要能够：

- 选择一个已发布的评价标准版本。
- 记录内容审核、课堂试用、评分培训和评分一致性检查。
- 保存日期、参与人数、完成状态、处理结论、发现的问题和修改说明。
- 对评分一致性检查填写一致率。
- 查看历史记录并导出 XLSX。
- 使用模拟数据先验证完整页面和接口流程。

完成条件：

- 数据库迁移、教师课程权限、API、Vue 页面和 XLSX 导出全部完成。
- 其他教师和学校管理员不能读取或修改当前教师记录。
- 未发布的评价标准不能创建试用记录。
- 已完成记录保留历史，避免误删。
- 自动化测试、Vue 构建和桌面/手机页面检查通过。

课堂使用规则：

- 评价标准由教师在标准库维护，课时环节只选择已发布版本。
- 课堂首次开启评价时冻结版本，后续工作稿修改不影响历史课堂。
- 评价提交关联同一学生在本课堂、本环节的作答和作品，缺少材料时不自动给低星。
- 每个指标选择 1-5 星或暂不评价；平均星级排除暂不评价项，同时保留原因和覆盖数。
- 正式评价版本写入学习事件，旧课程评价兼容保留但不自动进入正式标准证据。

### 3.2 题目完整管理

状态：**已完成。** 题库题目已按以下状态运行：

```text
个人可用 -> 申请共享 -> 待审核 -> 可试用 -> 已启用 -> 已停用
```

同时记录：

- 人工创建或 AI 生成。
- 创建教师和所属学校。
- 审核人、审核意见和审核时间。
- 试用次数、作答人数、正确率和选项分布。
- 是否可以进入正式测试和共同测试。
- 发现答案错误、泄题或明显异常后停用。

已完成规则：

- 教师创建、XLSX 导入和 AI 确认均先保存到“我的题目”，本人无需审核即可组卷。
- 只有教师主动申请校内共享时，题目才进入学校管理员审核列表。
- 教师申请共享后，学校管理员可退回或准许试用。
- 可试用题只允许创建教师组卷；至少有 1 次真实学生作答后才可正式启用。
- 已启用题进入本校共享题库，其他教师只读并可组卷。
- 题目内容保存不可修改版本；试卷记录实际引用版本和当时状态。
- 使用次数、作答人数、正确率和选项分布从试卷与答卷计算，不维护人工递增计数。
- 教师和学校管理员页面、XLSX 导出、API 权限和自动化测试已完成。
- 个人/共享范围和审核状态是题库权限字段，不进入学生分层特征或标签；学生端不接收这些内部字段。

### 3.3 共同测试和版本比较

状态：**已完成工程闭环。**

- 每个学科保留一部分各班都完成的共同题目。
- A、B、C 或 A/B、B/C 专属题不能替代共同题目。
- 保存题目版本，旧答卷继续对应旧版本。
- 比较不同学期、不同课程版本和不同学校前，先确认题目仍可比较。
- 评分差异过大时只提示重新检查，不直接用于分层。
- 共同题集合由学校管理员按学科发布；教师组卷绑定集合后自动加入必备共同题。
- 每次组卷保存题目版本、用途、层级范围和比较编号。
- 有效作答少于 30 时逐题指标只显示“数据不足”，测试间比较也不输出假结论。

### 3.4 学生学习情况汇总

状态：**工程汇总已完成，研究特征继续开发。** 当前已经支持：

- 学生日、7 日、30 日和单元学习情况。
- 完成率、按时提交、首次作答、订正、资源学习和课堂参与。
- 没有任务、请假、离线和数据错误分别记录，不能统一算成 0。
- 汇总结果可按固定日期重新计算，不能使用未来数据。
- 教师按任教班级和本人课程查看、筛选并导出 XLSX。
- 夜间任务在学校学习数据检查通过后执行；模拟学校不进入正式夜间任务。

### 3.5 教师分层建议

状态：**透明规则和班级校准候选审核均已完成工程闭环。**

- 教师看到当前学习情况、建议任务难度、原因和需要补充的数据。
- 教师可以接受、保持、调整或延后。
- 学生只看到实际获得的任务和帮助，不显示 A/B/C、概率和排名。
- 学校管理员只看汇总，不默认查看学生个人内部层级。
- 有效任务少于 5 或已评分项目少于 3 时不建议层级变化。
- 教师采纳、保持、调整或暂缓只保存审核结果，不直接改写学生当前层级。
- 教师页面默认只显示待处理项，历史记录单独分页且只读。
- 班级校准候选存在时，同一学生、课程的透明规则仅作为比较记录，不形成第二条并行待办。
- 判断依据使用教师可读的指标名称和单位，不展示模型内部字段键。

### 3.6 模型试验

状态：**MODEL-01/02/03 工程闭环已完成，正式试用未开始。** 当前正式学校记录仍不足，模拟数据结果只验证程序，不形成正式效果结论。

当前已在相同数据折比较总体平均、透明规则、正则化统计、班级收缩、CatBoost 和 LightGBM，并生成全局模型加班级校准候选。IRT/BKT 仍需共同测量和真实数据后再接入。

- 所有模型使用相同训练数据和测试范围。
- 先检查是否比简单规则更可靠。
- 数据不足时不生成建议。
- 每个班保存自己的调整参数，不用几十名学生从零训练复杂模型。
- 新模型没有通过检查时继续使用旧版本。
- 每次比较保存模型卡、验证折、负对照和拒绝预测记录。
- 学校管理员可以手动运行完整训练，并查看平均残差、MAE、MSE、RMSE、R²、覆盖率和残差分布图；研究细节单独展开。
- 没有独立学校数据时，V-D 只显示“暂不适用”，不能假装完成跨校验证。

### 3.7 学习指标与未来结果

状态：**已完成。** 详细设计见[学习指标、未来结果与数据版本设计](feature_outcome_dataset_design.md)。

- 首期登记 25 项学习指标，保存定义、版本、用途和计算代码摘要。
- 每次分析固定班级、课程、学生范围和时间，不允许页面补建过去时间点。
- 当时可用数据同时按行为发生时间和服务器接收时间截止，防止迟到数据进入历史输入。
- 保存 7 日、14 日、30 日窗口的值、分子、分母和缺失原因。
- 没有任务、未开始、进行中、离线、数据错误、数量不足和不适用分别保存。
- 已实现随后 7 日完成率和新增逾期数，未观察结果不记为 0。
- 数据版本使用匿名编号，固定学生分组和时间分组，支持 XLSX 导出。
- 数据质量和教师支持字段只用于检查，不进入首期主模型。

## 4. 测试数据怎么使用

当前没有足够真实数据不影响工程开发。模拟数据可以用于：

- 验证数据库、接口、页面、导出和夜间任务。
- 验证同一批数据重复运行不会产生重复记录。
- 验证异常数据、缺失数据和任务失败后的处理。
- 提前开发教师页面和统计图表。

模拟数据不能用于：

- 宣称模型对真实学生有效。
- 宣称动态分层改善了学习效果。
- 替代真实教师审核、正式课堂试用和评分一致性检查。
- 与正式学校数据混合生成对外报告。

## 5. 技术边界

- 正式部署使用 PostgreSQL、Redis、Celery 和 Django Channels。
- 当前本机可使用 SQLite 快速开发，但涉及并发、锁和夜间任务时必须补做 PostgreSQL 验证。
- 学生个人数据和原始答卷不得发送给教师自带的外部 AI 接口。
- 教师自带 DeepSeek API 只用于生成可修改的个人题目，不能直接进入校内共享题库或自动改变学生分层。
- 每次数据库调整都要有迁移、测试、回滚说明和数据清理方法。
- 页面调整后检查桌面和手机视口，临时截图检查后删除。

## 6. 每阶段验收

每个阶段只有同时满足以下条件才算完成：

- 后端模型、权限和接口完成。
- 前端页面可以完成真实操作，不是静态演示。
- SQLite 和 PostgreSQL 关键测试通过。
- Vue 类型检查和生产构建通过。
- 文档、API 说明和数据模型同步更新。
- Git 提交可单独回滚。

## 7. 当前测试基线

- Django SQLite 当前全量 `142/142` 通过；PostgreSQL此前全量 141 项通过，本轮新增模型指标与手动训练专项 `5/5` 通过。评价、共同题、测试、学习汇总、特征/未来结果、重复测量、透明基线、模型发布和权限均有专项回归测试。
- Vue 类型检查与生产构建通过。
- PostgreSQL、Redis、Channels 和 Celery 已完成基础组件验证；新增迁移仍需在每所学校正式升级前执行备份和迁移演练。
- 当前正式学校记录量不足，机器学习比较继续使用隔离模拟数据验证工程，不形成正式模型结论。

## 8. 正式试用前的下一阶段

1. 教师与学校共同完成共同测试 V2 的内容审核、锚题确认和知识点映射。
2. 完成伦理审批、未成年人同意材料、学校数据协议、教师培训和研究预注册。
3. 先运行影子阶段，只检查数据与建议，不改变教学安排。
4. 候选模型由学校管理员发布签名版本，教师只审核本人课程建议，学生端继续隐藏内部层级。
5. 达到预注册的真实纵向样本与时间要求后，再运行稳定性、公平性、V-E 和跨校独立验证。
6. IRT/BKT 只在逐题序列、锚题和知识点数据满足条件后进入，不作为当前上线前置条件。

正式试用、伦理、培训、预注册和共同测试 V2 分别见对应专题文档；模拟数据不能完成这些研究闸门。
