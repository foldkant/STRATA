## 第 1 轮：构念效度与行为解释

### 审查问题

平台日志是否足以测量学习投入、认知投入、自我调节和协作？当前术语是否会诱导开发人员把代理指标当成能力？

### 主要发现

1. 原方案文字上承认“行为不是构念”，但特征仍按掌握、SRL、协作等构念命名，实际实现时存在重新实质化代理指标的风险。
2. R42 的轨迹协议即使经过理论与 think-aloud 对齐，识别匹配仍有限，说明“有理论映射”不等于“测量有效”。
3. R71、R64 和 R81 表明增加通道可以提高粒度，但时间对齐、理论解释和跨情境有效性仍是独立问题。
4. R79 显示教师对学生 SRL 的判断可能准确性较低并受整体成绩等线索影响，教师标签不能作金标准。

### 已修改

- 建立 E0 业务事实、E1 行为指标、E2 理论代理、E3 已验证构念分数四级体系。
- 22 个“核心特征”改为“候选特征注册表”，并为每项指定证据等级和用途。
- E2 在教师界面必须显示为“代理指标”，不得命名为 SRL、投入或能力分数。
- 新增轨迹效度研究：理论、数据、时间三重对齐，并报告覆盖率、敏感度、特异度和误判。
- 教师判断在模型展示前独立采集，只作带来源的弱证据。

### 尚需实证

- 在 STRATA 真实课堂中验证答案修改、求助、坚持和反思轨迹。
- 比较课堂观察、刺激回忆、学习日志和 think-aloud 的可行性及反应效应。

## 第 2 轮：事件、时间序列与学习机会

### 审查问题

7/30 日汇总是否保留了学习过程？系统能否区分未投放、未开始、技术不可用和真实未完成？

### 主要发现

1. SRL 和协作具有阶段性，同一行为在计划、执行、遇阻和收尾阶段含义不同 [R64, R76, R82]。
2. R40 显示支架可能改变活动频次而不改善学习结果，说明频次、序列和结果必须分别检验。
3. 原方案缺少明确的机会状态和教学阶段，固定 120 秒空闲阈值也可能被误写成有效学习标准。

### 已修改

- 增加 `assigned -> released -> exposed -> started -> submitted -> graded` 机会状态，并加入撤回、豁免和不可用分支。
- 保存环节、课时、单元和 `instructional_phase`，协作任务区分个人、组和共同作品。
- 持续时间只定义为技术活动量；对 60/120/300 秒会话阈值做敏感性分析。
- 增加环节、课时、阶段和单元窗口，不再只依赖日/7/30 日聚合。
- 序列特征设为独立研究模块，必须先完成过程边界和外部效度验证。

### 尚需实证

- 不同资源类型的“完成”规则和心跳间隔。
- 并发标签页、离线补传和课堂暂停下的可靠事件排序。
- 哪些任务阶段转移在跨课堂条件下具有稳定含义。

## 第 3 轮：特征工程与统计有效性

### 审查问题

模型输入是否混合了学生行为、教学处理和设备条件？重复快照、预处理和缺失是否会产生泄漏或虚假精度？

### 主要发现

1. 教学实施差异会影响行为特征的可迁移性，同名课程也不保证模型可移植 [R50]。
2. 既往教师干预属于时间变化的教学条件；干预后变化属于后处理变量，进入主模型会造成反馈循环和错误解释。
3. 离线率和数据错误可能成为家庭/设备条件代理，不应提高学生风险。
4. 同一学生每天多个快照并不独立，随机拆分快照会夸大样本量和性能。

### 已修改

- 特征分为 F0 基线、F1 直接指标、F2 理论代理、F3 已验证测量、F4 审计五个递增块。
- 主模型最多使用 F0-F3；教师干预、干预后变化、离线和事件检查信息进入 F4 审查，不进入首期主层级模型。
- 预处理、编码、特征选择和校准全部在训练折内拟合。
- 按学生和时间分组，设置学生-周期权重，并使用学生/班级层级 bootstrap。
- 缺失原因分别建模；`OFFLINE`、`DATA_ERROR`、`unavailable` 触发不建议或人工核查。
- 合作贡献改为角色和机会校正证据，不再使用聊天/编辑次数或组内占比代表质量。

### 尚需实证

- F2/F3 相对 F0/F1 的跨时间、跨班和跨校增量效度。
- `min_n`、时间窗、异常值和会话阈值的敏感性。
- 缺失机制和代理偏差是否在不同学校/群体间变化。

## 第 4 轮：评价标准与心理测量

### 审查问题

一张通用五星评价标准能否同时测成果、SRL、参与、协作和学科素养？AI 动态改权重是否保持纵向可比？

### 主要发现

1. 参与和按时属于行为事实，将其与成果、策略和协作相加会混合课堂服从性与学习质量。
2. 并非每个任务都提供协作、调节或伦理实践的观察机会，通用必评维度会制造伪低分。
3. R16 对评价标准促进学业表现提供总体支持，但对 SRL 的证据较弱，不能把使用评价标准等同于测量或改善 SRL。
4. 内部一致性不适合自动用于刻意多维的分析性评价标准；跨任务评分还包含任务和评分者误差。
5. 让 AI 根据预测效果动态改评价标准权重会破坏构念与时间可比性。

### 已修改

- 改为任务级模块化评价标准：成果 P、策略 S、调节 R、协作 C、学科实践 D、伦理实践 E。
- 出勤、完成率、按时率和课堂积分从评价标准中移除。
- 未提供观察机会的模块记 `暂不评价`，不计 0 或 1 星。
- 五星必须绑定任务化星级说明、证据、允许支持、反例和评分示例；星星不是独立测量工具。
- 自评、互评和师评按证据可见性设计角色版本，互评加入培训、校准和教师抽查。
- 取消 AI 动态改评价标准权重；测量版本冻结，预测模型系数独立更新。
- 验证加入概化理论/多面 Rasch、评分者严厉度、任务误差和使用后果；omega 只用于适合的单维反映性量表。

### 尚需实证

- 首个信息科技单元的评价方案、评价指标、星级表现说明和评分示例库。
- 不同教师、任务和学校下的评分稳定性及标签噪声。
- 评价标准是否真正促进反馈、修订和学习，而不只是增加评分负担。

## 第 5 轮：诊断、分层与教学干预

### 审查问题

预测之后能否形成正确支持？A/B/C 是否错误地把知识、完成、设备和调节问题压成一个轴？

### 主要发现

1. 完成信号高不等于掌握低，不能仅因逾期或未完成把学生降为 C。
2. R47、R66 和 R76 指出诊断到行动仍是学习分析的薄弱环节；显示数据不会自然产生有效教学。
3. R78 的中学生随机试验显示 GenAI 支架对不同结果的作用不一致，不能笼统宣称 AI 反馈有效。
4. 人本系统需要师生纠错、共同设计、使用透明度和对不可靠输出的控制 [R46]。

### 已修改

- `support_need` 改为范围更窄的 `completion_support_signal`。
- 内容 A/B/C 主要依据可比掌握证据；完成信号只触发计划、提醒、访问或教师核查支持。
- 新增多维证据画像和版本化支持处方，如概念重教、范例、计划检查、访问支持和小组协调。
- 支持完整记录建议、教师选择、投放、学生使用/拒绝、完成和近端结果，投放不等于有效。
- 教师和学生可提交数据/建议纠错，原始事件不被直接覆盖。
- DeepSeek 只起草教师可审核的资源或反馈；每类 AI 支架分别验证目标结果和副作用。
- 模型上线检查取消任意固定 ECE/Brier 公平阈值，改由先导数据、教育后果和区间精度预注册。

### 尚需实证

- 每种支持处方的可实施性、教师负担、学生接受和近端效果。
- A/B/C 阈值与资源容量、误报/漏报成本之间的决策分析。
- 影子模式中教师是否正确理解并使用多维建议。

## 五轮后的关键变化

| 原设计倾向 | 审查后设计 |
| --- | --- |
| 日志特征映射到 SRL/投入构念 | E0-E3 分级，代理必须先做效度研究 |
| 日/7/30 日聚合为主要过程数据 | 加入环节、阶段、单元和序列验证 |
| 22 个特征默认一起建模 | F0-F4 递增块、增量效度和消融 |
| 一张跨任务通用评价标准 | 按任务观察机会启用模块 |
| 参与责任作为评价标准维度 | 作为机会校正行为事实，退出评价标准 |
| AI 动态修改评价标准权重 | 测量权重冻结，预测系数独立版本化 |
| 完成风险可直接导致 C 层 | 完成支持与内容难度解耦 |
| A/B/C 同时承担诊断和投放 | 多维诊断 + 支持处方 + 内容投放带 |
| 显示建议即完成闭环 | 记录选择、使用、拒绝和近端结果 |

## 当前结论

修订后的方案在构念边界、机会分母、时间过程、特征防泄漏、评价标准用途和诊断到行动方面更严谨，但仍是待验证设计。当前不能宣称 STRATA 已经有效测量 SRL、评价标准已经具有信效度、模型可以稳定跨校泛化，或动态分层能够改善学习结果。

下一阶段应先做：新旧学习记录兼容写入与核对、一个信息科技单元的评价方案和评价标准试评、E2 轨迹效度子研究、F0-F3 回顾性影子验证。四项完成前不应上线自动分层或撰写效果性结论。
