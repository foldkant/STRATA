# 学生评价、积分与奖章设计

> 状态：产品与数据边界已确认，`DATA-02B` 已完成积分流水、冲正和缓存对账底座；`DATA-01C` 已迁移抢答、点名和聊天扣分，其他课堂入口继续推进，评价标准和核心素养框架安排在 `EVAL-01`。  
> 依据：[学生行为分析与 AI 隐性动态分层设计报告](student_behavior_ai_stratification_design.md)。

## 1. 总体原则

平台同时存在五类含义不同的数据，禁止相加为一个综合总分：

| 数据 | 用途 | 是否进入主分层模型 |
| --- | --- | --- |
| 测试与任务成绩 | 描述具体知识点、任务和作品的正式结果 | 可按计划时点、共同测量和版本规则使用 |
| 五星评价标准 | 当前任务中的成果、策略、调节、协作和学科实践反馈 | 仅经验证、版本可比的结果可使用 |
| 核心素养证据画像 | 按学科框架汇总有来源的任务与测评证据 | 只有达到 E3 验证等级的构念结果可使用 |
| 课堂激励积分与奖章 | 课堂反馈、正向激励和实施记录 | 主模型禁用，只作实施和敏感性审计 |
| AI 内容投放带与支持建议 | 任课教师内部教学决策 | 学生不可见，不是学生评价总分 |

积分和奖章不能命名为掌握度、能力、核心素养或学习态度，也不能用于公开排名。

## 2. 积分流水

目标模型为 `ParticipationPointLedger`，采用不可变流水，不直接覆盖历史：

- 学校、学期、课程、班级、课堂和学生作用域。
- 来源事件、原因码、积分增量、执行教师和发生时间。
- 修正通过反向流水完成，不能编辑原记录。
- `StudentProfile.score` 在迁移期只作重算缓存。
- 同一来源事件只能产生一条有效流水，防止刷新和 WebSocket 重试重复加分。
- 不同模块执行同一余额下限和单次增减上限，不允许一处截断、一处产生负数。
- 缺勤、请假、网络离线、未投放任务和数据缺失不自动扣分。
- 教师可从学校批准的原因码中选择并在限定范围内调整分值；重大扣分必须二次确认。

学生可以看到自己的当前积分、来源明细和冲正结果；任课教师可以查看本人任教班级。默认不提供班级、年级或学校积分排行榜。

## 3. 奖章

奖章是版本化规则产生的可核验学习经历，不是永久能力标签。第一批建议：

| 方向 | 证据要求 |
| --- | --- |
| 持续完成 | 连续完成实际投放的必做任务 |
| 及时行动 | 多次按截止时间提交已投放任务 |
| 认真修订 | 根据反馈形成可核验的新版本 |
| 主动求助 | 在明确可求助的挑战片段中主动求助 |
| 协作贡献 | 按公布分工完成共同任务贡献 |
| 优质反馈 | 同伴反馈具体、可执行并引用任务证据 |
| 项目推进 | 完成计划内里程碑、日志或阶段成果 |

`BadgeDefinitionVersion` 保存名称、说明、作用域、评价依据、有效期和版本。`StudentBadgeAward` 保存学生、定义版本、证据引用、获得时间、授予方式和撤销记录。

禁止使用“优等生”“低水平进步”“A 层达人”“计算思维大师”等可能暴露内容带或超出证据范围的名称。课程自定义奖章统一标记为“课堂荣誉”，不能冒充校级核心素养认证。

## 4. 学生评价方面

学生评价由六个方面构成，但不强制每项任务同时评价全部方面：

1. 学业结果：题目、测试、作品和项目任务的正式评分。
2. 学习过程事实：机会校正完成率、按时率、有效修订和资源使用。
3. 策略与调节：计划、方法选择、监控、求助、调整和反思。
4. 协作与反馈：分工、共同成果贡献、协调和反馈质量。
5. 项目与创新：问题解决、设计实现、迭代和表达展示。
6. 学科核心素养：由学科任务、评价标准和测评工具提供的有限证据。

出勤、点击量、在线时长、聊天数量和课堂积分只作为行为事实或教学情境，不进入五星评价标准，也不与成绩相加形成“综合素养分”。

## 5. 学科核心素养

每个学校的每个学科维护版本化 `SubjectCompetencyFramework`。信息科技首个框架包含：

- 信息意识
- 计算思维
- 数字化学习与创新
- 信息社会责任

每个评价指标、题目和表现任务通过 `CompetencyEvidenceBinding` 显式关联一个或多个指标。`StudentCompetencyEvidence` 保存学生、学科、任务、指标、评价者、评价标准/工具版本、证据和时间；不得从普通页面访问量直接推导核心素养。

教师自建或 AI 生成评价标准默认属于 `course`，学生端应显示为“本任务表现”。只有经过学科专家审查和测量验证的 `school/analysis` 版本才能显示正式构念名称并用于跨任务趋势。

AI 可以辅助生成条目、整理证据和提示缺失，但不能动态修改已发布评价标准权重，也不能把预测结果回写成核心素养测量值。

## 6. 可见范围

| 内容 | 学生 | 任课教师 | 学校管理员 | 超级管理员 |
| --- | --- | --- | --- | --- |
| 本人积分和流水 | 可见 | 任教班级可见 | 本校聚合及审计 | 不看个体 |
| 本人奖章和证据 | 可见 | 任教班级可见 | 本校聚合 | 不看个体 |
| 成绩和教师反馈 | 本人可见 | 任教班级可见 | 按职责聚合/审计 | 不看个体 |
| 自评、互评、师评 | 本人任务结果可见；互评者默认不公开 | 原始分角色证据可见 | 聚合质量 | 不看个体 |
| 核心素养证据画像 | 本人可见，显示来源、时间和证据充分性 | 任教班级个体与聚合可见 | 本校聚合 | 去标识化跨校聚合 |
| E2 理论代理 | 不显示为能力结论 | 标注“代理指标”和竞争解释 | 只看聚合质量 | 只看研究监测 |
| A/B/C、概率和风险 | 不可见 | 任教范围内私有审核 | 默认聚合 | 去标识化聚合 |

学生档案可以展示个人积分与奖章入口，但核心素养页面不混入积分，且任何页面都不展示积分排名、A/B/C、风险概率或组内能力构成。
